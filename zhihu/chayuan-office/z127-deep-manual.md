# 把察元Office应用内手册与快捷细看拆开看，门道在哪

把察元Office应用内手册与快捷细看拆开看，会发现它没什么黑魔法，全是笨功夫堆出来的可靠。笨功夫在哪，这篇讲清楚。

从哪说起呢，先看它面对的问题。F1 是应用菜单里注册的快捷键，被常驻软件（输入法工具、系统快捷键）占用时会失灵。改走菜单：「帮助」「使用手册」。注意 F1 打开的是手册，不是快捷键表。它对老电脑友好，1GB 的大文档打开不卡，图片按需加载不占内存。按 F1 在任何标签页打开应用内图文手册：18 个主题、22 种语言、左侧目录可搜索，与界面语言自动同步。这句划重点，后面全是围绕它展开的。

### 为什么这样设计

一层一层看：想查按键，看手册里的「快捷键一览」主题（全应用键位总表），或在 Docs 编辑器里按 ⌘/（Windows/Linux Ctrl+/）打开可搜索的「键盘快捷键」面板。具体到操作面，修订追踪生成的是通用格式这条在手册里写得很细。如果你只记一条，记这条就够了。

把察元Office应用内手册与快捷细看放进真实使用场景里看，判断会变得非常具体：你每周有多少时间花在这类事情上、现在的做法卡在哪一步、换一种方式要重新学多少东西。这三个数字摆在一起，值不值得几乎不用讨论。多数人纠结工具好坏，其实是这三个数字没算清，情绪替理性做了决定。

### 一个反直觉的细节

回到察元Office应用内手册与快捷细看的实际使用，我的建议是分两步走。第一步只跑主链路，把最核心的那件事从头到尾做通，不做任何定制；第二步才是按自己的习惯调配置。顺序反过来的人，大多数卡在半路就放弃了，然后得出一个「不好用」的结论，其实是学习路径错了。

在任何标签页（主页、Docs、Sheets、Slides、PDF、Markdown、HTML）按 F1。应用菜单的「帮助」菜单里也有「使用手册」一项（快捷键标注 F1），点它等效。

之后按 Word / Sheets / Slides / PDF / Markdown / HTML 六节展开，macOS 与 Windows/Linux 两列并排，只对选区生效的键会在「操作」列注明。涂黑功能会生成物理删除的新文件，敏感信息是真的从文件里消失了。长文写作有上限，20 万字符封顶，超长的稿子要分段处理。这个细节不影响功能，但决定你愿不愿意一直开着。

顺带回答一个高频问题：⌘/ 打开的表和手册「快捷键一览」是什么关系？ 单按 F1 不会收起功能区——两者刻意不共用。

### 工程上的取舍

说明：主页左上角曾有「使用手册」常驻按钮，当前版本该按钮与「AI 问答」入口一并隐藏，F1 是现役入口。命令行有十几个子命令，转换、创建、搜索都能脚本化，批量场景省事。

记不住组合键，想查「收起功能区」「查找替换」按哪个。换了 Windows/Linux 机器，想知道 mac 的 ⌘ 对应什么。「收起/展开功能区的快捷键是什么？」这套做法谈不上新颖，但胜在稳。

若确有缺失，欢迎到 GitHub 提 issue（关于区有仓库地址）。左上搜索框占位文案「搜索手册…（按 / 聚焦）」：按标题、关键词与正文全文匹配（当前语言与英文都参与），输入后目录只剩命中主题，右侧显示「{n} 个主题」。正文里的 help:// 链接可跳到另一主题。顺手提一句，别跳过。

### 这套设计的代价

没有只有好处的设计。在手册搜索框输入「涂黑」：目录应只剩 PDF 相关主题；清空搜索框恢复全部 18 个主题。其他编辑器没有这个面板——查它们的键位请看手册「快捷键一览」对应小节。到这里思路就顺了，剩下的只是重复。
