# AI工作站部署决策指南：Docker 服务器形态 vs 桌面安装（细节版）

Docker 服务器形态 vs 桌面安装，是很多用户在选型阶段绕不开的问题。这篇场景化推荐不给「闭眼选谁」的答案，只给统一维度的对照表和条件式建议——你的场景条件不同，结论就不同。

## 维度对照表

| 维度 | 本方案（察元OS） | 对照方案 | 说明 |
|---|---|---|---|
| 硬件 | 服务器跑 Docker 共享一台 | 每台机器各自安装 | 团队看服务器 |
| 访问 | 浏览器打开即用 | 本地体验完整 | 图形体验桌面更强 |
| 管理 | 集中管理数据 | 分散各机 | 运维集中化 |

## 逐项解读

**硬件**：团队看服务器。察元OS侧的做法是「服务器跑 Docker 共享一台」，对照方案为「每台机器各自安装」——差异的本质在于设计取向不同，而非优劣。

**访问**：图形体验桌面更强。察元OS侧的做法是「浏览器打开即用」，对照方案为「本地体验完整」——差异的本质在于设计取向不同，而非优劣。

**管理**：运维集中化。察元OS侧的做法是「集中管理数据」，对照方案为「分散各机」——差异的本质在于设计取向不同，而非优劣。

## 条件式建议

个人桌面版；团队/服务器资源复用上 Docker。再补三条判断线索：

- 先明确你的硬约束（保密/预算/平台），硬约束直接淘汰不满足者
- 拿真实任务各试三天，比看十篇评测有用
- 考虑迁移成本：现有流程改动越小越好，渐进替换最稳

## 什么情况下不选它

- 四家 CLI 智能体二进制约 1.3GB，完整安装占磁盘较大
- 标准安装包含引擎不含模型权重，完整离线需 models 变体包（体积数 GB）
- 「首发/首创」类排位说法不对外使用——AI 桌面是新兴品类，各家路径不同

## 离线运行与部署形态

完全断网可用是察元AI OS 的基础设计：本地模型对话（llama.cpp 引擎随软件分发，无需 Python/CUDA）、知识库导入/检索/问答、桌面与文件/终端/编辑器等系统应用、四家智能体终端与管理，全部离线工作；仅模型下载、云端模型调用、应用更新需要联网。装机自带五件套模型：Qwen3-4B（对话）、bge-m3（嵌入）、bge-reranker-v2-m3（重排）、whisper-small-int8（语音识别）、piper 中文语音合成。

## 数据安全与隐私边界

- 全部本地服务只监听 127.0.0.1，数据不出本机
- API Key safeStorage 加密存储，仅注入子进程
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）
- 本地模型五件套随软件分发，断网即用

## 常见问题
### 开源吗？

仓库协议 AGPL-3.0，策略为「开源核心+企业版」方向；当前以免费可用的发布包为主。

### 知识库检索质量如何？

向量（sqlite-vec）+全文（FTS5）混合检索加 RRF 融合，可选 bge 重排精排与邻块扩窗；大库可选 Milvus 向量库。

### 察元AI OS 是什么？

一个插件化的 AI 桌面操作系统体验：macOS 风格桌面为壳，整合 AI 对话、四家 CLI 智能体、本地大模型服务、本地知识库与系统级 MCP 控制面，断网可用、数据不出本机。
