# 合法动作回捞：全文扫描与词边界防误配

轮到黑棋走某步关键棋。模型洋洋洒洒推演了三百字，JSON 碎在半路，截断补尾没救回来，正则抽取也落了空。这手棋是不是只能判废？还差一步：合法动作回捞。它是解析容错链里不丢模型本意的最后一环，拿着裁判给的合法动作清单，回到模型那三百字里做全文扫描，把它亲口提到的动作认领回来。这篇把回捞原理、词边界防误配与「绝不产非法串」的底线讲透。

## 回捞的基本原理

合法动作回捞的逻辑起点是一份清单：viewFor 给模型喂局面时，显式附上了当前的全部合法动作。这份清单是有限集合，成员由裁判引擎担保。回捞做的事，是把模型整段输出与这份清单求交集——逐个拿清单成员去全文里做精确词命中，命中者即候选。它不猜格式、不修结构，因为格式与结构已经在前几级被证明救不回来了；它只回答一个问题：模型有没有用任何形式提到过合法动作。

这个思路跟前面的解析环节有本质区别。解析是自上而下，从文本猜结构；回捞是自下而上，从合法清单反向验证文本。清单这一侧是确定无疑的，不确定性全在文本一侧，把确定的一侧当锚，出错的空间就被压到最小。

它和正则抽取的区别也在此：正则找的是 JSON 的形状，回捞认的是词汇本身。前者关心「这段文本像不像一个结构」，后者关心「这串字符是不是裁判眼里的合法动作」。形状可以造假，词汇被清单锚死，这就是自下而上验证的可靠性来源。

## 词边界：防的是前缀误配

裸的子串匹配在动作串上会出事。设想合法清单里有形如 g4g5 的动作，而模型文本里写的是 g4g55——可能它想走一条更长的线，也可能纯粹是笔误。裸匹配会在 g4g55 的前四个字符里命中 g4g5，一步并不合法的动作就这样被拼凑成了「合法命中」，语义错了一截。词边界的做法是要求命中位置两侧都不是字母或数字：g4g55 里的 g4g5 两侧贴着字符，判为嵌在更长词内部，不算命中；文本里独立出现的 g4g5 才算真命中。

这条规则防的是一类系统性的坑：动作串天然由字母数字组合而成，前缀重叠在棋类记谱里司空见惯，坐标相邻的动作更是只差一位。没有词边界，回捞就成了误配制造机，捞回来的动作看似合法，实则不是模型指的那一个。

清单本身的规模也让这件事不能含糊。小棋盘围棋的合法落点有几十上百个，扑克的合法动作是按轮次有限的牌型与下注选择，麻将的出牌与立直声明各成一格。清单越大，精确词命中越要小心，词边界从规则上保证了匹配粒度恒定，不随玩法清单的大小而变形——11 款玩法共用同一条回捞逻辑，靠的就是这层与具体记谱法解耦的设计。

## 为什么取最靠文末的命中

模型的语言习惯是先分析、后收束，结论压在输出尾部。深度思考档更是明确要求三段式：分析段推演三条候选线，那可是至少三个动作；结论段才定板。全文扫描很可能命中多次：开头提一条线、中段提一条线、结尾拍板。多个命中里选哪个？取最靠文末的那个，命中最终意图的概率高。这是从模型的表达习惯反推的启发式，不是数学保证，但方向可靠：人写文章把结论放最后，模型学人说话，也把拍板放在收尾。

## 绝不产非法串

合法动作回捞有一条铁律：只认合法清单成员，绝不产出非法串。它在清单与文本之间做匹配，清单里没有的动作，无论模型写得多像那么回事，都不会被转写成合法近似。这条底线把回捞与「帮模型圆场」划清了界限：圆场是启发式代走的事（能挡杀就挡、能吃就吃，麻将取缺门里价值最低的一张），而且回捞失败、重试回喂也失败之后，才轮得到它出场。回捞产出的一切动作天然合法，送进裁判的 apply 不会撞墙，也不会把局面推向规则之外的歧途。

## 与代走的分工

回捞与代走经常被混为一谈，其实分工明确。回捞的动作来自模型自己的文本，是它亲口提过的，属于尊重模型意图；代走的动作来自启发式规则，与文本无关，属于保对局不中断。顺序也定死了：解析链、回捞、重试回喂一路走完，最后才是代走；代走计数超限判负，兜底的链条每一环都比前一环更不由模型做主。

分工之外还有一层约束机制：代走不是无限供应，同一玩家代走计数超限会被判负。这条红线让兜底不变成纵容——模型可以抽风一手，不能整局躺平。回捞则不占这个额度，因为它救回的动作本来就是模型的，算模型自己走的棋。

## 边界

回捞的判断力有上限。取文末命中是启发式，模型在防守推演里提到的动作未必是它的最终选择，偶尔会认领错——认领错的代价有限，毕竟认领的是合法动作，局面照常推进。输出里一个合法动作都没提到的模型（比如通篇在评价局面却忘了出招），回捞无能为力，只能走重试与代走。还有一层：协议里的 comment 附着在 JSON 结构上，JSON 碎到需要回捞，这一手多半也没有解说可看，对局室少一条气泡，属于可感知的小损失。

### 合法动作回捞和启发式代走有什么区别

区别在动作的来源。回捞的动作来自模型自己的文本，是模型亲口提过的；代走的动作来自启发式规则，与模型文本无关，是系统替它下的。前者尊重模型意图，后者保对局不中断，回捞在前、代走在后。

### 词边界会不会漏掉真的命中

极端情况可能：模型把动作写成与标点粘连的变形，可能被边界规则拒之门外。但漏掉的代价只是落到重试环节，误配的代价却是走出语义错误的棋，两害相权，规则偏向保守是对的。

### 回捞在整条容错链里排第几

排在正则抽取之后、重试回喂之前。前面六级清洗处理的是格式，回捞处理的是词汇；格式救不动了，才动用清单去全文里认领。它之后是重试与代走，那两环已经不再指望从模型原文里找到答案。

### 回捞的成功率有单独统计吗

协议画像统计的是 JSON 格式遵守率与平均耗时这类协议习惯，回捞命中率没有单独成榜。想知道某个模型的回捞频率，翻对局记录看重试与代走的次数分布，能看出大致轮廓。

合法动作回捞体现的是一种工程态度：在放弃之前，把模型已经说过的话再听一遍。它不炫技，只是拿一份清单、一条词边界、一个文末偏好，把散落在散文里的意图捞回棋盘。容错链的每一环都遵循同样的气质：先尊重模型，再兜底，绝不让一局棋卡在一次格式事故上。
