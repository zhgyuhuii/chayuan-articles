# 本地模型测试：Ollama模型横向摸底

显卡在机箱里吃灰，硬盘里躺着七八个本地模型，你知道它们参数各不相同，却说不上谁更能打——本地党的日常困境。跑分脚本测的是答题能力，问答测得再花哨，也不如让它们真刀真枪下几盘棋。本地模型测试这件事，察元竞技场给了一套零成本的摸底流程：Ollama 免 Key 直连、断网可玩、对局不花一分钱 API 费，你可以放心大胆让模型们互殴一整晚。这份测试还有个隐藏好处：过程本身就有乐子，看着两个本地小模型在棋盘上互相犯错，比看任何评测文章都直观。

## 这件事原来的难处

本地模型的横向对比，一直缺个像样的考场。

评测脚本门槛高。会跑 Ollama 不等于会写评测，要自己设计任务、统计得分、控制变量，很多人卡在第一步就退了，回头只能靠社区博主的体感结论。

跑分类评测不对味。问答跑分考的是知识量，本地模型在这上面被云端大模型甩开几条街，测了伤心。但决策能力——一步一步推演、记住前面的得失、在压力下不出昏招——这类考察在跑分里很少见。

成本顾虑。接云端模型做对比动辄烧额度，舍不得放开跑，样本永远不够。

还有对比环境不一致的老问题。社区里的结论东一块西一块，别人用他的卡、他的版本、他的玩法，你照着选模型，到了自己机器上经常不是那回事。

## 用竞技场怎么做

第一步，接 Ollama。本机装好 Ollama，拉下你想对比的几个模型；察元竞技场设置 ＞ 模型配置里选 Ollama，免 Key 直连，LM Studio、Xinference 这类本地推理引擎同样支持。接上之后断网也能玩，整条链路不出本机，Key 都不用申请。想接云端模型做对照组也行，85 家厂商目录点选即填，但记住云端那份是计费的。

动手前先认清自己机器的斤两。显存决定能跑多大的模型，硬盘决定能养几个；摸底要的是横向可比，挑几个都跑得动的中等模型，比凑一大一小有意义得多，也不必贪大。

第二步，设计对局矩阵。别拿两个模型单挑了事，批量选模型建一场锦标赛，循环赛自动排程，积分榜实时刷新，打完直接出冠军。玩法建议从五子棋和中国象棋起步：规则清晰、胜负干脆，最能拉开差距；然后加一场德州扑克，看看小模型在不完全信息里的表现——看牌、记牌、下注，这是跑分测不出来的维度。矩阵还能继续加码：围棋 9 路小棋盘节奏快，适合大量场次；军棋翻翻棋运气成分高，专测模型面对随机性的心态；日麻立直藏在大厅隐藏入口里，引擎完整可用，想压轴考规则理解，可以翻出来用。

第三步，三个视角一起看。只看输赢会漏掉大半信息。视角一是 TrueSkill 积分：多打几轮，段位分层自然浮现，谁是老实人谁是搅局者榜上见。视角二是协议画像：本地模型的出招格式纪律差异比云端大得多，JSON 格式遵守率低、平均耗时长的模型，接到业务里也是同样的脾气。视角三是思维链气泡：小模型的推理链经常半路短路，你能当场看到它是真在想，还是照着语料背棋谱。三个视角交叉着读才有意思：积分高但遵守率低的，赢在容错兜底多；积分平平但耗时短的，适合当快节奏场景的备选。

第四步，记录并复测。把每轮积分榜截图存档，棋谱支持 JSON 导出，想复盘哪手昏招随时翻。更进一步，把结果整理成一份摸底报告：每场积分榜截图、协议画像数据、你标注的性格关键词，配上棋谱归档。这份报告会随时间增值——下次新版本发布、新模型开源，同一套矩阵再跑一遍，纵向对比就出来了。摸底期间记得关掉无关的后台任务，显存被别的程序占一块，成绩单就失真了，这是本地测试特有的坑。

## 适合谁、不适合谁

适合：手上有消费级显卡的本地部署玩家、要给内网环境选离线模型的运维、想理解参数量与决策能力关系的工程师和学生；写本地模型横评内容的创作者也合适，这套流程本身就是一篇文章的骨架。不适合：想借本地模型打上高手段位的棋友——本地小模型棋力有限，出招跑偏是常态，系统的代走兜底会频繁介入，观赏性要打折扣；硬件吃紧的旧机器也要掂量，模型长考的时间由你的显存与算力决定，急脾气慎入。

## 常见疑问

### 真的零成本吗

是。软件 MIT 协议开源免费，本地推理不产生 API 费用，电费网费自理；偶尔想拉云端模型做对照才产生 API 费用，按需开关即可。这也是本地摸底的优势：可以不限量地跑，样本管够。

### 需要什么配置的机器

能跑起 Ollama 对应模型的机器就行，显存越大、模型越快。小参数模型核显也能拖动，代价是长对局里历史变长时容易顾此失彼，出招质量明显下滑。拿不准就从最小的模型试起，跑通流程再逐级加码，试错本身不花钱。

### 本地模型打得过云端大模型吗

同台打过才知道，别信任何人的定论。你的显卡、你的玩法、你的对局样本，结论只对你自己成立——这正是自己摸底的价值。好奇的话，在锦标赛里混入一个云端模型当标尺，本地梯队的层级立刻看得更清楚，只是那一部分的额度要另算。

### 对比结果能给别人看吗

棋谱 JSON 导出后随便分享，积分榜可以截图。注意注明是你的个人对局样本，别写成普适结论，样本量摆在那里。分享时把硬件环境一并写上，别人复现时才有对照的基准。

### 长对局会不会越下越差

会有这个趋势。对局信息靠着法历史喂给模型，越到后面上下文越长，小参数模型容易忘事、重复犯错。观察这个退化过程本身，也是摸底的一部分——它告诉你哪个模型只适合短任务，哪个模型能撑住长流程。

本地模型的价值，不该由别人的跑分表来定义。把它们拉上同一张桌，让积分榜说话、让协议画像说话、让思维链气泡说话，一个周末的挂机就能换来一份属于自己的摸底报告——零成本这件事，意味着你随时可以推翻重测。
