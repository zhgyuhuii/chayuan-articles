# 向量数据库入门指南：知识库应用左栏输入库名即建

向量数据库这个词自带门槛感，其实在你自己的电脑上，它就是一个装着「文档切块向量」的库文件。这篇从知识库应用的视角，把向量怎么来、存哪里、检索时发生什么讲白。

## 什么是向量数据库

向量数据库存的是向量：文本切块经嵌入模型转成的数字序列，检索时按相似度找最近邻，语义相近的段落即使没有共同关键词也能被找到。它和传统数据库的差别一句话能说清：SQL 按条件精确匹配，向量库按语义模糊接近——找「客户对交付节奏的反馈」，关键词匹配可能漏掉写着「项目节奏太赶」的段落，语义检索能把它捞出来。察元AI OS（Chayuan AI OS，简称察元OS）把这件事包进了知识库应用。这套 AI 桌面操作系统以完整桌面环境为壳，本地大模型五件套、引用式知识库、17 家外部 CLI 智能体管理、宠物群聊多模型讨论、系统级 MCP 控制面都在壳内，支持 Windows/macOS/Linux（银河麒麟、统信 UOS）与 Docker 云桌面形态，断网可用、数据不出本机。

## 核心口径一张表

| 口径 | 内容 |
|---|---|
| mcpTools | 86 个 MCP 工具（2026 年 10 月实测） |
| kbPort | 52582（知识库对外服务，固定端口） |
| storeCats | 插件、技能、MCP 插件、智能体、技能包五大类 |

与向量库关系最直接的是 kbPort 一行：知识库对外服务固定走 52582，WPS 加载项等外部引用方都认这个端口。端口固定意味着排障时有明确的靶子——引用不到知识库，先探这个端口通不通。

## 库文件与向量从哪来

每个库在磁盘上就是 <数据根>/storages/chatop-kb/<归一化库名>/ 一个目录：kb.db 装着文档档案、分块、全文索引与向量，files/ 存原始文件，系统按该目录扫描库清单。上传的文档点「加载」后才解析与向量化，切块由嵌入模型转成向量写入库中。

设置页里管着两件跟向量库直接相关的事：向量库可选本地或 Milvus——换嵌入模型必须重建索引，大库上 Milvus，这些运维动作都收在设置页。换言之，嵌入模型一换，旧向量全部作废，这是所有向量数据库的共同约束，不是缺陷。

切块的策略也直接影响检索质量：块太大，一段里混多个主题，命中了也不精；块太小，上下文被切碎，模型拿到的是碎片。应用内置的切分不用你调参，但理解这一层，有助于判断「为什么没检索到」——问题多半出在原文写法而不是库坏了。

## 检索时发生什么

右栏检索测试台就是 kb_search 工具的所见即所得：向量加全文加可选重排的混合检索。向量负责语义相近，全文负责关键词精确命中，重排负责把两者结果再排一次序。初检索追求召回，宁可多捞；重排负责精排，把最相关的顶上去。智能体侧对应三个工具：kb_list 列出本机全部库，kb_search 与 kb_read_doc 可带 kbId 参数查指定库，不带时默认查 default。

## 分库与多库

- 多库并存，独立存储互不干扰，秒建秒删
- 按客户分：给每个客户建独立资料库，检索范围天然隔离
- 按类别分：制度归制度库、技术归技术库，查制度不会被代码片段打扰
- 串联离线：全量离线包含五件套权重，约 4.7GB，从官方渠道获取

分库的本质是控制检索的候选集：候选集越小越干净，回答被污染的概率越低。这也解释了为什么秒建秒删重要——分错库的纠正成本接近零，你才敢按业务精细地分。实践中可以先粗分两三个库跑起来，用两周再看哪里查询串了味，届时再细分成也不迟。

## 先把边界放桌面上

- 内存设备在 8GB 这一档的，对话模型开一个就好，复杂任务受限
- 龙芯平台适配还没轮到；视频生成不在本地，由云端路由跑
- 用云端厂商的模型，手里得有自己的 API Key
- Docker 云桌面与跨终端互联偏进阶，得花点动手功夫

向量库本身对硬件不挑，挑的是内存——上面几条多数都跟内存预算有关，先算清再动手。

## 数据与安全设计

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用
- 远端调用以远端访客身份过对端权限门并留审计
- 清除桌面数据属破坏性操作，操作前有警示

对向量库而言，安全模型很简单：库文件在哪个盘、目录给谁可读，向量数据的边界就在哪里，没有中间商。

## 关于向量库的几个疑问

### 向量检索这步要不要联网？

不要。嵌入、向量检索、重排全链路都在本机完成，断网可用、数据不出本机；本地服务只监听 127.0.0.1 回环地址。需要联网的只有云端厂商模型那条线，与向量库无关。资料涉密的场景，这条边界就是决定性的。

### 向量数据落在磁盘哪个位置？

就在前文说的库目录里：kb.db 与 files/ 都在 <数据根>/storages/chatop-kb/<归一化库名>/ 之下。数据目录自选意味着整个系统可以装在非系统盘，换机迁移就是拷目录；覆盖安装与更新也不动数据目录。想备份向量成果，备份这个目录就够。

## 一句收束

向量数据库不需要你先成为数据库管理员：库建在应用里、向量长在文件里、检索过程看得见。选型时盯住两点——嵌入模型能不能换、大库有没有 Milvus 这条路——就够避开大多数坑。其余细节，回看前文「库文件与向量从哪来」一节即可。
