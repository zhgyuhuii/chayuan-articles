# 建筑工程行业怎么用察元Office：从痛点到落地

建筑工程行业的文档与信息工作有其固有节奏：跨部门数据与引用需要反复核对出处。察元AI Office在建筑工程场景下的定位，是把可标准化的环节交给工具、把判断留给从业者的「人机协同」。本文按痛点→能力→落地步骤→边界的顺序，给出建筑工程行业的完整应用路径。

## 建筑工程行业的典型痛点

- 跨部门数据与引用需要反复核对出处
- 文档量大、格式要求严，人工处理占用大量时间
- 多岗位协作时版本混乱、批注流转低效

## 对应的能力组合

- **Markdown 编辑器**（Markdown编辑器）：Tiptap 块编辑器：标题、列表、表格、图片、代码块所见即所得，存储仍是纯 Markdown 文本。
- **浏览器 SaaS 形态**（在线办公）：除桌面版外提供浏览器 SaaS 形态（Fastify BFF + Docker：Postgres + MinIO），团队可私有化部署网页版。
- **模板与字体**（办公模板）：空白文档模板（docx/xlsx/pptx）与内置字体（Liberation/Carlito/Caladea/Noto CJK），字体目录可下载扩展。
- **导出 PDF**（导出PDF）：docx/xlsx/pptx/md/html 一键导出 PDF，本地渲染，版式与打印一致。

## 落地四步

1. 盘点本岗位高频文书/信息任务，挑最耗时的两个作为切入口
2. 按法务/合同管理员场景的工作流试跑一周，记录节省的环节
3. 把常用任务固化为助手或规则模板，团队复用
4. 建立人工复核节点：工具产出 → 从业者裁决 → 定稿

## 合规与边界

- 涉密与敏感材料遵循本单位管理规定，必要时使用离线部署形态
- 网页版 SaaS 形态需要自行部署维护（Docker + 数据库）
- 行业判断责任始终在人，工具输出作为参考

## 离线运行与部署形态

官方安装包默认开启匿名 GA4 统计（不收集文档内容、文件名、路径与身份），设置里一键关闭；源码自行构建的版本零遥测。

## 数据安全与隐私边界

- 安全工程：全窗口 contextIsolation + sandbox、IPC schema 校验、外链协议白名单、无硬编码密钥
- 文档打开/编辑/保存全程本机完成，不经任何服务器
- 遥测仅匿名统计且可一键关闭，永不收集文档内容与身份信息
- PDF→Word/PPT/Excel 转换与 OCR 均为本地引擎，扫描件不上传

## 费用与授权的边界（如实说明）

开源 Apache-2.0 + 可选授权支持（桌面版 90 天免费试用后温和提醒）。免费部分：apps 编辑器本身免费开源、可自行构建；官方安装包提供 90 天免费试用期。付费部分：试用期满后每日一次购买提醒弹窗（可手动关闭）+ 主页每 30 分钟温和提醒；离线 HMAC 短序列号激活，绑定机器指纹本地验证，无需联网激活服务器

## 常见问题
### 低配电脑能跑吗？

常规办公 4GB 内存可用；AI 本地推理建议 16GB 内存或独立显卡跑小模型，或直接配云端 API。

### 遇到 bug 去哪反馈？

GitHub 仓库提 issue，或通过官网渠道反馈；项目有 75 个端到端测试用例保障迭代质量。

### 扫描件能变成可编辑文档吗？

可以：先本地 OCR（系统引擎，不上传）生成可选中文字层，再一键转 Word/PPT/Excel 继续编辑。
