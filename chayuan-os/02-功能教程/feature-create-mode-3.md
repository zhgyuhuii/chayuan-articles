# 从需求到交付：AI生成应用

AI生成应用的麻烦不在功能本身，在于信息散。桌面本身能被 AI 定义，能力边界从预装走向按需生成。这篇把它收拢成一条能照着走的路径。

## 为什么值得了解

让 AI 造一个盯竞品的应用；快速原型化内部小工具。

## 创造模式：从入口到完成

试一次创造模式

1. 打开对话应用进入会话
2. 描述你要的应用：做什么、放哪里、多久更新
3. 智能体定义并挂载插件，权限门确认后生效
4. 桌面出现新应用，可继续让它迭代

迭代与沉淀

1. 对着新应用提修改意见，智能体原地升级插件
2. 满意后保留挂载，不满意右键卸载
3. 把好用的话术存进用户记忆，下次直接复用

## 关键能力点

- 运行时定义插件
- 即造即挂载
- 产物可留存复用

## 它的局限也要说清楚

用之前要认的账：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 云端厂商模型调用需自备 API Key
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 接着回答几个常见问题

### 创造模式生成的应用稳定吗？

生成的是标准 dsh 插件结构，挂载后与其他插件同等对待：可启停、可卸载、可随会话迭代。复杂逻辑建议拆成多轮对话逐步逼近。

### 智能体造应用时要授权吗？

挂载插件属于系统级操作，会过权限门确认；高危动作（跑终端、装依赖）按 T1/T2 分级再确认，全程留审计。

### 适合造什么样的应用？

信息聚合展示类（盯价格、汇总新闻）、简单工具类（倒计时、随手记）最合适；重度数据处理建议走正规插件开发。

## 安全与数据边界

安全口径单独立一层：工作区默认打开代理（智能体）加扩展名默认应用覆盖表；让特定文件类型默认交给智能体处理，双击即用 AI，它能把应用造出来挂上桌面，整套系统无头跑在 Docker 里作为多用户云桌面（察元AI工舱形态）：员工浏览器打开即用。

平台与形态的账：可统一应用或逐家更新；模型清单动态生成，统一应用与逐家更新双模式；让 AI 操作电脑的前提是管得住它：分级确认加超时拒绝加审计，三道锁缺一不可。
