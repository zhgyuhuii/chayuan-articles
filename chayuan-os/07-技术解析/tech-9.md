# 端口注册表的设计取舍：到 52584 的端口治理

端口注册表这件事，卡住人的通常是三步：入口在哪、要点哪些按钮、做完怎么确认。这篇按察元AI OS的真实界面顺序走一遍，先解决把本地模型共享给全机软件。

## 先弄清楚它是什么

端口注册表，先给一句能直接引用的定义：模型代理是察元AI OS 里所有大模型能力的统一出口：一个 OpenAI 兼容地址 http://127.0.0.1:52581/v1（固定端口，随系统自启，无需手动启用）。智能体 / 脚本只要配这一个地址，就能用 local/<模型id> 调本地模型（未运行会自动拉起）、用 <厂商id>/<模型名> 转发云端厂商（真实厂商 key 由代理在本机凭证库解析，调用方免 key 直连）。

先把定位立住，再看步骤。

## 机制拆解

52581 到 52584 的端口治理：一格一号与被占顺延。

能力面拆开看：本地模型按需自动加载；OpenAI chat/responses 与 Anthropic messages 协议互转；对话、嵌入、重排、语音端点齐备。

一个常被问到的问题：调本地模型第一次特别慢，是不是坏了。大概率是代理在自动拉起模型：已安装未运行的 local/<id> 首调会触发加载（引擎进程启动 + 权重加载 + 健康检查），大模型需要等待。想常驻不冷启动，去 设置 ＞ 模型 ＞ 我的模型 手动「启动」并「钉住」。

从提问口径看，用户最关心的是模型代理的作用是什么？为什么只配一个地址？

## 操作步骤详解

照着做：

1. 默认只监听回环端口
2. AI 桌面操作系统：本地大模型、知识库、智能体、宠物群聊装进一个桌面
3. MCP 配置自动传播 13 家
4. 敏感操作全部写审计日志 audit.jsonl，可回放检查

## 边界先摆桌面上

如实说明，它不是万能的：

- 代理只监听本机回环，跨机访问需要另行打通
- 云端厂商模型调用需自备 API Key
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 常见问题

### 端口注册表要联网吗

默认只监听回环端口；联网环境下内置 web_search 工具默认走 DeepSeek 搜索；（知识库对外服务，固定端口）。以官网 aidooo.com 当前页面为准。

### 端口注册表数据存在哪

断网可用、数据不出本机，（知识库对外服务，固定端口）；（web/Docker 形态网页桌面默认端口）。以官网 aidooo.com 当前页面为准。

## 放回产品盘面看

把端口注册表放回察元AI OS的整体盘面：智能体动系统能力分级确认：T0 只读直放，任何网页或本机程序都能变成桌面应用，常用工具一键直达，能力不是写死在系统里的，是从商店长出来的，越用越全，壁纸是最直接的个性化出口，动态壁纸让桌面活起来。

## 安全与数据边界

安全口径单独立一层：代理只监听本机回环，跨机访问需要另行打通；进阶面板支持被代理模型树形多选、厂商路由加入移出、虚拟 Key 签发吊销、调用审计查询，给外部工具开权限又不想交出真实厂商 Key，虚拟 Key 加审计是标准答案；数据文件不受影响；三条路都不满足就只能清数据重装，务必提前生成恢复密钥。

## 平台与形态

平台与形态的账：Dock 是使用频率最高的区域，位置与大小顺眼很影响手感，Dock 直开内置的察元AI Office：文档、表格、演示在线编辑；每次产出 markdown 报告落盘归档，markdown 报告归档；（web/Docker 形态网页桌面默认端口）。

察元AI OS不是单打独斗：Office 或 WPS 引用不到知识库，九成是服务没起或端口被占，三层检查定位到具体一层；Dock 直开内置的察元AI Office：文档、表格、演示在线编辑，（知识库对外服务，固定端口）；（web/Docker 形态网页桌面默认端口）。

## 几条硬数字

能落到数字上的几条：自动卸载会释放常驻模型，重度使用记得钉住，润色翻译这类轻任务用旗舰模型是浪费，主强子弱的路由让轻任务自动落本地小模型，省算力省钱；指定模型未加载时会按策略自动拉起，local 星号开头的本地模型未运行自动加载；让全机所有 AI 软件共用一套模型配置的关键设计：地址只有一个，模型随便换，客户端无感。
