# 智能体记忆实操：全局记忆库三档作用域，一次走通

智能体记忆实操这件事，值不值得专门学一篇，看一个细节就够：三档作用域。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 是什么与为什么

为什么要有智能体记忆实操：换个智能体接班不用重新自我介绍，记忆全机共享是系统级的黏合剂。用户记忆的定位是全局记忆库三档作用域（global 全机、agent 单智能体、project 按项目）：

入口、步骤、验证三段看清，这事就顺了。

## 前置条件

- 桌面形态（察元AI OS）。「会话提炼」「跨智能体采集」走桌面主进程，浏览器打开的 web 形态点这两个按钮会提示「需要桌面形态（Electron 桥）」；手动添加与待确认队列在 web 形态可用。
- 会话提炼需先加载一个本地对话模型（设置 ＞ 模型），蒸馏由本地模型完成，不经云端。
- 跨智能体采集要求对应智能体本机存在声明式记忆文件（见步骤 4 的文件清单），文件不存在则该家采集为空。
- 记忆数据存本机 os-data，按用户隔离；多用户各自一份，互不可见。

## 一步步来

入口：Dock ＞ 设置 ＞ 左栏「记忆」分区。页面由三张卡片组成：「用户记忆」「跨智能体记忆采集（枢纽制）」「会话提炼（默认关）」。卡片右上角有「?」按钮（悬停提示「使用帮助」），点开显示「怎么设置 / 怎么验证」两段官方说明。

1. 手动添加（来源①）

1. 「用户记忆」卡片顶部输入框（占位文案「输入要记住的一条事实或偏好」）输入一行内容，点「添加」按钮（或直接回车），条目立即出现在下方列表。
2. 每条记忆右侧有一个小号来源徽标：user=你手动添加，mcp:claude-code 等形如 mcp:<智能体>=某家智能体经工具写入，refine=会话提炼入册——谁写的永远可追溯。
3. 条目行尾「关闭」删除该条；删除后投影（见步骤 6）随之更新。列表为空时显示「还没有记忆条目」。
4. 适合最核心的几条；一两句说不清的内容不适合进记忆。

2. 智能体写入（来源②）

1. 已连接 chatop MCP 的智能体（Claude Code / Codex / OpenCode / ZCode / OpenClaw 等）可在对话中直接说「记住我喜欢用 pnpm」之类，智能体经 memory_create / memory_update / memory_delete / memory_list / memory_search 五个工具读写同一份记忆。
2. 写入按作用域隔离：智能体不显式指定时默认写进自己的桶（agent:<智能体>，只有它自己可见）；只有明确写 global 的才全机共享。
3. 2026-10-18 起 memory 工具为 T0 直放（设置 ＞ 隐私与存储 ＞ 智能体权限门中不设确认），写入不再弹确认卡；每次工具写入都记入 <userData>/audit.jsonl 审计（来源 + 放行/拒绝）。

## 如何确认操作生效

验证

1. 手动添加一条记忆后，打开主目录 ~/AGENTS.md，应看到「## User memory (chatop)」托管段里出现这条内容（500ms 内）。
2. 在任一已连接 chatop MCP 的 CLI 智能体（如 Codex）新会话里问「我之前告诉过你哪些偏好」，回答应能引用你的记忆条目。
3. 删除该条后重新打开 ~/AGENTS.md，托管段里该行随之消失。
4. 让智能体写一条记忆（如对 Claude Code 说「记住：我的项目在 ~/work/demo」），设置 ＞ 记忆 列表应出现新条目，来源徽标为 mcp:claude-code。

## 谁需要这个功能

会话里聊出了稳定偏好，想蒸馏成一条长期记忆，又怕系统乱记东西；每次新会话都要重新自我介绍（称呼、常用语言、项目路径），想让所有智能体默认就知道；在 Claude Code / Codex 等工具里攒过一批 CLAUDE.md / AGENTS.md 记忆，换到察元OS 后不想手动搬家，把项目背景写进记忆。

用户常搜的问法：怎么让所有智能体都记住我的称呼和技术栈；以前 Claude Code 的记忆文件能搬到察元OS 吗。

## 注意事项与真实边界

功能归功能，这几个边界先摆清楚：

- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 云端厂商模型调用需自备 API Key
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 接着回答几个常见问题

### 点「现在提炼」提示「本地模型未运行」？

蒸馏用本地对话模型（只找已运行的对话实例，不自动拉起）。到 设置 ＞ 模型 加载一个对话模型后再回来提炼。会话存档格式不可解析时会提示降级为手动整理，属正常保护。

### 智能体说「记不住」我的偏好？

该智能体需经 chatop MCP 连到本机（设置 ＞ MCP 确认「察元本机 MCP」运行中且已写入该智能体配置）。另外检查记忆作用域：智能体默认写自己的桶，其他智能体看不到；想全机共享，在对话里明确说「记住为全局」，或把该条删了手动重加。

### 「现在采集」一直「没有提炼出新的候选」？

三种情况：① 首次已采过且文件未变化（哈希台账跳过，不重复采）；② 内容与既有记忆/候选重复（精确去重）；③ 该家开关被关或本机没有对应记忆文件。先确认对应智能体确实在本机写过 CLAUDE.md / AGENTS.md 记忆。

### 删除记忆后，智能体那边怎么还在引用？

投影有 500ms 合并窗口；CLI 智能体已开的会话上下文不会回缩，新会话才反映删除结果。若仍见旧内容，打开对应文件确认托管段已更新（标记外的内容是智能体自己的，察元不会动）。

### 多用户会串记忆吗？

不会。记忆存本机 os-data，按用户分库隔离，切换/登录不同用户各看各的。

## 更多操作细节

3. 会话提炼（来源③，默认关）

1. 「会话提炼（默认关）」卡片中点「现在提炼」，按钮变「提炼中…」。过程：读取最近最多 8 个 dsh 会话存档里的用户发言，交给本地模型蒸馏出最多 8 条候选事实。
2. 成功后提示「新增 {n} 条候选，待确认」，候选进入下方待确认队列（绝不直接入册）；没有可提炼内容时提示「没有提炼出新的候选」。
3. 失败时给出具体原因，如「本地模型未运行——先在「模型」里加载一个对话模型再提炼」「未找到会话存档（session.jsonl.zstd）」「近期会话里没有可提炼的用户发言」。
4. 勾选「自动提炼（每日一次，产生候选仅通知提醒）」可保存该偏好。
