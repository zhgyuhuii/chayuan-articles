# 控制条管理讨论节奏：自动接力完整走法

自动接力的麻烦不在功能本身，在于信息散。不设控制的群会无限聊下去，共识模式让它们互相评审收敛出结论，这篇把它收拢成一条能照着走的路径。

## 一句话说清定位

自动接力在察元AI OS里的形态一句话说清：控制条管理讨论节奏：自动接力（停滞保护）、共识模式（达成一致自动停）、视角讨论（反方、核查者、展开者、举例者四种角色任务）、@指定发言、继续或结束讨论。

先把定位立住，再看步骤。

## 动手前的准备

- 已按对应教程建群并发过至少一条命题（部分按钮在讨论进行中才有意义）；
- 「/」等开关按群的协同方式显隐：串行/多步骤群不显示「」，多步骤群不显示「」（详见下表显示条件）。

## 群聊讨论控制：从入口到完成

第 3 步 · 继续 / 结束

1. 「结束讨论」随时可点，效果是全停：
    1. 正在「思考中/发言中」的成员全部中止（已流出但未完成的段落会以「中断」样式落账，不凭空蒸发）；
    2. 自动接力、共识推进、串行续轮调度全部清空，接力交接单一并清空；
    3. 消息流落「讨论已结束」系统条；
2. 「继续讨论」按群模式各显神通：
    1. 并行群 = 手动再跑一轮（同一命题手动接力最多 5 轮，超出提示「已达本轮讨论轮次上限」）；
    2. 串行群 = 推进下一轮（轮次计数保留，「从头重新执行步骤链」才重置）；
    3. 多步骤群 = 从头重跑步骤链；
    4. 有成员失败过时（出现「一位成员暂时离席（调用失败，可在群设置重试）」系统条），先点「重试离席成员」补跑失败者。

第 4 步 · 自动接力（，默认开）

1. 默认 ON：一轮结束、全员空闲后约 5 秒自动开下一轮，不需要你点任何按钮；
2. 想改回手动：点 切到 OFF（此时用「继续讨论」逐轮接力）；
3. 停滞保护：接力开轮后没有任何灵宠成功回复（模型/代理故障）时，自动暂停并提示「连续无有效回复，自动接力已暂停（发出新消息后自动恢复）」——开关不会被翻掉，你发新消息即恢复；
4. 成员失败会先自动自救：提示「成员离线，正在自动排查并重连…」，按故障类型预热引擎后自动重试（最多 2 次），重试耗尽才落「暂时离席」交给「重试离席成员」。

第 5 步 · 共识模式（，仅并行群）

1. 点 切 ON：
    1. 自动关闭 ；
    2. 消息流落系统条「已切至共识模式（收敛讨论）：视角任务暂停，全员中立作答直到达成共识」；
2. 此后每轮结束自动判定（约 5 秒一查）：
    1. 达成（最近一轮回复里「同意/共识/一致/赞成/没意见/没问题/就按/可以/OK」等信号过半）＞ 「已达成共识，自动停止」，共识模式随之自动关闭；
    2. 未达成 ＞ 「尚未达成共识，继续推进…」自动续轮；
    3. 连续 2 轮没有任何灵宠新回复 ＞ 「连续无有效回复，共识推进已自动暂停（请检查模型服务后重试）」并自动关闭共识模式；
    4. 随时可用「结束讨论」硬终止。

## 如何确认操作生效

验证

1. 讨论进行中点「结束讨论」：所有「思考中/发言中」立即消失，出现「讨论已结束」系统条，「结束讨论」按钮变灰、「继续讨论」恢复可点。
2. 并行群点 切 ON：出现「已切至共识模式…」系统条且 自动变 OFF；持续几轮后出现「已达成共识，自动停止」或「尚未达成共识，继续推进…」。
3. 发「@{某灵宠名} 你怎么看」：消息流出现「@{名} 已接单（其余成员旁观）」，只有它一只发言。
4. 发一条含「讨论/分析」字样的命题：多只成员的发言应呈现明显分工（一只挑毛病、一只举例子等），而不是各说各的相似观点。

## 什么情况下用得上

群讨论停不下来（一轮接一轮自动续），想让它停下或只推一轮；想让几只灵宠辩到「达成共识」为止，而不是无限发散，全员发言大同小异，想看不同视角（挑毛病/核实/展开/举例）的分工讨论；只想让某一只灵宠回答（点名），或讨论跑题了想把话题拉回来。

用户常搜的问法：宠物群聊怎么停止讨论？停了怎么继续；共识模式是什么？达成一致会自动停吗。

## 边界先摆桌面上

如实说明，它不是万能的：

- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 云端厂商模型调用需自备 API Key

## 接着回答几个常见问题

### @了灵宠但全员都说话了？

@名字必须与灵宠档案名逐字一致（含空格）；写错一个字就当作普通消息全员回应。可先在群管理面板「成员列表」核对名字。

### 搜索框输入关键词没反应？

当前版本搜索框只提供输入，未对消息流做过滤（输入内容不改变渲染）。翻旧消息用「查看更早的 {n} 条消息」逐段展开。

### 串行群插话后怎么又从头讨论了？

串行群的新人类命题会重置轮次并从头起链——这是「新命题=新讨论」的口径；想补充而不是重开，等本轮结束再发，或接受引擎把插话并入当前命题（流水线在跑时插话会并入命题槽，标注「用户补充」）。

### 成员失败后还要手动重试吗？

先不用：引擎会自动排查重连（「成员离线，正在自动排查并重连…」），按故障类型自动预热并重试至多 2 次；仍失败才落「暂时离席」，此时点头部「重试离席成员」。

这篇把群聊讨论控制的链路拆完了。卡住就回看常见问题那一节，多数坎都在那里。
