# LLM博弈研究：高校实验室的轻量观察台

研究大模型的决策行为，常规路径是自建评测流水线：题目集、评分器、批量脚本，从立项到能跑往往要几周。如果你的观察目标是「受控规则环境里模型怎么做决策、决策过程长什么样、协议行为稳不稳」，LLM博弈研究有一条轻量得多的起步路径：用察元竞技场把模型拉进棋牌对局，规则由纯逻辑裁判执行，思考、耗时、协议行为全部留痕，数据可以导出带走。这篇面向高校实验室，讲清楚能观察什么、能拿到什么数据、怎么搭。

## 研究场景：博弈环境能观察什么

一类观察是完全信息与不完全信息的对照。五子棋、中国象棋、围棋（9 路/13 路）里模型看得见全局；斗地主、德州扑克、掼蛋、军棋、麻将里只看得见自己手牌，要靠推理猜对手、靠下注表达牌力。同一批模型在两类玩法上的行为差异，本身就是值得记录的素材。

另一类观察是协议行为。LLM 玩家统一走 {move, comment} 出招协议；深度规则模式（DEEP_RULES）会要求三段输出——分析（推演三条候选着法线，至少一条吃子线一条防守线，各限字数）、结论、答案 JSON。这个开关相当于实验里的处理变量，开与不开，模型的输出结构与耗时分布都会变。

还有一类观察是鲁棒性。429 限流自动退避、重试回喂、解析失败后的启发式代走、代走超限判负，这条容错链让「模型 API 不稳定时系统怎么表现」也变成了可观察对象。解析容错本身也值得看：剥思维链块、剥代码围栏、抽取大括号、正则兜底，模型输出格式漂移时会走到哪一级，一级一级都有痕迹。

对照实验也好设计：同一批模型、同一玩法，只动一个变量——换模型、开关深度规则模式、换本地与云端，其余全部锁死。变量少，归因才干净。

## 数据面：能拿到哪些东西

过程层面，对局室里思维链气泡实时流式滚动，每手的延迟与 token 用量都有展示。统计层面，协议画像按模型汇总 JSON 格式遵守率、平均耗时等指标，可以直接做横向对比。结果层面，每局支持棋谱 JSON 导出，配合形势曲线、逐手的 ？!标注与回放器按协议字段筛选关键手，数据不是黑盒。这些数据都在本机产生与保存，涉及模型账号的部分只在调用时出网，实验数据管理起来不复杂。排位层面，TrueSkill 评分随对局更新，可以当长期观察的纵轴——前提是样本量撑得起结论。

几个可以直接立项的观察问题：同一模型在 9 路围棋与德州扑克里的思维链长度怎么变；深度规则模式开与不开，JSON 格式遵守率差多少；429 退避出现后，恢复后的出招质量有没有明显波动；开局记忆开启前后，同型局面的重复错误次数变化。这些问题都能在现有数据面里找到答案素材，不用改造软件。

## 搭建：一台普通电脑的轻量方案

察元竞技场是 Electron 桌面应用，Windows、macOS、Linux 都有安装包，当前版本 0.1.0（2026 年 11 月），一台实验室常规电脑即可承载，不必申请服务器资源。

模型接入在设置 ＞ 模型配置里完成。实验室自建的推理服务只要兼容 OpenAI 协议，手填 baseUrl 就能接；Ollama 本地推理免 Key；85 家厂商目录点选即填，点「获取模型」可实拉账号下可用模型列表。有个工程细节要记：配置写入带写锁、运行时热读取，跑批中途改配置会影响对局一致性，改动要么排在批次之间，要么记录在案。

跑批用两个模式：机机观战支持批量选模型逐组合跑；锦标赛把多模型循环赛自动排程、积分榜实时刷新，适合夜里挂机攒样本，早上收一批完整对局。环境记录建议固定成一张表：软件版本、玩法与规则档、模型清单与端点、参数、日期时段，五列填满，每批一行，日后写报告直接引用。

## 研究纪律：三条别踩的线

它是观察台，不是学术基准。胜负有随机性，单局结果不能进结论；这个环境的长处是过程与行为数据，不是官方名次，报告里别写「XX 模型排名第几」这类表述。

样本量自己报。同一组合至少要多局，方差要在报告里如实呈现；不同玩法的方差结构不同，别混在一起求平均。报告里连负结果一起写：模型在某类玩法上系统性失败，同样是发现。

版本快照写进论文。0.1.0 的数据格式与功能可能随版本调整，实验报告里注明软件版本、玩法规则与模型清单，别让复现者去猜环境。

## 边界

费用上，软件 MIT 开源免费，云端模型的调用费用由实验室向厂商支付，挂机跑批前先估好额度；Ollama 零成本，但本地小模型的行为与云端大模型不是一个分布，两组数据别混用。数据格式以导出 JSON 的实际字段为准，写二次解析脚本前先看真实结构。它不提供官方胜率榜单，也不做深度搜索对照实验，这些缺口要心里有数。还有一层要说明：裁判引擎是仓库自带的纯逻辑实现，规则细节的论文表述建议直接引用开源仓库，别凭记忆转述。

## 常见疑问

### 对局数据能导出来做二次分析吗
能。棋谱 JSON 导出加协议画像统计是基础数据面，回放器支持按协议字段筛选关键手，接进自研分析脚本即可开工。

### 实验室自建的模型服务能接吗
能。只要兼容 OpenAI 协议，在设置 ＞ 模型配置里手填 baseUrl 即可；本地 Ollama 免 Key 直连。

### 能复现同一局吗
不能逐手复现，模型输出有随机性。可复现的是环境：同版本、同玩法、同模型清单，结论建立在多局分布上就经得起复检。

### 适合投什么研究问题
决策过程观察、协议稳定性、容错行为、完全信息与不完全信息下的策略差异这类行为层面的问题，比「谁的棋力高」更匹配这个环境。

### 要不要担心模型厂商的服务条款
实验室用途通常落在各厂商 API 条款允许的范围内，跑批前把条款过一遍，尤其注意数据用于研究的表述边界，拿不准就写邮件问厂商。

观察工具和基准测试不是竞争关系，而是分工关系：基准给出分数，观察给出过程。对研究大模型的人来说，很多时候过程比分数更想说清楚——它是怎么想的、什么时候失稳、失败以什么形态出现。棋牌对局把这些问题放进了一个规则透明、数据完整的沙盘，一个下午就能搭起来。与其争论榜单，不如先攒一批自己的对局数据。
