# 模型出招异常怎么办：从乱走到代走的兜底逻辑

看模型对弈，乐趣在于琢磨它每一步在想什么；可总有那么一刻，一方突然走出一手棋盘上根本不存在的着法，观战的人当场愣住。模型出招异常怎么办，对局会不会就此报废，是很多人接触大模型棋牌竞技场时冒出的头一个问题。察元竞技场为这件事准备了一整条兜底链路：从解析容错到启发式代走，再到代走超限判负，外加限流退避，层层都有安排。先给结论：异常会被层层接住，对局不崩，代价只是那一手的观赏性。这篇按异常发生的顺序把链路拆开讲，顺带把弱模型的合理预期也交代了。

### 模型走出一手不合法的棋，对局会崩吗

不会崩，这是整套设计的前提。胜负判定百分之百归代码，模型只出招、不判罚，它自己宣布「我赢了」没有用，裁判只认棋盘真值。不合法的招在进裁判之前就会被拦下来处理，走不到「棋盘被污染」那一步，这套裁判契约在 11 款玩法上是同一套原则，棋类、牌类、麻将都一样，不存在哪个玩法特别容易崩。演示和真博弈的分水岭也在这里：演示怕出错，真博弈有裁判。所以你看到的异常，最多表现为一手废招或者一手代走，不是整局报错退出。

### 解析容错链是怎么一层层把招救回来的

模型的回文要先过出招协议这一关：标准答案是带 comment 的 JSON，强模型支持两段式先分析再给答案，深度规则模式下甚至要求推演三条候选线再收敛到结论，分析段有字数上限、结论段要求短句收敛，解析器对这种结构都做了适配。文本不规整时，解析容错链逐级放宽：先剥掉思维链块和代码围栏，再抽大括号里的内容，截断的补尾、空白做规整，正则抽取接力，实在抽不出 JSON，就全文扫描当前合法动作串做精确词命中，还带了词边界防误配。合法步清单是显式附在给模型的输入里的，多人游戏还有合作上下文，容错链只认这份清单，绝不产出清单之外的着法。这条链的目的很朴素：模型的回答格式再花，只要意图落在合法清单里，就把它捞出来。

### 实在解析不出来，系统会替它走吗

会，这就是启发式代走。容错链走完仍然没招，系统按启发式帮这个玩家落子：能挡杀就挡，能吃就吃，麻将里从缺门里挑价值较低的一张打出去。代走不是乱走，它有一条朴素的底线——至少不吃大亏，观战时你可以把它理解成裁判替这个玩家打了张保险牌。对观感来说，代走那一手会打断模型的叙事，你看到的不是它的思考结果，而是系统的救场，但牌局能继续；它的价值在于维持对局的叙事连续，而不是替模型赢棋。

### 代走的招会不会很离谱

不会离谱到哪去，但也别指望灵光。启发式的逻辑就是防守优先、吃子优先，放在象棋里大概是个不送子的稳妥招，放在麻将里是弃胡保平安的打法，它救的是「对局能继续」这个底线，不是模型的水平。换句话说，代走棋的水准大概是「不打亏牌」，指望它走出妙手是不现实的。所以看回放时，代走的那几手通常就是这局里这个模型发挥最差的部分，这也算是容错机制诚实的另一面：它兜住了下限，也标记了短板。

### 代走次数超了会怎么样

判负。同一个玩家的代走会计数，超过限度这一局就直接判它输。这条规则把「烂模型拖垮整局」的风险关掉了：API 一直抽风的玩家会体面退场，对局继续，其他座位的模型照常厮杀；判负的局照样进记录和天梯，谁因代走超限输掉的，回放里查得到。对你来说这也算个信号——如果一个模型在你手里频繁被判负离场，别急着怀疑裁判，先换模型或者换更稳的端点，这比反复重开对局省时间。

### 遇到 429 限流，对局会卡死吗

不会卡死，限流有自动退避。云端模型请求太密时厂商会回 429，竞技场的处理是自动退避等待，然后重试回喂——退避结束前模型已生成的上下文会原样接回去接着用，不浪费前面的轮次。多数限流在几轮等待后自己恢复，对局只是节奏慢下来；退避之后仍然失败的，才落入代走逻辑。429 在免费额度或高并发账号上更常见，遇到时先查厂商侧的限额说明。限流的观感是「这个模型出手变慢了」，而不是「对局卡住了」，两者的性质完全不同，前者等一等就好，后者有代走和判负接着。

### 弱模型出招异常是常态吗，要有怎样的预期

要有预期：弱模型异常率高是正常现象。大模型出招靠语料和推理，不做深度搜索，参数量小、训练不足的模型，连输出格式都可能管不好，何况招法本身。竞技场给的信息其实很足，着法历史、合法步清单、合作上下文都显式附上，强模型在长对局里通常更稳，弱模型则可能反复触发代走。想预判一个模型稳不稳，可以看协议画像里记录的 JSON 格式遵守率这类数据；把弱模型当陪练和对照，认真比拼留给强模型，你的战绩统计也会因此更有含金量。头一回看到代走也别慌，那是系统在工作，不是 bug。

这套兜底逻辑的价值，是把「模型上桌」从演示变成真博弈：再离谱的模型也污染不了棋盘，再抽风的 API 也卡不死整局。同时它也诚实地暴露了差距——谁常被代走、谁被限流拖慢，对局记录里都写着。异常不可怕，可怕的是异常被藏着，这里选择了不藏。下次再看到模型走出怪招，先别急着截图吐槽，等一手看看系统怎么接，那才是这个产品工程化的成色所在。兜底链路平时隐身，出事时站出来，这是工程该有的样子；把代走当彩蛋看，心态会好很多。
