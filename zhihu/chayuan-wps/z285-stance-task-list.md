# 为什么说察元文档助手任务清单被低估了？

看到察元文档助手任务清单这个问题底下清一色的吹或黑，忍不住说两句。我的看法是：这不是噱头，但也不是人人必需。

先把背景交代清楚。这个问题的来源很实际。任务执行时由运行窗口每 4 秒写一次心跳。范围下拉：「全部范围 / 全文 / 选中文本」。详情区自带搜索框（占位「搜索原片段 / 建议 / 根因 / 诊断 / 输出」）和「复制搜索摘要」「下载搜索摘要」按钮，可对逐条命中项再过滤。顺手提一句，别跳过。

要判断它，得先知道它的底细：它对离线场景友好，接本机 Ollama 全程不出网，涉密文档也能用。具体到操作面，看保密检查风险概览卡这条在手册里写得很细。如果你只记一条，记这条就够了。

有一个观感上的误区要先拆掉：点「最近保密检查」会定位到最近一次保密检查任务。脱密是付费能力，没有免费额度，涉密场景再考虑上这一项。说实话，第一眼我以为多余，用下来才知道是刚需。

### 先看它的定位

左上是统计范围切换：「统计全部任务」/「仅统计当前筛选结果」。用筛选栏缩小范围（一行控件，从左到右）：排序下拉：「最新更新时间 / 最早更新时间 / 按状态 / 按分块数降序」。这不是玄学，是写进文档里的行为。

同时跑过多个检查/助手任务，想找「上次那次保密检查」的结果与命中项。跑一次保密检查后，概览区出现且「最近保密检查」显示本次时间；点「高危任务」卡后列表只剩含高危项的任务。进行中的任务行有进度条和「停止」按钮（悬停提示「停止任务」）。这个细节不影响功能，但决定你愿不愿意一直开着。

批量导出与清理（筛选栏右侧，按条件出现）：「清理筛选结果（N）」删除当前筛出的可清理任务。WPS 重启后想确认：上次没跑完的任务到底完成了没有。根因下拉：「全部根因」+ 按当前任务动态生成的根因项。

### 它做对的那件事

下方一排五张卡：「高危任务」「中危任务」「关键词命中任务」「未见明显风险」「最近保密检查」（显示最近一次检查时间，无则显示「暂无」）。点前四张卡会把下方列表筛到对应风险，再点一次取消。

macOS 安装有个著名的坑，权限不足会假成功，官方给了修复脚本。看详情：点「详情」（或点任务行展开）在窗口内展开详情区：范围、分块数、定位汇总（精确/回退/失败/跳过 各多少）、根因与说明、创建/开始时间等。免费额度按天重置，对话和助手是两个独立池子，轻度使用够用。别嫌它啰嗦，啰嗦的地方正是容易翻车的地方。

「复制汇总 Markdown（N）」把筛选结果汇总为 Markdown 复制到剪贴板。在跑。任务清单只是查看器，任务由各功能窗口执行；关闭清单不影响执行，再次点「任务清单」会聚焦已开窗口或重开。想批量清理历史任务，或把某次检查的全部结果导出成 Markdown/JSON 存档。这一点挺难得，很多同类产品只在宣传页里讲。

一个绕不开的问题：为什么我没有看到风险概览卡？ 高危/中危计数取自任务结果里的「高风险项」「中风险项」小节，关键词计数取自「可疑关键词汇总」小节。

### 代价与边界

搜索框：占位「搜索任务标题、根因、摘要」。WPS 关闭后心跳停止，任务清单打开时会把心跳超过约 20 秒的非终态任务判为中断（状态「异常结束」，原因「应用已退出或重启，任务执行中断」）。助手类任务还有「结论摘要」卡（文档写入、任务结论、重点提示、可疑关键词）。

「下载汇总 JSON（N）」下载 JSON 文件。状态下拉：「全部状态 / 进行中 / 已完成 / 失败 / 已取消 / 异常结束」。有人觉得这步多余，我持相反意见。

关于察元文档助手任务清单的适用边界，有一个简单的自测方法：把你要解决的问题写成一句话，越短越好。如果写出来发现要三个从句才能说清，说明需求还没收敛，这时候上任何工具都是浪费。先收敛需求，再挑工具，顺序不能反。

一个绕不开的问题：表格/演示里怎么找不到「任务清单」按钮？ 每次确认写入都进审计日志，谁改了什么查得到。

当然，反对的理由我也听过，有一条是有道理的：看工作流任务：工作流任务行内展开「工作流任务树」，逐节点显示状态与耗时；点节点可跳到对应子任务详情。审查结论下拉：「全部审查结论」+ 动态结论项（如「高风险」「未见明显AI痕迹」「已占位脱密」等）。发起一次「拼写与语法检查」或「保密检查」，打开任务清单，应能看到对应任务行，进行中时进度条会前进。很多人在这里浅尝辄止，其实往下还有一层。

它的边界也得摆出来。关闭 WPS 再打开（等 20 秒以上），打开任务清单：上次遗留的「进行中」任务应已被判为「异常结束」，原因为「应用已退出或重启，任务执行中断」。到这里思路就顺了，剩下的只是重复。

费用与版本这笔账也要算：定位质量下拉：「全部定位质量 / 仅精确命中 / 包含整句回退 / 包含定位失败 / 高风险任务」。「任务清单里那个『异常结束』是什么意思？」

还有一个判断角度常被忽略：看察元文档助手任务清单失败的时候是什么样子。顺的时候大家都差不多，差别全在出问题的那一刻，报错信息是否说人话、能不能原地重试、数据会不会丢。这些细节官方文档很少写，但恰恰是它们决定你用一个月之后还愿不愿意继续用。

最后把话说全：察元文档助手任务清单的立场摆在这了，证据也给了，你手里有自己的情况，自己称。判断过程比结论值钱。
