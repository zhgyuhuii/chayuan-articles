# 大模型上手配置排查路径：概念页解释模型代理机制

「开机弹出来的『统一模型设置向导』是什么，必须配吗」——这个问题最近被问了好几次。答案不复杂：大模型上手配置在察元AI OS里是现成能力，这篇把入口、步骤、验证一次写全，按钮文案原样引用。

## 先定位问题在哪一层

排大模型上手配置的错，顺序比速度重要：环境与模型先就位，然后对操作路径，最后核边界。三层各有一些典型症状，对号入座能省很多时间。

## 高频故障与对策

### 第 2 步模型树一直显示「…」或加载失败？

约 8 秒未到会亮「重试」按钮，先点重试；仍失败多为模型服务未响应，到 设置 ＞ 模型 查看服务健康灯后再回来。

## 正确的操作路径

第 3 步 · 「统一应用到智能体」

1. 页面标题「统一应用到智能体」，正文说明：把默认模型写入各智能体配置（写入前自动备份，可随时回退）；也可以稍后在 设置 ＞ 默认模型 ＞ 「应用到全部智能体」 重做。
2. 顶部等宽字体显示写入目标，形如 local/qwen3.5-4b-q4km @ http://127.0.0.1:52581。
3. 桌面形态下点「选择智能体并应用…」弹出应用对话框：
    1. 「模型名（写入智能体配置的长期契约）」输入框已预填第 2 步选的默认模型；
    2. 智能体勾选清单（默认五家全勾选）：「DeepSeek Harness（模型下拉）」「Claude Code（~/.claude/settings.json）」「Codex（~/.codex/config.toml）」「OpenCode（~/.config/opencode/opencode.json）」「OpenClaw（启动环境注入）」；本机感知到但不支持自动写入的智能体会灰显列出并注明「暂不支持自动写入模型配置」；
    3. 点「应用」逐家写入：每家成功显示绿色「已写入」，失败显示红色具体原因；写入内容 = 模型代理的 OpenAI 兼容地址 + 默认模型名（代理对本机调用免 key 直连，真实厂商密钥不出本机凭证库）；
    4. 点「关闭」收起弹窗；全部完成后向导页显示绿色「已应用」。
    5. 浏览器形态没有应用按钮，改为提示框：默认模型已保存，请到桌面应用里用 设置 ＞ 默认模型 ＞ 「应用到全部智能体」或重跑本向导补做。
    6. 左下「上一步」回第 2 步；右下「下一步」进第 4 步。

第 4 步 · 「设置完成」

1. 标题「设置完成」，正文「默认模型已就绪。想深入了解更多：」，列出两篇帮助中心教程：「统一模型设置与模型代理」「运行本地模型详解」（帮助中心 ＞ 模型服务）。
2. 提示行：「随时可在 设置 ＞ 模型设置 ＞ 「设置向导」 重新运行本向导。」（实际按钮位置见「验证」第 3 条）。
3. 「打开帮助中心」直接打开帮助中心应用；「完成」关闭向导。

## 做完后的验证

验证

1. 第 3 步面板显示的写入目标端口是 52581（模型代理固定端口，一号一口写死）。
2. 浏览器或终端访问 http://127.0.0.1:52581/v1/models（免 key）：返回的模型清单应含 local/<…> 条目；已配置并加入代理的厂商还有 <厂商>/<模型> 条目。
3. 重跑入口核对：设置 ＞ 模型，左栏「本地模型」组（默认展开）内有一项「统一模型设置向导」，点击即重新弹出向导。
4. 应用成功后打开 DeepSeek Harness 对话窗，模型下拉框里能看到所写的默认模型。

## 常见问题

### 误点了「我已经配置过，不再显示」，其实还没配置？

没有影响。该按钮只是不再自动弹出，配置本身什么都没动；按 Q1 的入口重跑即可。

### 向导里选了厂商模型，但智能体调用报未知模型？

向导保存时会自动确保该厂商的代理路由可用；若你之后在 设置 ＞ 模型 停用了该厂商，路由随之移除。重新开启厂商或换一个默认模型即可。

## 动手前再核对一遍

- 桌面形态（察元AI OS）。浏览器打开的 web 形态可以走完第 1、2、4 步；第 3 步「统一应用到智能体」要把配置写进本机各智能体的文件，必须由桌面主进程完成——浏览器形态不提供该入口。
- 自动弹出条件：这台机器从未保存过默认模型、且未标记「向导完成」时，登录进桌面自动弹一次。任何方式退出（「跳过向导」、点弹窗外的遮罩关闭、走完「完成」、「我已经配置过，不再显示」）都会写完成标记，之后不再自动弹出。
- 模型代理随模型服务自启（本机固定 127.0.0.1:52581）。向导保存默认模型时会先确认代理在运行，没在运行会自动拉起一次。
- 第 2 步要能选出模型，二选一：本地已装对话模型（完整安装包随机播种 Qwen3.5-4B Q4_K_M；未带模型包的形态先按 M3 从模型库补装），或已配置过一家云端厂商。
