# 多文档错别字校对（MCP）实操教程：从入口到完成的完整流程

批量校对是察元AI文档助手里使用频率很高的一项能力。它的「多文档错别字校对（MCP）」这样工作：通过本机 MCP 服务的 proofread_run 工具对多个文档执行错别字校对：先 dryRun 预览问题清单，确认后用 proofread_apply_comments 把批注钉到具体错字（含表格单元格），支持异步任务轮询。外部智能体（Claude Code、Codex、Cursor）可直接调用。这篇实操教程从入口、步骤、场景讲到技巧与边界，新手照做能跑通，老手能查漏。

## 它是什么，解决什么问题

通过本机 MCP 服务的 proofread_run 工具对多个文档执行错别字校对：先 dryRun 预览问题清单，确认后用 proofread_apply_comments 把批注钉到具体错字（含表格单元格），支持异步任务轮询。外部智能体（Claude Code、Codex、Cursor）可直接调用。

从任务视角看，它对应的关键词是「批量校对」——也就是用户带着这个需求搜索时，最应该被满足的那类任务。

## 操作步骤

1. 在 Claude Code / Cursor / Codex 中连接本机 MCP 服务 http://127.0.0.1:62588/mcp
2. 调用 proofread_run 发起 dryRun，拿到全量问题清单
3. 人工复核清单后调用 proofread_apply_comments 批量落批注
4. 回 WPS 逐条接受批注修改

## 适用场景

- 整目录标书/合同批量错别字体检
- 科室多份材料的统一校对

## 实用技巧

- dryRun 预览→确认→写回是固定铁律，未确认绝不落盘
- 异步任务用 proofread_job_poll 轮询，长文档不阻塞

## 注意事项与边界

- 校对质量依赖所配置的模型：本地小模型对复杂逻辑错误的把握弱于云端旗舰模型
- 模型相关能力建议先在非关键文稿上试跑一次，确认输出风格符合预期

## 离线运行与部署形态

从 4.0 版本起，安装包内嵌 sidecar 单文件二进制并注册开机自启，适配离线、内网与县级环境部署；推理指向本地或内网端点后，文档内容不出本机。MCP 服务只监听 127.0.0.1:62588 回环地址，本机即信任边界，远程机器无法直连——这是「涉密不出域」的安全设计，可用环境变量 CHAYUAN_MCP_PORT 调整端口。

## 数据安全与隐私边界

- 发布包逐源 sha256 强校验（Gitee→aidooo→GitHub 多源回退），防供应链篡改
- 开源 Apache-2.0，全部代码可审计，政企可自行审阅后离线打包
- MCP 服务仅监听 127.0.0.1:62588，无需 Token 与命令行，sidecar 与 WPS 同机运行，文档与密钥不出域
- 知识库凭据采用 AES-GCM + HKDF 端侧加密落盘，密钥派生自设备绑定 OPFS 盐，明文永不落盘、不参与同步

## 常见问题
### 企业能内部署吗？

可以。官网提供四档形态：加载项（个人）、桌面版（单机断网）、服务版（Docker 全科室共用）、至臻版（数百到上万人网络版）。

### 察元AI文档助手是什么？

一款 WPS 文字智能加载项（jsaddons），在 WPS 内提供 AI 对话、校对审查、表单填报与正文写回，同时内置本机 MCP 文档智能体服务，可被 Claude Code、Codex、Cursor 等外部智能体调用，支持离线/内网模型。

### 知识库功能怎么用？

设置中绑定知识库服务（JWT/HMAC 认证），即可对选中文字做核对、总结、问答，结果带引用并可下载原文。
