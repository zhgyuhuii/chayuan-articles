# 数据标注行业怎么用察元OS：从痛点到落地

数据标注行业的文档与信息工作有其固有节奏：历史文档数字化程度低，检索与复用困难。察元AI OS在数据标注场景下的定位，是把可标准化的环节交给工具、把判断留给从业者的「人机协同」。本文按痛点→能力→落地步骤→边界的顺序，给出数据标注行业的完整应用路径。

## 数据标注行业的典型痛点

- 历史文档数字化程度低，检索与复用困难
- 多岗位协作时版本混乱、批注流转低效
- 新人上手慢，经验沉淀在个人手里而非工具里

## 对应的能力组合

- **察元智能广场**（智能体门户）：内嵌 aidooo.com 能力广场的桌面应用：离线时回落本地页；与网页版同源，检索 2.5 万+ 插件/技能/MCP/提示词/模型资源。
- **创造模式**（智能体插件）：会话内 Agent 现场定义与挂载插件（cordis_define/cordis_run）：不离开对话就能「造」一个带工具的智能体。
- **Dock 与窗口管理**（Dock栏）：Dock 支持位置/自动隐藏/放大效果/图标三挡大小、分组（徽章+溢出计数）、Windows 式最小化磁贴；多窗口可拖拽、多屏切换。
- **webwindows 智能体开窗**（智能体窗口）：智能体可打开真实 Electron 原生窗、加载网页/HTML、执行 JS、截图、点击穿透、置顶与透明度调节——AI 的「眼睛和手」延伸到图形界面。

## 落地四步

1. 盘点本岗位高频文书/信息任务，挑最耗时的两个作为切入口
2. 按内网/涉密单位用户场景的工作流试跑一周，记录节省的环节
3. 把常用任务固化为助手或规则模板，团队复用
4. 建立人工复核节点：工具产出 → 从业者裁决 → 定稿

## 合规与边界

- 涉密与敏感材料遵循本单位管理规定，必要时使用离线部署形态
- 云厂商模型调用需自备 Key，免费额度视厂商政策
- 行业判断责任始终在人，工具输出作为参考

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 本地模型五件套随软件分发，断网即用
- 全部本地服务只监听 127.0.0.1，数据不出本机
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）
- API Key safeStorage 加密存储，仅注入子进程

## 常见问题
### 内置了哪些模型？

装机五件套：Qwen3-4B-instruct（对话）、bge-m3（嵌入）、bge-reranker-v2-m3（重排）、whisper-small-int8（语音识别）、piper 中文（语音合成）；标准包含引擎不含权重时可通过 models 完整离线包或在线下载补齐。

### 应用商店卖什么？

插件与技能为主（规划含 MCP/提示词/智能体/技能包五类），默认源为 aidooo.com；免费直下、付费内嵌收银台，支持断点续传与 sha256 校验。

### 智能体操作电脑安全吗？

有三级权限门：T0 直接放行、T1 每次运行询问（可记住）、T2 每次必问（截图/关机等）；审批超时视为拒绝，全部操作写审计日志。
