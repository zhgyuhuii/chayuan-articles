# 职业教育AI方案：AI 桌面操作系统

## 职业教育为什么需要这套方案

职业教育行业的文档与信息工作有几个共性：材料格式要求严、数据敏感不能乱传、人手紧重复劳动多。察元AI OS的切入点不是推倒重来，而是把 AI 能力装进现有流程，数据不出本机是底线设计。

## 落地路径：三步走

1. 基础层：先把模型设置向导跑通，验证环境与模型可用
2. 流程层：职业教育日常最高频的文档环节（配置云端厂商模型所属的场景）交给 AI 处理，人只做审核
3. 治理层：权限门与审计机制上线，形成使用规范

## 关键能力对齐

### 模型设置向导

- 概念页解释模型代理机制
- 默认对话模型选择
- 统一应用到智能体

### 配置云端厂商模型

- 国内/国际/本地/聚合四组厂商目录
- OpenAI 风格与阿里百炼风格 API 自动适配
- 填 Key 后可测试连通再启用

### 下载本地模型

- 内存预算分层推荐
- 断点续传与多路换源

### 离线导入模型权重

- 路径导入零拷贝
- 扫描本地放置的模型
- whisper 语音权重同样支持

## 一个行业侧影

公文与材料写作者的典型链路：

1. 知识库导入本单位制度与历年材料
2. 对话绑定知识库写初稿，回答带出处
3. 察元AI Office 修订追踪留痕，逐条接受拒绝
4. 发文前保密检查扫一遍

从初稿到核稿全流程 AI 辅助且可溯源。

提醒：保密检查是辅助参考，定密以人工审查为准。

## 合规与边界

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

行业落地最容易翻车的不是技术，是把边界讲清楚。

## 几条硬数字

能落到数字上的几条：设置默认模型里给文生图与图生图各选自动或指定模型（本地已装生图模型或已启用厂商），生图模型不配好，画图应用与智能体的生图指令都落空；各家能力矩阵标明能否一键安装、写入模型、收系统技能、收 MCP、记忆采集，两条路：自动一键把代理地址加模型写入五家（备份可回退）；智能体不知道它会哪些本机工具就等于没有，技能手册镜像让它们天生会用系统能力。
