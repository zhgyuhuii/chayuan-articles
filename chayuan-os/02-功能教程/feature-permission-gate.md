# 权限门实操，智能体调用察元系统能力

权限门的麻烦不在功能本身，在于信息散。让 AI 操作电脑的前提是管得住它：分级确认加超时拒绝加审计，这篇把它收拢成一条能照着走的路径。

## 是什么与为什么

权限门是察元AI OS（aidooo.com）里的一个能力模块：AI 桌面操作系统，本地大模型、知识库、智能体、宠物群聊装进一个桌面，智能体权限门是其中面向这类需求的一环。

概念一分钟，操作十分钟，这篇都覆盖。

## 先确认这些再开始

- 桌面形态（察元AI OS）：权限策略管理依赖桌面桥，其他形态显示「需要桌面形态（Electron 桥）才能管理权限策略。」。
- 权限门只治理智能体经察元控制面的调用——MCP chatop 条目、chatop os 命令行、回环 HTTP 三条通道在同一道门收口；智能体自己终端（pty）里跑的命令走各家 CLI 自己的机制，不在管辖内。
- 策略文件 permissions.json 存在当前登录用户的 profile 目录里，多用户互不继承（A 的「始终允许」不代表 B 允许）。

## 一步步来

1. 进入页面：打开「设置」，左栏点「隐私与存储」。第一张卡「智能体权限门」，说明文字原文：「分级管控智能体对桌面控制面工具的调用：T0 直放（只读与可逆写）、T1 会话内首次确认、T2 每次确认（截屏与电源）。审计始终记录；无人在场时超时即拒（fail closed）。」（同分区另两卡「遥测」「清除桌面数据」见清单 R9，不在本篇范围。）

2. 认识三档默认档（逐工具固定，改档见步骤 5）：

3. 武装权限门：勾选「启用权限门（关闭=全放行，仅审计）」，改动即时生效并显示「已保存」。默认不勾——即 shadow 模式：所有调用（含 T1/T2）直接放行，但决策照算照审计（日志记 shadow_ask / shadow_deny）。勾选后 T1/T2 立即开始弹确认卡；T0 与你自己点界面发起的操作（来源 renderer）永远直放。

4. 调审批超时：「审批超时」滑条 30–600 秒（步进 30，默认 120 秒）——确认卡倒计时归零即自动拒绝。（进阶：策略文件还支持「预授权窗口」，如 22:00–08:00 内指定 T1 工具自动放行、供常驻任务夜里跑；当前没有设置界面，经控制面 HTTP POST /policy 配置，T2 永不预授权。）

5. 逐工具改档：卡片下方「工具策略（默认档 + 覆盖）」表按组列出全部控制面工具，每行三键「允许 / 询问 / 拒绝」，当前生效档高亮，默认档带「·默认」角标：点非默认档即写入覆盖，点回默认档即清除覆盖，改动即时生效。把 T2 工具（如 desktop_capture）点成「允许」= 永久放行（这是 T2 仅有的永久放行入口——审批卡上没有这个键）；点成「拒绝」= 智能体调用被策略直接拒掉，收到 permission denied: tool '…' is blocked by the permission policy (settings ＞ privacy)。

6. 认识确认卡（武装后才会出现）：桌面顶部中央的非模态横幅卡，不抢焦点。内容：标题「智能体权限请求」＋档位徽标（T1「会话内首次确认」/ T2「每次均需确认」）＋等宽工具名＋可展开的「参数」（脱敏后的参数摘要）＋倒计时进度条与「{s} 秒后自动拒绝」＋按钮——T1 三键「本次允许」「始终允许」「拒绝」，T2 只有「本次允许」「拒绝」。多条请求 FIFO 排队，同屏最多 3 张，多余的显示「另有 {n} 个待确认请求」。按键效果：

7. 看审计：每一次控制面调用（放行或拒绝）都追加一行 JSONL 到桌面用户数据目录的 audit.jsonl：来源（哪个智能体，如 mcp:claude-code）、工具名、耗时、结果，以及权限门决策值（allow_default / allow_session / allow_card / shadow_ask / deny_user / deny_timeout 等）；参数里的敏感键（密码/token/key 类）已脱敏。

1. 「本次允许」：该工具本次桌面运行期内不再问（设置卡里出现「本会话已放行： …」列表，重启清零）；
2. 「始终允许」：持久写进 permissions.json（仅 T1 有此键）；
3. 「拒绝」：该次调用失败，智能体收到 permission denied: the user rejected '…' on the approval card；
4. 不回应：倒计时归零自动拒（permission denied: '…' needs user approval and no one answered within …ms (fail closed)）；锁屏/桌面壳关闭时所有未决请求直接按拒绝处理。

| 档位 | 设置页标签 | 语义 | 代表工具 |
|---|---|---|---|
| T0 | 「直放」 | 直接执行 | 备忘录/日历/提醒/联系人/便签内容、记忆读写、窗口管理（windows_*）、壁纸/主题/Dock、settings_* 设置键、MCP 本机工具等绝大多数只读与可逆写 |
| T1 | 「首问」 | 每次桌面运行期首次询问，答过一次本会话不再问 | terminal_run / terminal_kill、system_open_external（系统浏览器开网址）、stickies_attach / stickies_window、alwayson_*（常驻任务增删改与立即运行）、全部 webwindows_*（智能体原生窗口组，前缀整组） |
| T2 | 「每问」 | 每次调用都问 | desktop_capture（截取桌面画面）、system_shutdown / system_restart（关机/重启） |

最短路径走一遍：

1. 三级分级确认
2. 120 秒超时 fail-closed
3. 审计日志全量记录
4. 场景验证：放心让智能体跑终端任务
5. 场景验证：事后审计谁动了系统设置
6. 串联场景：官网下载全量离线包（含五件套权重，约 4.7GB）

## 如何确认操作生效

验证

1. 勾选「启用权限门」后出现「已保存」；让任一智能体做一次 T1 动作（如「用系统浏览器打开 https://example.com」），桌面顶部应弹出「智能体权限请求」卡。
2. 卡上点「本次允许」，同一会话内再做同类动作不再弹卡；设置卡出现「本会话已放行」列表。
3. 取消勾选「启用权限门」后再做同类动作：直接执行、不弹卡；audit.jsonl 新增行的 decision 为 shadow_ask。

## 谁需要这个功能

想让智能体截取桌面画面（desktop_capture）、关机/重启（system_shutdown/system_restart）这类高敏操作必须经你确认，反过来：担心无人值守任务被确认卡卡死，或好奇为什么智能体执行命令从来不问我；事后审计谁动了系统设置，桌面顶部弹出了「智能体权限请求」卡片，想知道三个按钮怎么选、倒计时走完会怎样。

用户常搜的问法：智能体要截屏/关机，能加一道确认吗；弹出来的『智能体权限请求』是什么？不点会怎样。

## 这些坑和边界要知道

边界先摆在桌面上：

- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力

## 你可能会问

### 为什么从来没见过确认卡？

2026-10-29 用户裁定后的出厂默认：权限门不武装（shadow 模式），智能体调用全部直接放行、只记审计——弹卡等待/超时曾造成无人值守场景「调不通」。要弹卡按步骤 3 勾选「启用权限门」。

### 「始终允许」和「本次允许」差在哪？

「始终允许」永久写盘（permissions.json，按用户隔离）；「本次允许」只在本次桌面运行期生效，重启即清零。T2 工具的卡上没有「始终允许」键——要永久放行只能到设置表里把该工具点成「允许」。

### 夜里跑常驻任务会被确认卡卡死吗？

会——无人应答超时（默认 120 秒，可调 30–600 秒）自动拒绝（fail closed）。夜间免打断的办法：不武装权限门；或把对应对应教程 工具在设置表改成「允许」；进阶可用预授权窗口（见步骤 4）。

### 智能体在自己终端里执行命令，怎么没弹卡？

权限门只治理桌面控制面这条通道（MCP chatop / chatop os / 回环 HTTP）；智能体 pty 终端里的 shell 本就有用户全权，由各家 CLI 自带的审批机制管理——门不是沙箱。

### 我想让某个工具彻底禁用？

设置表里该工具点「拒绝」：智能体调用立即被策略拒绝（deny_policy），不弹卡、不用等超时。
