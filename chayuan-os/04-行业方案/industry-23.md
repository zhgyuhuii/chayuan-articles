# 高校实验室AI方案落地：AI 桌面操作系统

## 高校实验室为什么需要这套方案

高校实验室行业的文档与信息工作有几个共性：材料格式要求严、数据敏感不能乱传、人手紧重复劳动多。察元AI OS的切入点不是推倒重来，而是把 AI 能力装进现有流程，数据不出本机是底线设计。

## 落地路径：三步走

1. 基础层：先把模型设置向导跑通，验证环境与模型可用
2. 流程层：高校实验室日常最高频的文档环节（配置云端厂商模型所属的场景）交给 AI 处理，人只做审核
3. 治理层：权限门与审计机制上线，形成使用规范

## 关键能力对齐

### 模型设置向导

- 概念页解释模型代理机制
- 默认对话模型选择
- 统一应用到智能体

### 配置云端厂商模型

- 国内/国际/本地/聚合四组厂商目录
- OpenAI 风格与阿里百炼风格 API 自动适配
- 填 Key 后可测试连通再启用

### 下载本地模型

- 内存预算分层推荐
- 断点续传与多路换源

### 离线导入模型权重

- 路径导入零拷贝
- 扫描本地放置的模型
- whisper 语音权重同样支持

## 一个行业侧影

小团队负责人的典型链路：

1. 服务器 Docker 部署察元AI工舱云桌面
2. 员工浏览器打开即用，账户隔离
3. 共享模型代理与知识库，配置统一
4. 常驻任务统一跑巡检与日报

一台服务器全组使用，配置与数据集中管理。

提醒：需要一台性能尚可的服务器与基本的 Docker 能力。

## 合规与边界

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

行业落地最容易翻车的不是技术，是把边界讲清楚。

- 试点建议：先选一个三人以内小组、一个高频场景跑两周再扩大

## 几条硬数字

能落到数字上的几条：本地模型多宠同发会排队（本地档 4 路并发上限）；右栏检索测试台就是 kb_search 工具的所见即所得：向量加全文加可选重排的混合检索，换嵌入模型必须重建索引，大库上 Milvus，这些运维动作都收在设置页，就触发 kb_search、kb_list、kb_read_doc 工具链。

## 离线与内网

离线内网这条线的口径：断网环境、涉密内网、不想花钱调 API，这三类需求都指向同一件事：把模型放在自己机器上跑，完全隔离的内网没法在线下载，U 盘搬运权重文件是最现实的路径，系统为此做了零拷贝导入；帮助中心离线可读，断网也能查手册；断网可用、数据不出本机。
