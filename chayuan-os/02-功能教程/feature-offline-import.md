# 断网的电脑怎么装本地模型：GGUF导入完整走法

GGUF导入的麻烦不在功能本身，在于信息散。完全隔离的内网没法在线下载，U 盘搬运权重文件是最现实的路径，这篇把它收拢成一条能照着走的路径。

## 一句话说清定位

GGUF导入是察元AI OS（aidooo.com）里的一个能力模块：AI 桌面操作系统，本地大模型、知识库、智能体、宠物群聊装进一个桌面，离线导入模型权重是其中面向这类需求的一环。

按真实界面写，按钮文案原样引用。

## 动手前的准备

- 权重格式：仅支持 .gguf（对话/嵌入/重排/决策/代码补全/图像理解，走 llama-server）与 whisper ggml 的 .bin（语音识别）；.safetensors / 原始 .bin 权重不能直接用，需先用 llama.cpp 工具链转量化。
- 磁盘空间：放置法文件多大占多大（无解压放大）；路径导入法不占额外空间（零拷贝引用）。
- 放置法要知道模型目录位置：桌面多用户形态的权重根 = <数据根>/shared/models/chatop-models/models/，数据根默认在「文档」目录下的 chatop-data（如 macOS ~/Documents/chatop-data，首次开机也可自选/导入别的位置）；本机实时真实路径以 GET http://127.0.0.1:52584/api/chatop-models/status 返回的 paths.modelsRoot 为准。
- 在线下载、断点续传等常规路径见对应教程；本篇只讲离线两条路。

## 具体怎么操作

1. 进入本地模型页

打开 设置 ＞ 模型，左栏「本地模型」组（默认展开）选一个能力分类（对话 / 嵌入 / 重排序 / 决策 / 代码补全 / 图像理解 / 语音识别 / …），右栏即该分类的本地模型页。

2. 打开导入对话框

「我的模型」标题行右侧点「＋ 添加模型」，弹出对话框，标题「导入本地模型文件」。

3. 填「模型文件路径」

1. 输入框占位提示 /Users/you/Downloads/model-Q4_K_M.gguf；
2. 桌面形态输入框旁有「…」按钮（系统文件选择器）；web/docker 形态没有该按钮，需手动填服务侧完全路径；
3. 填入路径后系统自动做两件事：按文件名猜「模型类型」并自动填「显示名称」（默认取文件名去掉扩展名）。

## 收尾检查

验证

1. 「我的模型」出现该模型：路径导入的带「本地」小标、第二行显示原路径；放置法的显示名 = 目录名（或侧车 name）。
2. 点「启动」后行首亮绿点，顶部计数 +1；点「测试」显示「测试通过 · <耗时>ms」（嵌入模型附维度）。
3. 浏览器打开 http://127.0.0.1:52581/v1/models（免 key）：清单出现 local/<模型id> 条目。
4. 放置法识别后，DeepSeek Harness 对话窗的模型下拉出现该模型（对话/图像理解类）。

## 几个容易忽略的细节

边界先摆在桌面上：

- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 文件放错目录扫描不到，需按指引路径放置

## 接着回答几个常见问题

### .safetensors / HuggingFace 原始权重能导吗？

不能。导入校验只放行 .gguf 与 whisper ggml 的 .bin（.bin 恒按语音识别处理），其他扩展名直接报「仅支持 .gguf 与 whisper .bin 模型文件」。先用 llama.cpp 的转换/量化工具产出 GGUF 再导入。

### 点了「导入并运行」，模型在列表里了但没跑起来？

「导入并运行」的动作是零拷贝登记（把路径登记进注册表），加载仍要回「我的模型」点「启动」。这与按钮文案的「并运行」有出入，以实际行为为准。

### 导入后把原文件移动/删除了会怎样？

导入是引用不是拷贝：原文件不在了，该条目自动从「我的模型」消失（登记仍保留）；把文件放回原路径即自动恢复。行内「删除」对导入模型只弹「移除「<名称>」的本地导入登记？原文件不会被删除。」——也绝不删你的原文件。

### help 里说「放好后点扫描按钮」，按钮在哪里？

当前版本的设置 ＞ 模型 页没有扫描按钮（旧「模型服务」应用已并入设置，该按钮未随迁）。放置后重启应用自动扫描，或用第 10 步的 curl 再扫描。

### 放置的模型没被识别，检查什么？

按序核对：目录是否在 paths.modelsRoot（第 8–9 步的 API 查真实路径）下；子目录名是否以 . 开头（会被跳过）；文件是否 .part 半下载残骸（被跳过，删掉 .part 后缀或重新拷贝完整文件）；补装内置模型时文件名是否与期望主权重文件名完全一致。

## 更多操作细节

4. 选「模型类型」（可选，自动识别可改）

七个类型 chips：对话 / 嵌入 / 重排序 / 决策 / 代码补全 / 图像理解 / 语音识别。文件名自动识别规则：.bin ＞ 语音识别；含 decision/startlux ＞ 决策；含 embed/bge ＞ 嵌入；含 rerank ＞ 重排序；含 coder/code ＞ 代码补全；含 vl/vision/minicpm ＞ 图像理解；其余 .gguf ＞ 对话。选「决策」时下方提示：决策标签仅适用于 StartLux 系（Qwen 词表）决策模型，其他基座会产出无效概率。

## 更多操作细节

5. 填「显示名称」与「上下文 (K)」

1. 「显示名称」默认取文件名，可改；
2. 「上下文 (K)」默认 8（即 8192 token，有效范围 512–1048576 token）；语音识别类型不需要。

## 更多操作细节

6. 点「导入并运行」

1. 成功：对话框关闭，模型立即出现在「我的模型」列表，行首带「本地」小标、第二行显示原路径；此时只是登记引用，模型还没加载进内存——点行内蓝色「启动」按钮完成加载；
2. 失败（红色提示，对应校验顺序）：「请填写模型文件路径」＞「仅支持 .gguf 与 whisper .bin 模型文件」＞「文件不存在或不可读：<路径>」＞「导入失败」。

## 更多操作细节

7. 认领（可选）

导入的文件若与内置目录里的模型疑似同款：强匹配自动认领（直接继承该目录模型的引擎参数与上下文；视觉目录模型例外——单文件导入没有多模态投影器，认领后收窄为纯文本链路）；弱匹配在行内显示「认领」按钮，点了才联动，已认领显示「已认领（撤销）」。

GGUF导入能不能用好，一半看操作，一半看你认不认边界：文件放错目录扫描不到，需按指引路径放置。
