# 嵌入模型配置为什么这样工作：模型配置可一键写入五家

「知识库的语义检索怎么配？嵌入模型在哪选」——这个问题最近被问了好几次。答案不复杂：嵌入模型配置在察元AI OS里是现成能力，这篇把入口、步骤、验证一次写全，按钮文案原样引用。

## 先弄清楚它是什么

嵌入模型配置能做的事拆开就这几件：对外服务示例可直接复制；Milvus 可选，重建索引一键，五档嵌入链路。对应的界面入口是知识库设置

概念一分钟，操作十分钟，这篇都覆盖。

## 操作步骤详解

| 树里选什么 | 档位 | 含义与兜底顺序 | 适用 |

|---|---|---|---|

| 首行「自动（推荐）」（旁注「本地优先，逐级兜底」） | 自动 | 先本地（正在运行的嵌入实例；没运行则从已装嵌入模型里挑一个经模型代理自动拉起，bge-m3 优先），没有再厂商路由，再自定义云端 | 大多数人；不用管模型启停 |

| 「本地模型 · N」组里选一个具体模型 | 仅本地 | 锁定该模型：运行中直连；未运行但模型代理可达时按需自动拉起；两者都不可用降厂商＞云端 | 数据不出机、离线可用 |

| 某厂商组（组名＝厂商 id · 模型数）里选模型 | 厂商 | 直连该厂商的 OpenAI 兼容嵌入端点，密钥沿用「模型代理」里该厂商的凭证；不可用降自定义云端＞本地 | 有厂商 Key、不想本地跑模型 |

| 末行「自定义 OpenAI 兼容」 | 自定义云端 | 用下方自填的 Base URL/模型/密钥；不可用降厂商＞本地 | 自建/其他 OpenAI 兼容服务 |

| 「语义检索」切「关闭」 | 关闭 | 不向量化，纯全文检索（FTS5 字面匹配） | 只想用字面检索、零模型开销 |

1. 本地运行时状态卡（最上方）：两个状态项——「本地嵌入」「本地对话」。绿色脉冲点＋「已就绪」＝模型服务里对应实例正在运行；黄色「未运行」＝没有。右侧按钮「去模型服务加载」打开 设置 ＞ 模型（模型服务已并入系统设置）。
2. 嵌入链路卡（标题「嵌入链路」，说明「决定文档向量化的模型：本地 / 厂商 / 自定义云端；切换模型后需重建索引」）。上半部分是「语义检索」开关「开启 / 关闭」：切到「关闭」＝完全不向量化、仅全文检索（旁侧提示「已关闭：仅全文检索」，下方模型树整体置灰，「测试连接」按钮同时置灰）。下半部分是模型树单选，对应五个档位：
    1. 本地组每行行尾带「运行中 / 未运行」状态；模型未运行且模型代理不可达时该行灰选（悬停提示「模型未运行且代理不可达——先到「模型设置」启动」），组头标「代理未就绪」；组内为空显示「还没有本地模型——到「模型设置」下载或导入」。
    2. 厂商组的清单来自「设置 ＞ 模型 ＞ 模型代理」的厂商路由表（把厂商「加入代理」后出现在这里）；密钥没配的组头带「密钥未配置」标记。
    3. 选「自定义 OpenAI 兼容」后展开：预设胶囊「SiliconFlow / DashScope / 智谱 / 自定义」（点预设自动填 Base URL、模型名与密钥引用名）；字段「Base URL」（占位 https://api.siliconflow.cn/v1）、「嵌入模型」（占位 BAAI/bge-m3）、密钥行「API 密钥（写入 harness 凭证库，不回显）」。
    4. 对话链路卡（标题「对话链路（云端兜底）」，说明「「问答」使用的对话模型：本地 / 厂商 / 自定义云端」）：同一棵模型树（「自动（推荐）」旁注「本地优先，云端兜底」），决定右栏「问答」在本地对话模型缺席时走哪里。选「自定义 OpenAI 兼容」展开：预设「DeepSeek / SiliconFlow / 智谱」＋「Base URL」（占位 https://api.deepseek.com/v1）、「对话模型」（占位 deepseek-chat）、密钥行「API 密钥（写入凭证库，不回显）」。
    5. 密钥怎么存（每处密钥输入行同构）：密码框（未配置时占位「粘贴 API Key…」，已配置时「已配置（输入新值可覆盖）」）＋按钮「保存」（已配置后变「更新」）＋徽标「已配置 / 未配置」，框内按 Enter 同保存。值经 harness 凭证库加密落盘，知识库配置里只存引用名（如 SILICONFLOW_API_KEY），界面永不回显。引用名由预设自动决定（嵌入自定义档＝EMBEDDING_API_KEY，对话默认＝DEEPSEEK_API_KEY），须为环境变量风格大写。
    6. 向量库卡（标题「向量库」，右侧小徽标显示当前库向量实际存放的后端，如 sqlite-vec）：双挡切换「本地（内置）」/「Milvus」。本地＝向量存在每库自己的 kb.db 里（内置 sqlite-vec，数据不出机）；选 Milvus 展开三个字段——「Base URL」（占位「https://你的域名/milvus 或 http://服务器IP:19530」）、「数据库名（可选）」（占位 default）、密钥行「访问令牌（写入凭证库，不回显；形如 root:密码）」（缺省引用名 MILVUS_TOKEN）。每个知识库在 Milvus 里对应一个独立集合。若当前库的向量存在另一后端，卡内出现橙色横幅「当前库的向量存于「{后端}」，与所选后端不同——保存后点「重建索引」迁移」。
3. 操作栏（卡片下方一行按钮）：
    1. 「保存设置」——保存全部配置并即时生效（无需重启应用）；成功后按钮短暂显示「已保存」。
    2. 「测试连接」——会先自动保存当前设置，再用当前嵌入链路发一条样例文本：成功显示绿色「连接成功：{类型} · {模型} · {维度} 维 · {毫秒}ms」，失败红色「连接失败：{原因}」。「语义检索」处于「关闭」时该按钮置灰。
    3. 「测试向量库」（仅选 Milvus 时出现）——对 Milvus 地址做可达性测试（列集合）：成功「向量库可达：{n} 个集合 · {ms}ms」；Base URL 没填报「Milvus 参数未配齐：先填 Base URL」，连不上报「无法连接 Milvus：{原因}」。
    4. 「重建索引」——对当前选中的库（「文档」页左栏选中的那个库）重嵌全部「就绪/失败」文档（向量层整体重置、按新链路重嵌；切了 Milvus 也在这一步完成迁移），显示「已排队 {n} 篇文档重嵌——回到「文档」页看进度」，进度在「文档」页逐文档查看。
    5. 页脚两行说明：「密钥经 harness 凭证库加密落盘，知识库只存引用名；换服务商 = 选预设 + 粘新 Key。」「嵌入模型或维度变化后点「重建索引」，进度见「文档」页。」
    6. 对外服务卡：服务地址、端点清单与 curl 示例——健康检查与排障详见对应教程。

从这几步开始：（第 2 个切入角度）

1. 五档嵌入链路
2. Milvus 可选
3. 重建索引一键
4. 对外服务示例可直接复制
5. 场景验证：库变大后迁移 Milvus
6. 场景验证：换更强的嵌入模型重建索引

## 它的局限也要说清楚

用之前要认的账：

- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 接着回答几个常见问题

### 「测试连接」报「没有可用的嵌入来源：本地运行时未运行嵌入模型，且云端参数/密钥未配齐」？

当前档位下（自动/仅本地）本地既没有运行中的嵌入实例、也没有可经代理拉起的已装嵌入模型，且云端参数没配齐。三条路：到 设置 ＞ 模型 下载/加载一个嵌入模型；在厂商组里选一个已配 Key 的厂商模型；或选「自定义 OpenAI 兼容」填 Base URL＋模型＋密钥。

### 换了嵌入模型，检索怎么变差了？

每库记录索引时的嵌入指纹，模型或维度变了指纹即不符——系统自动降级为纯全文检索并在「文档」页顶部亮橙色横幅。点横幅（或设置页操作栏）的「重建索引」用新模型重嵌全部文档即可恢复语义检索。

### 「测试向量库」失败？

依次查：Base URL 填了没有（没填报「Milvus 参数未配齐：先填 Base URL」）；地址能不能通（报「无法连接 Milvus：…」时按随附的具体原因查网络/端口，Milvus 默认 19530）；访问令牌是否正确（形如 root:密码，写入凭证库不回显，可重新粘贴覆盖）。

### API Key 安全吗？换服务商怎么改？

密钥值只进 harness 凭证库加密落盘，知识库配置与界面只存/显示引用名，永不回显。换服务商＝选新预设＋粘贴新 Key（各预设密钥引用名不同，互不覆盖）；同引用名粘贴新值即覆盖旧值。
