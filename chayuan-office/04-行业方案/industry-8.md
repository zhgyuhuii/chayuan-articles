# 文化传媒AI方案实操行业应用：从选型到落地

## 文化传媒为什么需要这套方案

文化传媒行业的文档与信息工作有几个共性：材料格式要求严、数据敏感不能乱传、人手紧重复劳动多。察元AI Office的切入点不是推倒重来，而是把 AI 能力装进现有流程：开源 AI 办公套件，六编辑器一体，AI 嵌进每个编辑器，数据不出本机是底线设计。

## 落地路径：三步走

1. 基础层：先把AI 校对与文本分析跑通，验证环境与模型可用
2. 流程层：文化传媒日常最高频的文档环节（领域助手 4576所属的场景）交给 AI 处理，人只做审核
3. 治理层：权限与数据边界明确，形成使用规范

## 关键能力对齐

### AI 校对与文本分析

察元AI 页签常用助手组的拼写与语法检查：结果以批注锚定原文（命中片段逐字一致），对话里汇总条数，只报明确可证实的语言错误不报风格偏好；文本分析下拉 14 项（重写、润色、正式化、通俗化、扩写、缩写、提炼关键词、提取行动项、术语统一、生成标题、检查段落序号格式、AI 痕迹检查、批注解释、超链接解释）。

要点：批注锚定，只报实错不报偏好，14 项文本分析。

### 领域助手 4576

Docs 端 4576 个领域助手、229 个领域包（另有 24 个常用助手，全库约 4600 个），表格 102、演示 100、PDF 100、Markdown 100、HTML 130，搜索结果上限 80 条。

要点：五端独立小库，按领域检索，4576 个 Docs 助手。

### 连接察元OS 知识库

AI 面板与首页输入框下方书本图标选库（多选），每轮先并行检索（每库前 6 条），回答带编号引用角标，点开看来源与下载原文；上下文预算 8000 到 32000 字四档（默认 12000）；五级自动发现本机察元OS 知识库服务，检索失败不阻塞发送。

要点：四级上下文预算；多库并行检索，编号引用可溯源。

### 保密检查与文档脱密

安全保密组三件套：保密检查按八大类风险（密级标识、涉军涉装涉训、组织身份、人员联络、时间地点部署、内部编号、经营商业敏感、军工政企线索）出批注与报告；文档脱密把关键词换成 8 位随机占位符并在同目录留 AES-256-GCM 加密备份；脱密复原凭密码还原，密码丢失无后门。

要点：可逆脱密；加密备份随文件走；八类风险扫描。

## 一个行业侧影

研究生与科研人员的典型链路：

1. PDF 阅读器选区标注加问 AI
2. Zotero 引文插入与书目生成
3. 扫描件自动 OCR 变可搜索文本
4. Markdown 双链笔记沉淀文献网络

读、引、记、写在一个应用里闭环。

提醒：Linux 端无系统 OCR 引擎，扫描页不识别。

## 合规与边界

- API Key 存本机 ai-settings.json 不上传，支持环境变量引用
- PDF 涂黑生成物理删除的 -redacted.pdf 副本，不是注释遮盖
- 文档脱密用 AES-256-GCM 加密备份，PBKDF2-SHA-256 21 万次迭代

行业落地最容易翻车的不是技术，是把边界讲清楚：AI 功能依赖已配置的模型（BYOK 或本地端点），未配模型时只有传统办公功能可用。另外：.doc/.ppt 老格式明确不支持打开，需要先转成 docx/pptx。

## 接着回答几个常见问题

### 老格式 doc 文件打不开？

明确不支持 doc 与 ppt 老格式，先转成 docx 或 pptx 再打开；odt 等 ODF 格式可导入但采取保守策略。

### 必须配置 API Key 才能用 AI 吗？

现阶段是。内置账号登录当前版本未开放，AI 功能需要 BYOK 接入厂商或本机 Ollama 等端点；不配模型时传统办公功能完全可用。

### Linux 上扫描件 OCR 没生效？

Linux 无系统 OCR 引擎，扫描页保留位图不识别；macOS 与 Windows 走系统引擎自动识别。
