# 架构不符排查：uname 确认架构再选包

架构拿错是安装失败里最冤的一种：包没坏、步骤没错，只是型号对不上。这篇把架构不符排查的确认方法和典型表现讲清楚，动手前花一分钟看 uname，比装一半报错再返工划算。

## 安装前确认

- 系统要求：Windows 10/11，x64 或 arm64
- 安装包：NSIS 安装器（ChaAIOS-版本-架构.exe）
- 说明：uname 确认架构再选包。

安装包只认官方渠道发布的版本，其余来源不做参考。

## 主线的安装步骤

1. 对照 uname 结果，从官方渠道取架构一致的 exe 安装器
2. 双击安装，零额外依赖
3. 首次启动创建本机账户，进入桌面
4. 对话应用里选本地模型即可开聊，全程无需联网

## 怎么确认做成了

- 启动进入桌面，对话应用选本地模型能正常回复
- 首启初始化需要 5 到 30 秒，属正常现象，期间不用干预

## uname 输出怎么读

终端执行 `uname -m`，按输出选包：x86_64 对应 x64 安装包，aarch64 对应 arm64 安装包；输出是别的标识（比如 armv7l 这类 32 位字样）就不在上文确认的支持口径里，先换机器或换系统再谈安装。`uname -a` 顺带能看到内核版本与主机名，求助时把完整输出发出去，比只描述现象清楚得多。

## 两组容易混淆的概念

一组是位数与指令集：x64 指 64 位 x86 指令集，arm64 指 64 位 ARM 指令集，两者互不兼容，不能拿「都是 64 位」当兼容依据。另一组是模拟与原生：个别系统提供跨架构转译，让部分外来架构的程序能跑起来，但安装器、驱动这类深入系统的组件通常不在转译范围内，别指望转译层兜底，按原生架构选包才稳。

## Windows 侧怎么确认

设置＞系统＞关于里有系统类型一行，写明基于 x64 或 ARM64 的处理器；PowerShell 执行 `$env:PROCESSOR_ARCHITECTURE`，输出 AMD64 即 x64。ARM 笔记本用户尤其要留神，选包时按系统类型一字不差地对，不要凭习惯拿 x64 包。

## 架构不符是什么表现

Linux 下运行错误架构的二进制，终端报 exec format error 之类的内容；Windows 下双击不符架构的 exe，常见提示是无法在此设备上运行。两种表现都容易被人误判成文件损坏，先别急着删包重下，把架构确认一遍，多数所谓「装不上」到这里就真相大白。

## 几条使用上的边界

- 云端厂商模型的使用，API Key 需要使用者自己备好
- 内存 8GB 的设备，同时只载入一个对话模型比较合适，复杂任务受限
- 龙芯暂不在支持列表；视频生成不在本地，经云端路由完成
- 进阶的 Docker 云桌面与跨终端互联，得有点动手折腾的底子

## 灵宠与桌面的可见性

后台跑着的 AI 被灵宠具象成桌面上望得见的小生物；配置走右键编辑，删除前有两步确认把关，外面闯进来的野宠也能收编为正式灵宠并建档，定时任务的进度从日志文件变成桌面上的实时直播，跑没跑、成没成一眼可见；可选群分区（桌面出图标双击进群）。

## 让 AI 动电脑前的三道锁

MCP 服务清单增删改（stdio、HTTP、SSE、本机 52583），让 AI 操作电脑的前提是管得住它：分级确认加超时拒绝加审计，三道锁缺一不可；审计日志全量留痕，事后翻账能对到每一次动作。

## web 与 Docker 形态的端口口径

web/Docker 形态的网页桌面有默认端口；面向外网时提供 9 位字母外网后缀访问链接，配套 wa 会话管理，管理员可执行踢线操作。

## Office 与知识库的联动排错

知识库在 Office 或 WPS 侧引用不到，多半卡在服务没起或端口被占，顺着三层检查往下走，能定位到具体出问题的一层；内置的察元AI Office 从 Dock 就能点开，文档、表格、演示都在线编辑。

## 常驻任务与桌面环境的分界

与知识库、模型联动，共享同一个模型代理；建常驻任务时把指令写好，挑定模型或智能体（或选择直跑），再挂上工作区知识库与联网开关。它不是一个软件窗口，是一整套桌面环境，这是操作系统形态与工具软件形态的分水岭。编辑面板负责调整模型、知识库与人设；出了故障可转给智能体修复。

## 本地模型的加载与卸载

按直链目录放置后执行扫描，本地放置的模型即可入库；whisper 语音权重同样支持；显式加载、显式卸载，再配上自动卸载策略，这套机制是本地模型管理的主轴。这一套动作同样只认架构口径，权重文件与运行时对不上时，报错位置往往更隐蔽，选型时一并核对最省心。

## 帮助与反馈的位置

反馈与求助都在产品内帮助中心：六节手册加搜索、离线可读，提交反馈的入口也在那一带，不用出系统找。

### 断网状态下架构排查还能做吗

能。uname、系统设置里的架构信息都是本机数据，不依赖网络；联网时内置 web_search 工具默认走 DeepSeek 搜索，断网后这项自然不可用；本机的 Stable Diffusion 出图全程不依赖网络。

### 排查过程中产生的数据放在哪

新装时把数据目录定下来，或直接导入拷贝根，再建管理员账号；目录由自己定，整套系统就能搬去非系统盘住，日后换机把目录一拷即完成迁移；定时的巡检、早报和数据盯梢这类例行任务也归它，一觉醒来收结果就行。

架构这一关过了，后面的安装步骤基本是顺水推舟；再遇到报错，先想想是不是又换了台机器，把 uname 的输出重新贴出来对一遍，答案往往就在那串字符里。
