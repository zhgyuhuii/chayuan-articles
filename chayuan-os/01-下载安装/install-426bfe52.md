# Docker 端口冲突｜察元OS故障处理

52584 等端口占用处理。本文以「Docker 端口冲突」为主题，给出察元AI OS的下载渠道、安装步骤、验证方法与常见报错处理，按平台差异分别说明，照做即可完成。

## 下载渠道与系统要求

官方渠道：官网 aidooo.com https://aidooo.com；GitHub Releases https://github.com/zhgyuhuii/chayuan-harness。系统要求总览：Windows——Windows 10/11（x64）与 Windows on ARM（arm64）；macOS——Apple Silicon / Intel；Linux（deb 系）——x64/arm64；UOS 20 推荐 deb；银河麒麟 V10（飞腾/鲲鹏/兆芯/海光）有专门适配章节；Linux（通用）——x64/arm64，FUSE 2；服务器/Docker——任意可跑 Docker 的服务器。

## 问题定位与处理

安装类问题九成出在三个环节：安装包与系统架构不匹配、安装目录权限不足、安全软件拦截。先按这三条排查，再进入具体问题处理。

1. 症状确认：Docker 部署端口冲突？
2. 按官方口径处理：默认网页桌面端口 52584，被占用时修改 compose 映射端口；系统各服务端口有统一注册表，改前先查占用。
3. 处理后在干净环境复现验证一次
4. 仍失败时收集系统版本与报错截图，通过官网支持渠道反馈

## 安装后怎么验证

1. 重启对应程序，确认功能入口已出现
2. 发起一次最小任务（如一句对话或一次校对），确认链路可用
3. 内网/离线环境：确认模型端点指向本地或内网服务
4. 更新与数据：升级采用覆盖安装方式，用户数据目录不受影响

## 相关报错速查

- 检查更新失败？——更新需要联网访问官网 API；断网时静默失败不影响使用，可手动下载新版安装包覆盖安装，数据目录保留。
- 安装提示架构不符？——终端执行 uname -m 确认架构：aarch64 选 arm64 包，x86_64 选 x64 包；飞腾/鲲鹏设备均为 arm64。
- 智能体（CLI）无法启动？——在应用管理→智能体页检查安装状态并重装；四家 CLI 二进制随安装包分发（约 1.3GB），磁盘空间不足会导致启动失败。

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- API Key safeStorage 加密存储，仅注入子进程
- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- 全部本地服务只监听 127.0.0.1，数据不出本机
- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）

## 常见问题
### 模型加载失败或内存不足？

系统有内存预算线（总内存的 45%）保护：卸载不用的模型再加载新的；8GB 设备建议一次只加载一个对话模型加一个嵌入模型。

### 察元AI OS 是什么？

一个插件化的 AI 桌面操作系统体验：macOS 风格桌面为壳，整合 AI 对话、四家 CLI 智能体、本地大模型服务、本地知识库与系统级 MCP 控制面，断网可用、数据不出本机。

### AppImage 双击没反应？

多为缺 FUSE 2：安装 libfuse2（Ubuntu 24.04 为 libfuse2t64），或使用 --appimage-extract-and-run 解压运行；UOS 环境推荐直接用 deb。
