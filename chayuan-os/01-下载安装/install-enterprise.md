# 企业批量装机：批量安装与配置基线

企业批量装机，单台装好不难，难的是几十台装得整齐划一、出了问题查得到源头。这篇按察元AI OS的安装顺序走一遍，顺带把基线、验收与铺开节奏讲清楚。

## 安装前确认

- 系统要求：Windows 10/11，x64 或 arm64
- 安装包：NSIS 安装器（ChaAIOS-版本-架构.exe）
- 说明：批量安装与配置基线。

安装包统一从官方渠道下发到内网分发点，员工电脑不从来源不明的地方自行下载。

## 完整操作步骤

1. 从官方分发渠道取对应架构的 exe 安装器，放进统一的分发目录
2. 双击安装，零额外依赖
3. 首次启动创建本机账户，进入桌面
4. 对话应用里选本地模型即可开聊，全程无需联网

这四步是单台机器的标准动作，批量场景下可以当验收脚本用：装机员每完成一台，把第 3、4 步复走一遍，确认桌面与对话都正常，再进入下一台。零额外依赖这条对批量场景尤其重要——安装器不挑环境，机器不需要预装运行库，系统镜像保持干净，出错环节就少。

## 怎么确认做成了

- 进得了桌面、对话应用选本地模型能接上话，这条是硬门槛
- 首启的初始化耗时正常落在 5 到 30 秒区间，属预期行为，不用人工干预

两条指标之外再补一个观察点：桌面加载完成后操作是否跟手。批量采购的机器硬件新旧不一，同一个安装包在不同批次的机器上初始化耗时会有差别，台账里记下每台的初始化耗时，几轮下来就能摸出这批设备的基准线。

## 它的局限也要说清楚

先把底数交清楚，以下是当前版本的既有边界：

- 安装包暂未覆盖龙芯平台；视频生成也不在本机能力里，交给云端路由处理
- 8GB 内存档的设备一次只挂一个对话模型，复杂任务的压力它扛不住
- API Key 不在安装包里，调云端厂商模型前各人自行注册填入
- Docker 云桌面与跨终端互联属于要花精力伺候的进阶形态，团队按运维力量量力选用

## 批量分发前的统一基线

批量装机最忌每台机器各装各的。稳妥的做法是先拿一台当样板机：安装器选对架构，默认模型在设置里配好，恢复密钥生成后抄进公司的密码管理流程——几条恢复途径都走不通时，最后只剩清数据重装一条路，届时基线配置一并丢掉，密钥是唯一的兜底。样板机验收通过后，其余机器照抄同一套动作，中途不换包、不改配置，出问题才好定位。账户命名也属于基线的一部分：管理员账户用统一规则命名，普通账户按工号走，日后审计与交接都省事。

## 铺开顺序怎么排

几十台机器一口气全装完是大忌。合理的节奏是：先装样板机所在的部门，跑一两周收集反馈；再按部门分批铺，每批之间留缓冲，前一批暴露的问题补进后一批的检查表。批次之间把分发目录里的安装包重新校验一遍，防止中途被误替换。这样铺下来，同一个问题不会在每台机器上重演一遍，管理员的精力也花在刀刃上。

## 逐台验收的最小清单

批量场景的验收只有两条硬指标：对话应用选本地模型能正常回话；首启初始化 5 到 30 秒内完成。逐台过这两条，比抽样靠谱——初始化时间明显超出正常范围的那台单独留下排查，其余机器继续走流程，免得一台异常拖着整批返工。顺手把每台机器的数据目录与账户名记进台账，日后维修换机时对得上号。

## 内网离线环境的批量口径

企业内网多半不通外网，批量机器默认按本地模型跑：模型权重统一放置后，系统会扫描本地放置的模型，whisper 语音权重同样在支持之列；加载策略可选自动（本地优先）或指定，机器一多就选自动，省得逐台手动配。显式的加载卸载搭配自动卸载策略，本地模型的内存占用才管得住。

## 端口与安全基线

内网防火墙要预留的口子先列清楚：本机的 OpenAI 兼容统一模型代理固定走 52581；知识库对外服务用固定端口；web/Docker 形态的网页桌面有自己的默认端口。代理相关的进阶能力集中在进阶面板：被代理模型树形多选、厂商路由加入移出、虚拟 Key 签发吊销、调用审计查询。给外部工具开权限又不想交出真实厂商 Key 时，虚拟 Key 加审计是标准做法，这套口径写进企业的安全规范里最合适。

## 常见翻车点

批量铺开时最常见的三种返工：安装器架构发错，x64 与 arm64 的包混进了同一个分发目录；首启初始化的半分钟里有人等不及硬关机，给后续使用埋雷；恢复密钥没人抄，后期找回时才发现无从下手。三种都能靠分发前的检查表拦住。检查表不用做复杂，一页纸足够：架构核对、密钥抄录、初始化计时、对话验证四行，装机员逐台打勾，管理者抽查台账即可。
