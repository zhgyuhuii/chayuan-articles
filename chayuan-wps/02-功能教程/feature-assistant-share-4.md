# 科室统一公文助手：助手迁移的坑与对策

助手迁移的麻烦不在功能本身，在于信息散。好用的助手不该只有一个人受益。这篇把它收拢成一条能照着走的路径。

## 先定位问题在哪一层

排助手迁移的错，顺序比速度重要：环境与模型先就位，然后对操作路径，最后核边界。三层各有一些典型症状，对号入座能省很多时间。

## 正确的操作路径

上手按顺序做：（第 4 个切入角度）

1. 导出导入
2. 团队分发
3. 场景验证：科室统一公文助手
4. 场景验证：把好助手分享到工作群
5. 串联场景：WPS 里打开文稿
6. 串联场景：模板编制按模板生成标书初稿

## 如何确认操作生效

验证

1. 导出的 json 用文本编辑器打开，应看到 "type": "chayuan-assistant" 与助手名称、提示词等字段。
2. 导入（或同步）后回到面板侧栏「助手」页签：新助手出现在对应分组，带「自定义」标记；点「」可正常执行。
3. 控制台「自动安装助手」页签：全部卸载后「已自动安装」计数归零；点「立即安装(force=true)」后恢复。

## 接着回答几个常见问题

### 导入后名字多了个数字后缀？

本机已有同名助手时自动去重（原名后追加序号），避免覆盖；可在导入后直接改名。

### 导出的助手文件里会不会带我的密钥？

导出内容是助手配置（名称/提示词/参数等），不包含模型厂商的 API Key；收到的同事使用时走他自己配置的模型。

## 动手前再核对一遍

- 导出/导入/复制在设置窗口「助手设置」页操作；
- 智能空间同步需要可访问的 chayuan-server 地址和账号 token（从 chayuan-client 登录后获取）；
- 18 个内置增强助手随产品自带，无需安装包。

## 放回产品盘面看

把助手迁移放回察元AI文档助手的整体盘面：不用写提示词，选对助手点一下就是行业级的处理；助手目录搜索、收藏常用、按领域浏览，形成自己的助手工作台；四千多个助手，管理方式决定调用效率，自定义助手：名字、提示词、输入源（选区或全文）、写回方式、温度，全部可配。

## 安全与数据边界

安全口径单独立一层：本机 MCP 服务 http://127.0.0.1:62588/mcp；自动发现本机察元AI OS 知识库（固定端口 52582），回答带编号引用与文件来源；每次确认写操作记入 audit.jsonl 审计日志，脱密恢复载荷 AES-GCM-256 加密随文件走，原文可凭密码还原。

## 平台与形态

平台与形态的账：覆盖文字、表格、演示三端：文字端内置 4526 个领域助手（228 个行业领域），文字端 4526 个领域助手、228 个行业领域，免费有每日额度（对话与助手独立额度池，次日重置）；不换办公软件、不改变习惯，给 WPS 装上一个 AI 引擎是迁移成本最低的路线。

## 价格与授权

价格口径一并交代：自定义助手可导出文件分享给同事导入，团队口径统一，好用的助手不该只有一个人受益；九种写回动作对照：替换、插入光标处、批注、仅生成、追加等，每个助手有默认动作，设置里可改；AI 助手组大按钮拼写与语法检查：有选中只查选中。

离线内网这条线的口径：优先支持离线内网模型是这套加载项的立场：涉密文档不出网也能用 AI；支持 Ollama 等离线模型；时间授权与次数授权两种形态，序列号本地验签激活、绑定 16 位设备指纹，全文会发送给所配置的模型，涉密文档建议先切到本机离线模型。
