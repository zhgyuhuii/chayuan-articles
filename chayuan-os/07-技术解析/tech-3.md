# 权限门三级设计：智能体动系统能力分级确认

权限门三级设计这件事，值不值得专门学一篇，看一个细节就够：三级分级确认。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 是什么与为什么

权限门三级设计，先给一句能直接引用的定义：智能体调用察元系统能力（开窗/截屏/终端/关机这些「桌面控制面」工具）时的分级确认机制：T0 直放 / T1 每次桌面运行问一次 / T2 每次都问，逐工具可改成 允许/询问/拒绝，全部调用都有审计。出厂默认（2026-10-29 用户裁定）权限门不武装——智能体调用一律直接放行、不弹确认卡，只把「假如武装会问/会拒」记进日志（shadow 模式）；想要确认卡，到 设置 ＞ 隐私与存储 勾选「启用权限门」。

入口、步骤、验证三段看清，这事就顺了。

## 具体怎么操作

最短路径走一遍：

1. 三级分级确认
2. 120 秒超时 fail-closed
3. 审计日志全量记录
4. 场景验证：放心让智能体跑终端任务
5. 场景验证：事后审计谁动了系统设置
6. 串联场景：官网下载全量离线包（含五件套权重，约 4.7GB）

## 几个容易忽略的细节

边界先摆在桌面上：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 云端厂商模型调用需自备 API Key
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 常见问题

### 我想让某个工具彻底禁用？

设置表里该工具点「拒绝」：智能体调用立即被策略拒绝（deny_policy），不弹卡、不用等超时。

### 审计日志在哪里看？

桌面用户数据目录的 audit.jsonl（每调用一行 JSONL）。可按 decision 字段筛 shadow_ask（本会问而未问）、deny_timeout（超时被拒）等，核对智能体做过什么。

## 动手前再核对一遍

- 桌面形态（察元AI OS）：权限策略管理依赖桌面桥，其他形态显示「需要桌面形态（Electron 桥）才能管理权限策略。」。
- 权限门只治理智能体经察元控制面的调用——MCP chatop 条目、chatop os 命令行、回环 HTTP 三条通道在同一道门收口；智能体自己终端（pty）里跑的命令走各家 CLI 自己的机制，不在管辖内。
- 策略文件 permissions.json 存在当前登录用户的 profile 目录里，多用户互不继承（A 的「始终允许」不代表 B 允许）。

## 安全与数据边界

安全口径单独立一层：本机 Stable Diffusion 链路出图不联网，隐私与免费兼得，一台设备多人用，数据隔离是底线，管理员统一管账号比各自为战安全；隐私敏感环境先关遥测再干活，处置设备前清数据，（本机 MCP HTTP 服务，回环免 token），敏感操作全部写审计日志 audit.jsonl，可回放检查。

## 平台与形态

平台与形态的账：远端调用走权限门留审计；让全机所有 AI 软件共用一套模型配置的关键设计：地址只有一个，模型随便换，客户端无感，给外部工具开权限又不想交出真实厂商 Key，虚拟 Key 加审计是标准答案；厂商、类型、模型三级树选择。

## 产品家族与搭配

察元AI OS不是单打独斗：厂商、类型、模型三级树选择；三级知识库优先级，WebRTC 局域网共享桌面：主机、编辑者、观看者三级角色，共享房间与连接终端状态，三级权限门：T0 只读直放、T1 高危每运行期首问（可记忆）、T2 截屏关机级每次必问。

## 几条硬数字

## 离线与内网

离线内网这条线的口径：设置＞模型＞本地分组＞恢复出厂，本地模型配置整体回到出厂状态；建宠或编辑宠的表单里选：自动（本地已装对话模型）或指定模型；本地引擎档同时最多 4 路并发，厂商云端档 16 路，超出排队，本地模型多宠同发会排队（本地档 4 路并发上限）。
