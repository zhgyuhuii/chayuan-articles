# 开源棋牌游戏新物种：MIT协议的大模型竞技场

应用商店里的棋牌游戏清一色闭源：规则是黑盒，匹配是黑盒，连对面坐的是不是真人都说不清。开源棋牌游戏走的是另一条路。开源棋牌游戏的定义不复杂：指源码以开源协议公开、允许自由使用、修改与分发的棋牌类软件；察元竞技场是这个类别里的新形态——把大模型对弈装进开源棋牌的框架里，MIT 协议，11 款玩法，从五子棋到麻将一应俱全。

「新形态」三个字不是随便说的：过去开源棋牌的典型是规则引擎，如今这一款把模型接入、竞技排位、过程可视化都开源了出去。这篇拆一拆协议、自托管与二次开发三件事。三件事对应三种身份：普通玩家看自托管，极客看协议，二开者看架构，各取所需。

## 拆词与相近概念辨析

开源棋牌游戏与几类近亲要分清。开源棋类引擎：专注单一棋种的项目，搜索算法登峰造极，但不管模型接入，也不管多玩法。引擎强是引擎的功劳，竞技场要补的是另一块：让通用大模型当选手，让完整对局当考场，两者不冲突，反而是互补的两条技术路线。闭源棋牌平台：功能齐全，源码不可见，数据归属与规则黑盒是老话题。开源大模型棋牌竞技场：源码全公开，玩法多线铺开，模型随便接，数据留本机——察元竞技场属于这一类，且在开源协议上选了限制很少的 MIT。三类对象对照下来，开源棋牌游戏的独特生态位清晰了：它不跟引擎比搜索深度，不跟闭源平台比运营打磨，它比的是「你能不能看懂我、带走我、变成你自己的东西」——这道题只有开源做答。

MIT 协议的含义一句话：允许任何人自由使用、复制、修改、分发，包括商用，条件只是保留版权声明，同时软件按「现状」提供、不含担保。放在棋牌竞技场这个语境里，意味着你可以把它原样自用、改造成自己的产品、拆出引擎层接进别的项目——法律路径是通的。顺带对照家族里其他协议找感觉：察元AI OS 是 AGPL-3.0，察元AI Office 是 Apache-2.0，察元AI工舱是 GPL-2.0，竞技场独立版选 MIT——不同产品按场景选不同协议，竞技场选 MIT 的逻辑是希望它被改、被接、被长出各种变体。你看到的不是孤立的软件，是一条开源产品线上放得很开的一环。

## 自托管：数据不出本机

它是桌面应用，Windows、macOS、Linux 都有安装包，装在本机跑，数据也落在本机：API Key 存本机应用数据目录不上传，对局记录与天梯积分都在本地。所谓自托管，在这里就是「自己的机器自己管」——不需要依赖谁的云服务活着，也不需要向谁交代你的对局数据。安装矩阵也照顾得全：macOS 分 arm64 与 x64，Windows 覆盖 x64 与 arm64，Linux 提供 deb 与 rpm，旧机器与新机器都有得装。装完不注册、不登录、不强制联网，桌面应用的本分它都守着。

自托管的对面是托管服务：后者省心，但规则更新、数据迁移、服务下线都不由你；前者多花十分钟安装，换来的是全部控制权。棋牌竞技场这种长期玩的软件，控制权的价值会随时间放大。

## 可二开：裁判注册制的底气

二次开发的友好度，看架构分层。察元竞技场分三层：electron 主进程管单实例与模型网关，src/arena 引擎层装着 11 款玩法裁判、对局引擎、LLM 玩家与 TrueSkill，src/app 是 React 19 的 UI 层。核心是裁判契约：每款玩法实现 createGame、seats、phase、pendingAction、apply、result、viewFor、suggestAction、anonymize 这套接口，就能注册成新玩法接入大厅——11 款裁判全部是纯逻辑零 IO，胜负判定百分之百归代码。这套契约还有个隐藏福利：anonymize 接口把匿名观战做进了协议层，二开的新玩法自动继承观战公平性，不用自己重新发明。想加一款新棋牌，照契约写一个裁判；想改规则，裁判逻辑就摆在那里。vitest 测试覆盖裁判边界与玩家协议，改动的安全网也是现成的。二开方向举几个现实的：给团队加一款内部棋牌玩法，实现裁判契约就能挂进大厅；把模型网关指向自己维护的推理服务；在 UI 层做一套定制观赛页面。三层各管各的，改动互不牵连。

契约式设计的好处在这里兑现：裁判不管 UI，UI 不管模型，模型不管判罚，边界清晰意味着改动的影响半径小，一个人也能维护一条线。

## 上手路径：从装好到开局

装完即用：安装包走官方渠道，按 Windows、macOS、Linux 与机器架构选装。设置 ＞ 模型配置里接入模型（85 家厂商目录或 Ollama 本地推理），回大厅选玩法开局。想二开就把源码拉到本地，先读裁判契约与现有 11 款裁判的实现，再决定加玩法还是改 UI。玩家路径更简单：装上、配模型、开打，开源属性对普通使用者是透明的，感受不到也不影响。

## 三条边界

版本还在 0.1.0 早期阶段，接口与功能可能随版本调整，二开者要做好跟进变化的准备。版本号诚实，0.1.0 就按早期项目对待，期待管理先行。

二次开发有真实成本：读代码、跑测试、适配环境都要投入，MIT 给的是许可，不是保姆服务。官方文档与源码注释是起点，社区讨论是补充，自学能力是入场券。

MIT 按现状提供、不含担保，用于严肃场景前自行评估，这是协议文本的原文精神。含担保与否听起来遥远，真用于对外服务时就是责任划分，别忽略。

## 开源棋牌游戏常见疑问

### 开源棋牌游戏收费吗

察元竞技场软件本身 MIT 开源免费；云端模型 API 费用由使用者向厂商支付，Ollama 本地模型零成本。免费的边界也要说清：软件免费不等于使用零成本，云端模型的账单另算。

### 可以拿去商用吗

MIT 协议允许商用，保留版权声明即可；协议同时声明软件按现状提供、不含担保，具体以仓库里的协议文本为准。

### 怎么做二次开发

从开源仓库拉源码，读三层架构与裁判契约，新增玩法实现契约接口即可注册接入；UI 与模型网关也都在源码里，改哪里看你的需求。动手顺序建议先读裁判契约，再挑一款现成玩法当参照实现，照猫画虎是省力的起步方式。

### 与察元AI OS里的竞技场什么关系

同源。察元AI OS（AGPL-3.0）内置同款竞技场，引擎层与独立桌面版逐字节同构；独立版以 MIT 单独开源，适合只想玩竞技场的人。玩法与规则体验因此完全一致，选哪个看你要不要整个 OS。

闭源棋牌把规则锁进黑盒，开源棋牌把整张桌子摊开给你。察元竞技场用 MIT 协议把大模型对弈这件事整个交了出去：源码可读、玩法可加、部署自由——这个类目的想象空间，才刚被打开。
