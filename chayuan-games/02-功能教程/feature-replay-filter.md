# 回放协议筛选：快速定位对局关键手

看一场机机观战的回放，最磨人的是拖进度条：两三百手匀速划过去，真正值得停的手就那么几处，全靠缘分碰。察元竞技场的回放器给了一件顺手的工具：按协议字段筛选。回放协议筛选是什么意思、怎么用它定位大争议手，这篇从原理到步骤讲清楚。

## 先弄清楚它是什么

得先从协议说起。竞技场里所有大模型玩家走统一出招协议：每一手除了着法本身，还带着协议侧的数据——这一手的延迟、token 用量，以及解析是否顺利、有没有触发代走兜底这些运行痕迹。这些数据本来是工程侧用来保障对局能顺利打完的，换个角度看，它们也是每一手的「体检报告」。

回放器把这份报告用了起来：支持按协议字段筛选，把符合条件的手一次挑出来。哪几手模型想得特别久、哪几手 token 烧得多、哪几手解析得磕磕绊绊，一筛就是一张清单。经验上，长考、高消耗、解析挣扎的手，往往和对局里的关键手、大争议手高度重合——模型在那里遇到了难题。

这些字段是怎么来的？模型出的招要过解析容错链：按标准格式解析，解析不出就剥思维链、抽大括号、补截断的尾巴，再不行全文扫合法着法，最后才是代走兜底。这一路走过的每道工序，都会在协议数据里留下痕迹——筛选筛的其实就是这些痕迹。

一句话定位这个功能：回放协议筛选是回放器的加速器，帮你从「逐手找关键手」升级成「先筛再验」。

## 动手前要备好什么

一局打完的对局（进行中的局等它打完再筛更从容），顺手记着这局里大概哪个阶段出现过你看不懂或者觉得离谱的手——带着目标筛，效率更高。回放协议筛选面向愿意读一点数据的用户，不需要编程基础，但你要对「延迟」「token 用量」这些词有基本概念，知道它们大致反映什么。

另外提醒一句：协议侧数据每一手都在产生，对局越长、选手越多，积累的原始信息量越大。这正是筛选存在的意义——信息量大到没法逐条读的时候，条件筛就是那把漏勺。

## 具体怎么操作

第一步，从记录页进入目标对局的回放。

第二步，找到协议筛选入口。回放器里提供按协议字段筛选的能力，具体有哪些筛选项、条件怎么组合，以你手头版本的实际界面为准（0.1.0）。常见思路是围绕每手的延迟与 token 用量设条件，把协议侧的异常值挑出来。

第三步，执行筛选，得到一张手列表。列表里的每一手都能直接跳转，不用你再拖进度条大海捞针。

筛的条件怎么定？没有统一答案，取决于你想找什么。想找「卡壳现场」，把耗时长的手捞出来；想找「高消耗的纠结」，看 token 用量的高位段；想把「翻车链路」连起来看，就盯解析费劲、触发代走的那一批。先有问题，再定条件。

第四步，逐手验证。跳到筛出的手上，看盘面：这一手是不是局势的分水岭？配合形势曲线看它前后的走势，配合问叹号标注看它被标了妙手还是失误。多数时候你会重复同一种体验——筛出来的手，恰恰落在曲线上剧烈起伏的位置附近。

第五步，复盘定性。验证完把结论串起来：这一局的关键手是哪几手，模型在哪里卡壳、在哪里发力。协议数据负责把嫌疑人带上来，盘面负责定罪。

## 做完后的验证

给自己计时：一场上百手的对局，从打开回放到锁定三五个关键手，用回放协议筛选应该只要几分钟。如果你还在匀速拖进度条，说明这套筛选没用起来；如果几分钟内已经坐在关键手前看思维链气泡了，说明你会用了。

顺手再练一局：换一种玩法重复同样的流程，体会不同玩法里「协议异常」与「关键手」的重合度差异——棋类里重合度高，牌类里诈唬会让两者错位，这个差异本身就是观察模型的好素材。

## 这些边界要心里有数

筛选是初筛不是结论。协议侧异常的手值得看，但不等于每一手都是关键手；反过来，有些静悄悄的好棋协议数据毫无波澜，筛不出来。盘面与形势曲线才是最终裁判。

另一个容易踩的坑：代走。模型出招解析失败到一定程度，系统会按启发式代走兜底，能挡杀就挡、能吃就吃。这些兜底手同样留在记录里，筛的时候别把它们当成模型的真实水平——它们恰恰说明那个模型在这一手翻车了，属于「翻车现场」而非「正常发挥」。

token 用量还和你的钱包挂钩。每一手消耗的都是模型 API 的计费 token，长考多、废招多的对局，费用曲线跟着往上走；用筛选顺手看看这些分布，也是给自己的额度做个体检。

还有一句实话：这个功能面向愿意读数据的用户。如果你只想轻松看棋，形势曲线加问叹号标注的组合更省心；回放协议筛选是进阶玩法，值得会，不必强求常用。

## 高频疑问

### 回放协议筛选具体能筛什么

围绕每手的协议侧数据筛，比如延迟、token 用量这类字段，具体筛选项以回放器实际界面为准。筛选结果是一张可跳转的手列表。

### 筛出来的手一定是妙手或失误吗

不一定。筛选只说明这些手在协议侧表现异常（想得久、烧得多、解析费劲），是不是关键手要回盘面验证，形势曲线与标注是很好的裁判。

### 不用筛选，直接看形势曲线行不行

行，曲线定位转折点也很快。回放协议筛选的增量价值在于覆盖「协议侧异常但曲线变化不大」的手，两条路互补，不冲突。

### 代走的手会出现在筛选结果里吗

可能出现。代走兜底的手留在对局记录里，看到这类手，把它们当模型翻车的证据，而不是模型的棋力体现。

### 进行中的对局能用吗

建议等打完再筛。对局进行中每一手的协议数据还在滚动生成，复盘场景下用筛选的收益明显得多。

### 筛选出来的手怎么跳回去看

筛选结果里的每一手都支持跳转，从列表点进去就落在那一手的位置，配合前后几手慢慢看，比拖进度条省事得多。

协议筛选是个典型的「工程能力外溢成观看体验」的功能：本来是解析容错链留下的运行痕迹，被回放器借来当成了检索索引。学会它之后，你看长对局的姿势会变——不再陪跑全程，而是带着筛子进场，直奔有故事的那几手。
