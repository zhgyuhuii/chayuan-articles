# 写给写作者的AI写作指南：清单式指南

如果你是写作者，下面这些场景大概率不陌生：灵感与资料管理割裂。长线写作的上下文管理。这篇清单式指南以察元OS为工具，把这个岗位的AI写作工作流从头到尾串一遍。

## 这个岗位的三个真实痛点

- 灵感与资料管理割裂
- 长期项目上下文丢失
- 多智能体写作风格不一

## 用察元OS怎么解：工作流拆解

1. 共享记忆保持项目上下文
2. 知识库放参考资料
3. 本地模型保隐私

## 一天的使用节奏示例

以一个工作日为例：早上到岗先处理积压材料，用「共享记忆保持项目上下文」完成首轮处理；上午协作时段按流程推进；下班前把当天产出归档。长线写作的上下文管理。工具不改变职责边界，只是把重复劳动压缩掉。

## 边界与注意事项

- 生成类结果需要人工确认后采用
- Docker/云通道等进阶形态需要一定动手能力
- 建议先在低风险材料上试跑，形成自己的使用习惯后再铺开

## 离线运行与部署形态

离线部署有专门的五步法与政企/涉密内网/野外隔离环境专章（帮助中心 offline 栏目）；国产化环境（银河麒麟 V10、统信 UOS，飞腾/鲲鹏/兆芯/海光）有逐平台安装指引。

## 数据安全与隐私边界

- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- 本地模型五件套随软件分发，断网即用
- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）
- API Key safeStorage 加密存储，仅注入子进程

## 如实说说它的不足

- 8GB 内存设备需克制使用：一次一个对话模型，复杂任务受限
- 标准安装包含引擎不含模型权重，完整离线需 models 变体包（体积数 GB）
- 云厂商模型调用需自备 Key，免费额度视厂商政策

## 常见问题
### 升级会丢数据吗？

不会。覆盖安装/自动更新保留数据目录；升级前备份 dsh-home 更稳妥。

### 四家智能体是内置的吗？

是。Claude Code、Codex、OpenCode、OpenClaw 的 CLI 二进制随安装包分发（约 1.3GB），装完即用；无模型偏好时自动指向本地模型。

### 支持哪些系统？

Windows 10/11（x64/ARM）、macOS（Apple Silicon/Intel）、Linux x64/arm64（deb/AppImage；银河麒麟 V10、统信 UOS 有专门适配），另有 Docker 服务器形态。
