# 构建打包的跨平台矩阵：察元OS的原理解析

构建打包的跨平台矩阵常被用户问到。这篇原理解析从察元AI OS的实际实现出发，讲清楚设计取舍与使用层面的意义。

## 一句话结论

交付形态覆盖：Windows（NSIS 安装器 exe（ChaAIOS-<版本>-<arch>.exe））；macOS（dmg（ChaAIOS-<版本>-arm64.dmg））；Linux（deb 系）（deb（ChaAIOS-<版本>-<arch>.deb））；Linux（通用）（AppImage（ChaAIOS-<版本>-<arch>.AppImage））；服务器/Docker（docker compose）。跨平台打包的难点在架构矩阵与依赖就位，而不是功能本身——每个平台的安装步骤都在官方文档有逐条说明。

## 为什么这样设计

这个设计的动机可以概括为三点：把风险控制在机制而不是纪律里（靠制度约束人的行为总会失效，靠架构约束才稳定）；把复杂度封装起来（用户不需要理解内部实现，只需要理解行为边界）；把可验证性留给用户（声明的能力都能在产品里实际验证）。软件工程里没有免费的设计——每一条这样的取舍都是在「体验、安全、性能、成本」之间做的显式权衡，约束变了，结论就可能反转。

## 对使用者意味着什么

- 全部本地服务只监听 127.0.0.1，数据不出本机
- API Key safeStorage 加密存储，仅注入子进程
- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- 相关能力以官网 https://aidooo.com 最新版本为准

2. 构造一个最小场景验证行为是否符合描述
3. 观察边界情况的表现（断网、权限、并发）
4. 把验证结论沉淀进团队内部文档

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）
- API Key safeStorage 加密存储，仅注入子进程
- 全部本地服务只监听 127.0.0.1，数据不出本机

## 费用与授权的边界（如实说明）

免费下载使用，购买只停提醒、永不锁功能。免费部分：首运行起 90 天完全静默；之后每日首次启动弹一次购买页（可手动关闭），主页每 30 分钟一条温和提醒，「买了只停提醒，不买照用」。付费部分：四档价格：¥149 / ¥359 / ¥599 / ¥1049（年度推荐）；弹窗内扫码支付或复制机器指纹到官网购买；离线激活：客服后台签发 HMAC 短码（Crockford base32 + 校验位），绑定 16 位机器指纹，本地验签、无需联网激活服务器

## 常见问题
### 四家智能体是内置的吗？

是。Claude Code、Codex、OpenCode、OpenClaw 的 CLI 二进制随安装包分发（约 1.3GB），装完即用；无模型偏好时自动指向本地模型。

### 开源吗？

仓库协议 AGPL-3.0，策略为「开源核心+企业版」方向；当前以免费可用的发布包为主。

### 其他软件能用本机模型吗？

能。统一模型代理提供 OpenAI 兼容与 Anthropic 协议接口（对话/嵌入/重排/语音），任何支持的客户端指向本地代理即可。
