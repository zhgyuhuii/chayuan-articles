# webwindows：智能体的 GUI 之手（原理解析）

这是「察元OS技术解析」系列的一篇。webwindows：智能体的 GUI 之手是理解这款产品设计哲学的关键切面——看完你会明白它为什么这样设计、这样设计换来了什么、代价是什么。

## 一句话结论

webwindows 工具族让智能体打开真实 Electron 原生窗：load_url/load_html/execute_js/截图/点击穿透/置顶/透明度——配合桌面截图与权限门，智能体第一次有了「眼睛」（看屏幕）和「手」（操作窗口），且全程受审批与审计约束。

## 为什么这样设计

这个设计的动机可以概括为三点：把风险控制在机制而不是纪律里（靠制度约束人的行为总会失效，靠架构约束才稳定）；把复杂度封装起来（用户不需要理解内部实现，只需要理解行为边界）；把可验证性留给用户（声明的能力都能在产品里实际验证）。软件工程里没有免费的设计——每一条这样的取舍都是在「体验、安全、性能、成本」之间做的显式权衡，约束变了，结论就可能反转。

## 对使用者意味着什么

- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）
- 本地模型五件套随软件分发，断网即用
- 全部本地服务只监听 127.0.0.1，数据不出本机
- 相关能力以官网 https://aidooo.com 最新版本为准

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 全部本地服务只监听 127.0.0.1，数据不出本机
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）
- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）
- 本地模型五件套随软件分发，断网即用

## 常见问题
### 数据存在哪里？怎么备份？

数据根目录三平台路径统一（Win %APPDATA%\chatop、mac ~/Library/Application Support/chatop、Linux ~/.config/chatop），备份 dsh-home 目录即备份全部对话、知识库与配置。

### 哪里下载、遇到问题去哪反馈？

官网 aidooo.com 或 GitHub Releases（zhgyuhuii/chayuan-harness）；应用内置帮助中心（26 篇离线文档）与诊断入口。

### 什么是系统级 MCP？

系统提供 chatop MCP server（80+ 工具），智能体能开窗、嵌网页、跑终端、读写便签日历、换壁纸截屏等；配置自动同步到六家智能体。
