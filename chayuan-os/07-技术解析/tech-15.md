# CLI智能体接本地模型：先搞清五家配置各认什么

CLI智能体接本地模型这件事，动手之前值得先搞清一个事实：难点不在模型那一头，而在智能体这一头。同一台机器上装着 Claude Code、Codex、OpenCode、OpenClaw，想让它们都走同一个模型，听起来只是改个地址的事，实际改起来会发现五家各有各的配置文件、各有各的模型清单格式，改完一家还有四家，改完四家还可能遇上协议不兼容的坑。

这篇以察元AI OS 的实现为例，先把五家配置面的差异逐个摆开，再讲一个回环统一出口怎么把这些差异收拢，最后给出一次写入五家的完整操作与验证方法。内容基于 3.1.15 版本的真实配置文件与界面整理。

## 五家配置面，五个模样

先把五家的模型配置写在哪、写什么格式列清楚，这张表是全文的地基：

| 智能体 | 配置文件 | 模型清单写在哪 | 智能体内在哪看 |
|---|---|---|---|
| Codex | ~/.codex/config.toml | model_catalog_json 指向一份目录文件，整份替换内置列表 | /model 面板 |
| OpenCode | ~/.config/opencode/opencode.json | provider.<id>.models 映射，键就是切换器里显示的模型名 | 模型切换面板 |
| OpenClaw | ~/.openclaw/openclaw.json | models.providers.<id>.models 数组 | 设置的 Models 页与 /model |
| Claude Code | ~/.claude/settings.json | 没有目录，只有 Opus、Sonnet、Haiku 三档环境变量槽位 | /model 三档加手输 |
| DeepSeek Harness | 桌面端模型设置 | providers.<route>.models 路由清单 | 会话模型下拉 |

有一个认知比表格本身更重要：五家里没有一家会自己从连接配置里读出模型清单。把地址和密钥配好，只解决「连得上」这一半；想让智能体内部能选到这个模型，还得按它认的格式把清单单独写给它一份。很多「代理明明配了、模型面板里却看不到」的问题，根子都在这一步没做。

Claude Code 的三档槽位值得单独说。它没有模型目录这个概念，/model 里固定只有 Opus、Sonnet、Haiku 三档。想把一批模型放进去，办法是分槽：Sonnet 槽放默认模型，Opus 槽放清单里的第二个，Haiku 槽放第三个；只写一个模型时三档同值。这是 Claude Code 自身机制决定的，不是分发环节的将就。

## 一个回环地址，收拢协议差异

配置面五样，协议也未必统一。察元AI OS 的做法是在本机跑一个 OpenAI 兼容的统一模型代理，默认地址 127.0.0.1:52581：本地模型从它出，云端厂商路由也从它出，写入五家配置的始终是这同一个地址。代理默认只监听本机回环，不出网；厂商密钥留在系统的凭证库里，写到各智能体配置里去的只有代理地址本身。

Codex 是五家里最讲究的一家。它对外的接口形态是 responses，而第三方厂商的兼容面多数只认 chat completions，工具形态对不上，直连过去就是一个 400，会话直接起不来。所以厂商模型接 Codex 要一律改道经模型代理做协议转换，模型名换成「路由名/模型名」的命名空间写进去。理解了这一层，遇到 Codex 会话异常时就不会往密钥方向瞎排查。

## 动手：一次写入五家

界面把上面这些差异全部包掉了，操作只剩四步：

1. 打开 设置 ＞ 模型，进入「模型代理设置」，滚到被代理模型的卡片，里面是一棵按厂商、分类、模型名组织的三级树。
2. 在树上勾选要下发的模型，勾分组即全选其下，然后点右上角「应用选中（N）…」，弹出的对话框里五家默认全部勾选。
3. 点「应用」，写入逐家进行，每家一行结果：成功显示绿色的「已写入」，失败给出具体原因，一家失败不影响其余几家。写入是幂等的，重复应用不会堆出重复配置。
4. 验证要重开会话再做：Codex 里输入 /model，列表应当只剩注入的模型；OpenCode、OpenClaw 在各自的模型面板核对；Claude Code 看 /model 三档是不是换成了新模型。

每次写入前，系统会按时间戳自动备份原有配置，落在 ~/.chatop/backup/<时间戳>/<智能体名>/ 目录下。想回退，把备份里的文件拷回原位即可；想核对这次到底写了什么，直接 cat 对应的配置文件看一眼，比任何转述都可靠。

## 四条边界，先说清楚

- 写进各家的只是代理地址，代理没在跑，智能体就找不到模型。遇到集体失联，先看模型服务状态，再查配置。
- Codex 的模型目录是启动时加载的，写入之后不重开会话，/model 永远不刷新，这一条坑过的人不少。
- 本地模型按需加载，引擎刚被唤醒时第一个请求可能要等一会儿，界面上看像卡住，其实在冷启动，等待一次就好。
- 内存 8GB 的机器建议一次只加载一个对话模型；云端厂商调用需要自备密钥，密钥无效时厂商路由不会工作。

## 几个常见问题

### 五家之外的智能体还能接吗？

可以，但不走自动写入。界面会把本机感知到、暂不支持自动写入的智能体（如 Gemini CLI、Aider）灰显列出并注明原因；这类工具可以手动把代理地址填进它自己的配置，因为代理本身就是 OpenAI 兼容接口，通用性是够的。

### 为什么在浏览器形态里找不到应用按钮？

因为写配置必须经过桌面主进程去动各家的配置文件，web 形态不提供这个入口。回到桌面应用里，按上面四步操作即可。

### Claude Code 只有三个槽位，模型多了放不下怎么办？

三档槽位放默认与头两个备选，其余模型等需要时再换入。槽位机制是 Claude Code 自己的边界，换模型时重新应用一次即可覆盖。

### 怎么确认每家到底被写入了什么？

直接看配置文件：cat ~/.codex/config.toml、cat ~/.claude/settings.json。备份目录里还留着写入前的版本，两相对照，改动一目了然。

把这件事收拢成一句话：模型侧统一成一个回环出口，智能体侧按各家认的格式分发清单。理解了五家配置面的差异，再遇到模型看不见、会话起不来这类问题，排查路径自然就顺了：先看代理在不在跑，再看清单写没写对格式，最后看重开会话没有。
