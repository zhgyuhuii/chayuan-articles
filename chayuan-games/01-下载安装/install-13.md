# 察元竞技场API Key管理：存储位置与安全机制

把 API Key 填进任何一个第三方应用之前，都值得先问一句：它存哪了、谁能看到、会不会传出去。这篇把察元竞技场API Key管理的机制摊开讲：存储位置、读写机制、网络通道、上传与否，四件事都给你可核实的答案，最后附上你自己能做的加固动作。

## Key 存在哪：本机应用数据目录

答案直接给：你的 Key 以明文形式存在本机的应用数据目录里，具体是 userData 下的 arena/config.json 这份文件，加密升级位已预留。userData 是 Electron 应用的标准数据目录，跟着你的系统用户走，Windows 与 macOS 各在对应系统的用户数据位置，卸载软件前它都在那里。

明文存储这件事值得如实说：它意味着拿到你系统用户权限的程序都能读到这份文件。这是当前版本的现实边界，加密升级位已预留说明后续有强化计划，但今天你不该把这份文件当加密保险箱看待。反过来，明文也带来一个实用能力：这份配置文件可读、可备份、可迁移，换电脑时把它带走，配置原样恢复。

## 为什么 Key 和对局数据放在一处

arena/config.json 这份文件里不止 Key，厂商配置与对局相关的设置都在这一套本机数据体系里，统一放在 userData 的设计有三个理由。

跟着用户走：个人数据集中在系统用户数据区，备份迁移的边界清晰，带上应用数据目录就是带走全部。权限一致：能读你配置的程序与能读你对局记录的是同一批，不存在「配置很安全、记录裸奔」的错位。清理简单：想彻底重来时删一个目录就够了，不会东一份西一份留残渣。

理解了这个布局，备份与迁移就只有一句话：带走应用数据目录，全部搞定。

## 读写机制：写锁与热读

这份配置文件的读写有两道机制，都是工程口径的实在设计。

写锁：配置写入带写锁。你在设置里保存厂商与 Key、应用在运行中更新对局数据，都会走同一份文件体系，写锁保证并发写入不会把文件写坏——多场对局同时结算时，谁先谁后有秩序，不会出现两笔写入互相覆盖成乱码的情况。

热读：运行时热读取。你在设置里改的模型配置，运行中的应用即时就能读到，改完配置不用重启整个应用，下一手对局就能用上新配置。这个体验平时不显眼，挂机跑锦标赛中途想换模型时特别有用——赛程不用停，配置跟人走。

## 网络通道：一个口子出本机

Key 相关的网络行为只有一种：向你在配置里填写的厂商端点发起模型调用请求。所有模型流量只走本机网关一个口子，网关用随机端口加路径令牌鉴权，外部进程够不到这个通道。也就是说，别的程序没法顺着你机器上的竞技场去蹭你的模型接口。

除了你配置的厂商地址，Key 不会流向任何地方。没有遥测回传、没有配置同步到云端、没有「匿名收集以改进产品」。软件是 MIT 开源的，源码可自行检索获取，这类结论你可以自己到代码里核实，这正是不做闭源黑盒的产品敢把机制写成文档的底气。

这套设计还有一个隐含的好处：应用不常驻一个写死的对外端口，随机端口加令牌的组合让外部扫描也难以撞上通道，安静且收敛。

## 不上传声明与对局数据

把话说全：Key 永不上传。对局记录、天梯积分、协议画像这些数据同样全部落在本机。你打过的每一局、每个模型出过什么招，都只存在于你的电脑里，想清理就删文件，想带走就拷走，不存在服务器上还留一份的问题。

需要说明的另一面是：用云端模型时，请求内容本身会到达厂商，厂商按其政策处理请求，这是调用任何云端服务的固有属性，与竞技场无关。想做到内容完全不出本机，用 Ollama 这类本地推理，整条链路彻底离线。

## 你自己能做的加固

三条务实建议。给系统开磁盘加密，Windows 用 BitLocker，macOS 用 FileVault，机器丢了 Key 也不至于跟着丢。不要把 arena/config.json 分享给任何人，也不要截图 Key 所在的配置页发群里，备份这份文件等于备份你的全部 Key，迁移和分享是两回事。定期到厂商控制台轮换 Key，尤其是你把 Key 用过多个工具的情况下，轮换是成本很低的习惯。

## 边界与实话

三条说在前面。明文落盘是当前现实，拿到你系统权限的恶意程序可以读到它，电脑本身的账户安全就是 Key 的安全下限，这一点不因任何应用而改变。热读与写锁覆盖的是竞技场自己进程的读写，你手动编辑配置文件时仍要自己注意别写坏格式。版本 0.1.0 的存储结构可能随版本调整，以你实际版本的应用数据目录为准。

还有一条与热读相关：运行中改配置即时生效很方便，但正在进行的那局不会中途换阵容——已经上桌的模型把这局打完，下一局才用新配置，这是特性不是缺陷。

## Key 安全的常见疑问

### Key 会传给察元AI 的服务器吗

不会。Key 只存在本机配置文件里，只在你发起模型调用时流向你配置的厂商端点。源码开源可核实，不放心就去仓库读代码。

### 换电脑怎么迁移 Key

把应用数据目录里的 arena/config.json 带到新机器对应位置即可，配置原样生效。备份与迁移是同一件事，这份文件等于你的全部 Key，别外传。

### 忘了 Key 存哪、只记得填过，安全吗

安全属性取决于你的系统账户安全。文件在本机用户数据目录里，建议顺手做好两件事：开系统磁盘加密、控制台轮换一遍 Key。

### 配置文件被删了怎么办

配置丢失只能重新填，Key 本体要去各厂商控制台重新复制。所以上一节才建议备份这份文件，它丢了等于所有厂商的凭证都要重拿一遍。

### 怎么自己验证真的没上传

两个办法：读开源仓库里的相关源码，所有网络出口都写在代码里；或者用系统的网络监控工具观察应用进程的对外连接，看它们是否只指向你配置的厂商地址。开源软件的这类声明，本来就是拿来让人查的。

Key 管理的机制说穿了就三句话：明文本机存、写锁加温读、流量一个口。机制透明加上开源可查，是这个产品在安全这件事上的态度。你知道 Key 住在哪，用起来才踏实，配置环节到此讲完，下一篇处理剩下的麻烦：装不上、打不开怎么办。
