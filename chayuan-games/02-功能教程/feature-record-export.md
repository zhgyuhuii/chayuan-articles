# 棋谱JSON导出：把对局数据带去自建分析

数据存在别人的平台上，分析就得看平台脸色；数据能带走到自己手里，想怎么折腾都行。察元竞技场在这件事上态度干脆：棋谱JSON导出，整局对局打包成一个 JSON 文件，拿去喂脚本、做可视化、建数据集，随你。这篇讲清导出里有什么、怎么导，以及自建分析的几个真实场景。

## 先弄清楚它是什么

棋谱导出是竞技场提供的数据出口：把一局已完成的对局导出成 JSON 格式的文件。JSON 是程序圈通用的数据格式，文本编辑器能打开，Python、JavaScript 等各种语言都能直接解析。

文件里装的是这一局的数据本体：对局的基本信息——什么玩法、哪些玩家座位、结果如何；逐手的着法与事件记录；以及协议侧的信息，比如每手的耗时。反过来说，你的 API Key 这类凭证不在棋谱数据里，导出的是对局数据，不碰密钥。换句话说，你在应用内回放里看到的逐手过程，和导出文件里的逐手记录，是同一份数据的两种呈现——回放负责好看，JSON 负责好用，底层同源，怎么用看你的目的。

具体字段名与嵌套结构，以你导出的文件为准——打开看一遍，比背任何文档都快。版本 0.1.0 阶段字段结构还可能演进，这一点后面边界里细说。

为什么是 JSON 而不是别的格式？因为它足够通用：不挑语言、不挑工具、人也能直接读，脚本拿过来就能解析。对局数据走通用格式，意味着你的分析工具链完全自由，不会被绑在任何特定软件上——数据归你，出口敞开。

## 动手前要备好什么

三样东西。一是有已完成的对局记录；二是本机装着能处理 JSON 的工具，随手一个文本编辑器就够入门，想认真分析建议配一门脚本语言；三是想清楚你要分析什么问题——是统计某个模型在斗地主里的叫牌倾向，还是给五子棋对局画自己风格的走势图。带着问题导，数据才用得起来。如果本机一场对局都还没有，先去打几局——人机局、机机观战都行，有数据才有分析的原料，空谈结构没有意义。

## 具体怎么操作

第一步，打开记录页，找到想带走的那一局。

第二步，用棋谱导出功能把这一局存成 JSON 文件，选个你找得到的位置保存。

第三步，先做完整性检查。用编辑器或命令行工具打开文件，确认它能被正常解析（不是半截乱码），粗看里面有玩法信息、着法序列与结果字段。这一步花两分钟，能省掉后面脚本调试的大半小时。

第四步，写你的分析。几个真实场景供参考：

统计场景——把同一模型在多局里的着法数据汇总，看它的开局偏好、叫牌倾向、长考分布，在应用内置的协议画像之外，补一层自己的观察维度。

可视化场景——拿逐手数据画自己风格的攻守图、耗时图。应用内置的形势曲线是通用视角，你的脚本可以是私人订制视角，想突出什么就画什么。

数据集场景——把对局导出整理成训练或评测用的数据集，喂给自己的程序；与朋友互换导出文件，互相研究对方攒下的对局，也是一条路。

归档场景——重要对局导出留档，本机记录之外多一层保险，换设备、清磁盘时心里不慌。

教学场景——把典型对局整理成案例讲给朋友，讲棋牌规则或者研究模型行为，带数据的案例比空口白话有说服力。

第五步，校验结论。拿一两局做交叉验证：你脚本算出的东西，跟应用内回放、形势曲线的呈现能不能对上。对得上，你的分析管线才算跑通。跑通之后，这套管线就是你的了：往后每打一批新对局，导出、解析、出图一气呵成，分析的复利从这一刻开始攒。

## 做完后的验证

标准就一条：你的脚本或工具读导出文件时不再报错，而且算出的关键数字（比如总手数、胜负结果）与应用内看到的一致。两边对得上，这份 JSON 才算真正吃透了。

再补一个健壮性检查：故意把文件里某个字段值改坏再读一次，确认你的脚本会报错而不是静默吞掉——分析管线的报错能力，跟解析能力一样重要。

## 这些边界要心里有数

JSON 面向程序不面向人。想「看」一局棋，应用内回放直观得多，导出文件是给分析用的原料，不是给眼睛看的成品。

字段结构会随版本演进。0.1.0 阶段别把解析代码写死在某个字段名上，给脚本留一层兼容处理，将来版本更新不至于全线报废。

导出不改变数据归属。对局记录本身仍在本机，导出是复制不是搬移，记录页里的原局照常回放，不因为你导出过就消失。

分析的深度取决于你自己。竞技场负责把数据完整交到你手上，结论靠谱不靠谱，平台不背书——这是自建分析的乐趣，也是责任。

导出文件体积不大，胜在干净：着法、事件、结果齐齐整整放在一个文件里，跨局归档、跨机搬运都方便。注意备份节奏，重要对局导一份放网盘，本机出问题时还有底。

## 上手路径

1. 对局室终局后点「导出棋谱」，JSON 自动落盘
2. 回放器载入棋谱，按协议字段筛选想看的事件类型
3. 配合「？！标注」跳到关键手，逐段回放
4. 批量分析就把多份 JSON 丢给脚本或智能体处理

## 高频疑问

### 导出的 JSON 用什么打开

任何文本编辑器都能打开看，想结构化处理就用 Python、JavaScript 之类的语言解析，或者用各类 JSON 查看工具。

### 能导出成图片或者其他棋谱格式吗

官方口径里导出格式是 JSON，面向自建分析。要看棋局，应用内回放最直接；要其他格式，自己写脚本转换。

### 能一次批量导出所有对局吗

应用内以逐局导出为准。批量需求属于自建分析的范畴，可以基于本机存档与脚本自己搭，动手前先摸清数据结构。

### 导出文件里有没有我的 API Key

没有。导出的是对局数据——着法、事件、结果与协议侧信息；密钥存放在本机应用数据目录的配置文件里，不在棋谱数据中。

### 导出之后原对局还在吗

在。导出是复制，不是搬移，记录页里的原局照常回放复盘，两边互不影响。

### 分析自己的对局需要编程基础吗

轻量观察不需要，文本编辑器打开看结构就能有个概念；要做统计与可视化，一门脚本语言会省力很多，但门槛也就是入门级。

数据可携带这件事，平时感知不强，用上一次就知道值钱：平台给你的是一手原料，应用内的形势曲线、协议画像都是官方视角的成品，而导出让你能做出自己的成品。把它当成竞技场递过来的门钥匙，门后面是你自己的分析世界，规矩由你定。
