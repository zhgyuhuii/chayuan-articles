# 模型配置可一键写入五家：本地模型接口完整走法

「模型代理的作用是什么？为什么只配一个地址」——这个问题最近被问了好几次。答案不复杂：本地模型接口在察元AI OS里是现成能力，这篇把入口、步骤、验证一次写全，按钮文案原样引用。

## 模型代理是个什么东西

本地模型接口在察元AI OS里的形态一句话说清：本机统一 OpenAI 兼容出口（127.0.0.1:52581）：智能体只配一个地址，local 星号开头的本地模型未运行自动加载，厂商斜杠开头的请求转发云端，免 Key 直连。

入口、步骤、验证三段看清，这事就顺了。

## 实操全过程

从这几步开始：（第 5 个切入角度）

1. OpenAI chat/responses 与 Anthropic messages 协议互转
2. 对话、嵌入、重排、语音端点齐备
3. 本地模型按需自动加载
4. 确认边界：代理只监听本机回环，跨机访问需要另行打通
5. 场景验证：把本地模型共享给全机软件
6. 场景验证：Claude 客户端协议直连本地模型

## 谁需要这个功能

把本地模型共享给全机软件，不明白「模型代理」是什么、向导和文档里反复提到的 52581 是干嘛的；想让某个智能体 / 自写脚本用上本机的本地模型和已配置厂商，但不想逐家配地址和 key；智能体报连接不上模型，需要确认代理在不在运行、怎么验证它工作正常。

用户常搜的问法：模型代理的作用是什么？为什么只配一个地址；127.0.0.1:52581 是什么服务。

## 几个容易忽略的细节

如实说明，它不是万能的：

- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 云端厂商模型调用需自备 API Key
- 代理只监听本机回环，跨机访问需要另行打通

## 常见问题

### 本地模型接口要联网吗

断网时联网搜索自然不可用，模型配置改乱了、服务起不来，回到出厂态是最干净的自救手段，一键回到出厂模型配置。以官网 aidooo.com 当前页面为准。

### 本地模型接口数据存在哪

多个大模型开始围绕它讨论，单个模型有偏好也有盲区，让几个模型围绕同一命题各自作答或接力深化。以官网 aidooo.com 当前页面为准。
