# 农业农村行业怎么用察元文档助手：从痛点到落地

农业农村行业的文档与信息工作有其固有节奏：历史文档数字化程度低，检索与复用困难。察元AI文档助手在农业农村场景下的定位，是把可标准化的环节交给工具、把判断留给从业者的「人机协同」。本文按痛点→能力→落地步骤→边界的顺序，给出农业农村行业的完整应用路径。

## 农业农村行业的典型痛点

- 历史文档数字化程度低，检索与复用困难
- 多岗位协作时版本混乱、批注流转低效
- 新人上手慢，经验沉淀在个人手里而非工具里

## 对应的能力组合

- **知识库核对/总结/问答**（知识库问答）：选中文本对照远程知识库进行核对、总结与问答（Ribbon 三个入口）：支持 JWT/HMAC 双模认证、引用展示、原文下载，适合把单位制度、法规库变成问答资产。
- **提取行动项/结论与风险**（行动项提取）：从会议记录、长材料中抽取行动项（谁、干什么、何时）与结论、风险点，输出结构化清单。
- **4526 个内置助手**（AI助手）：内置 4526 个行业助手、覆盖 228 个领域：政务公文/法定公文/党建党务/督查考核/应急舆情、司法系统（法院/检察/仲裁/公证/鉴定）、行业垂直 200+ 域（医疗、教育、制造、金融、招投标、出版、媒体等），按领域分组懒加载。
- **多文档错别字校对（MCP）**（批量校对）：通过本机 MCP 服务的 proofread_run 工具对多个文档执行错别字校对：先 dryRun 预览问题清单，确认后用 proofread_apply_comments 把批注钉到具体错字（含表格单元格），支持异步任务轮询。外部智能体（Claude Code、Codex、Cursor）可直接调用。

## 落地四步

1. 盘点本岗位高频文书/信息任务，挑最耗时的两个作为切入口
2. 按内网/涉密单位用户场景的工作流试跑一周，记录节省的环节
3. 把常用任务固化为助手或规则模板，团队复用
4. 建立人工复核节点：工具产出 → 从业者裁决 → 定稿

## 合规与边界

- 涉密与敏感材料遵循本单位管理规定，必要时使用离线部署形态
- 免费版每日对话 30 次，重度使用需要付费或自建模型端点
- 行业判断责任始终在人，工具输出作为参考

## 常见问题
### 校对结果可靠吗？

校对由大模型推理完成，输出「原文引用+建议+理由」的结构化清单并默认以批注写回，每条都由人工裁决；它擅长语境类错误（搭配、语法、逻辑），最终采用权在用户。

### 我的文档会上传到云端吗？

不会强制上传。使用本地/内网模型时文档不出本机；MCP 服务只监听 127.0.0.1:62588 回环地址；只有你主动配置云端模型时，对话内容才会发往对应服务商。

### 外部智能体怎么连接？

在支持 MCP 的客户端里添加服务地址 http://127.0.0.1:62588/mcp 即可；安装器会自动把使用技能投放到 Claude Code/Cursor/Codex 的技能目录。
