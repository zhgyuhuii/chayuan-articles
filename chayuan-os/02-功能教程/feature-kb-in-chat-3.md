# 自然语言检索实战：一个真实场景的完整工作流

很多自然语言检索的教程只讲是什么，不讲怎么做；或者讲了一半步骤，剩下的让你自己悟。这篇反着来：步骤写全、按钮文案原样引用、每步的界面反馈都说清楚，用的是察元AI OS（aidooo.com）。

## 解决什么痛点

想让 Claude Code / Codex 等命令行智能体干活时引用公司资料、产品手册，但不打算逐家配接口，想确认智能体检索到的内容和知识库应用里看到的是不是同一套结果，让 Claude Code 查内部规范；资料已经入库，想在日常对话里直接问「库里怎么规定的」，不想每次打开知识库应用。

用户常搜的问法：怎么让 AI 对话的时候查我的知识库；Claude Code 能用察元OS 的知识库吗？需要配什么。

## 操作步骤详解

1. 在 Harness 对话窗查库（dsh 会话）

1. 在对话输入框直接说：「查一下知识库里关于〈关键词〉的内容」（工具描述里写明的触发语：「知识库 / 资料 / 文档里的…」，或需要私有资料时）。
2. 看到什么：智能体调用 kb_search，工具结果显示为编号出处块——每条形如 [1] 文档名 · 章节路径 换行接命中片段（单块超 1600 字符截断）；回答正文在依据处标注 [1][2] 编号。检索默认取 5 条（topK 可在 1–20 指定），与知识库应用右栏「检索」测试台走同一引擎、同一排序。
3. 库里没有：工具返回「知识库中没有找到相关内容。」，AI 按纪律如实说明，不编造。

2. 多库：先列清单，再指定库

1. 不确定有哪些库时说：「列出我的知识库」——kb_list 按「【库名】」逐库列出文档清单（每行「文档名（状态）」，无文档的库显示「-（无文档）」）。
2. kb_search / kb_read_doc 不带库名（kbId）时默认查 default 库；说「在〈库名〉里查…」即可让智能体带上 kbId 指定目标库。

3. 要完整原文：让它读全文

1. 命中片段是截断的检索块。需要完整原文时说：「把第 2 条的全文读出来」——智能体用 kb_read_doc 按结果里的 docId 分页读全文（默认从第 0 块起、每页 20 块，可翻页），返回文档名、状态与全文文本。

4. 在 CLI 智能体里查库（Claude Code / Codex 等）

1. 打开对应智能体的会话（如灵宠挂的智能体工作台、或直接在终端跑 CLI），同样说「查一下知识库里…」。
2. 工具经由自动写入的 MCP 条目接入：chatop-kb（HTTP，52582 /mcp，三工具语义与 dsh 原生一致）与 chatop（系统控制面，含 kb 三工具）。智能体同时收到《察元知识库检索手册》技能，按「先 kb_list 看库 ＞ kb_search 检索 ＞ 需要原文再 kb_read_doc」的顺序工作，回复带 [n] 文档名 · 章节路径 出处。

5. 灵宠对话窗（模型直跑）：绑定库自动注入

1. 灵宠对话窗输入框左侧有一个书本按钮（悬停提示「选择知识库」），点开选一个库（「不绑定知识库」/ 各库名 / 空态「暂无知识库（桌面建库后可选）」）。绑定后会话 Tab 上出现「KB」徽标，此后每条发言自动先检索再把【知识库参考】注入（片段带 [n] 文档名 · 章节）；本轮没检索到时注入「【知识库参考】本轮对所提内容检索无结果：库里没有匹配内容，请如实说明没查到……」的指令。详见对应教程。

6. 宠物群聊：挂群库

1. 群聊输入框的 选择器给全群挂「群默认库」（优先级：群库 > 宠物绑定库）；没挂库时命题里提到「知识库」，消息流会落系统提示「本群与成员宠物都未挂知识库——宠物无法真的查库…」。详见对应教程。

## 关键能力点

- 三个 KB 工具自然语言触发
- CLI 智能体经 MCP 自动接入
- 出处引用不丢

## 注意事项与真实边界

如实说明，它不是万能的：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重

## 高频疑问

### 智能体说「没有找到相关内容」，但文件明明传了？

三查：文档状态是否「就绪」；是否查错了库（不带 kbId 默认查 default，先让它 kb_list 看清单）；嵌入链路是否可用。

### 怎么保证 AI 不把库里没有的说成有？

工具侧有三重纪律：返回 0 条时固定文案「知识库中没有找到相关内容。」；《察元知识库检索手册》技能明确要求「回答前必须先检索、回复带出处、库里没有的内容不要伪装成检索结果」；灵宠/群聊的注入链在没有命中时会显式注入「如实说明没查到」的指令。看到 AI 编造时，追问一句「用 kb_search 查一下再回答」即可纠偏。

### 检索片段被截断了，怎么拿全文？

检索面的单块片段有 1600 字符上限（防整篇文档灌进上下文）。让智能体用 kb_read_doc 按结果里的 docId 分页读全文（每页默认 20 块）。

## 补充答疑

### kb_search 一次查几个库？

一次一个库（kbId 参数）。想跨库对比就分别指定库名多次检索；跨终端的库共享是另一回事。

### 灵宠对话窗绑定了库，为什么有的发言没带引用？

模型直跑灵宠的检索注入是每条发言自动执行的，但检索无结果时不注入片段（只注入「没查到」指令），此时回答自然没有 [n] 编号；另外绑定是会话 Tab 级的，新开的 Tab 要重新选库。

### CLI 智能体里没有 kb 工具？

按序查：① 智能体是否已安装并被桌面感知（装好后才会写入 MCP 条目）；② 知识库服务是否在运行——chatop-kb 条目只在服务在场的机器上写入，服务停了条目会自动移除（浏览器打开 http://127.0.0.1:52582/health 应返回 {"ok":true,"service":"chatop-kb",…}，详见教程对应教程）；③ 条目是启动/保存时写入的，重开会话再试。
