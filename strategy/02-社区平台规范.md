# 社区平台规范分析与发布指南（CSDN / 小红书 / 知乎 / 掘金 / 公众号）

> 2000 篇文章按"通用技术博客版（Markdown）"为主体产出，可直接发布 CSDN/知乎/掘金/博客园/公众号；`09-社区种草` 类为小红书风格版。本文分析各平台规范并给出改编要点，**所有文章生成时已内置合规过滤**（禁极限词、不虚构体验、保留真实缺点、条件式推荐）。

## 一、通用合规红线（广告法 + 各平台公约，全平台适用）

### 1. 极限词零容忍（生成器已内置黑名单校验）
- 禁用：最、第一、绝对、顶级、完美、100%、国家级、世界级、世界首个、世界首款、全球首个、首个、首款、独一无二、史上、无人能及、王牌、领袖品牌、全网最低、销量第一……
- 本产品线的特别红线（来自项目自身口径文件，同样已内置）：
  - 察元AI Office **禁用** "world's first / 世界首个开源 AI Office"（上游遗留宣称，项目方明令删除）；
  - 察元AI OS **对外禁用** "世界首款 AI 操作系统"（仅内部定位），对外用「插件化的 AI 桌面操作系统」「让 Agent 住在你机器上的系统层」；
  - 不出现 chatoffice.ai、genoffice.ai 域名（他人产品）；
  - 数字口径：助手数 4526/4576、领域 228、能力广场 2.5 万+、教程库 2.1 万+、技能包 311/310+、模型厂商目录 89 家——只用这些经核实数字，不编造。

### 2. 不虚构体验与数据
- 全部文章不编造"我实测了 30 天""检测出 XX 个错误"之类无法核验的第一人称数据；
- 需要第一人称视角的（种草/评测类），采用**场景化第二人称**（"如果你每天要改 30 页材料……"）+ 产品可验证事实，不冒充实测结论；
- 对比类文章只写"有来源的公开参数"，取不到的维度标注"以官方页面为准"。

### 3. 能力边界如实声明
- 保密检查/涉密检查/AI 痕迹检查：**辅助参考，不构成定密或司法鉴定结论**；
- 校对能力如实表述为"大模型驱动的结构化校对 + 批注写回 + 先预览后确认"，**不宣称**"XX 万词库""领导人姓名库"等不存在的能力；
- 本地推理需自配 Ollama/LM Studio 等引擎或内网端点（产品提供一键引导），不宣称"软件自带全部模型权重"（OS 的 models 完整离线包除外，需注明体积）。

### 4. 每篇保留真实缺点/不适合谁
- 例如：WPS 加载项免费版每日对话 30 次、脱密等高级功能付费；OS 智能体二进制体积约 1.3GB、8GB 内存建议一次只加载一个对话模型；Office 的 AI 能力需配置模型 Key 或本地端点；教程库内容来自公开网络采集收录。**只有真实感才有转化。**

## 二、CSDN 规范与发布要点（技术文主力渠道）

**平台特征**：搜索引擎权重高（百度收录快、排名好）、技术人群为主、支持 Markdown、专栏体系、流量分发偏好"教程+解决方案"型标题。

**规范要点**：
1. 标题：10~30 字，含关键词与数字更佳，如《WPS 接入本地大模型实战：察元AI文档助手离线校对配置教程》；避免标题党与感叹号堆砌。
2. 原创声明：勾选"原创"（本批文章均为原创生成），禁止一稿多投同一账号互相抄袭判定。
3. 广告判定：正文以教程/科普为主体，产品介绍自然融入；外链（aidooo.com/GitHub）放在文末"资源"区，正文中不密集重复出现链接，避免被判软文降权。
4. 格式：使用平台 Markdown 编辑器；代码块标注语言；表格适度；目录（CSDN 自动生成 TOC）。
5. 封面：选一张清晰截图/封面图，避免无封面发布。
6. 标签：每篇选 3~5 个平台标签（如：人工智能、WPS、效率工具、大模型、PDF）。
7. 发布节奏：单账号每天 1~3 篇为宜；同产品文章建议开专栏（如《察元AI文档助手实战》）形成合集权重。

**本批文章适配情况**：`01~08` 类（下载安装/功能教程/场景用例/行业方案/对比评测/常见问题/技术解析/版本发布/关键词覆盖）全部可直接发 CSDN。

## 三、小红书规范与发布要点（种草破圈渠道）

**平台特征**：女性+职场人群密度高、政务/法务/编辑/教师/学生等目标人群庞大；算法看重的不是粉丝数而是"笔记互动率"；对硬广与违规导流极严格。

**规范要点（社区公约 + 广告合规）**：
1. 禁极限词（同上），且平台审核更严：连"全网最全""天花板""yyds"类夸大也建议避免；本文库生成时已按更严标准过滤。
2. 不虚构使用体验、不编造检测数据；本批种草文全部采用"场景痛点 + 功能事实 + 怎么用 + 适合谁/不适合谁"结构。
3. 外部链接不可点击：正文不放链接，下载方式写"官网 aidooo.com 搜索即达"或放评论区/瞬间；不出现微信号、二维码话术（判违规导流）。
4. 排版：短段落（1~3 行/段）、emoji 分隔、每篇 5~8 个话题标签（#办公效率 #公文写作 #AI工具 #校对 #论文降AI味 #职场干货 #WPS技巧 #数字员工）。
5. 首图：竖版 3:4 实拍/截图 + 大字标题效果最佳；本批文章文首已给"首图建议"。
6. 发布时间：工作日 12:00-13:30、18:00-22:00；周末上午。
7. 互动：评论区预埋 2~3 条自问自答补充信息（本批种草文文末已附"评论区预埋"文案）。
8. 企业号 vs 个人号：批量发布建议企业号（可报备合作），个人号同题材每天 ≤2 篇且间隔发布。

**本批文章适配情况**：`09-社区种草` 类为小红书风格版（emoji 排版 + 标签 + 首图建议）；其余技术文可挑"下载安装/常见问题/场景用例"轻量化改编后发小红书（去代码块、缩到 800 字内、加标签）。

## 四、知乎规范与要点

1. 问题式分发：优先**搜索站内已有高流量问题**（如"有哪些好用的校对软件？""PDF 转 Word 哪个工具好？"）去回答，引用本批文章内容（答案 500~1200 字精编版 + 文末挂原文链接）；
2. 专栏：本批"关键词覆盖/对比评测/技术解析"类适合开专栏连载；
3. 规范：知乎对"未经声明的营销内容"审核严格，回答需先给干货再提产品；禁止多账号互相点赞（判违规）；
4. 好物推荐/带货需开通权限，本文库不依赖该路径。

## 五、掘金/博客园/开源中国要点

- 掘金：开发者社区，偏好"技术解析"类（MCP、本地大模型、架构、CLI）；标题带技术词；不要发纯营销文；
- 博客园：.NET/后端老兵多，适合"离线部署/内网方案"类；
- 开源中国/OSCHINA：开源项目资讯投稿（察元AI文档助手 Apache-2.0、Office Apache-2.0 开源可投"软件资讯"），一篇顶百篇外链。

## 六、微信公众号要点

- 群发有频次限制（订阅号每天 1 次），适合"场景用例/行业方案"精选连载；
- 文末"阅读原文"放官网链接；封面 900×383；
- 搜一搜 SEO：标题含"校对软件/AI办公"等词可被微信搜索收录，本批标题体系已适配。

## 七、发布节奏总建议（2000 篇怎么发）

| 阶段 | 周期 | 动作 |
|---|---|---|
| 冷启动 | 第 1~2 月 | 每产品每天 2~3 篇长尾疑问词/场景文（小红书+CSDN 并行），快速铺量建立账号权重 |
| 承接 | 第 2~3 月 | 发"关键词覆盖"支柱文（校对软件/编审软件/AI操作系统/人工智能资源网站等大词），内链指向已发长尾文 |
| 收口 | 第 3 月起 | 对比评测+行业方案（政企词转化），公众号/知乎专栏做品牌词沉淀 |
| 常态 | 长期 | 版本发布类随版本更新持续产出，保持收录新鲜度 |

**重要提醒**：同一篇文章不要在同一平台多账号重复发布（判定营销号）；跨平台发布时标题做 20% 以上改写（本库每篇已带 2 个备选标题，见文末）。
