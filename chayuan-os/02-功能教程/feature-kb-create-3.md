# 私有知识库场景拆解：知识库应用左栏输入库名即建

私有知识库的麻烦不在功能本身，在于信息散。按项目或按类别分库，检索范围可控，回答不会被无关资料污染。这篇把它收拢成一条能照着走的路径。

## 先看看痛点对不对得上

制度与技术资料分库；想把不同项目的资料分开（「公司制度」和「产品手册」各一个库），检索互不干扰，给每个客户建独立资料库，想先建一个测试库试上传、试检索，不动正式库。

## 完整操作步骤

从这几步开始：（第 3 个切入角度）

1. 多库并存
2. 独立存储互不干扰
3. 秒建秒删
4. 场景验证：给每个客户建独立资料库
5. 场景验证：制度与技术资料分库
6. 串联场景：官网下载全量离线包（含五件套权重，约 4.7GB）

## 关键能力点

- 多库并存
- 独立存储互不干扰
- 秒建秒删

## 注意事项与真实边界

如实说明，它不是万能的：

- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 云端厂商模型调用需自备 API Key

## 你可能会问

### 库里的数据怎么备份/迁移到别的机器？

所有库都在 <数据根>/storages/chatop-kb/ 下，整机迁移时把整个 storages 目录一起拷到新机同位置即可（配置文件 config.json 也在该目录，嵌入链路等设置随之带走）。

## 放回产品盘面看

把私有知识库放回察元AI OS的整体盘面：输入框旁有知识库绑定与模型选择（含智能路由自动选模型），AI 桌面操作系统：本地大模型、知识库、智能体、宠物群聊装进一个桌面；知识库应用左栏输入库名即建，每库独立存储，系统缺省带一个 default 库，知识库应用的知识图谱页签：自动生成文档与实体的二部图，点实体或文档互跳、定位来源、可重新生成。

## 安全与数据边界

安全口径单独立一层：管理员建停删用户（删除会抹掉该用户全部数据）、为普通用户重置密码、踢下线、开关开机登录；全新安装选数据目录或导入拷贝根，创建管理员；数据目录自选意味着整个系统可以装在非系统盘，换机迁移就是拷目录；智能体不知道它会哪些本机工具就等于没有，技能手册镜像让它们天生会用系统能力。

## 平台与形态

## 几条硬数字

能落到数字上的几条：润色翻译这类轻任务用旗舰模型是浪费，主强子弱的路由让轻任务自动落本地小模型，省算力省钱；指定模型未加载时会按策略自动拉起，local 星号开头的本地模型未运行自动加载；让全机所有 AI 软件共用一套模型配置的关键设计：地址只有一个，模型随便换，客户端无感。

## 离线与内网

离线内网这条线的口径：知识库应用左栏输入库名即建，每库独立存储，系统缺省带一个 default 库；导入零门槛是知识库能不能被用起来的第一道坎，拖进去点加载两步完事，知识库应用的知识图谱页签：自动生成文档与实体的二部图，点实体或文档互跳、定位来源、可重新生成，在 dsh 会话、灵宠或群聊里说一句查一下知识库里的什么。
