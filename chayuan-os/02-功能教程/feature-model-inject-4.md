# CLI智能体配模型：家外部 CLI 智能体，别再瞎试

CLI智能体配模型这件事，值不值得专门学一篇，看一个细节就够：五家写入面覆盖。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 先定位问题在哪一层

排CLI智能体配模型的错，顺序比速度重要：环境与模型先就位，然后对操作路径，最后核边界。三层各有一些典型症状，对号入座能省很多时间。

## 高频故障与对策

### OpenCode 用本地模型时，第一个请求卡了好几分钟像死了一样？

代理对 local/* 模型懒加载：引擎被 15 分钟空闲自动卸载后，第一个请求要现场拉起引擎（分钟级）且无中间反馈。先用 curl http://127.0.0.1:52581/v1/chat/completions -d '{"model":"local/<id>","messages":[{"role":"user","content":"hi"}]}' 预热，之后即恢复。

### 从厂商卡「直接应用…」时报「厂商 X 未随行密钥：请先在模型设置粘贴密钥再应用」？

厂商直连（不经代理）必须把该厂商的密钥一并写进智能体配置，空 key 写出去运行期必 401，所以应用前会拦截。先在 设置 ＞ 模型 该厂商卡里粘贴密钥再应用；或改走「加入代理」再从模型代理面板统一应用（密钥留在凭证库）。

## 正确的操作路径

入口三：模型代理面板（可一次写入多个模型）

1. 打开 设置 ＞ 模型 ＞ 左栏「本地模型」组 ＞ 「模型代理设置」，滚到「被代理模型（local/ 本地 + 厂商路由）」卡片。
2. 卡片内是一棵三级树（厂商 ＞ 模型分类 ＞ 模型名）。两种用法：
    1. 单模型应用：模型行尾点「应用」，弹出的对话框为单选形态，输入框已预填该模型（如 local/qwen3.5-4b-q4km）；
    2. 多模型一次写入：勾选若干模型（勾分组即全选其下；顶部有「全选」「清空」），点右上蓝色主按钮——未勾选时显示「统一应用…」，勾选后显示「应用选中（N）…」。
    3. 点「应用」逐家写入。完成后提示「应用完成（逐项结果见上）」。多选语义（对话框内提示原文）：Harness 写入完整模型清单、OpenCode 写入可切换清单；Codex / Claude / OpenClaw 取第一个作默认模型（其余模型写进各自的可见性面，见下表）。
    4. 本地模型行尾另有「帮助」按钮，打开接入指南弹窗，含可直接复制的各智能体配置片段（Claude Code / Codex / OpenCode / OpenClaw）——展示片段与「应用」实际写入的内容由同一生成函数产出，不会漂移。

写入了什么（五家落点）

经模型代理的写入一律免 key：代理对本机调用不验证密钥（审计记为 anonymous），配置文件里不会出现任何真实厂商密钥。

| 智能体 | 写入落点 | 写入内容 |
|---|---|---|
| DeepSeek Harness | harness 模型服务配置（llm-pi-ai provider 档案，非文件） | 代理地址 + 模型清单 ＞ 会话窗模型下拉可见（显示 `local (proxy)`） |
| Claude Code | `~/.claude/settings.json` 的 `env` 段 | `ANTHROPIC_BASE_URL`（代理地址，不带 `/v1`）+ `ANTHROPIC_AUTH_TOKEN`（免 key 时落哨兵 `chatop-local`）+ 默认模型与三档分槽 |
| Codex | `~/.codex/config.toml` + `~/.codex/model-catalogs/chatop.json` | 根表 `model` / `model_provider`、`[model_providers.*]` 托管块（代理地址 + `wire_api = "responses"`）、`model_catalog_json` 指向目录文件（`/model` 面板整体替换为注入模型） |
| OpenCode | `~/.config/opencode/opencode.json` | 顶层 `model`（`<providerId>/<模型名>`）+ `provider.<id>` 表（代理地址 + `models` 映射，模型切换器可见） |
| OpenClaw | `~/.openclaw/openclaw.json` + 启动偏好 | `models.providers.<id>`（代理地址 + `models[]` 清单）+ `agents.defaults.model.primary`；同时落启动环境偏好 |

## 收尾检查

验证

1. Harness：打开 DeepSeek Harness 对话窗（Dock ＞ DeepSeek Harness），会话模型下拉里出现所写模型。
2. Codex：重开一个 codex 会话（模型目录是启动时加载，已开的会话不刷新），在 codex 内输 /model，面板列表只剩注入的模型；或终端执行 codex debug models 查看目录加载结果。
3. OpenCode：opencode 内打开模型切换面板，chatop-proxy provider 下出现所写模型。
4. OpenClaw：openclaw Control UI 设置 ＞ Models，或 TUI 内 /model，出现注入模型；终端执行 openclaw models list 可见注入行。
5. 代理连通性：终端 curl http://127.0.0.1:52581/v1/models（免 key）应返回含所写模型的清单。
6. 备份存在：ls ~/.chatop/backup/ 能看到刚生成的时间戳目录。

## 进阶用法与边界

- 五家写入面覆盖
- 配置备份与回退
- 密钥不出凭证库
- 边界：写入的是代理地址，代理停了智能体就连不上模型

## 你可能会问

### 应用成功了，但 Codex 里 /model 还是老列表？

Codex 的模型目录是启动时加载的——重新应用后必须重开 codex 会话，/model 才刷新。还不行就终端跑 codex debug models 看目录是否可载。

### 写入之后后悔了，怎么恢复原配置？

每次写入前都自动备份在 ~/.chatop/backup/<时间戳>/<智能体>/ 下，按「备份与回退」小节把对应文件拷回原位即可（Harness 例外，重新应用一次其他模型即覆盖）。

### 勾选清单里只有一部分智能体，另外装的（Gemini CLI 等）是灰的？

灰显 = 该智能体当前没有模型配置写入面（行尾标「暂不支持自动写入模型配置」），只能走各家自己的账号配置。五家（Harness/Claude Code/Codex/OpenCode/OpenClaw）之外暂不支持自动写入。

## 更多操作细节

入口一：模型设置向导第 3 步

1. 首次登录桌面自动弹出「统一模型设置向导」（重跑：设置 ＞ 模型 ＞ 左栏「本地模型」组 ＞ 「统一模型设置向导」），走到第 3 步「统一应用到智能体」。
2. 顶部等宽字体显示写入目标，形如 local/qwen3.5-4b-q4km @ http://127.0.0.1:52581；下方提示「应用内容：OpenAI 兼容地址（模型代理）+ 虚拟 key + 默认模型名。真实厂商 key 不会离开本机凭证库。」
3. 点「选择智能体并应用…」打开上文的对话框 ＞ 确认勾选 ＞ 「应用」。
4. 全部写入成功后弹窗自动收起，向导页显示绿色「已应用」。详细流程见对应教程-模型设置向导 第 3 步。

## 更多操作细节

入口二：设置 ＞ 默认模型（对话分类确定即同步五家）

1. 打开 设置 ＞ 默认模型，左栏选「默认对话模型」。
2. 点分类卡右上蓝色按钮「设置…」，弹出「选择默认对话模型」选择弹窗。
3. 弹窗内蓝色提示条写明：「确定后将同步为全部智能体（Harness / Codex / OpenCode / OpenClaw）的默认模型」。在树里选一个模型（「自动」不触发写入），点「确定」。
4. 系统先保存默认模型，再把代理地址 + 所选模型写入五家（Harness / Claude Code / Codex / OpenCode / OpenClaw）。全部成功：弹窗关闭并提示「已设为系统默认，并同步全部 5 个智能体」；部分失败：弹窗保持打开，逐项显示五家的成功/失败结果，红字为失败原因。
5. 若代理未运行会报「模型代理未运行，无法接入云端厂商（先在模型设置里确认服务状态）」——去 设置 ＞ 模型 恢复服务后重试。
6. 注意：只有「默认对话模型」分类会触发写五家；其余分类（嵌入、重排、文生图等）只写系统默认并分发技能文档，不改智能体配置文件。

这篇把模型应用到智能体的链路拆完了。卡住就回看常见问题那一节，多数坎都在那里。
