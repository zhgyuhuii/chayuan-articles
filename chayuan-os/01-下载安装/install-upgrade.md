# 覆盖升级装机指南：设置关于里检查更新、下载并重启安装

很多人搜「察元OS 怎么升级？在哪里检查更新」，搜到的多是概念解释，落不到操作。这篇以察元AI OS为准，把覆盖升级从打开哪个应用讲到看到什么结果。

## 安装前确认

- 系统要求：Windows 10/11，x64 或 arm64
- 安装包：NSIS 安装器（ChaAIOS-版本-架构.exe）
- 说明：升级不丢数据的机制。

升级用的安装包与首次安装同源：官方渠道，版本挑目标版本。

## 覆盖安装走的还是安装器

1. 从官方渠道下载目标版本的 exe 安装器（覆盖升级就靠它）
2. 双击安装，零额外依赖
3. 首次启动创建本机账户，进入桌面
4. 对话应用里选本地模型即可开聊，全程无需联网

## 怎么确认做成了

- 启动进入桌面，对话应用选本地模型能正常回复
- 首启初始化需要 5 到 30 秒，属正常现象，期间不用干预

## 升级前认下四条边界

- 云端厂商模型的调用，API Key 由自己准备
- Docker 云桌面、跨终端互联这路进阶形态，动手量不小
- 龙芯暂无安装版本；本地不出视频生成，云端路由代劳
- 8GB 内存设备同一时间只开一个对话模型，复杂任务受限

## 覆盖安装为什么安全

覆盖安装指直接在新版安装包上再装一遍，程序文件被替换，数据根目录不动，这就是升级不丢数据的机制来源。设置、知识库、对话记录都长在数据目录里，程序层怎么换都不碰它们。

## 升级前花一分钟做的两件事

虽然机制上数据不动，升级前还是建议做两件事：把正在编辑的内容存盘退出，免得安装器重启应用时丢掉未保存的状态；记下当前版本号（关于面板那串等宽字），升级后对照确认。

## 高频疑问

### 「检查更新失败」怎么回事？

多为访问发布页的网络失败。按提示「可到 Releases 页手动下载」操作：从官方发布渠道取最新安装包，覆盖安装即可。

### 更新会丢数据吗？

不会。安装包只更新程序文件，你的数据根目录不动（帮助中心 ＞ 参考 ＞ 常见问题 FAQ 同口径）。

### 点「检查更新…」却打开了一个网页？

那是网页（浏览器）形态：没有桌面更新桥，按钮降级为打开官方站点页。完整的检查-下载-安装流程需要桌面安装版（察元AI OS 桌面应用）。

## 第 1 步的落点：关于面板

两个入口，打开的是同一个面板：

面板内容从上到下：logo、名称「察元」、副标题「察元AI OS · 离线 AI 办公助手」、等宽字体的版本号 v{X.Y.Z}。版本号单一来源是 dsh-plugin/package.json 的 version（打包时自动同步外壳，关于窗口与设置分区都从这里取，杜绝手写过期）。

1. Dock ＞ 「设置」＞ 左栏「关于」，内容卡片标题「察元」；
2. 屏幕左上角菜单（logo 菜单）＞ 「关于 察元」，弹出独立关于窗口。

## 第 2 步：「检查更新…」的行为

1. 做什么：点面板下方的「检查更新…」按钮。
2. 状态行按结果变化（就在按钮下方，进度实时刷新）：
    1. 检查中：显示「正在检查更新…」；
    2. 已是最新：显示「已是最新版本」；
    3. 有新版本：自动开始后台下载（无需再点下载），状态行显示「下载更新中 {p}%」实时走百分比；按钮下方同时显示新版发布说明摘要（取自发布页的 releaseNotes，剥掉 HTML 按纯文本展示，最多 400 字）；
    4. 失败：显示「检查更新失败（可到 Releases 页手动下载）」，并在后面附具体错误原因。
    5. 没有自动检查：开机、日常使用中都不会自动检查更新，只有点这个按钮才检查。

## 第 3 步：「重启并安装」的细节

1. 下载完成后，状态行变为「已下载 v{新版本}，重启完成安装」，下方出现蓝色按钮「重启并安装」。
2. 做什么：点「重启并安装」＞ 应用退出并自动安装新版，装完自动重启回到桌面。
3. 不点它也没关系：已下载的更新会在下次正常退出应用时自动安装（安装器开启 autoInstallOnAppQuit），再开机即是新版。
4. 设置分区和独立「关于 察元」窗口是同一个面板、同一份更新状态：一边看下载进度，另一边打开也是同样的状态行（状态由主进程实时推送）。

## 升级后的验证

1. 升级完成后重新打开 设置 ＞ 关于，等宽版本号应显示为新版本号。
2. 下载过程中可以关掉设置页去干别的；重新打开关于面板会拉取当前更新状态（进度/已下载/出错都会照常显示）。

## 补充答疑

### 下载进度一直不动 / 下载中断了？

重新打开关于面板看状态行；若已报错会显示失败原因（网络断续常见），网络恢复后再点一次「检查更新…」重新下载即可。

### 为什么从来不弹更新提醒？

产品采用手动检查模式：不静默检查、不强更。想升级时到 设置 ＞ 关于 点一次「检查更新…」。

## 形态差异带来的三条注意

- 完整检查更新流程仅桌面（打包安装）形态：需要 Electron 更新桥（chatopDesktop.updateCheck），更新源是代码托管平台的发布通道（发布通道在 desktop/electron-builder.yml 里配置 provider: github）。
- 网页形态没有更新桥：点「检查更新…」不进入检查流程，而是在新窗口打开官方站点页（见「形态差异」）。桌面开发（未打包）形态有桥但接的是空更新器，检查恒显示「已是最新版本」。
- 检查与下载依赖能访问发布页所在托管平台的网络。

## 升级能力的三个关键词

- 在线检查更新
- 重启安装
- 数据保留

## 桌面能力与共享形态

智能体在桌面上能完成的事，差不多就是一个熟练用户能完成的事，内置终端就是凭据；打开即看，不挑格式，系统级默认打开体验；WebRTC 局域网共享桌面：主机、编辑者、观看者三级角色，共享房间与连接终端状态，接班的智能体不必重新自我介绍，记忆全机共享。

## 权限与数据的几道口径

远端调用以远端访客身份过对端权限门并留审计；API Key 存储经 safeStorage 加密，遥测有一键全关的选项；模型库按本机内存预算分层推荐，能跑、勉强、跑不动三档各有标记；本机统一 OpenAI 兼容出口（127.0.0.1:52581）：智能体只配一个地址。

全篇浓缩成一句话：想升级就进设置关于点检查更新，其余细节按上面四步的顺序走。
