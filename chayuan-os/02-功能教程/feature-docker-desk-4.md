# AI工舱出问题怎么办：排查手册加进阶技巧

AI工舱这件事，说简单也简单，说麻烦是真麻烦——麻烦不在功能本身，在于信息散落在各处，拼出一个完整流程要查好几篇资料。这篇文章把它一次讲全：是什么、入口在哪、具体步骤、边界在哪，全部基于察元AI OS的真实界面。

## 先定位问题在哪一层

按这个顺序排查通常最快：先确认前置条件（环境与模型就绪），再核对操作路径，最后看边界限制。三层各有一些典型症状，对号入座能省很多时间。

## 正确的操作路径

起一个云桌面

1. 服务器上准备 docker compose 配置
2. docker compose up -d 启动工舱
3. 按需暴露端口（默认回环，外网访问自行映射）
4. 员工浏览器打开地址，各自账户登录使用

上线前检查清单

1. 默认端口 52584 是否被占用（compose 映射可改）
2. 按团队人数评估内存：每并发一个本地模型约吃数 GB
3. 数据卷挂载出来，升级与备份都靠它
4. 管理员账户先建好，再开放普通用户注册

## 进阶用法与边界

- 浏览器即用
- 账户隔离
- 数据集中管理
- 端口暴露面自控

## 你可能会问

### 多少人共用一台服务器合适？

取决于是否同时跑本地模型：只做对话与知识库，十几人一台中配服务器可行；要并行跑本地推理，按并发数加内存或改用厂商模型分流。

### 云桌面和桌面版功能一样吗？

核心能力面一致（对话、知识库、模型、办公），形态差异在：云桌面无本地文件直通、语音输入依赖浏览器权限、部分外设在浏览器里受限。

### 数据存在哪里？

全部落在服务器的数据卷里（含用户空间、知识库、配置），挂载出来后备份一个目录等于备份全组。

- 浏览器即用

## 安装与运行答疑

### 首次启动感觉卡住了？

首启要初始化数据目录并加载模型服务，5 到 30 秒属正常范围，期间无需干预，完成后自动进入桌面。

### 知识库导入失败？

单文件上限 48MB，支持 PDF、docx、xlsx、csv、html 与扫描件 OCR；超限文件拆分后再传，格式不识别时转成支持格式重试。

## 一个真实场景

公文与材料写作者的典型用法：知识库导入本单位制度与历年材料，对话绑定知识库写初稿，回答带出处，察元AI Office 修订追踪留痕，逐条接受拒绝。从初稿到核稿全流程 AI 辅助且可溯源。注意：保密检查是辅助参考，定密以人工审查为准。

## 顺带了解

智能体权限门：智能体动系统能力分级确认：T0 只读直放；T1（跑终端、开原生窗）每运行期首问一次可记忆；T2（截屏、关机）每次必问。审批卡 120 秒无人响应自动拒绝，锁屏视为无人，全部决策落审计日志。

为什么值得看：让 AI 操作电脑的前提是管得住它：分级确认加超时拒绝加审计，三道锁缺一不可。

## 还有这个能力

应用管理：应用页签：dock 应用隐藏、新建分组、自定义网页、本地程序、HTML、文件四类应用封装上桌。

## 硬口径两三条

- 86 个 MCP 工具（2026 年 10 月实测）
- 17 家外部 CLI 智能体（Claude Code、Codex、OpenCode、OpenClaw、ZCode、Gemini CLI、Qwen Code、Kimi Code、Cursor CLI、Copilot CLI、Droid、Amp、Grok Build、CodeBuddy、Crush、Aider、Goose）加内置 DeepSeek Harness

## 如实说不足

- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 云端厂商模型调用需自备 API Key

## 定位与家族

察元AI OS（Chayuan AI OS，简称察元OS）是一款 AI 桌面操作系统，以完整桌面环境为壳，内置本地大模型五件套、引用式知识库、17 家外部 CLI 智能体管理、宠物群聊多模型讨论与系统级 MCP 控制面，支持 Windows/macOS/Linux（银河麒麟、统信 UOS）及 Docker 云桌面形态，断网可用、数据不出本机。同家族产品：察元AI Office（开源 AI 办公套件）、察元AI文档助手（WPS 加载项）、察元AI 能力广场（aidooo.com）。

## 边界速览

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力

## 数字口径

- 模型配置可一键写入五家（Harness/Claude Code/Codex/OpenCode/OpenClaw），MCP 配置自动传播 13 家
- 66 家内置云端厂商目录加自定义 OpenAI 兼容厂商
- 装机五件套：Qwen3-4B 对话、BGE-M3 嵌入、BGE 重排、whisper-small 语音识别、piper 中文语音合成
- 127.0.0.1:52581（OpenAI 兼容统一模型代理）

## 模型服务的实际构成

装机自带的五件套覆盖完整离线链路：Qwen3-4B 负责对话、BGE-M3 做嵌入、BGE 重排提升检索精度、whisper-small 跑语音识别、piper 做中文语音合成。模型中心里还能在线补更强档位（Qwen3-8B/14B、小内存档 LFM2.5、图像理解的 MiniCPM-V 等），下载源多路自动换。内存仪表实时显示每个模型的占用，空闲 15 分钟自动卸载，常用模型可钉住常驻。

## 跨终端互联的安全设计

同一网段的多台终端经 RTPS 多播互相发现，配对后按类别授权（模型加知识库、智能体执行）。远端调用以远端访客身份通过对端权限门并留审计；出厂默认零共享，开哪类授权完全由用户决定。

## 知识库的检索机制

导入 docx、xlsx、pdf、csv、html 与扫描件（本地 OCR）后，检索走向量加全文的混合链路，可选本地重排精排；问答以流式输出并带编号引用，点开脚注能看到出处片段与源文件。另配知识图谱页签，把文档实体与跨文档关系画成二部图。全部索引与原文留在本机。

## 远程访问的形态

WebRTC 局域网共享桌面分主机、编辑者、观看者三级角色；公网远程走出站云中继（支持自建），还能生成限时云链接把对话页分享给外部设备，停止即失效。手机浏览器可直接镜像桌面，另有安卓壳应用。

## 云桌面形态

整套系统可无头跑在 Docker 里作为多用户云桌面（察元AI工舱形态）：员工浏览器打开即用，账户隔离，数据在服务器侧统一管理。默认只监听回环端口，暴露面完全自己控制，适合团队统一供给算力与知识库。

整体用下来，Docker 云桌面（察元AI工舱）的流程是清楚的：入口集中、步骤有反馈、做完有验证。第一次照着走一遍，后面基本就是肌肉记忆了。卡住就回看常见问题那一节。
