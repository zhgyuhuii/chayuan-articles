# 拆开看知识库搭建：知识库应用左栏输入库名即建

知识库搭建这件事，值不值得专门学一篇，看一个细节就够：多库并存。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 先弄清楚它是什么

知识库搭建在察元AI OS里的形态一句话说清：知识库应用左栏输入库名即建，每库独立存储，系统缺省带一个 default 库。

先把定位立住，再看步骤。

## 实操全过程

上手按顺序做：（第 2 个切入角度）

1. 多库并存
2. 独立存储互不干扰
3. 秒建秒删
4. 场景验证：给每个客户建独立资料库
5. 场景验证：制度与技术资料分库
6. 串联场景：官网下载全量离线包（含五件套权重，约 4.7GB）

## 边界先摆桌面上

功能归功能，这几个边界先摆清楚：

- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 云端厂商模型调用需自备 API Key

## 你可能会问

### 能改库名吗？

界面没有改名入口。库名即目录名，两条路：新建一个名字正确的库、把文档重新上传一遍；或退出应用后把 <数据根>/storages/chatop-kb/ 下的目录改名，重启应用即按新名显示（库内文档数据随之保留）。

### 能建多少个库？每个库能用不同的嵌入模型吗？

建库没有数量限制（只有库名 120 字符的长度限制）。但嵌入链路等模型配置是全局一份（各库共用）：每个库只记录自己索引时用的嵌入指纹，全局换了嵌入模型后，旧库检索会提示需要「重建索引」。

### 多个库时，智能体怎么知道查哪个？

智能体先用 kb_list 看全部库，再在 kb_search / kb_read_doc 里带库名（kbId）指定目标库；不带就查 default。想省事可以约定：正式资料放 default，其余库按项目命名。

### 库里的数据怎么备份/迁移到别的机器？

所有库都在 <数据根>/storages/chatop-kb/ 下，整机迁移时把整个 storages 目录一起拷到新机同位置即可（配置文件 config.json 也在该目录，嵌入链路等设置随之带走）。

## 更多操作细节

验证

1. 左栏出现新库名（未被改名的库会自动选中高亮），行尾计数为 0。
2. 往新库上传任意一个支持的文件：上传完成后左栏该库计数变为 1——文档确实落在新建的库里。
3. 左栏点回 default 库：中栏文档列表与刚才新库的内容互不相同——多库隔离生效。
4. 数据落盘核对：本机打开 <数据根>/storages/chatop-kb/，能看到以新库名命名的目录（内含 kb.db 与 files/）。

## 动手前再核对一遍

- 桌面形态（察元AI OS）：Dock 中有「知识库」应用（翡翠绿＞青渐变的书籍图标），随系统自带、无需安装；点开默认以接近全屏的大窗打开。
- 建库本身不依赖任何模型配置——不配嵌入模型也能建库、上传文档、做全文检索；语义检索（向量路）需要嵌入链路，在知识库应用的「设置」页签配置（见教程对应教程《知识库设置》）。
- 知识库数据全部落在本机磁盘：<数据根>/storages/chatop-kb/<库名>/（数据根即 dsh 数据根目录，缺省 ~/.dsh），不联网、不上传。

## 安全与数据边界

安全口径单独立一层：本机统一 OpenAI 兼容出口（127.0.0.1:52581）：智能体只配一个地址；代理只监听本机回环，跨机访问需要另行打通，进阶面板支持被代理模型树形多选、厂商路由加入移出、虚拟 Key 签发吊销、调用审计查询；给外部工具开权限又不想交出真实厂商 Key，虚拟 Key 加审计是标准答案。
