# 用察元Office新建与打开文件实录之前，先接受这几条现实

这个话题下晒成果的多，讲代价的少。我来补后半部分：察元Office新建与打开文件实录的坑在哪里，怎么绕。

先把预期摆正：新建表格与新建 PDF 这类带本机临时底稿的未保存文档，若带着退出或崩溃，下次启动主页顶部出现横幅「上次有 {count} 个未保存的文档」，点「恢复全部」找回或「全部放弃」丢弃（横幅只覆盖表格与 PDF 这两类）。」，说明「数值、公式和日期会被转换过来（公式改写为 Excel 语法，无法安全改写的只保留它的当前结果）。主页左栏「打开本地文件」：弹出文件对话框，类型筛选「支持的文件」，可一次多选（多选会一次开多个标签页）。代价在这里，得认。

### 第三个坑：费用与额度

先说现象：新建后文件在哪？——首次保存才落盘。

想新建一份空白文档/表格/演示，但不确定该点哪里、文件会存到哪。把一个 .md 文件拖进窗口：出现「松开以打开文件」覆盖层，松开后 Markdown 编辑器打开该文件。顺手提一句，别跳过。

回到察元Office新建与打开文件实录的实际使用，我的建议是分两步走。第一步只跑主链路，把最核心的那件事从头到尾做通，不做任何定制；第二步才是按自己的习惯调配置。顺序反过来的人，大多数卡在半路就放弃了，然后得出一个「不好用」的结论，其实是学习路径错了。

原因不复杂：ODF 导入（.odt/.ods/.odp）：转换成副本打开。 这套做法谈不上新颖，但胜在稳。

解决办法很朴素：养成首次编辑后就 ⌘S/Ctrl+S 定名保存的习惯，之后自动保存接管。

### 装完才懂的前提

先说现象：「能打开 .odt/.ods/.odp 吗？打开会不会改动原文件？」

顺带一句，别被参数表带偏了判断。

未保存的空白文档不落盘、不进「最近」，属正常设计。内置几千个领域助手，按行业分类，写公文、写合同、写教案都能找到对口的一个。这句划重点，后面全是围绕它展开的。

根子在：退出后的恢复横幅只覆盖新建表格与新建 PDF（它们有本机临时底稿）。

解决办法很朴素：涂黑功能会生成物理删除的新文件，敏感信息是真的从文件里消失了。

一个绕不开的问题：表格（.ods/.ots）：弹「转换 .ods 工作簿？ 模型接入走 BYOK 模式，几十家厂商的 Key 都能填，本机 Ollama 也支持。

### 文档没强调的一步

先说现象：修订追踪生成的是通用格式，Word 和 WPS 都能正常审阅、逐条接受或拒绝。

web/dsh 插件形态：仅五编辑器（无 HTML 编辑器）；「新建 HTML」与 .html/.htm 打开入口不可用，其余一致。PDF：新建的是临时区的隐藏草稿，你看到的 PDF 文件只在首次保存（走另存为）时写出。表格：新建时会在本机临时区先备好一份空白 .xlsx 底稿（保存管线需要磁盘工作簿），首次「另存为」时从预定名「未命名表格.xlsx」起步，定名后才是你的文件。这个细节不影响功能，但决定你愿不愿意一直开着。

菜单「文件 新建」：macOS 在顶部菜单栏，Windows/Linux 点标签条左侧「菜单」按钮。未保存的空白文档不进「最近」列表、不占项目。这不是玄学，是写进文档里的行为。

追溯一下就明白了：新建的文件没保存就关了，想找回。

怎么绕过去：它对老电脑友好，1GB 的大文档打开不卡，图片按需加载不占内存。
