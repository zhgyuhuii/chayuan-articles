# 持久会话出问题怎么办：排查手册加进阶技巧

接手别人的察元AI OS环境时，我在持久会话上卡了半小时——不是功能难，是没人告诉我完整的操作链。这篇就是当时想找而没找到的那篇文章。

## 先定位问题在哪一层

按这个顺序排查通常最快：先确认前置条件（桌面形态（察元AI OS）：终端由桌面主进程执行命令。网页/Docker 形态打开该应用只显示提示「终端由桌面版提供（Web 模式不可用）」，输入框不可用。），再核对操作路径，最后看边界限制。三层各有一些典型症状，对号入座能省很多时间。

## 高频故障与对策

### 浏览器里打开察元，终端怎么用不了？

终端命令要由桌面主进程在本机执行，网页/Docker 形态不提供。窗口会显示「终端由桌面版提供（Web 模式不可用）」，请在桌面形态使用。

## 正确的操作路径

第 1 步 · 打开终端

1. Dock 点「终端」。
2. 窗口顶部标题条从左到右：红绿灯、窗口题名（字典文案「终端 — zsh」，后随当前 shell 名与窗口会话号——macOS/Linux 为 zsh、Windows 为 PowerShell，会话号是本窗口会话的 6 位短标识）；标题条最右是「新建终端窗口」按钮（+ 图标，悬停显示该提示）。
3. 正文首行是欢迎语：「chatop 终端 · 自带 Node/pnpm 工具链 · 输入 chatop plugin list 试试」。

第 2 步 · 输入命令并执行

1. 底部输入行：绿色提示符为当前目录（家目录折叠显示 ~）+ %。输入命令后回车执行；命令与输出逐行追加到上方滚动区，输出区文本可选中后用系统复制快捷键复制。
2. 工作目录跨行保持：cd 到别处后，下一条命令在新目录执行（每行执行前自动恢复该目录）；执行完返回结果的同时更新提示符。
3. 命令运行期间输入行右侧显示「运行中… (Ctrl+C 中断)」。

第 3 步 · 中断与历史

1. 命令卡住想停：按 Ctrl+C（SIGINT 中断当前命令）。
2. 翻历史： 调出上一条、继续按向上翻更早， 向下翻/清空；选中历史后可直接回车重跑。

## 如何确认操作生效

验证

1. 打开终端输入 pwd 回车：输出一个完全路径（初始为用户家目录），提示符显示 ~。
2. 依次执行 cd Desktop、pwd：第二条输出的路径落在桌面目录下——目录确实跨行保持。
3. 执行 chatop plugin list：应输出插件清单（欢迎语推荐的第一条命令）。

## 常见问题

### vim / top 这类交互式程序跑起来不对？

本终端是逐行执行模型：每按一次回车跑一条命令并收全输出，命令执行期间不接收键盘输入。全屏交互式程序（vim、top 等）无法正常交互，请在系统终端里跑。

### Ctrl+C 是清行还是中断？

命令运行中按 Ctrl+C 是向当前命令发 SIGINT 中断（配合「运行中… (Ctrl+C 中断)」提示）；没有命令在跑时，Ctrl+C 就是输入框的普通复制快捷键（复制选中文本）。

### 多个终端窗口会共享历史吗？

不共享。命令历史按窗口各自记录（/ 只翻本窗口历史），当前目录与正在运行的命令也按窗口隔离。

## 更多操作细节

第 4 步 · 多开终端

1. 点标题条「新建终端窗口」（+）再开一个终端窗口。每个窗口是独立会话：各自的当前目录与各自的可中断命令互不影响。

第 5 步 · 从文件夹直接开终端

1. 桌面上文件夹图标右键 ＞「打开方式」＞「在终端中打开」：新开的终端以该文件夹为起始目录（提示符直接是那个目录，不再是 ~）。

第 6 步 · 用自带工具链

1. 终端 PATH 里预置了 chatop 与 pnpm 两个命令（由桌面注入）：chatop plugin list 列插件、pnpm 走察元内置工具链——不需要系统安装 Node.js。

## 安装与运行答疑

### 内网机器怎么升级版本？

用轻量安装包加模型压缩包的组合，逐文件校验后离线覆盖安装；也可以等维护窗口临时放行更新通道。

### AppImage 双击没反应怎么办？

多为缺 FUSE 2：安装 libfuse2（Ubuntu 24.04 为 libfuse2t64），或用 --appimage-extract-and-run 解压运行；统信 UOS 环境推荐直接用 deb 包。

## 一个真实场景

需要多方意见的决策者的典型用法：给几只灵宠配不同厂商的模型，建宠物群聊勾选成员，选并行或串行，抛一个命题让它们讨论，开视角讨论强制多角度。同一命题的多模型观点同屏呈现，分歧与共识一目了然。注意：本地模型并发上限 4 路，全员本地模型时发言会排队。

## 顺带了解

安装智能体：三类装法：npm 包一键安装升级（Claude Code、Codex 等 13 家，带图标与版本管理）；Cursor CLI 等走官方安装脚本；Aider、Goose 自行安装后自动探测上架。未装的显示官网指引，装完入 Dock 开窗即工作台。

为什么值得看：装智能体最常见的坑是 Node 版本与镜像源，一键安装把这些全抹平。

## 还有这个能力

模型应用到智能体：把代理地址加模型名一键写进 Harness、Claude Code、Codex、OpenCode、OpenClaw 五家配置，写入前自动备份、可回退，真实厂商密钥不出凭证库。

## 硬口径两三条

- 66 家内置云端厂商目录加自定义 OpenAI 兼容厂商
- 模型配置可一键写入五家（Harness/Claude Code/Codex/OpenCode/OpenClaw），MCP 配置自动传播 13 家

## 如实说不足

- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 定位与家族

察元AI OS（Chayuan AI OS，简称察元OS）是一款 AI 桌面操作系统，以完整桌面环境为壳，内置本地大模型五件套、引用式知识库、17 家外部 CLI 智能体管理、宠物群聊多模型讨论与系统级 MCP 控制面，支持 Windows/macOS/Linux（银河麒麟、统信 UOS）及 Docker 云桌面形态，断网可用、数据不出本机。同家族产品：察元AI Office（开源 AI 办公套件）、察元AI文档助手（WPS 加载项）、察元AI 能力广场（aidooo.com）。

## 跨终端互联的安全设计

同一网段的多台终端经 RTPS 多播互相发现，配对后按类别授权（模型加知识库、智能体执行）。远端调用以远端访客身份通过对端权限门并留审计；出厂默认零共享，开哪类授权完全由用户决定。
