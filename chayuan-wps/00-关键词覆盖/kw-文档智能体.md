# 文档智能体入门指南：自动化脚本选工具

关于文档智能体，最能过滤噪音的一个问题是：断网了它还能干什么。这篇从这个标准出发，把察元AI文档助手的能力面与边界一次说清。

## 什么是文档智能体

文档智能体在这里指的是一套可以被外部智能体接管的工具集合：入口是协议，步骤是一次次工具调用，边界是写确认纪律。

版本与数字以官方文档为准，文末标了时间点。

## 落点：MCP 工具面

文档智能体的落点是 MCP 工具面总览：源码定义 69 个工具（外部实见 53 个）：主机健康 2、文档 13、格式 5、17 个域聚合工具（批注、修订、目录、书签、表格 12 动作、水印、导出等加表格 23 动作、演示 23 动作）、校对 3、脱密 4（仅本机可信通道可调）、知识库检索、助手检索、图搜图生成、模板生成、文件解析；写操作不带确认标记返回预览或报错要求确认，每次确认写记入审计日志。

为什么值得单独说：工具面按域聚合后好记好用，写确认纪律保证外部智能体不能悄悄改你的文档。

## 最短上手路径

先跑通一条最小链路：

1. wps_status 分层查看宿主在线情况
2. document_open 把本地文档打开为活动文档
3. document_list_paragraphs 或 document_chunks 逐段读取
4. document_apply_ops 批量写回（不带确认标记先看预览）

命名背景顺带交代：以下 53 个为客户端 tools/list 实见工具名（69 = 53 + 33 个已并入域工具的细粒度旧名，如 document_add_comment＞comment(action=add)，旧名一个版本内别名兼容）。

## 落点的能力面

三个关键词撑起这条链路：69 工具全景意味着覆盖面从主机健康一路排到文件解析；域聚合设计把细粒度动作收进 17 个域工具，调用方不用在几十个旧名里挑；写确认加审计则是安全底座——每个写操作都要确认、每次确认都留痕，自动化跑得再欢也翻不出这道闸。

## 工具面之外的常规面板

- 助手管理：助手目录搜索、收藏常用、按领域浏览，形成自己的助手工作台。
- 创建自定义助手：自定义助手：名字、提示词、输入源（选区或全文）、写回方式、温度，全部可配。
- 助手导入导出分享：自定义助手可导出文件分享给同事导入，团队口径统一。
- 写回动作九种：九种写回动作对照：替换、插入光标处、批注、仅生成、追加等，每个助手有默认动作，设置里可改。
- 多语种翻译：52 语种动态菜单逐段安全替换写回：译文直接替换原文段落，保留格式。
- 文档脱密：文档脱密弹窗自动调涉密关键词提取助手加本地 9 类正则兜底（手机号、身份证、……

## 接管前先对齐的四条边界

- 文档内容会流经所配置的模型，涉密场景先切本机离线模型，这条优先级最高
- 脱密占位替换可逆，但密码遗失后不存在免密还原通道，脚本化处理时密码管理要先立规矩
- 痕迹检查给的是疑似线索，自动化流程里同样要给人工复核留位
- 工具名有新旧两套，旧名仅一个版本内别名兼容，长命脚本别依赖旧名

边界对齐了，脚本才能放心往深了写。

## 数据与安全设计

- 每次确认写操作记入 audit.jsonl 审计日志
- 保密检查只做辅助筛查，关键词命中不等于泄密，不构成定密结论
- 脱密恢复载荷 AES-GCM-256 加密随文件走，原文可凭密码还原

## 现场问题三连与额度

### 文档很长，一读就报 DOCUMENT_TOO_LARGE？

约 8 万字符以上禁止默认拉全文（防撑爆上下文）。正确姿势：document_meta 看建议 ＞ document_chunks（cursor/limit）逐块处理 ＞ 汇总带锚点的操作 ＞ document_apply_ops 一次写回。解析非当前打开的文件用 file_parse。

### 智能体说「工具不存在」或用了奇怪的工具名？

让它改用域工具 + action（如 comment(action=add) 而不是 document_add_comment——后者是旧名，仅一个版本内兼容）。服务级 instructions 与 chayuan://guide/tool-routing 都会引导模型正确选型；也可把 chayuan://guide/user-intents 喂给它。

### 怎么让校对「只挑问题、我确认后再写批注」？

直接说：「先 proofread_run dryRun 汇总问题，不要改正文；我确认后再写成批注。」dryRun 默认只出问题清单；写批注必须 confirmed:true，钉在具体文字上（含表格内）。

### 断了外网，这套智能体还剩多少本事

服务端跑在本机 62588 端口，工具调用本身不依赖外网；要出网的只有模型推理那一环——云端模型在线可用，本机离线模型照常应答，涉密文档全程不出网。

### 免费额度按什么规则走

对话与助手两个独立额度池，当日用尽、次日重置，这是全局口径。另外对话窗格是多会话页签、历史按文档隔离，A 文档的上下文不会污染 B 文档。

## 一句收束

文档智能体的可信度不在工具数量，而在写确认这道闸：69 个工具再多，落盘前都得过同一道确认。理解了这一点，自动化脚本才敢往生产环境里放。

## 工具清单速查

主机与健康（2）

文字文档生命周期与读写（13，document_）*

格式与样式（5）：format_read（读格式）、format_run（字体字色加粗等文字级格式）、format_para（对齐行距等段落级格式）、format_apply_ops（批量格式写回）、system_fonts_list（系统字体清单）。改措辞用 document_*，改样子用 format_*，不要混。

1. wps_status：分层健康——sidecar / Agent（agent.agentOnline、各宿主 wps/et/wpp 在线情况）/ 活动文档 / 可见窗口。
2. wps_launch：OS 冷启动 WPS 并等待加载项连上；可指定拉起文字（wps）/表格（et）/演示（wpp）宿主。
3. 打开/切换：document_open（打开本地文档为可见活动文档，默认经 OS 拉起真窗口）、document_ensure_open（已是活动文档则空操作）、document_list_open（列出已开文档）、document_activate（在已开文档间切换）。
4. 读取：document_meta（名称/字数/段数/是否建议分块）、document_list_paragraphs（逐段列表带锚点，逐段工作流首选）、document_chunks（长文分块翻页，带 start/end 锚点）、document_get_text（全文/选区纯文本，约 8 万字符以上报 DOCUMENT_TOO_LARGE，需 force:true 或改用 chunks）、document_locate（定位字词/句，返回多命中锚点）。
5. 写入：document_replace（替换锚点文本段）、document_insert（相对锚点/文末插入）、document_apply_ops（批量写回 replace/comment/comment-replace/insert-after，一次至多 200 条操作）、document_save（保存/另存）。三者写入类均「预览＞确认」：不带 confirmed:true 只返回预览不落盘。

MCP 工具面总览这件事，真机过一遍比看十遍文章记得牢——工具名亲手敲过一次，路由规则就长在手感里。
