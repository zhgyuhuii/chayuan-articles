# 本地模型管理上手指南：照着做十分钟跑通

内网机器要内存吃紧时手动卸载闲置模型，过去要折腾好几个工具拼起来。现在察元AI OS把这件事做成了一个功能：本地模型运行管理。下面按我实际操作的顺序走一遍，包括容易踩的坑。

## 先对齐一下概念

在 设置 ＞ 模型 的各本地分类页里对「我的模型」做全生命周期管理：启动加载 / 停用卸载 / 删除权重 / 钉住防闲置自动卸载 / 调启动参数（省内存·均衡·性能三档 + 高级覆盖）；页面顶部的健康灯与「重启全部 / 全部关闭」负责整个本地引擎服务的状态与自救。

一台 16GB 内存的机器跑两个 8B 模型必然卡死，显式的加载卸载加自动卸载策略是本地模型的生存之道。

按真实界面写，按钮文案原样引用。

## 动手前的准备

- 至少有一个已安装的本地模型。
- 本地模型服务在运行：页面顶部健康灯绿色「正常」。推理引擎（llama-server / whisper-server）随安装包分发，缺失时见对应教程 常见问题 Q6。
- 「启动参数」仅对带对话能力的模型开放（嵌入/重排/语音等小件行内没有「设置」按钮）。

## 操作步骤详解

1. 进入「我的模型」

打开 设置 ＞ 模型，左栏「本地模型」组选能力分类（对话 / 嵌入 / 重排序 / 决策 / 代码补全 / 图像理解 / 视频解析 / 生图 / 视频生成 / 语音识别 / 语音合成），右栏自上而下：状态条 ＞ 服务地址条 ＞ 「模型全机只保留一份」提示 ＞ 「我的模型」＞ 「模型库」。模型按能力归入仅有分类页。

2. 认识状态条（顶部）

1. 健康灯 + 文字：绿「正常」/ 黄「引擎异常」或「引擎缺失」/ 红「不可达」/ 灰「已停用」；
2. 实例计数：「N 个模型运行中」或「无运行中的模型」；
3. 「空闲自动卸载策略」下拉：「自动卸载：关 / 5 / 15 / 30 / 60 分钟自动卸载」，默认 15 分钟，改动持久化（重启不丢）；
4. 「重启全部」「全部关闭」：点击后行内出现红色确认条——「重启全部运行中的模型？」/「关闭本地模型服务？全部实例将卸载（厂商模型不受影响）」，点「好」执行、「取消」收回；服务被停用后这里只剩「启动」按钮。

3. 启动加载

点模型行尾蓝色「启动」＞ 提示「已发起启动（后台预热）」。加载流程：内存预算预检（预算 = 物理总内存 × 75%）＞ 拉起引擎进程（本机回环，引擎实例池 52665–52899 一模型一进程）＞ 健康检查 ＞ 行首亮绿点。预检不过会明确报：「内存预算不足：加载需要约 XGB，当前预算 YGB 已被运行中的模型占用。请先在模型管理中卸载：<名单>」或「此机器内存不足以加载该模型…请选择更小的模型」。刚亮灯时若显示黄点（悬停「运行中·探针验证中」），是系统在发最小推理请求验证——通过后转绿。

4. 测试链路

行内「测试」：未加载会先自动加载，再按能力发最小真实请求——通过显示「测试通过 · <耗时>ms」（嵌入模型附维度、对话模型附样例回复），失败显示「关闭 测试失败 · <原因>」。

5. 停用（卸载释放内存）

行内「停用」立即卸载该实例并释放内存。手动停用会记入预热豁免清单：之后重启应用/触发预热，不会自动把它拉回来，直到你再次显式「启动」。

6. 钉住（防空闲自动卸载）

行内「钉住」（悬停「钉住：空闲自动卸载豁免」）：钉住后行内显示 （悬停「已钉住（空闲不卸载）」），按钮变「取消钉住」（悬停「取消钉住：空闲 15 分钟自动卸载」）。空闲计时 = 最后一次经模型代理/桥接的调用；嵌入、重排、语音识别、语音合成四类小件默认就是钉住的（常驻设计），对话模型默认参与自动卸载。常用对话模型建议钉住，避免每次冷加载等待。

7. 删除权重

行内「删除」＞ 行内确认「删除 <名称> 的已下载权重（<体积>）？删除后可重新下载。」点「好」执行。运行中的模型要先「停用」；「装机即用」五件套随安装包分发不占额外磁盘，删除会被拦（提示内置权重无需删除）。装机即用模型删除后重启不会复活，找回走「恢复出厂模型」。本地路径导入的模型「删除」只移除登记、不动原文件。

8. 启动参数（对话模型专属）

对话类模型行内点「设置」（悬停「启动参数」）打开弹窗「启动参数 · <模型名>」：

1. 三个预设档 chips：省内存（并发 1 路）/ 均衡（2 路，默认）/ 性能（3 路）——选档只改并发路数与内存，每路上下文上限恒等于模型基础上下文（如装机对话档 32K），不会因选省内存档把单条消息容量砍半；
2. 右侧实时显示「预计内存 ≈ XGB · 当前生效 N 路 × XK」；
3. 高级字段：并发路数（1–16）、上下文(K)（1024–262144）、GPU 层（自动 / 仅 CPU / 自定义 0–999）、线程（自动 / 自定义 1–64）；
4. 底部说明原文：「并发路数=灵宠/群聊同时应答数；预设档每路上限=模型基础上下文，选档只改并发与内存。保存后运行中实例自动重启。」
5. 点「保存并重启生效」：参数持久化，运行中的实例自动按新参数重启——成功提示「已保存并按新参数重启」，实例重启失败提示「已保存，但实例重启失败」（参数已生效，回列表再点「启动」即可）；未在运行的只提示「启动参数已保存」。

9. 重启全部 / 全部关闭

1. 「重启全部」：记录当前运行清单 ＞ 全部卸载 ＞ 按原清单依序重载（提示「已发起全局重启（按原运行清单依序重载）」），处理引擎假死；
2. 「全部关闭」：卸载全部实例（含钉住的）并置停用位，健康灯变灰「已停用」；此后状态条只剩「启动」，点击清停用位并走预热链补齐加载。

## 收尾检查

验证

1. 「启动」后行首绿点、状态条计数 +1（如「2 个模型运行中」）；黄点在数秒到十几秒内转绿。
2. 点「测试」显示「测试通过 · <耗时>ms」。
3. 浏览器打开 http://127.0.0.1:52581/v1/models（免 key）：该模型 local/<id> 条目的 running 为 true。
4. 改启动参数保存后，若模型在运行会自动重启——再发一条消息仍正常回复，即新参数生效。

## 什么情况下用得上

灵宠群聊/多智能体并发时被 500「Context size has been exceeded」打断，要调并发路数；下载或导入完模型，要把它加载进内存供对话/知识库使用，给常用模型上钉子，模型用一会儿自己「消失」，想搞清 15 分钟空闲自动卸载并固定常用模型。

用户常搜的问法：本地模型怎么加载/卸载？在哪里操作；模型跑着跑着自己停了是坏了吗。

## 别在这几处栽跟头

功能归功能，这几个边界先摆清楚：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 自动卸载会释放常驻模型，重度使用记得钉住

## 你可能会问

### 灵宠群聊同时提问时报 500「Context size has been exceeded」？

并发路数不足或上下文打满。到该模型「设置」里升档（均衡 ＞ 性能）或手填并发路数（1–16），保存后实例自动重启按新参数拉起；每路上下文上限不变。

### 删除了「装机即用」模型，怎么找回？

「删除」只删共享副本并记账（重启播种不复活）。到 设置 ＞ 模型 ＞ 左栏「本地模型」组底部「恢复出厂模型」一键重播种五件套，详见对应教程。

### 启动报「内存预算不足…请先卸载」？

加载前有硬预算预检（物理总内存 × 75%）。按提示先「停用」名单里的模型，或换小参数量模型。这是保护机制，不会让整机卡死。

### 模型跑一会儿自己停了？

默认「15 分钟无人使用自动卸载」在释放内存，不是故障。空闲计时按最后一次实际调用刷新。要常驻：点「钉住」豁免；或把状态下拉调成「自动卸载：关」。嵌入/重排/语音小件默认已钉住。

本地模型管理的能力边界也写清楚了：能做什么、不擅长什么。工具好不好用，很大程度上取决于你知不知道它的边界。
