# 内网升级安装：在线检查更新

内网升级的麻烦在于：机器不通外网，更新通道却大多按公网设计。这篇把察元AI OS在隔离环境里的版本更新路径拆开讲，连同在线检查更新的完整流程一并覆盖。

## 安装前确认

- 系统要求：x64/arm64；银河麒麟 V10、统信 UOS 20 推荐 deb
- 安装包：deb（ChaAIOS-版本-架构.deb）
- 说明：隔离环境的版本管理。

安装包从官方渠道取得后由介质摆渡进内网，内网机器不直接对外下载。

## 一步步来

1. 按 CPU 架构选包：飞腾/鲲鹏选 arm64，兆芯/海光选 x64
2. sudo dpkg -i 安装 deb 包
3. 应用菜单启动，首次启动自动初始化数据目录
4. 麒麟/UOS 环境优先本地模型，离线即用

## 如何确认操作生效

- 桌面正常进入，对话应用挑本地模型应答一句，响应无误即可
- 初始化通常 5 到 30 秒内结束，属于正常节奏，等一下就好

## 注意事项与真实边界

先交代几条现实约束：

- 想玩转 Docker 云桌面、跨终端互联，得先攒点动手底子
- 云端厂商的模型不随装随用，API Key 各自申请后再填
- 8GB 内存的设备对话模型一次装一个，复杂任务别指望同时开
- 龙芯平台暂时没有包可装；视频生成这项能力本地没有，由云端路由代劳

## 高频疑问

### 「检查更新失败」怎么回事？

多为网络访问 GitHub Releases 失败。按提示「可到 Releases 页手动下载」：到项目的 GitHub 发布页手动取最新安装包，覆盖安装即可。

### 更新会丢数据吗？

不会。安装包只更新程序文件，你的数据根目录不动（帮助中心 ＞ 参考 ＞ 常见问题 FAQ 同口径）。

### 点「检查更新…」却打开了一个网页？

那是网页（浏览器）形态：没有桌面更新桥，按钮降级为打开官方站点页。完整的检查-下载-安装流程需要桌面安装版（察元AI OS 桌面应用）。

## 第 1 步：打开「关于」面板

两个入口，打开的是同一个面板：

面板内容从上到下：察元 logo、名称「察元」、副标题「察元AI OS · 离线 AI 办公助手」、等宽字体的版本号 v{X.Y.Z}，再往下是厂商行与版权行。版本号单一来源是 dsh-plugin/package.json 的 version（打包时自动同步外壳，关于窗口与设置分区都从这里取，杜绝手写过期）。

1. Dock ＞ 「设置」＞ 左栏「关于」，内容卡片标题「察元」；
2. 屏幕左上角察元菜单（logo 菜单）＞ 「关于 察元」，弹出独立关于窗口。

## 第 2 步：点「检查更新…」

1. 做什么：点面板下方的「检查更新…」按钮。
2. 状态行按结果变化（就在按钮下方，进度实时刷新）：
    1. 检查中：显示「正在检查更新…」；
    2. 已是最新：显示「已是最新版本」；
    3. 有新版本：自动开始后台下载（无需再点下载），状态行显示「下载更新中 {p}%」实时走百分比；按钮下方同时显示新版发布说明摘要（取自 Releases 的 releaseNotes，剥掉 HTML 按纯文本展示，最多 400 字）；
    4. 失败：显示「检查更新失败（可到 Releases 页手动下载）」，并在后面附具体错误原因。
    5. 没有自动检查：开机、日常使用中都不会自动检查更新，只有点这个按钮才检查。

## 第 3 步：「重启并安装」

1. 下载完成后，状态行变为「已下载 v{新版本}，重启完成安装」，下方出现蓝色按钮「重启并安装」。
2. 做什么：点「重启并安装」＞ 应用退出并自动安装新版，装完自动重启回到桌面。
3. 不点它也没关系：已下载的更新会在下次正常退出应用时自动安装（安装器开启 autoInstallOnAppQuit），再开机即是新版。
4. 设置分区和独立「关于 察元」窗口是同一个面板、同一份更新状态：一边看下载进度，另一边打开也是同样的状态行（状态由主进程实时推送）。

## 升级后的验证

1. 升级完成后重新打开 设置 ＞ 关于，等宽版本号应显示为新版本号。
2. 下载过程中可以关掉设置页去干别的；重新打开关于面板会拉取当前更新状态（进度/已下载/出错都会照常显示）。

## 补充答疑

### 下载进度一直不动 / 下载中断了？

重新打开关于面板看状态行；若已报错会显示失败原因（网络断续常见），网络恢复后再点一次「检查更新…」重新下载即可。

### 为什么从来不弹更新提醒？

产品采用手动检查模式：不静默检查、不强更。想升级时到 设置 ＞ 关于 点一次「检查更新…」。

## 形态差异与网络前提

- 完整检查更新流程仅桌面（打包安装）形态：需要 Electron 更新桥（chatopDesktop.updateCheck），更新源为 GitHub Releases（发布通道在 desktop/electron-builder.yml 里配置 provider: github）。
- 网页形态没有更新桥：点「检查更新…」不进入检查流程，而是在新窗口打开官方站点页。桌面开发（未打包）形态有桥但接的是空更新器，检查恒显示「已是最新版本」。
- 检查与下载需要能访问 GitHub Releases 的网络。

## 这套更新机制的三条要点

- 在线检查更新
- 重启安装
- 数据保留

## 隔离内网的替代路径

完全隔离的内网没法在线下载，这时升级回到最朴素的形态：在有外网的机器上取好新版安装包，介质摆渡进内网，覆盖安装——更新失败提示里「可到 Releases 页手动下载」那条路，指的就是这个动作。权重文件同理，U 盘搬运是最现实的路径，系统为此做了零拷贝导入。

## 数据与网络边界

升级之外的安全口径顺带交代：本地起的全部服务默认只绑 127.0.0.1 回环，数据不出机器；一台设备多人用时，数据隔离是底线，管理员统一管账号比各自为战安全；对隐私敏感的环境，先把遥测关了再干活，设备转手或报废前记得清数据。

全文压缩成一句话：内网里的版本管理，能联网的走「检查更新…」，彻底断网的走安装包摆渡，两条路都保留数据。
