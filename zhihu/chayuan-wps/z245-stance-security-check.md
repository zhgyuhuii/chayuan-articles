# 为什么察元文档助手保密检查值得单独说一篇？

看到察元文档助手保密检查这个问题底下清一色的吹或黑，忍不住说两句。我的看法是：比多数替代品克制，比宣传页朴素。

先把背景交代清楚。这个问题的来源很实际。文档外发、上报、公开前的自查：想知道里面有没有密级标识、部队/单位敏感表述、内部编号、联系人信息等。批注：每条命中的「命中片段」按结构化锚点策略定位到原文，以链接批注形式写在该片段处。已在 WPS 中启用加载项，三端 Ribbon 出现「察元AI助理」。

要判断它，得先知道它的底细：打开要检查的文档，在 Ribbon「察元AI助理」选项卡找到「安全保密」组，点「保密检查」（按钮标题取该助手的显示标题，默认即「保密检查」）。锚点要求命中片段与正文逐字一致，定位失败时跳过该条、不做整篇兜底批注，并提示「未能将批注锚定到原文……已跳过全文单条批注。这个细节不影响功能，但决定你愿不愿意一直开着。

回到察元文档助手保密检查的实际使用，我的建议是分两步走。第一步只跑主链路，把最核心的那件事从头到尾做通，不做任何定制；第二步才是按自己的习惯调配置。顺序反过来的人，大多数卡在半路就放弃了，然后得出一个「不好用」的结论，其实是学习路径错了。

### 先看它的定位

涉密程度高的文档，建议先在设置里切换到本机离线模型再执行保密检查与脱密。任务清单：完整审查报告存入任务记录，小节固定为「总体结论 / 高风险项 / 中风险项 / 低风险或待人工复核 / 建议处理 / 可疑关键词汇总」，每条命中项含命中片段、命中关键词、风险类别、判断依据、建议处理。单看没什么，连起来看就有意思了。

它的保密结论只是辅助筛查，不构成定密结论，这点文档写得明明白白。表格/演示端：AI 助手窗格中出现自动发送的保密检查指令及智能体输出的问题清单。说实话，第一眼我以为多余，用下来才知道是刚需。

助手的研判原则是「关键词只是线索，是否涉密由语义+实体+上下文决定」：高/中风险按证据分级，拿不准的归入「待人工复核」而非静默放过，同时对公开、教材、泛指语境降噪避免机械误报。具体到操作面，内部编号与项目标识这条在手册里写得很细。这套做法谈不上新颖，但胜在稳。

### 它做对的那件事

还有一个判断角度常被忽略：看察元文档助手保密检查失败的时候是什么样子。顺的时候大家都差不多，差别全在出问题的那一刻，报错信息是否说人话、能不能原地重试、数据会不会丢。这些细节官方文档很少写，但恰恰是它们决定你用一个月之后还愿不愿意继续用。

「保密检查发现问题后会改我的文档吗？」高危/中危计数取自报告「高风险项」「中风险项」小节的条数，「关键词命中任务」看「可疑关键词汇总」小节。这句划重点，后面全是围绕它展开的。

内部编号与项目标识：项目代号、型号代号、合同编号、文号、图号、批次号等。进度窗内的查看、换模型重跑、撤销等操作见对应教程。这不是玄学，是写进文档里的行为。

### 代价与边界

校对结果是批注，锚定在原文上，不硬挂锚不上位置的错误。经营与商业敏感信息：报价、成本、投标方案、采购清单、客户名单、未发布经营数据等。很多人在这里浅尝辄止，其实往下还有一层。

打开任务清单看完整报告，对照「命中片段」手工定位即可。具体到操作面，收到一份「要脱密处理」的文档这条在手册里写得很细。这一点挺难得，很多同类产品只在宣传页里讲。

打开任务清单：「察元AI编审」选项卡 「察元设置」组 「任务清单」。具体到操作面，扫描已用区域这条在手册里写得很细。

它的边界也得摆出来。它对离线场景友好，接本机 Ollama 全程不出网，涉密文档也能用。如果你只记一条，记这条就够了。

最后给一个折中做法：军工/政企文档高频敏感线索：机场、阵地、雷达站、研究所、专项任务、技术指标等。脱密是付费能力，没有免费额度，涉密场景再考虑上这一项。
