# RAG建库避坑指南：边界、限制与对策

很多RAG建库的教程只讲是什么，不讲怎么做；或者讲了一半步骤，剩下的让你自己悟。这篇反着来：步骤写全、按钮文案原样引用、每步的界面反馈都说清楚，用的是察元AI OS（aidooo.com）。

## 先定位问题在哪一层

按这个顺序排查通常最快：先确认前置条件（桌面形态，已在知识库应用「文档」页选中一个库。），再核对操作路径，最后看边界限制。三层各有一些典型症状，对号入座能省很多时间。

## 高频故障与对策

### 单文件上限多少？超了怎么办？

上限 48MB（代码硬编码 48×1024×1024 字节），超限文件在上传阶段即被拒绝并提示「文件过大（>48MB）」。请拆分文件后再传。

## 正确的操作路径

第一段 · 上传（只存原文，不解析）

1. 在哪：知识库应用「文档」页中栏顶部。三种上传方式任选：
    1. 拖拽：把文件或整个文件夹拖到知识库窗口的任意位置（整个窗口都是热区，包括左栏、右栏），列表顶部出现虚线提示条「松开即上传」后松手。拖文件夹会递归展开其中所有文件一起上传，并保留相对路径作为分组。
    2. 点按钮「上传文件」：弹出系统文件选择器，可多选；选完即开始上传。
    3. 点按钮「上传文件夹」：弹出系统文件夹选择器，选中整个文件夹（含子文件夹）一次导入。
    4. 上传过程看到什么：工具行下出现「上传中 {done}/{total}」＋总进度条（同时并发传 4 个），期间「上传文件」「上传文件夹」两个按钮置灰防重复。上传全部结束后进度行消失、文档列表自动刷新。
2. 上传阶段的自动处理：
    1. 不支持的扩展名、以 . 开头的隐藏文件自动跳过，并在窗口顶部红色提示条显示「已跳过 {n} 个不支持的文件」；
    2. 自动去重：按内容指纹（文件内容前 64KB＋文件字节数）判重——与库内「就绪」或「未加载」的已有文档同内容时，不会出现第二行；「失败」状态的旧档案不参与去重（保留重试语义）；
    3. 单个文件上传失败（空文件、超 48MB 等）在顶部红条逐条列出，形如「文件名： 文件过大（>48MB）」（最多显示 3 条，多了以「…」结尾），其余文件继续传。
    4. 上传完成的形态：中栏文档列表新增一行——文件图标＋文件名＋「来源路径 · 大小 · 日期」（文件夹上传的显示来源路径，散文件没有）＋状态徽标「未加载」（黄色）；同时左栏该库的文档计数 +1。此时检索不到任何内容——原文还没解析。窗口标题栏右上角同时显示本库统计行「向量 {vec} · 分词 {fts}」（本地默认形态如「向量 sqlite-vec · 分词 trigram」）。

第二段 · 加载（解析＋向量化）

| 格式 | 解析行为 |
|---|---|
| txt / md / markdown / log / csv / tsv | 按 UTF-8 文本逐行读；Markdown #～###### 行识别为对应 1–6 级标题，其余行为段落 |
| html / htm | 剔除 script/style/noscript；<title> 作为一级标题；h1–h6 为标题、p/li 为段落、表格行 tr 为表格块 |
| docx | mammoth 抽取为结构化块（标题/段落/列表/表格） |
| xlsx / xls | 每个工作表生成一级标题「工作表：名称」，每行数据转成表格行（每表最多读 5000 行） |
| pdf | pdf.js 抽取文本层；开头生成标题「PDF（N 页）」，逐页输出「第 N 页：文本」；无文本层的页写入提示「[第 N 页无可提取文本（可能是扫描件，建议 OCR）]」——扫描版 PDF 请先 OCR 再上传 |

1. 触发加载（三个入口，任选）：
    1. 单个文档：鼠标悬停到行尾出现操作图标簇，点 （悬停提示「加载（解析并向量化）」）；
    2. 多选若干文档（点行勾选）后，列表上方批量操作栏点「加载」；
    3. 库里有待加载文档时，批量操作栏直接显示「{n} 个文档待加载」＋「全部加载」。
    4. 进度看到什么：状态徽标沿「解析中 ＞ 向量化中」推进并显示百分比（解析起步 5%、切分完成 15%、嵌入阶段从 20% 走到 92%、完成时 100%），徽标前带状态圆点、行（卡片）下方有进度条；界面每 1.2 秒自动刷新一次。docx/xlsx/pdf 这类 CPU 密集格式的解析跑在后台线程，不会卡住桌面。同一库内多个文档逐个串行处理（每库一条队列），不会互相抢写库文件。
2. 每类文件被怎么解析（写进索引的内容）：
    1. 切分成块（决定检索粒度）：按标题层级分章，每块记住自己的「标题路径」（检索结果里显示为「文档名 · 标题路径」）；段落块目标约 650 token（估算口径）、硬上限 1200，相邻块保留 1 段重叠；表格不与段落混块；超大的单表/单段会再细切。后台一次「加载」的完整动作＝读磁盘原文 ＞ 抽取结构块 ＞ 切分 ＞ 逐块嵌入（可中断）＞ 单事务写入分块＋全文索引＋向量 ＞ 状态「就绪」。
    2. 完成：状态徽标变绿色「就绪」，进度条消失；右栏检索台立即可命中。块的条数不在界面上单独显示，可用右栏「检索」验证命中内容，或让对话里的智能体用 kb_read_doc 分页读全文核对。

中断与异常

失败的文档 图标仍在，修复原因后可再次加载。

1. 取消：加载中的行悬停出现 ■ 图标（悬停提示「取消加载」）；库里有加载中的文档时，批量操作栏显示「加载中 {n} 项」＋「全部取消」。取消后该文档状态回到「未加载」、进度归零，原文保留，随时可再点 从头加载。
2. 失败态：状态徽标红色「失败」，行内直接显示红色错误原因，常见的有：
    1. 「不支持的格式：.{ext}（当前支持 txt/md/html/docx/xlsx/pdf）」——这条提示文案是简化清单，实际支持面以本篇「前置条件」的完整清单为准；
    2. 「嵌入端点 HTTP {status}：{body}」「嵌入端点返回数量与输入不符」——厂商/云端嵌入端点报错或返回异常，检查密钥与端点配置（设置页签）；
    3. 解析器报错（损坏或加密的文件等）；
    4. 「重建失败：原始文件缺失」——库目录里的原文文件被外部删掉后重新加载。
    5. 崩溃恢复：加载中途应用窗口关闭不影响后台处理；只有整个桌面/系统退出才会真正中断。重启后不会自动续跑——状态为「解析中/向量化中」的文档被重置回「未加载」，重新点「加载」即可（原文都在，不需要重新上传）；只有极老版本遗留的、原文缺失的档案会被标「失败」并注明「上传中断：原始文件缺失」。

## 收尾检查

验证

1. 上传完成：文档行出现，状态徽标「未加载」；此刻到右栏检索台搜文件里的词，无命中——证明「上传≠可检索」。
2. 点 加载：状态徽标依次走到「解析中 x%」「向量化中 x%」，最终变「就绪」、进度条消失。
3. 加载完成后右栏切到「检索」，输入文档中的关键词：出现带序号的命中卡（文档名 · 标题路径 ＋ 片段文本）——解析、切分、索引全部生效。

## 进阶用法与边界

- 六种格式加扫描件 OCR
- 自动去重
- 进度可取消可恢复
- 边界：单文件 48MB 上限，超限拆分
- 边界：点加载才开始解析，上传不等于入库

## 高频疑问

### csv / tsv 是按表格解析吗？

不是。csv/tsv 与 txt/md 走同一文本解析（逐行读，Markdown 标题规则生效），不识别表格结构；按工作表/行解析的是 xlsx/xls。要表格结构进索引，请转成 xlsx。

### 没有配嵌入模型，文档还能加载吗？

能。加载链路在没有可用嵌入来源时会跳过向量化，只建全文索引——文档状态照样到「就绪」，字面检索可用，语义（自然语言）检索命中为空。「没有可用的嵌入来源：本地运行时未运行嵌入模型，且云端参数/密钥未配齐」这条报错出现在设置页的「测试连接」，按提示到「设置」页签配嵌入链路（本地/厂商/自定义云端，见教程对应教程），配好后重新加载或「重建索引」。

### 加载到一半关机/系统崩了，文件要重传吗？

不用。重启后处于「解析中/向量化中」的文档自动重置为「未加载」，原文完好，再点一次「加载」即可。
