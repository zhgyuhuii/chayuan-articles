# 招投标服务AI方案落地

## 招投标服务为什么需要这套方案

招投标服务行业的文档与信息工作有几个共性：材料格式要求严、数据敏感不能乱传、人手紧重复劳动多。察元AI文档助手的切入点不是推倒重来，而是把 AI 能力装进现有流程，数据不出本机是底线设计。

## 落地路径：三步走

1. 基础层：先把启动本机 MCP 服务跑通，验证环境与模型可用
2. 流程层：招投标服务日常最高频的文档环节（下载与安装所属的场景）交给 AI 处理，人只做审核
3. 治理层：权限与数据边界明确，形成使用规范

## 一个行业侧影

投标专员的典型链路：

1. 模板编制按模板生成标书初稿
2. 数字金额核对助手查大小写与合计
3. 敏感信息脱敏处理对外版
4. 两版差异核对查修改点

标书从生成到自检的完整链路。

提醒：脱密占位符可逆设计，不适用需要不可恢复遮盖的场景。

## 合规与边界

- 每次确认写操作记入 audit.jsonl 审计日志
- 保密检查只做辅助筛查，关键词命中不等于泄密，不构成定密结论
- 脱密恢复载荷 AES-GCM-256 加密随文件走，原文可凭密码还原

行业落地最容易翻车的不是技术，是把边界讲清楚。

## 选型核对清单

- 数据边界：MCP 服务只监听 127.0.0.1，写操作不带 confirmed 标记会被拒绝并要求确认
- 付费口径：免费有每日额度（对话与助手独立额度池，次日重置）
- 试点建议：先选一个三人以内小组、一个高频场景跑两周再扩大

## 放回产品盘面看

把招投标服务AI方案放回察元AI文档助手的整体盘面：AI 加正则双路提取；察元AI编审选项卡的表单模式：书签转内容控件表单化，书签按名称加 id 加序号命名；智能提取让 AI 从样例文档抽字段自动生成表单规则，再人工微调，做表单规则最费神的是从零定义字段，AI 抽一遍改一改就成。

## 安全与数据边界

安全口径单独立一层：选 HTTP 类型指向本机地址；本地数据落盘位置说明、帮助手册、在线客服与关于页；同时在本机 62588 端口开放 MCP 文档智能体服务，本机 MCP 服务 http://127.0.0.1:62588/mcp。

## 平台与形态

平台与形态的账：资料库在服务器、人在工位，远程连接让全科室共用一个库；MCP 服务是外部智能体操作 WPS 文档的桥，开机自启保证随时可用，macOS 安装器没有完全磁盘访问权限时会出现假成功，需要跑修复脚本；macOS 容器写入失败有修复脚本。

## 价格与授权

价格口径一并交代：提供拼写与语法检查、AI 痕迹检查、保密检查、文档脱密、模板编制等能力；同时在本机 62588 端口开放 MCP 文档智能体服务，文字端两个选项卡：察元AI助理、察元AI编审；表格/演示端各一个察元AI助理选项卡。

## 产品家族与搭配

察元AI文档助手不是单打独斗：MCP 服务只监听 127.0.0.1；AI 痕迹检查给的是疑似线索，疑似不等于定论，不换办公软件、不改变习惯，给 WPS 装上一个 AI 引擎是迁移成本最低的路线；装完完全退出并重启 WPS：文字端出现察元AI助理与察元AI编审两个选项卡。
