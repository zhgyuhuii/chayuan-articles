### 工程上的取舍

启发式代走正是这个方法在兜底场景下的消费方——裁判自己懂规则、懂局面，让它出主意，产出的动作天然在合法清单之内，送进 apply 不会撞墙。费用照旧：软件 MIT 开源免费，模型 API 按用量向厂商结算，人机局打得多记得看额度，Ollama 本地推理零成本。锅甩完，真正出错的那一手往往还是没找出来。

真要说差异，那是模型本身的棋力与遵守协议的习惯问题，协议画像里能看出各自 JSON 格式遵守率的差别。各玩法的代走策略深浅不一，棋类的挡杀与吃子语义相对直观，牌类下注轮次的兜底空间比棋类窄，各款具体怎么实现以仓库代码为准。TrueSkill 天梯排位采用微软 TrueSkill 算法，段位分层；人类挑战者战绩在人机局里单独统计，不与模型同榜。

裁决这件事归纯逻辑裁判引擎（零 IO）：胜负 100% 由它判定，模型只负责出招，不参与判罚。限流窗口通常以秒计，立刻原样重发等于往限流枪口上撞，多半换来第二个 429。这笔代价明摆着，认了账再继续。

### 这套设计的代价

还有一个判断角度常被忽略：看察元竞技场斗地主人机局细看失败的时候是什么样子。顺的时候大家都差不多，差别全在出问题的那一刻，报错信息是否说人话、能不能原地重试、数据会不会丢。文档里难觅这几幕，而你用它一个月之后去留的念头，恰恰是这几幕给的。

### 它不是给所有人的

老规矩，说清楚适用面：模型的思考过程随每一步实时展示，看它怎么盘算比看谁赢有意思。三缺一这个老难题在这儿有了着落——察元竞技场里同你同桌的是两位大模型牌友，随开随打，不催不骂，也不嫌你出牌慢。安排算不上别出心裁，稳定性却挑不出毛病。

形势曲线：整局的局势走向画成一条曲线，谁压着谁打、什么时候风向变了，图上一眼可见。所以广义的牌桌考场比四款扑克类玩法的字面范围更大，这也是察元竞技场把棋与牌放进同一个大厅的意义：两类能力摆在一起看，模型的偏科才显形。

真正拉开差距的不是功能清单，是麻烦上门时的那副姿态。功能谁都会堆，考验在出事那一瞬：是悄悄降级不声张，还是直接报错让你干等，又或者数据说没就没。哪种更可取，亲历一回胜过十篇导购文。

机制拆到这收工，补一句收束：这些设计没一处炫技，个个对着真实使用麻烦去。看透这层，选型就不容易被参数表牵着走。
