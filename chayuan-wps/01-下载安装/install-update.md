# 文档助手升级安装：察元 AI 文档助手

文档助手升级这件事，卡住人的通常也是三处：入口、按钮、确认方式。这篇按察元AI文档助手的真实界面顺序走一遍，把升级前后的验证点排清楚。升级和首次安装走的是同一条链路：取新版安装包、退出 WPS、重跑安装、验证选项卡；区别在心理预期——升级前已有一套能用的环境，任何异常都更容易被察觉，所以升级后的第一要务是回归验证，而不是急着探索新功能。

## 升级前的环境盘点

- 系统要求：WPS Office 已安装
- 安装包：chayuan-6.1.2-windows-x64.exe（自解压）
- 说明：加载项更新机制。

升级用的安装包同样只认官方渠道，版本号以包名里的 6.1.2 为准。

## 升级安装的四个环节

1. 取来新版 exe 安装包（官方渠道）
2. 双击安装：加载项放进 WPS jsaddons 目录，本机服务自注册并带看门狗
3. 完全退出 WPS 后重启
4. 文字端能看到察元AI助理与察元AI编审两个选项卡，升级就算完成

升级时最容易被轻视的是第 3 步：WPS 还开着就继续操作，安装动作与运行状态搅在一起，验证结果并不可靠。把完全退出当成分水岭——退出前是旧环境，重启后才是新版。

## 升级完先验拼写检查

升级完打开一篇文档，从察元AI助理选项卡跑一次拼写与语法检查，模型链路通不通一试便知；再到设置里把写回动作默认值过一遍。升级后跑这两步，等于把模型链路与写回链路各验一遍：一头管输入，一头管输出，两头都通，这轮升级才算闭环。

## 升级包与首装包是同一个东西

这篇通篇没有出现单独的升级包：升级用的就是带版本号的完整安装包，跑一遍安装流程即完成版本切换。反过来讲，手里安装包的版本号就是升级后的环境版本，取包时认准包名里那串数字即可，不必再到处找「升级专用」的产物。

## 落位与否的判断

- 文字端两个选项卡都在，这一轮升级就算落位
- 没落位就先彻底退出宿主软件，再启动一次

升级场景的收尾比首装更要紧：选项卡出现之外，再抽查一处常用功能确认行为正常，比如跑一次拼写与语法检查。环境是旧的、习惯也是旧的，任何细微变化都值得当场确认，别等用到一半才发现。

## 升级路上的三条边界

- macOS 上安装器若缺「完全磁盘访问权限」，会假成功
- 脱密的占位替换支持还原，可免密恢复通道一条也没有，密码忘了就是进不去
- Win7/Win8 与 MCP 预编译二进制不兼容，得用 Node 16 回落

升级语境下，假成功那条尤其值得警惕：旧版本还在正常运转，新版没落位时不容易察觉，可能过了几天才发现功能停在原地。升级完当场把验证做完，别拖到下次使用。

## 升级相关的能力速记

- 三平台安装包
- macOS 的容器写入失败有脚本兜底
- 企业侧可用 HTTPS 静态部署集中更新

第三条对多机环境尤其有用：服务器上的产物换成新版，各机器重新走一遍安装即完成集中更新，不必逐台分发安装包。有多台机器时，升级节奏值得规划：先升一台跑日常事务，观察一两轮使用没有异常，再铺到其余机器——集中更新让铺开动作本身很轻，需要斟酌的只是那台先行机器选谁。

## 编辑能力一览

AI 结果怎么落到文档里决定了信任度：批注式让你过目，替换式提效率。AI 助手组大按钮拼写与语法检查，有选中只查选中；整机文档翻译保持排版不走样，比复制出去翻再贴回来强太多；文档配图不用出软件，写好提示词就地生成。升级完成后，顺着这份能力清单各点一遍，是比翻更新说明更直接的回归方式。

## 助手体系怎么用

四千多个助手，管理方式决定调用效率：助手目录支持搜索、收藏常用、按领域浏览，形成自己的助手工作台。自定义助手的名字、提示词、输入源（选区或全文）、写回方式、温度全部可配，把重复劳动固化下来，一次配置长期复用；配置好的助手可导出文件分享给同事导入，团队口径统一。写回动作共九种：替换、插入光标处、批注、仅生成、追加等，每个助手有默认动作，设置里可改。这一节的知识在升级后同样适用：自定义助手本就讲究一次配置长期复用，目录怎么搜、写回怎么选，熟悉一遍之后每次升级都不必重新学起。

## 会话与数据口径

按文档隔离的会话不会串味，A 文档的上下文不会污染 B 文档；AI 先读懂你的文档再干活，而不是让你复述内容，不用写提示词，选对助手点一下就行。数据层面：加密载荷随文件走，收上来的表单先审计再入库，缺项错项一目了然，凭据走 AES-GCM 设备绑定加密。涉密口径两句话：其一，AI 干活时收到的材料是整篇文档，涉密稿件先换到本机离线模型；其二，优先支持离线内网模型是这套加载项的立场，涉密文档不出网也能用 AI。

升级链路到这里就走完了：取包、退出、重跑、验证，四步一个环。哪一步卡住，回「升级路上的三条边界」和「升级相关的能力速记」两节对照。
