# 拆开看宠物模型配置：原理、架构与实现细节

聊宠物模型配置之前先划重点：它不是单一功能，而是一套带入口、步骤和验证的完整流程。察元AI OS在这件事上的设计思路是把入口收拢、把步骤做实、把边界说清，理解了这个，操作就顺了。

## 先弄清楚它是什么

决定灵宠用哪个模型说话/干活：建宠或编辑宠时，「自动（本地已装对话模型）」或「指定模型」二选一——指定档弹出统一模型树（本地已装＋已配置厂商，厂商组带 logo 回显）单选；保存时若挂了智能体且选了指定模型，会把「模型代理地址＋模型名」同步写进该智能体配置（保存即注入）。灵宠对话窗的模型按钮可在会话内临时换模型（不写档案）。

不同宠配不同模型是群聊多模型讨论的前提，轻任务宠配小模型、主力宠配旗舰。

入口、步骤、验证三段看清，这事就顺了。

## 背后是怎么运作的

不同宠配不同模型是群聊多模型讨论的前提，轻任务宠配小模型、主力宠配旗舰。

从提问口径看，用户最关心的是建灵宠时模型选『自动』和『指定模型』有什么区别？

## 实操全过程

按最短路径验证一遍：

第 1 步 · 表单里的两档（建宠 / 编辑宠同一选择器）

建宠或右键灵宠「编辑灵宠」表单中，「模型」字段是两个按钮档：

1. 「自动（本地已装对话模型）」（默认）：下方说明行原文「经本地模型代理直答；本地与已配置厂商模型均可选，真实厂商 key 不出凭证库」。保存时不做模型注入。
2. 「指定模型」：点击弹出「选择模型」树形弹窗：
    1. 统一模型树三级结构：第一级组——「本地与自建 · local/」（本机图标）与每家已配置厂商（厂商 logo＋厂商名）；第二级分类（本地按对话/嵌入等分类、厂商按模型类型）；第三级模型叶子，等宽字体引用串（local/<id>、<厂商>/<模型>）；
    2. 组行带模型计数药丸；整行可点即选中（行内任意处），选中行蓝底高亮＋行首蓝点，所选分支自动展开并滚动到可见位置；再点一次取消选中；本地正在运行的模型行尾有绿色「运行中」标记；
    3. 弹窗左下实时回显所选短名（如 glm-4-flash），未选时显示「未选择模型（点列表项选择）」且「确定」置灰；「取消」放弃；
    4. 树为空时显示「暂无可用模型：可在模型设置中配置厂商模型或安装本地模型」。
    5. 确定后表单里回显蓝色等宽短名标签（悬停显示完整引用串）。

第 2 步 · 「自动」档运行时用哪个模型（按运行面区分）

1. 群聊发言 / 灵宠直跑链：取本机第一个已安装的本地对话模型；一个都没装时该宠发言会失败（需先按 M3 装一个）。
2. 灵宠对话窗：「自动」视为未选——依次回落全局默认对话模型，再没有则按智能路由 smart/auto 发送。
3. 绑定常驻任务：任务侧模型留「自动」时用全局默认对话模型。
4. 名册（底栏「灵宠」）里「自动」档的宠，模型列显示「自动模型」。

第 3 步 · 「指定模型」保存即注入（挂了智能体时）

点「创建」/「保存」后，若该宠挂了智能体且模型是统一树引用串，自动执行注入链：

三点注意：注入切换的是该智能体的默认模型，全局生效（Dock 里直接开它的会话同样换模型）；模型直跑宠不注入；五家之外的智能体（如 Gemini CLI、Qwen Code 等）暂不支持自动写入，报「模型注入智能体失败：<智能体> 的 CLI 配置写入暂不支持（未内置其配置格式）」，档案同样保留。编辑换模型再保存走同一条链（幂等，同值重写无副作用）。

1. 确认模型代理在运行（未运行则报「模型注入智能体失败：模型代理未运行，无法注入模型（可稍后在群聊里重试，或重启应用）」——灵宠档案仍然保存，不丢）；
2. 选的是厂商模型时自动补齐该厂商的代理路由（缺则按已存配置补建）；
3. 把「代理地址 http://127.0.0.1:52581 ＋ 模型引用串」写进所挂智能体的持久配置：五家写入面——DeepSeek Harness（llm-pi-ai provider 配置）、Claude Code（~/.claude/settings.json）、Codex（~/.codex/config.toml）、OpenCode（~/.config/opencode/opencode.json）、OpenClaw（openclaw.json ＋启动偏好），其中走配置文件写入的几家（Claude Code/Codex/OpenCode）写前自动留备份；真实厂商密钥不出本机凭证库，代理对本机调用免 key；
4. 结束该智能体的旧终端会话，下次开窗/对话以新配置拉起。

## 几个容易忽略的细节

用之前要认的账：

- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 你可能会问

### 「自动」到底会用哪个模型？

按运行面区分：群聊发言/灵宠直跑＝本机第一个已安装的本地对话模型；灵宠对话窗＝视为未选，回落全局默认对话模型，再无则智能路由 smart/auto；绑定的常驻任务＝全局默认对话模型。想行为确定就用「指定模型」。

### 灵宠对话窗里选的模型会保存到灵宠档案吗？

不会。对话窗的模型选择只作用于当前会话 Tab；要让灵宠固定用某模型，用「编辑灵宠」改档案模型并保存（保存即注入）。

### 建宠的模型树里怎么混着嵌入、重排这类模型？

建宠/编辑宠的树列出全部类型（本地按十一类分类、厂商按类型分组）；灵宠对话窗的树只列可对话模型。给灵宠选对话用途请选「对话」类模型——选了嵌入/重排类模型对话请求会失败。

### 注入会影响这只智能体的其他会话吗？

会。「保存即注入」的语义就是把该智能体的默认模型切到所选模型，对该智能体全局生效（不只是这只灵宠的会话）；这是与 设置 ＞ 默认模型 一致的写入面。

## 补充答疑

### 保存时弹「模型注入智能体失败」怎么办？

两种常见原因：模型代理未在运行——到 设置 ＞ 模型 查看服务健康灯，恢复后重新「编辑灵宠」保存一次（保存即注入，幂等）；或该宠挂的是五家之外的智能体（暂不支持自动写入）——档案已保留，可改用「自动」档或换挂五家之一。

### 给灵宠换模型后，已经开着的智能体窗口还在用旧模型？

注入会结束该智能体的旧终端会话，下次开窗/对话以新配置拉起；编辑前已打开的旧窗口重开一次即生效。
