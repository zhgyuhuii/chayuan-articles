# WPS引用资料为什么这样工作：写公文时引用内部文件表述

先说这篇能帮你干什么：读完能在察元AI OS里独立完成WPS引用资料，路径是写公文时引用内部文件表述。步骤里的每个「」按钮都是界面原文。

## 概念先对齐

WPS引用资料在察元AI OS里的形态一句话说清：察元AI文档助手（WPS 加载项）自动发现本机知识库对外服务（52582 端口，跨端口访问已放行），在 WPS 里检索引用知识库内容。

概念一分钟，操作十分钟，这篇都覆盖。

## 操作步骤详解

按最短路径验证一遍：

4. 发消息（自动检索 + 引用回答）

1. 照常发送问题。发送链路自动执行：对本机会话绑定的各库发起多查询检索（GET /search，逐库逐查询受限并发），合并去重、按名次折算信任度排序，把来源注入本次请求并要求回答以 [c1][c2] 标注引用；随后由所配模型作答。
2. 看到什么：回答正文带 [c1][c2] 引用标记；消息下方出现「知识来源」折叠条——标题行「知识来源 · N 条 · 〈所绑库名列表〉」（无命中时显示「知识库已检索 · 0 条」，出错时「知识库检索异常」＋「检索异常」标记）。展开后每条来源一张卡：[cN] 编号 + 五星信任度（悬停显示信任度值）+ 所属库名 + 类型 + 「文件名」下载链接（悬停「下载附件: 〈文件名〉」，点击取回原文文件）；卡片可再展开片段详情（命中片段文本、章节、命中查询词）；鼠标悬停消息里的 [cN] 时对应来源卡高亮。

6. 发现链与 CORS（理解用，无需操作）

1. 加载项按「手动指定 ＞ 上次发现缓存 ＞ 并行端口梯探测」找本机知识库服务：端口梯首候选即 52582（对外服务严格固定段，含历史顺延残留 52582+0..20 兜底），其后是 dsh 主实例 52584（/api/chatop-kb 前缀）、会话段 52601..52610、旧段 3080..3085；每个候选先取 /status 做指纹校验（ok:true 且带 kbs 数组才算命中），并行竞速先命中先用。新装机第一个候选 52582 必中。
2. 加载项页面与 52582 不同源，浏览器会拦跨端口 fetch——察元OS 的知识库服务对所有响应放开 access-control-allow-origin: *（并带 Allow-Private-Network 兼容预检、OPTIONS 预检直接放行），WPS 内的跨端口检索因此畅通。

## 边界先摆桌面上

边界先摆在桌面上：

- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 云端厂商模型调用需自备 API Key

## 你可能会问

### 选择器里出现「未检测到本机「察元桌面版」」的引导卡？

说明加载项没发现本机察元OS 知识库服务：察元OS 未启动、未安装，或 52582 服务异常（端口被占时服务拒绝启动，排查见教程对应教程）。启动/修复后在 知识库设置 里点扫描按钮重试。装上察元桌面版后即可在 WPS 内直连本地知识库，全程本机运行、数据不出域。

### WPS 里的网页调 127.0.0.1:52582 会被跨域拦截吗？

不会。知识库服务对全部响应放开 CORS（*）并正确处理 OPTIONS 预检，这正是为 WPS 加载项这类浏览器形态消费方设计的。若仍异常，多为察元OS 服务未启动而非跨域。

### 察元OS 里新建了库 / 换了端口，WPS 侧要重配吗？

不用。库列表运行时实时从 /kbs 拉取；服务地址由发现链自动跟随（「本机 Harness 地址已更新」提示即地址迁移）。手动填过地址的连接（若你创建过）不受自动发现影响，可删掉让自动连接接管。

### [c1] 和来源条怎么对应？会不会错位？

一一对应：回答里的 [cN] 引用的就是来源条第 N 张卡，悬停 [cN] 时对应卡高亮；星级是检索信任度评分（并非内容正确性保证），核对内容请展开片段详情。

## 更多操作细节

1. 打开 AI 助手窗格

1. 打开 WPS 文字（表格/演示同款助手），顶部功能区切到「察元AI助理」选项卡，点「AI助手」按钮——右侧展开任务窗格。

## 更多操作细节

2. 连接本机知识库（通常零操作，确认即可）

1. 窗格右上角进「设置」＞ 主菜单「常规设置」＞ 子项「知识库设置」；
2. 面板打开时会静默自动扫描本机察元OS：发现后 toast 提示「已自动接入本机察元 Harness 知识库(127.0.0.1:52582,发现 N 个)」，左侧「知识库连接」列表出现「察元 Harness 本机知识库」（来源标「Harness 本机」）；
3. 也可手动触发：连接列表标题行的扫描按钮（悬停提示「自动发现本机察元 Harness 知识库」，扫描中显示「正在扫描本机服务…」）——地址变了提示「本机 Harness 地址已更新(…,N 个知识库)」；
4. 没发现时：手动点扫描按钮会明确报「未发现本机察元 Harness 知识库服务(默认端口 52582),请确认 chatop 已启动」——先启动察元OS 再回来扫。

## 更多操作细节

3. 给会话绑定知识库

1. 回到对话输入框，点工具条上的书本按钮（悬停提示「选择知识库」，已绑定时显示「已绑定 N 个知识库 · 点击编辑」）；
2. 看到什么：「选择知识库」弹窗——左侧「察元 Harness(本机)」分组平铺本机全部库（名称取库名），可按名搜索；点库勾选/取消，底部显示「已选 N 个知识库」，确定保存；
3. 绑定是会话级的：不同会话可以绑不同的库组合。

## 更多操作细节

5. 空态与异常

1. 检索正常但没命中：来源条显示「已检索所选知识库，但没有命中可引用内容。」（标题为「知识库已检索 · 0 条」）——AI 的回答没有库内依据，别当引用看；
2. 检索失败：来源条标题旁出现「检索异常」，展开显示具体错误（如「检索失败：…」）；
3. 察元OS 关停后再发消息：连接健康快照记录「本机 Harness 服务未发现(请确认 chatop 已启动)」，恢复运行后无需重配——地址随发现自动更新，库列表每次实时拉取（察元OS 里新建/删除库，WPS 侧下次打开选择器即同步）。
