# 察元竞技场配置要求：什么电脑能跑

一听「大模型」三个字，不少人的反应是要一张显卡起步的机器才配谈。察元竞技场配置要求其实没那么吓人：它是个 Electron 桌面应用，本体轻量，真正决定你这台电脑累不累的，是你选的模型跑在云端还是本地。一句话预告结论：只连云端，老电脑照玩；跑本地推理，内存和算力说了算。这篇把配置这件事按云端、本地、挂机三条路线拆开讲，内存、显卡、磁盘逐项过一遍，最后给你一套务实的判断顺序。

### 察元竞技场配置要求高吗？什么电脑能跑

不高，普通家用电脑就能跑。它是 Electron 桌面应用，界面是暗色竞技场风格，中英双语，支持 Windows、macOS、Linux 三大桌面平台，安装包按芯片架构细分，主流系统版本都能装，不存在只服务新机器的问题；安装后的产品名叫察元AI游戏，别在启动台里找错了名字。软件本体的活儿不重：11 款玩法的裁判是纯逻辑引擎，不吃外部输入、不做网络请求，胜负判定全在本地代码里完成，这点开销对现代电脑来说微不足道；界面渲染、棋盘绘制、思维链气泡、形势曲线、积分榜，都是界面层的常规活儿，吃的是普通桌面工具那份资源。真正的大头从来不在软件，在模型；把软件本体和模型负载分开看，是这篇的关键判断方法。

### 只连云端模型，老电脑够用吗

够用，这是门槛低的玩法路线。云端推理发生在厂商的服务器上，你的电脑只负责发请求、收结果、画界面，和开一个聊天的网页没本质区别；阵容里选几个模型、开什么玩法，本机负载几乎不变，重活在厂商那边。哪怕是几年的老笔记本，只要能正常跑浏览器，跑它就没压力，对局记录和天梯积分也落在本机小文件里，几百局也占不了多少地方。你需要的不是好电脑，而是各家的 API Key：进设置 ＞ 模型配置，从 85 家厂商目录里点选厂商，填 Key，点「测试连接」确认通了就能开局；选哪家对电脑没有影响，只对你的账单有影响。

### 跑 Ollama 本地推理，机器要什么条件

条件全在模型这边，不在竞技场这边。本地推理意味着模型整个搬进你的机器：内存要装得下模型，算力要转得动推理。装多大的模型，看 Ollama 页面上标注的体积，内存按这个体量往上留，留些余量为好。部署 Ollama 本身是常规操作，官网下载装好，把服务跑起来，竞技场这边配上地址就能接上，全程免 Key，连注册账号的功夫都省了。头一次玩本地推理，建议先用一两个小模型把流程跑通，机器不行别硬上大模型，从小模型玩起一样能看出门道。云端和本地也可以混搭着用，阵容里既有云端强模型也有本地小模型，配置互不干扰。

### 内存要留多少才稳妥

给个务实的判断方法。只连云端模型的话，你日常办公需要多少内存它就要不了更多，竞技场本体占不了多少地方；跑本地推理的话，内存按你选的模型体量往上加，模型文件多大、运行时的占用就往那个量级走，再给系统和界面留出余量。机机观战想同时开几个本地模型同台，占用是叠加的，按几家的体量一起算，这是本地玩法很实在的一条门槛，也是不少人低估的一项。内存吃紧的表现也直观：模型出手等待变长，系统跟着卡顿，观战体验打折；与其硬撑，不如退一档模型，观感损失换流畅，值不值你自己定。

### 独立显卡是必需品吗

不是必需品，但有了更顺。多数本地推理引擎没有独显也能跑，只是推理速度慢，模型出手等得久，长对局里这个等待会累加；有独立显卡的机器跑推理明显流畅，观看体验跟着上去，同一个模型，有显卡加持和纯 CPU 硬扛，每手的等待时间可能差出好几倍。竞技场本身对显卡没有额外要求，界面渲染是普通桌面应用的量级。所以别为了玩它专门去买卡，先想清楚自己玩不玩本地推理，再决定硬件投入，顺序别反。

### 笔记本能长时间挂机跑锦标赛吗

能，但有几件事要盯着。一是散热，锦标赛是自动排程的循环赛，跑一晚上机器一直在干活，笔记本注意别捂在被子沙发上；二是电源，挂机前把电源接好，顺便把系统睡眠关掉，赛事排程断在半夜就可惜了；三是额度，循环赛里若有云端模型，烧的是你的 API 余额，跑之前想好预算，本地模型则没账单压力，代价是电费和机器持续占用。锦标赛支持批量选模型，循环赛的轮次跟着阵容规模走，小机器办小比赛完全可行，跑完早上起来看积分榜战报，这也是竞技场玩家的经典玩法；本地阵容的挂机还要确认磁盘有余量，循环赛的记录会一点点累积。

### 磁盘空间要预留多少

分两块算。软件本体是个普通桌面应用的体量，安装包不大，装完不占多少地方；真正吃磁盘的是本地模型文件，玩几家就存几个，体积以 Ollama 页面标注的为准，动辄 GB 量级。只连云端模型的话，磁盘压力可以忽略，顶多留出对局记录和棋谱导出的空间，JSON 文件轻得很，想把棋谱带去别处分析，导出的文件本身也占不了多少空间。

配置这件事的答案其实是一句话：软件很轻，模型很重。选云端，老电脑照玩；选本地，内存和算力说了算，显卡锦上添花。与其纠结机器够不够格，不如先用云端模型跑两局试试水，等确定要深入本地推理了，再按模型体量去补硬件。先用轻的路线验证兴趣，再为重的路线补硬件，这个顺序能帮你把钱和折腾都省下来。机器是死的，路线是活的，配置要求说到底是路线选择的结果；空间紧张就定期清掉不再用的模型文件，随用随拉。
