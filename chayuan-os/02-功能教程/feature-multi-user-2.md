# 账号管理的设计取舍：用户增停删管

先说这篇能帮你干什么：读完能在察元AI OS里独立完成账号管理，路径是家庭共用一台电脑。步骤里的每个「」按钮都是界面原文。

## 概念先对齐

账号管理是察元AI OS（aidooo.com）里的一个能力模块：AI 桌面操作系统，本地大模型、知识库、智能体、宠物群聊装进一个桌面，多用户账号管理是其中面向这类需求的一环。

下面直接进正题。

## 完整操作步骤

按最短路径验证一遍：

第 4 步 · 停用 / 启用

1. 普通用户行点「停用」（管理员行没有此按钮，管理员不可被停用）。该行立即出现红色「已停用」标记与「启用」按钮。
2. 停用效果：登录门/锁屏不再显示该用户的卡片，其密码登录一律返回「该账号已停用」；数据原样保留，随时点「启用」恢复。

第 8 步 · 查看管理员操作审计

「管理员操作审计」卡按「时间 · 操作者 · 动作 ＞ 目标」逐行显示（最新在最上，保留最近 200 条），动作包括 create-user、disable-user、enable-user、reset-password、delete-user、kill-session、set-auto-login、shared-credential、recovery-key、erase-root 等。无记录时显示「暂无记录」。

## 这些坑和边界要知道

用之前要认的账：

- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 高频疑问

### 删除用户后反悔了，数据还能找回吗？

不能。确认框里「不可恢复」是实义：该用户的 profile、home、找回画像被整目录删除，无回收站。建议删除前先「停用」观察；确要保留备份，先把整个 chatop-data 目录拷贝一份。

### 管理员能被停用或删除吗？能增加第二个管理员吗？

都不能。主进程对管理员角色有硬保护（停用/删除直接拒绝），界面也不提供这两个按钮；新建用户一律是普通用户角色，目前没有提权/移交管理员的入口。

### 普通用户自己能改密码吗？

能，不用找管理员：设置 ＞ 用户 ＞ 「我的账号」卡，输当前密码+新密码点「修改密码」。管理员重置是给「用户自己也进不去」时用的兜底。

### 重置密码后，那个用户手机/浏览器上开着的远程桌面会怎样？

会立即失效：改密会话版本号 +1，其所有已签发的远程会话（wa_sess）全部作废，需用新密码重新登录。

## 更多操作细节

第 1 步 · 打开用户管理面

Dock ＞ 「设置」＞ 左栏「用户」分区。顶部第一张卡「我的账号」；管理员继续往下是「开机登录」「用户列表」「全员共享模型 Key」「全员安装插件」「管理员操作审计」。

## 更多操作细节

第 2 步 · 添加用户（用户列表卡）

1. 「用户列表」卡底部点「添加用户…」，弹出「添加用户」窗口。
2. 逐项填写：
    1. 头像：默认按用户名确定性预选一枚内置头像（20 枚 AI 人物形象，同名恒同图）；可点「上传头像」传本地图片（上限约 2MB），或在预设网格里改选/点已选中的取消（回退首字母圆）。卡内说明「不传则显示首字母；锁屏与登录门将显示该头像」。
    2. 「用户名（登录用）」（≤32 字符）：登录门/锁屏选人用的名字。
    3. 昵称输入框（占位符显示「昵称（锁屏显示，可选）」，实际提交时必填——留空点创建会报「昵称为必填（跨终端互联时其他终端将以此称呼你）」）。
    4. 「密码（至少 3 位）」与「再输一次密码」。
    5. 点「创建用户」。成功后弹窗关闭，页面出现「用户已创建」，用户列表新增一行。
    6. 失败分支：用户名重复 ＞ 「用户名已存在」；密码不足 3 位 ＞ 「密码（至少 3 位）」；头像超限 ＞ 「头像过大（上限约 2MB）」。
    7. 建好的用户名+密码就是该用户的同一套凭据：锁屏解锁、开机登录门、远程访问（外网 /a/ 访问链接）三处通用，创建/重置即时生效。

## 更多操作细节

第 3 步 · 为用户重置密码

1. 在用户列表找到目标行，点「重置密码」（每一行都有，含管理员自己）。
2. 弹窗标题「为「{用户名}」设置新密码」，在「新密码（至少 3 位）」框输入，点「重置密码」。
3. 成功提示「密码已更新」，新密码即时生效：该用户随即用新密码在锁屏/登录门/远程访问登录；其已登录的网页远程会话全部作废，需重新登录。
4. 注意：管理员重置不会清除该用户「智能体面试」找回通道的失败计数——若其面试通道正在冷却/锁死，重置密码后依旧要等冷却结束。

## 更多操作细节

第 5 步 · 踢下线

在线用户（行内有绿色「在线」标记且不是你自己）行内点「踢下线」＞ 提示「已结束该用户会话」。效果：该用户的桌面全部窗口被关闭、后台会话结束；账号、密码、数据都不动，其重新登录即可恢复使用。

## 更多操作细节

第 6 步 · 删除用户（不可恢复的危险操作）

「用户列表」卡自身的说明就写明：「删除用户会抹掉其全部数据（桌面布局、聊天记录、文档）且不可恢复。所有管理操作写入审计。」

1. 普通用户行点红色「删除」按钮，弹出系统确认框，原文：「删除用户「{用户名}」会抹掉其全部数据且不可恢复，确定删除？」——在确认框里点确认后才执行。
2. 确认后系统依次做这些事（以主进程代码为准）：
    1. 从账号注册表移除该用户；
    2. 若其在线，先拆除其正在运行的会话（全部窗口关闭）；
    3. 整个删除其用户数据目录 users/<用户id>/profile/（该用户的 dsh-home、os-data、var——桌面布局、聊天记录、文档、知识库等全部用户数据）与 users/<用户id>/home/（其终端/智能体 CLI 使用的假 $HOME）；
    4. 删除其找回画像文件（recovery/<用户id>.json，验证画像随账户一起消失）；
    5. 向管理员审计日志写入一条 delete-user 记录。
    6. 没有回收站、无法恢复。拿不准就先「停用」观察一段时间再删。管理员角色本身不可删除（主进程拒绝且界面无此按钮）。

如果只记一件事：用户增停删管。剩下的细节，照步骤节走就行。
