# 模型质量抽检：厂商与中转商的对局抽检方案

工厂管质量靠抽检：从批次里抽样、按规程测、拿指标说话。模型服务同样需要抽样手段——接口返回内容对不对、协议稳不稳、延迟有没有漂移，光靠几个固定 prompt 样例测不出毛刺。模型质量抽检可以借对局来做：察元竞技场把「调一次模型」变成「让模型连续几十手完成一局博弈」，每手的格式遵守情况、耗时、失败与重试全部留痕。连续输出比单次问答更接近真实业务负载，也更容易暴露问题。这篇给模型厂商与中转商一套可执行的抽检方案。

## 为什么用对局做抽检

一次调用测的是「能不能回」，一局对局测的是「能不能连续几十手稳定回对」。对局里每一手都要过解析容错链：按协议解析失败后逐级放宽——剥思维链块、剥代码围栏、抽取大括号、正则抽取，只认合法动作清单；解析不出来走启发式代走，代走超限判负；429 限流自动退避、重试回喂。这套机制本身就是现成的质量探针：一个端点的格式稳定性、耗时分布、限流频次，在几十手连招里藏不住。和传统拨测相比，对局抽检多了一层「任务压力」：模型要在长上下文里保持格式、按时出招、接受判罚，这些条件正是很多线上业务的真实形态。

## 抽检流程：五步走

定样本：列出玩法组合、模型、局数。建议完全信息玩法（五子棋、9 路围棋）与不完全信息玩法（斗地主、德州扑克）各至少一款，两类负载分开看。

定环境：同一台机器、同一版察元竞技场（0.1.0）、同一参数、同一时段。机型与系统版本也记进去，不同终端上的表现差异不该在事后才发现原因。环境要素写进抽检记录，报告才可复核。

跑批：锦标赛支持多模型循环赛自动排程，积分榜实时刷新；组合多的批次也可以用机机观战批量选模型逐组跑。

取数：协议画像里的 JSON 格式遵守率与平均出招耗时，对局室里的每手延迟与 token 用量，代走与 429 退避的出现情况，棋谱 JSON 全量留档。

复核：用回放器按协议字段筛选关键手，对异常局人工过一遍，别让指标单方面下结论。异常的判定标准赛前定好：什么算格式异常、什么算超时异常，写进规程，复核才有尺子。

## 样本设计：三条原则

多局降偶然。单局胜负受随机性影响大，抽检看的不是谁赢谁输，是过程指标的分布与稳定性，局数要撑得起分布。

分组对照。同一模型走官方端点与中转端点各跑一批（两端点都要求 OpenAI 兼容，中转端点手填 baseUrl 接入），画像摆在一起，差异自己会说话。

固定批次。避开业务高峰，同一批次同一时段跑完，减少上游漂移的干扰；跨批次对比才看趋势，跨批次混跑会引入说不清的变量。

玩法矩阵不用贪大：两款玩法、每款多局，比八款玩法每款一局有用得多，后者把方差和玩法差异搅在一起，数据好看但读不出东西。

## 画像指标怎么读

JSON 格式遵守率下滑，常见原因是端点侧动了输出模板或发生截断，先查服务端再怀疑模型。平均出招耗时漂移，对比历史批次看趋势，突增要查链路。代走频次上升，说明解析失败变多，模型输出质量或端点稳定性在变差。429 退避频次是限流配额的直观信号，配额调整前后各跑一批即可对比。

读指标还有个顺序建议：先看遵守率（格式层），再看耗时（链路层），最后看代走与退避（行为层），一层排除了再看下一层，定位快得多。

要强调的是：画像变化是信号，不是结论。任何对外表述都要回到原始棋谱复核之后才能下，这是抽检和打榜的区别。顺带一提，代走记录本身也是样本：把触发代走的那几手原文存下来，就是格式问题的直接证据。

## 抽检角色与频率

厂商视角：把抽检嵌进发版流程，模型或部署变更后跑一轮基准批次，指标对齐上一版再放量；日常按周小批量跑，盯趋势。采购方视角：验收时跑独立批次，环境与厂商提供的不一致反而有价值——两家环境的数据互为参照。角色别混：自检的规程与验收的规程分开写，用同一份规程既检自己也检供应商，动机容易拧。频率不用激进，批次可比比批次多更重要。

## 边界与合规

抽检反映的是抽样窗口内的表现，不能外推成整体质量承诺，报告里写明窗口与条件。批次结果出来后先自查一遍环境记录，确认没有变动再解读指标。费用上软件 MIT 免费，模型调用的费用由抽检方向厂商支付，对照组批次同样要花钱，预算按双份估。中转对比只对自己有权测试的端点做，别拿别人的服务做无授权压测。版本 0.1.0 的统计口径以软件内实际展示为准，升级版本后历史数据要重新对齐口径。

## 常见疑问

### 抽检多少局才有参考价值
没有统一数字，原则是每组合多局、分批次、看分布。局数越多指标越稳，在预算允许的范围内尽量多跑，并如实报告样本量。

### 能发现中转商有没有换模型吗
画像突变（遵守率、耗时、风格）是有价值的信号，但不是定性证据；结论要回到输出内容与棋谱复核，必要时多批次验证。

### 抽检报告能直接对外发吗
内部决策可以，对外发布建议只针对自己的端点或已获授权的对照端点，写明环境与窗口期，避免误导。

### 需要写脚本配合吗
基础抽检不用写代码，配置与跑批都是界面操作；要做大规模对比或接自己的数据管道，再基于导出的棋谱 JSON 自行开发。

### 抽检环境要几台机器
一台就够起步。机器多了反而引入机型差异，先把单机批次跑稳，需要并行时再保证同规格。报告存档时连棋谱一起存，一年后回看才有对照基准。

质量这件事，声嘶力竭的承诺不如一条能复核的曲线。对局抽检的价值在于把「服务稳不稳」变成一组可复盘的过程数据：遵守率、耗时、退避频次，每个数字背后都有棋谱可查。对厂商，它是内部质量的日常体温计；对采购方，它是验收时的第三方视角。工具是开源的，规程是自己的，抽检的公信力来自环境透明与样本诚实——这几件事做好，报告才立得住。
