# 思维链提示词怎么写：从模型出招里偷师

写提示词的人大概都有过这种时刻：对着空白输入框憋了半小时，「请一步步思考」写了，「仔细分析」也写了，模型的输出还是一团浆糊。思维链提示词怎么写，教程看了一箩筐，落到自己业务上总差口气。其实有个冷门但好用的办法：去看一个被逼着认真思考的模型长什么样。察元竞技场的对局室恰好就是这样一个现场——模型每出一招，完整的推演过程实时摊开给你看，那里面藏着现成的范本。

## 这件事原来的难处

提示词工程这门手艺，难就难在你看不到参照物。

网上的教程给你的是结论：「先分析后作答」「让模型列出选项」「要求结构化输出」。道理都懂，但好的思维链长什么样、差在哪，教程截几张图就完了，你没法看着一个强模型当场把一条推理链从头走到尾。

自己业务里更麻烦。你写的提示词只有你一个用户，输出好坏全凭感觉，没有对照组，改了一版也不知道是变好了还是换了种方式变糊。

而且思维链的质量和任务强相关。让模型解数学题的示范，搬到决策类任务上经常水土不服——你缺的是一个「必须做决策、必须给出理由、还要为结果负责」的场景，这种场景里模型的思维链才有含金量。

还有个更隐蔽的问题：你很少有机会围观「别人家的提示词」。高手的写法锁在各自团队内部，教程里的示例又经过美化，你缺的是一个能公开观看、还能验证效果的活样本。

## 从对局室里看范本

对局就是这样的场景。棋盘上没有含糊的空间，模型每手都要给出明确着法，而且系统会按 {move, comment} 协议要求它把想法说出来。你开机机观战，选中国象棋或围棋这类完全信息玩法，再在对局配置里选上深度规则模式，就能看到被严格约束过的思维链长什么样。

那个结构是三段式的。分析段：模型要推演三条候选着法线，每条给出自己走什么、对方可能怎么应、局面会变成什么样，其中至少一条吃子线、一条防守线，还要控制篇幅不许写成论文。结论段：把分析收敛成一句话，说清为什么选这条线。答案段：按协议落成规范的 JSON，着法与点评各就各位。

三段环环相扣，而这套东西在思维链气泡里实时流式滚动，你等于站在模型肩膀上看它想棋。看上几局，你会对「一段合格的推理链」产生手感：哪里该铺开、哪里该收敛、哪里必须落到结构化输出上。

## 把结构迁移到你的提示词

看完范本，回到自己的业务提示词，迁移四个要点。

给输出分区。别让模型一股脑写完，明确切成「分析、结论、答案」三块，每块干什么写清楚，就像对局里着法和点评必须分开一样。

限制每段长度。对局里分析段被约束在百来字，逼模型挑重点说。你的提示词也该给每段设上限，篇幅一放开，推理就开始灌水。

强制列候选。要求模型摆出两三个可选方案并互相对比，再选一个。对局里强制一条进攻线配一条防守线，就是在逼模型两面想，你的业务同理。

答案落到结构上。末段必须是可解析的格式，字段名写死。这样下游程序才接得住，你也才好验收。

拿个具体的映射说：你要模型输出技术方案评审意见，就照着对局的三段来写——分析段让它摆两三个候选方案、各自优劣与风险；结论段一句话说明推荐哪个；答案段落成带固定字段的结构化输出。棋牌桌上那副骨架，放进业务提示词一样立得住。

## 回桌验证改了有没有用

改完的提示词好不好，别靠感觉，回对局桌上验。你可以把随手写的指令和重构后的结构分别让模型打同一种玩法，对照两组思维链气泡的条理与对局结果，差异通常肉眼可见。多打几局再下结论，样本太少会骗人。顺带还能看每手的延迟与 token 用量，结构化提示词对推理成本的影响，这里也给了参考。验证时只换提示词这一个变量，模型与玩法都固定住，不然你分不清是结构的功劳还是别的因素在起作用。

这个循环还能反向跑：把你在业务里验证过的分区结构，拿回对局配置里试试，看同样的约束在棋盘上灵不灵。两头互相喂招，手感攒得越来越快。

## 适合谁、不适合谁

适合天天跟提示词打交道的开发者、做智能体编排的工程师、给业务写系统提示词的产品经理，也适合想搞明白「模型到底怎么想」的好奇党。不适合指望抄一个万能模板回去直接用的人——棋牌域的骨架是示范，搬到你的业务域必须自己再调再验；也不适合完全不做决策类任务的场景，纯文本润色这类活，思维链收益有限。

## 常见疑问

### 深度规则模式在哪里打开

在开局的配置里选，竞技场按档位约束模型的出招格式。选上之后模型出招就按三段结构来，思维链气泡里能完整看到。具体入口以应用内当前版本为准。

### 为什么模型有时不按格式输出

模型不是每次都听话。输出跑偏时，竞技场有解析容错链兜底：剥思维链、抽大括号、扫合法着法，实在不行还有代走机制救场。你写提示词时也要有这个心理预期，格式约束加解析校验要成对出现。

### 用哪个玩法看思维链最直观

象棋、围棋这类完全信息玩法最直观，推理链清晰可验证。德州扑克也有看头，你能看到模型在诈唬与求稳之间反复掂量，那是另一类决策风格。

### 这样偷师要花多少钱

软件 MIT 开源免费，看模型对局消耗的是你自己的 API 额度，几局下来花费不大但要心里有数；接 Ollama 本地模型就零成本，代价是小模型的思维链质量参差。想省钱有个顺序技巧：先在本地小模型上把三段结构看熟，再去云端强模型的对局里做对照，额度花在刀刃上。

提示词这门手艺，抄教程不如看现场。对局室里每个模型都是一位被迫交出思考过程的老师，它们怎么切分段落、怎么逼自己收敛，全摊在气泡里。看完再回来改你的提示词，改完再上桌验证，这个循环跑几圈，手感就有了。
