# 灵宠编辑的底层逻辑：它为什么这样工作

聊灵宠编辑之前先划重点：它不是单一功能，而是一套带入口、步骤和验证的完整流程。察元AI OS在这件事上的设计思路是把入口收拢、把步骤做实、把边界说清，理解了这个，操作就顺了。

## 先弄清楚它是什么

灵宠档案的三个维护动作：编辑——右键「编辑灵宠」（或名册铅笔）改名字/智能体/模型/知识库/分区/任务/形象/人设，保存同样走「保存即注入」；删除——右键「删除灵宠」两步确认，先掐在途回复、再清群成员与桌面位姿；收编——给没建档的「野宠」一键转正成正式灵宠。

## 机制拆解

误删有确认兜底，野宠收编让路上捡的宠也能入册管理。

能力面拆开看：野宠收编建档；两步确认防误删；编辑面板改模型、知识库、人设。

从提问口径看，用户最关心的是怎么修改灵宠的名字和模型？

## 完整操作步骤

按最短路径验证一遍：

一、编辑灵宠

1. 入口（三选一）：
    1. 右键桌面灵宠 ＞ 「编辑灵宠」；
    2. 名册（底栏「灵宠」）列表行点铅笔按钮；
    3. （群管理弹窗里改的是群，不是灵宠。）
    4. 弹出「编辑灵宠」弹窗——与建宠是同一张表单，全部字段按当前档案预填：名字、智能体（含「模型直跑（不经过智能体）」）、模型（「自动（本地已装对话模型）」或原指定串）、知识库、分区（工作区）、绑定常驻任务、「钉住常驻桌面（不受在场规则约束）」勾选框（沿档案当前值）、形象（原形象保持选中，即使它已不在注册表——保存不会偷偷改宠物样子）、人设。各字段含义与默认值见对应教程 第 2 步。
2. 改完点「保存」（提交中显示「…」；名字空/模型未选时置灰），「取消」放弃。保存行为：
    1. 仅元数据更新，灵宠身份（档案 id、创建时间）不变；
    2. 挂智能体且模型是「指定模型」时同样保存即注入（幂等写该智能体配置；「自动」档跳过）；注入失败弹「模型注入智能体失败：<原因>」，其余改动已生效不回滚；
    3. 名字截 20 字、人设截 60 字、分区路径截 300 字；
    4. 改动即时生效：桌面右键菜单、名册列表、群成员显示在新档案写入后同步刷新；形象区与建宠同款（含「自定义」上传与「···」直达商店形象页签，商店获取新形象后编辑弹窗卡组自动刷新）。

二、删除灵宠（两步确认）

删除时系统自动做四件事：掐掉它在群聊里的在途回复（防删后仍冒出「幽灵回复」）；把它从所有群的成员列表移除；清掉它的桌面位姿记录；档案写盘。群里的历史消息记录保留，不会整群清空。删除后该灵宠即时从桌面与名册消失（带退场动画）。

1. 右键桌面灵宠 ＞ 点「删除灵宠」：该行变为红底「确认删除？再点一次」；
2. 3 秒内再点一次才真删（超时或点开其他菜单/关闭菜单则解除待确认态，回到安全状态）。

三、收编野宠

不收编也无妨：野宠随该智能体终端窗的开闭出现/消失，关窗即走。

1. 认识野宠：直接打开某智能体的终端窗干活（没给它建过灵宠档案）时，桌面会出现该智能体的临时化身——茶茶形象 + 智能体徽标，右键菜单头部显示智能体名与「开工 <时间> · <目录>」。
2. 右键这只野宠 ＞ 「收编建档」。
3. 立即生成一份正式灵宠档案并上桌（默认钉住）：名字=智能体名（如 Claude Code）、挂该智能体、模型「自动」、形象茶茶、人设空。桌面上那只临时化身随之由档案接管——该智能体正在跑的终端会话状态（干活/待命/休眠）并入这只正式灵宠显示，不会出现「一智能体两只宠」。
4. 收编后按需「编辑灵宠」改名字、换形象、绑知识库/常驻任务——此时它就是一只普通正式灵宠（智能体终端窗关掉也不会消失，因为已有档案且钉住）。

## 这些坑和边界要知道

功能归功能，这几个边界先摆清楚：

- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 高频疑问

### 怎么删除一个群 / 改群名？

群实体右键 ＞「编辑群聊」打开群管理弹窗：改名、增删成员、协同方式、解散（解散是两步确认「确认解散？再点一次（分区目录保留）」）。详见群聊域教程。

### 编辑时把「钉住常驻桌面」去勾选了，灵宠怎么还在桌上？

取消固定对「闲置中」的灵宠即时离场；若它绑定的任务正在执行、或它的工作台窗还开着，要等任务结束/窗口关闭后才离场。也可直接关掉对应工作台窗。

### 野宠右键也有「删除灵宠」，删的是什么？

野宠没有档案；对野宠而言该按钮不会删除任何档案数据。想让它消失直接关掉对应智能体的终端窗，或用「收编建档」转正后再按正式流程删除。

### 编辑改模型后，已经开着的智能体窗口用新模型吗？

保存即注入会结束该智能体的旧终端会话，下次开窗/对话以新配置拉起；编辑前已开着的旧窗口需要重开才生效。

## 补充答疑

### 删除要点两次，第二次没反应？

第二次点击必须在第一次点后的 3 秒内完成，超时会自动解除确认态（变回「删除灵宠」）。重新右键再走一次两步即可。

### 误删了灵宠能恢复吗？

不能。删除直接清档案并写盘，没有回收站。被删灵宠在群里的历史消息保留，可用「编辑群聊 ＞ 添加成员」把别的（或新建的）灵宠补进群。

## 安装与运行答疑

### 模型加载失败或提示内存不足？

系统有内存预算硬底线（总内存的 45%）保护：先卸载不用的模型再加载新的；8GB 设备建议一次只加载一个对话模型加一个嵌入模型。

### AppImage 双击没反应怎么办？

多为缺 FUSE 2：安装 libfuse2（Ubuntu 24.04 为 libfuse2t64），或用 --appimage-extract-and-run 解压运行；统信 UOS 环境推荐直接用 deb 包。
