# 察元竞技场API Key安全吗：存储与传输机制

要把 DeepSeek、Claude、Gemini 这些模型的 Key 填进一个桌面应用，多数人心里都会打一下鼓：会不会被偷偷传走？察元竞技场API Key安全吗，这个问题值得用机制来回答，而不是用一句「放心」来打发。这篇把 Key 的存储位置、传输通道、鉴权设计挨个讲清，也把明文存储这个如实存在的边界摆到台面上，机制讲完后还有一份务实清单等你拿走，看完你自然知道该放心到什么程度、自己还要补哪些动作。

### 察元竞技场API Key安全吗？会不会被偷偷上传

不会被上传，这是口径里写得死的一条。Key 只存在你本机的应用数据目录里，竞技场没有任何把凭据外发的通道；请求只在你发起对局、观战或测试连接时产生，软件静默运行时不发这些，从装应用到打完一整局，Key 只出现在你本机的文件和发往厂商的请求头里。另外它没有账号体系，不存在绑定手机号之类的环节，Key 是凭据的全部，管好它就管好了一切。担心被传走的顾虑可以放下，真正需要留意的是本机文件层面的安全，这个后面单独展开；一个没有账号体系的应用，想上传也无门可走。

### Key 到底存在哪里，是明文还是加密

明文，存放在本机 userData 目录的 arena/config.json 里。产品的口径没有回避这一点：当前版本 Key 以明文落盘，加密升级位已经预留，后续版本可以升级。配置文件带写锁，运行时热读取，改配置不用重启对局；写锁加热读的组合，也保证对局进行中改配置不会把正在写的记录撕裂。先记住位置，想核对、备份或者删除你的 Key，文件就在那里；想备份的话注意它带着全部凭据，备份文件放哪里同样要想清楚。至于明文意味着什么、风险由谁兜底，下一节直接说透。

### 对局时的模型请求走哪条通道

走本机网关这一个大口子。竞技场里所有模型流量都经过一个跑在你电脑上的网关，不直连各家厂商，对局中的每一手、观战里的每个模型，请求都从这一个口子出去，想审计流量只需要盯一个地方；网关监听 127.0.0.1 上的随机端口，每次会话带路径令牌鉴权。Anthropic 的原生协议也由这台网关自动转换，各家协议差异在网关层消化，Claude 不用改任何代码就能上桌，你也不用为兼容性单独折腾。通道收窄成一个受控入口，比每个功能各自连外网好查得多，出了问题也容易定位。

### 随机端口加路径令牌，这套鉴权防的是谁

防的是本机里其他进程和局域网里的旁观者。随机端口每次启动都可能不同，按固定端口去猜的思路在它面前基本失效；路径令牌则让不带凭证的请求直接被拒，本机上没经你允许的进程很难冒用你的会话去调模型。如果你在局域网环境里用，这套设计尤其有意义，同网段的设备够不到你的会话。这套设计的目的朴素：你的 Key 兑换来的模型调用额度，只能被你亲手发起的对局用掉，别人想蹭，先过令牌这一关。

### 「测试连接」和「获取模型」会把 Key 发去哪里

发给你所填厂商自己的接口，仅此而已。「测试连接」走 GET 请求校验 Key 是否有效，失败时静默回退到手填模型列表，不堵配置这一步；「获取模型」更较真，用你当前还没保存的输入实拉一次该账号可用的模型全列表，返回裸模型 id 供你勾选入库，严格实拉不回退，你可以拿这个列表和厂商后台里的模型目录核对一遍。两个动作都是你在设置页主动触发的，不存在后台悄悄校验这回事；通讯对象都是厂商端点，中间没有别的经手人，你填哪家就发哪家。

### 明文存储有什么风险，我能做点什么

风险要说透：明文文件意味着任何能读你 userData 目录的进程或人都能看到 Key。竞技场能保证的是自己不上传、不外发，保证不了你电脑本身的安全边界；厂商后台的调用记录可以和本机用量对照，异常一目了然。务实的做法有几条：公共或共享电脑上不存重要的 Key，干脆只玩 Ollama 本地模型、不填任何云端 Key，这是利落的隔离；给系统上锁屏和磁盘加密，做了这两件基本功，明文存储的实际风险就压下去大半；额度高的 Key 定期在厂商后台轮换；用完就删配置文件里的 Key 也没问题，下次再填，厂商后台的限额告警也可以开着，双重保险。安全这东西，本机永远是你的责任田。

### 换电脑或不用了，Key 怎么处理

处理起来不麻烦。想迁移，把 userData 里的配置文件带到新机器对应位置即可，Key 就跟着走，模型阵容也原样复活，换机顺便就完成了；想彻底作废，删除那个配置文件，再去厂商后台把旧 Key 吊销换新，双保险，厂商后台的 Key 管理页通常有调用日志，定期看一眼是个零成本的好习惯。卸载应用本身不等于清理数据，记得动手删文件，这一点和大多数桌面应用的凭据管理是一样的，养成习惯就不会留下尾巴。

看完机制，答案可以自己下了：传不传出去，机制上堵死了；存得安不安全，明文是现状，加密升级位已预留。给它的评价是诚实——不吹安全无死角，把存储位置和边界写在明处，让用户知道自己那一半责任在哪。Key 的安全从来是产品和用户各管一半的事，产品把传输和不上传这一半做扎实了，另一半——本机的锁、共享电脑的警惕、定期轮换——写在你的待办里。Key 分级也是好习惯，重要的账号专门建一个低额度的 Key 给对局用，泄露了也伤不了主账户。
