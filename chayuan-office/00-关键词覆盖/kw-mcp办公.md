# MCP办公是什么：自动化文档流水线

MCP办公这个词新就新在：文档软件主动把操作能力开放给智能体，而不是等人来点按钮。它到底能自动化到什么程度、边界在哪，本文按官方口径逐项说清，载体是察元AI Office。

## 什么是MCP办公

MCP办公指通过 MCP 协议让外部智能体直接操作办公文档的工作方式；这里的载体察元AI Office（Chayuan AI Office）是开源 AI 办公套件，六编辑器一体，AI 嵌在每个编辑器里。

协议本身值得多说一句：MCP 把「工具叫什么、参数怎么传、结果怎么回」定成了通用格式，智能体与工具服务两端各自实现一次，就能互相听懂。对办公场景而言，这相当于给文档操作配了一层标准插座——任何支持 MCP 的智能体都能插上来用，不必关心插座后面是哪家软件。

数字与版本情况核对自官方文档，截止时间见文末。

## MCP 能力落在哪

MCP Server 是它的落点：壳内 MCP 服务跑在端口 52588，把文档操作能力开放成 MCP 工具，外部智能体借此可直接操作文档；命令行形态另有 29 个工具（25 核心加 4 deck）。

值得单独立篇的原因：Claude Code 这类智能体从此能按标准协议读写你的文档，办公自动化有了统一的对话接口，不必为每款软件单独写适配脚本，也不必受制于某家厂商的私有接口。

## 依序上手

按下面的次序推进：

1. HTTP MCP 服务：先确认壳内服务在 52588 端口就绪，这是智能体进来的门。
2. CLI 29 工具：命令行侧同一套能力的 29 个工具（25 核心加 4 deck），适合脚本化调用。
3. 外部智能体可接入：把智能体自带的 MCP 客户端指向上述服务，即可开始对话式操作文档。
4. 场景验证：智能体代写周报并落盘——让智能体读上周的记录、生成文稿、保存成文件，全程不碰键盘。
5. 场景验证：自动化文档流水线——入库、转换、归档交给一条智能体链路。
6. 串联场景：Docs 写正文，察元AI 页签全文校对出批注——智能体产出的初稿与人工复核在此衔接。

## 三个支点

- HTTP MCP 服务
- CLI 29 工具
- 外部智能体可接入

三者各自独立又互为补充：HTTP 服务面向交互式会话，CLI 面向脚本与定时任务，智能体接入则是把两者串起来的那双手。

## 疑问两条

### 智能体调用这套工具时走什么链路？

链路是智能体连到本机的壳内 MCP 服务（端口 52588），文档操作都在本地发生；要不要联网，取决于智能体那一侧的模型放在哪。

### 外部智能体能对文档做哪些操作？

读写能力经 MCP 工具开放；CLI 形态共 29 个工具（25 核心加 4 deck），各自能做什么以工具描述为准，调用前先列一遍工具清单心里就有数。

## 它改变的是什么

没有 MCP 之前，让程序操作文档得写专用脚本，格式一变脚本就废；有了标准协议，智能体按工具描述自己适应，你只描述要什么结果。写周报、整理归档、批量转换这类重复劳动，从「写脚本」变成「说一句话」。

不过也要冷静：智能体善后能力再强，产出的文档仍要过人这一关——校对、脱密、格式检查交给编辑器内的助手，人工确认后再落盘，这条流水线才站得住。

以周报为例走一遍完整链路：智能体先调检索类工具翻出本周的会议记录与任务表，再调生成类工具汇总成初稿，接着把文件保存到指定目录——三步都在 MCP 工具调用里完成。人需要做的只剩收尾：打开文件通读一遍、修正不准确的表述、确认发出。

## 模型前提

AI 面板与智能体协作都以配好模型为前提（BYOK 或本地端点皆可），模型没配时，MCP 服务与 CLI 的传统文档操作不受影响，只是智能化的部分无从谈起。

## 反方向也成立：外部 MCP 接进来

文档能力开放出去的同时，外部 MCP 也能接进编辑器 AI：搜索、数据库、浏览器这几类能力挂上之后，AI 面板可调用的就不止文档操作本身，查资料、查库、看页面都能在同一个对话窗里完成。

## 内网部署的适配性

壳内 MCP 服务跑在本机端口上，不依赖外部网络；内网环境里，智能体与本机服务之间的通信照常进行。涉及涉密文档时，配合本地模型端点即可把整条链路留在隔离环境内——文档不出机器，智能体调用的也只是本机工具，这在保密单位是能写进方案里的架构，而不是宣传页上的形容词。

## 什么时候不必上 MCP

不是所有文档工作都需要智能体代劳：偶发的、一次性的编辑，手动完成更快；MCP 的价值在于重复、成批、可描述成规则的任务。把「每周汇总」交给智能体合理，把「改一个错字」也交给它，就是为协作付了不必要的协调成本。判断某个任务适不适合，有个简单的自问：这件事的操作步骤能不能写成一段让实习生照做的说明——写得出来，智能体大概率接得住；写不出来，说明任务本身还没想清楚，先别急着自动化。

MCP Server 的实际体验，起一个智能体会话连上 52588 端口便见分晓；上文六步里的任何一步，都可以当作切入点。
