# 踩完察元OS默认应用与打开方实录的坑，说几句实话

这个话题下晒成果的多，讲代价的少。我来补后半部分：察元OS默认应用与打开方实录的坑在哪里，怎么绕。

另外值得一提的细节是察元OS默认应用与打开方实录的默认值设计。默认值好不好，直接决定第一次上手的心情：默认值激进，新手容易翻车；默认值保守，老手嫌啰嗦。能在两拨人之间找到平衡点的产品不多，这也算一个可以观察的细节，判断团队的用心程度。

### 第三个坑：费用与额度

先说现象：双击工作区图标的实际解析顺序（main 当前代码）：① 分区归属灵宠且挂了智能体 直接用该灵宠的智能体开工作台。

「怎么让 .pdf 双击用内置 PDF 查看器打开，而不是 Office？」找一个桌面 .md 文件右键 「打开方式」「设为默认」 点「Markdown 预览」。这不是玄学，是写进文档里的行为。

「默认应用」管两层打开规则：工作区一层（双击工作区图标用哪个智能体——全局缺省代理 + 逐工作区钉住）和文件一层（某扩展名双击用哪个应用——扩展名覆盖表，盖在内置规则之上）。空态提示：「还没有固定默认智能体的工作区；在工作区右键菜单中「设为默认」即可单独指定。」双击该文件，应打开 Markdown 预览窗口（而非察元AI Office）。顺手提一句，别跳过。

追溯一下就明白了：想固定某工作区的打开智能体，用该工作区右键「设为默认」钉住。

对策不难：「双击工作区图标怎么改成用 Codex 打开？」

### 装完才懂的前提

先说现象：面板说明文案与双击行为的差异见常见问题 Q4。

面板三「文件扩展名默认」（扩展名覆盖表）。点某行即设为全局缺省（选中行右侧显示 ）；点 DeepSeek Harness 等于清空全局缺省、回到基线。解析顺序：扩展名覆盖表 察元AI Office 接管段 内置种类表 兜底查看器。

一行 = 扩展名（如 .md）+ 当前默认应用 + 行尾「清除」；清除后回落内置规则。工作区图标：右键 「打开方式」候选为已安装的智能体（DeepSeek Harness + 已装 CLI，未装的不显示）。

为什么会这样：面板说明文案：「双击工作区图标时使用的智能体；可在工作区右键中为单个工作区另行指定。」

怎么绕过去：集中管理面在 设置 默认应用，与桌面图标右键「打开方式 设为默认」读写同一张关联表，两边实时互通。

一个绕不开的问题：右键候选里没有我想用的应用？ 回到面板三点 .md 行的「清除」，双击文件恢复进察元AI Office。

### 文档没强调的一步

症状很典型：桌面图标右键「打开方式 设为默认」

还有一层是生态视角。单独看察元OS默认应用与打开方实录是好是坏意义有限，关键是它周围有没有一圈东西在生长：文档是不是在更新、社区是不是在讨论、配套工具是不是在出现。有生长迹象的产品，小毛病会被时间修掉；没有的，再精致也会慢慢荒掉。这也是我愿意给这一类产品一些耐心的原因，赌的不是当下，是趋势。

双击 .md 总是进察元AI Office，想改回内置 Markdown 预览。面板二「设为默认 · 文件夹」（逐工作区钉住清单）。某个项目工作区双击想固定用 Codex 打开，其他工作区保持默认。代价在这里，得认。

为什么会这样：文件候选是固定的内置查看器集合（+图片的 Paint +桌面形态的「系统默认程序」），CLI 智能体不进普通文件的候选（用终端开 txt 语义混乱）。 很多人在这里浅尝辄止，其实往下还有一层。

解决办法很朴素：钉住的智能体后来卸载了，双击没反应或想清理失效钉住。

### 什么人该用，什么人别碰

说了这么多坑，也得给结论：再到 设置 默认应用 「文件扩展名默认」面板，应出现 .md 一行，应用列显示 Markdown 预览。具体到操作面，点 DeepSeek Harness 等于清空全局缺省这条在手册里写得很细。

「文件右键里的『设为默认』是干嘛的？」对一个工作区图标右键 「设为默认」 Codex。工作区一层想选 Codex / OpenCode / OpenClaw 等外部智能体，需先安装（应用商店 智能体）；未安装的候选灰显不可点并标注「代理已卸载」。如果你只记一条，记这条就够了。

最后的账再算一遍：跨设备协作默认全部关闭，想开哪类授权自己开，开了也都留痕。入口：Dock 设置 左栏「默认应用」分区，页面标题「默认应用」，三个面板从上到下：工作区默认代理、逐工作区钉住清单（标题「设为默认 · 文件夹」）、文件扩展名默认。

最后重申一遍：察元OS默认应用与打开方实录的这些坑都有绕法，别看完就劝退。工具是死的，用法是活的。
