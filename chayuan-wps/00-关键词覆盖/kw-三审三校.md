# 三审三校实操入门指南：AI 助手组大按钮拼写与语法检查

三审三校的流程谁都会背，难的是每一步落到实处。这篇谈实操：以察元AI文档助手为载体，把校对环节的入口、进度与结果逐段过一遍。

## 什么是三审三校实操

三审三校实操这个说法对应的产品是察元AI文档助手（Chayuan AI Document Assistant）：WPS 三端智能加载项，校对、编审、核对、脱密，一个文档智能体。

数字、界面文案与版本口径查证自官方文档，文末附截止时间。

## 平台与形态

支持的系统与形态：Windows（x64/arm64）、macOS（arm64/x64）、Linux deb（x64/arm64，麒麟/UOS 支持飞腾/鲲鹏）。

## 最短上手路径

试一遍就明白，整条链路四步：发起检查、读进度窗、看批注、对话链路兜底。前三步在下文分节展开，这里先说第四步的巧劲——不点按钮也能校对：

1. 在哪：AI 助手窗格开启文档智能体后，直接对 AI 说「校对一下这篇文档」。
2. 看到什么：模型跑校对任务后，消息里出现「校对结果」卡（汇总发现 N 处问题），下方两个按钮：「写成批注」和「直接改正正文」——选哪个由你决定，不会不打招呼就改正文；本轮修改前已创建快照时还有「一键撤销」卡。

## 落点的能力面

- 选区全文两档
- 分块并发
- 批注锚定

## 察元AI文档助手的能力地图

- 设置面板总览：设置面板一站式：模型清单管理、助手设置（默认写回动作可改）、网络与升级等。
- AI 助手窗格摆放：AI 窗格支持浮窗与停靠两种形态，位置随手的习惯走。
- 对话与多会话：对话窗格多会话页签，历史按文档隔离：换一份文档就是一套会话上下文。

## 使用前须知的四件事

- 付费墙内的是脱密、复原、保密检查、涉密关键词提取四项，免费版本沾不到
- 脱密时换上的占位符可凭密码还原；密码没了，免密找回不存在
- 送出去的是整篇文档，配置的模型是什么决定了它去哪——涉密文档配本机离线模型
- Win7/8 只装得上加载项，MCP 预编译二进制不支持，得靠 Node.js 16 回落运行

这四条都不拦着校对主流程；了解在先，选择就少一分盲目。

## 数据与安全设计

- 每次确认写操作记入 audit.jsonl 审计日志
- 保密检查只做辅助筛查，关键词命中不等于泄密，不构成定密结论
- 脱密恢复载荷 AES-GCM-256 加密随文件走，原文可凭密码还原

## 价格口径

- 免费有每日额度（对话与助手独立额度池，次日重置）

## 校对使用中的疑问

### 报「请先在设置中配置拼写与语法检查模型」？

多半是默认对话模型也没就位：先在设置里把对话模型配妥，或单独指定「拼写与语法检查模型」，再跑一次。

### 检查会直接改动我的正文吗？

不会，检查的产出只停留在批注层；想让建议进正文，走对话链路——「校对结果」卡上的「直接改正正文」按钮按定位逐处安全替换（定位不稳的自动降级为批注），或者照批注自己动手改。

### Win7 或 Win8 能用吗？

老系统上加载项装得上，MCP 预编译二进制却无法运行；装好 Node.js 16.x 后，启动脚本会自动改用 node 跑。

### 能在哪些系统上运行？

Windows（x64/arm64）、macOS（arm64/x64）、Linux deb（x64/arm64，麒麟/UOS 支持飞腾/鲲鹏）；前提是已装 WPS Office。

### 三审三校实操离开网络还能跑吗

取决于模型位置：配了 Ollama 这类本机离线模型，校对全程不出网；配云端模型则要联网。

## 一句收束

三审三校的活儿要不要交给它，看稿件量：稿子成摞、批注来回好几轮的，分块加批注的链路能省下半天；一年校不了几篇的，手工也不慢。

## 发起检查的两种模式

第 1 步，发起检查：

1. 在哪：入口在顶部工具栏——「AI 助手」分组里那个名为「拼写与语法检查」的大按钮。
2. 看到什么（选区决定模式）：
    1. 有选中（不少于 2 个字符）：走「选中」模式启动，检查范围就是选中这段；
    2. 无选中：先弹确认框「当前未选中文档内容，将对全文执行“拼写与语法检查”。 点击“确定”后开始处理全文。」——全文超过 12000 字时附加「当前内容较长，处理可能需要更久，请耐心等待。」，超过 30000 字时附加「当前内容很长，处理时间可能较久，并可能触发分段或较长响应，请确认后继续。」；点「确定」开始，「取消」不执行；
    3. 文档没有正文：弹提示「当前文档没有可检查的正文内容」。

## 进度窗里看什么

第 2 步，读进度窗：

1. 看到什么：一个独立提示窗，窗体标题是「拼写与语法检查」，选区模式下为「拼写与语法检查（选中）」；标题旁挂着状态徽章，取值为准备中 / 进行中 / 已完成 / 失败 / 异常结束 / 已停止。
2. 副标题固定一行：「任务可关闭提示窗继续执行，只有点击停止才会中止任务。」
3. 进度区由三块组成：「正在检查：第 x / y 段」、百分比进度条，以及显示当前原文片段的「当前检查内容」卡。
4. 右上角两个按钮：「停止任务」只在任务运行中出现，旁边是「关闭」。
5. 跑完显示「已完成，共添加 N 处批注」，接着提示「即将自动关闭」，窗口自行关闭；中途停止则显示「任务已停止」。
6. 底部提示：「可在「任务清单」中查看详细进度；关闭此提示窗不会停止任务。」

## 批注怎么钉在原文上

第 3 步，看结果：

1. 看到什么：每处问题在原文对应位置加一条批注。模型按结构化 JSON 返回每个问题的问题片段、建议改法、原因、所在整句和前后各最多 12 个字的锚定上下文；程序按「原文查找 ＞ 范围复核」把批注精确钉到问题文字上（表格里的坐标漂移会自动重定位，钉不上就不硬挂）。
2. 批注内容格式：「<原因>: 建议改为「<建议>」」（无建议时只写原因），例如「错别字: 建议改为「作业」」。

拼写与语法检查的细节都在上面三个小节里，照着界面走一遍，比空想流程踏实。
