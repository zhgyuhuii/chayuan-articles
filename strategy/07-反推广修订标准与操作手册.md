# 反推广修订标准与操作手册（平台去广告嫌疑 · 逐篇手改）

> 2026-11-12：平台审查将本库文章判定为广告推广嫌疑。全库普查确认触发点：① 统一商业尾注 458 篇（公司名+官网域名，2~3 个固定串指纹重复）；② aidooo.com 域名 3,287 次；③ CTA 入口话术 72 篇、购买转化话术 156 处；④ 正文品牌密度最高 54 次/篇；⑤ 13 个模板小节标题（1,187 篇命中 ≥4 个）；⑥ 471 处「X要联网吗/X支持哪些格式」模板问句；⑦ 60 句固定话术跨文重复（最高 552 篇共用同一收尾句）；⑧ 21 篇含「首图建议/评论区预埋」运营文案泄漏。本文是逐篇修订的唯一规范。

## 一、总则（先读五遍）

1. **逐篇手改**：每篇完整通读后逐项处理。禁止写脚本/正则批量替换文件；禁止把同一段改写文本用于两篇及以上——**每处改写的措辞都必须为该篇单独组织**（跨文查重门禁会拦截，平台指纹检测也会）。
2. **事实保真**：任何数字与事实口径（版本号、家数、字数、天数、端口号、边界限制等）不许改值、不许新增。要么原样保留（可重组句式），要么连同整句删除。
3. **删除优先**：可疑话术首选删除；信息确有必要才改写。
4. **门禁不回退**：改后必须仍满足 verify/audit 全部质量门禁（见第五节自查清单）。删节导致字数不足时，须围绕**该篇主题**补写原创内容（各篇措辞必须互不相同）。
5. **只动正文**：除第七节允许的情形外不改 frontmatter；不碰清单之外的任何文件；不跑 git。

## 二、逐项修订规则

### R1 商业尾注（458 篇）
文末 `---` 之后的尾注整行删除，代之以**该篇独有**的一句版本说明。硬性要求：
- 含「数据截至」或「以官方」二词之一（GEO 门禁）；
- **禁止出现**：公司名（北京智灵鸟）、任何域名、仓库 URL、「官网」二字、下载指引、「Releases」；
- 两段式写法：版本口径 + 一句与本篇主题相关的适用范围说明。**措辞每篇不同**——归一化后（去标点）与他篇尾注相同达 3 篇即判不合格。
- 示例方向（仅示意，禁止照抄）：「文中界面名称与行为对应 1.0.15 版，写稿时以官方文档核对过，后续版本可能调整」「这里的步骤按 2026 年 10 月的 3.1.15 整理，老版本界面略有差别，以官方手册为准」。

### R2 域名清零（3,287 处）
- 正文所有 aidooo.com 去除。「以官网 aidooo.com 当前页面为准」（411 篇）→ 改为「以官方文档/对应版本说明为准」类表述，**每篇措辞不同**；
- 下载来源指引（01-下载安装类常见）→ 中性表述如「安装包从官方渠道获取，第三方镜像站来路不明」（每篇各异），不出现具体网址。

### R3 仓库链接清零（games 线 235 处）
- 所有 github.com URL 删除。确需提及开源性时写「MIT 开源，仓库自行搜索」或直接说「开源」，不带 URL；
- 命令、技能名、包名中的合法文字不动（如 `chaoffice` 命令名本身保留）。

### R4 CTA 与转化话术（72 篇 CTA、156 处购买话术）
- 删除「## 怎么入」「入口就是官网」「官网搜索即达」「赶紧试试」类入口指引；若该节含必要信息（如激活方式），并入正文自然句；
- 删除劝购语气：「先免费用满 90 天，觉得值再买」「用顺手了再考虑付费」「不买不影响任何功能」类一律去劝购色彩；
- 授权/试用事实（90 天静默试用、到期不锁功能、付费四项）：仅当**该篇主题就是授权或价格**时，保留一句无立场的客观陈述；其余删除。

### R5 品牌密度（189 篇 ≥16 次）
- 正文（去代码块）「察元」≤12 次。超出部分按语境替换为：它 / 这套工具 / 这个项目 / 这款加载项 / 该系统 / 这套桌面环境 等（同一篇内替换词也要轮换）；
- frontmatter 的 title/description/keywords 及正文首段前 400 字的主关键词原词**不动**（关键词布局门禁）。

### R6 模板骨架小节（1,187 篇命中）
下列小节标题**不得原样保留**，按该节实际内容每篇另起自然标题；内容重复的相邻填充节合并或删除其一：
`放回产品盘面看 / 安全与数据边界 / 价格与授权 / 产品家族与搭配 / 几条硬数字 / 能力总账 / 补充几条口径 / 顺带说清的几件事 / 多交代一层背景 / 再往深一层看 / 这些坑和边界要知道 / 你可能会问 / 动手前再核对一遍 / 离线与内网 / 顺手记的要点 / 边角信息 / 补充细节清单 / 这几条能力放一起看更清楚 / 具体怎么操作 / 更多操作细节 / 能力面再摊开一层`
约束：
- 非知乎线改后 H2 ≥5（06-常见问题类目 ≥2 即可）；知乎线不卡 H2；
- 「边界/坑/不足」内容必须保留（边界门禁），只换标题；
- 「价格与授权」节：若整节删除会掉 H2 数，则改标题保留纯事实、去掉推销语气。

### R7 文内去重
同一句/段在篇内出现两次以上（无论长短）只保留信息量最足的一处；相邻重复行直接删（现状存在「说到底，工具是拿来用的」连排两遍这类硬伤）。

### R8 FAQ 模板问句（471 处）
「X 要联网吗」「X 支持哪些格式」两个问句骨架不得与其他篇目重复原样——每篇改写问法，但**必须保持疑问句式**（含 吗/？/怎么/如何/哪些/会不会 等疑问标记，FAQ 门禁）。FAQ 节本体不可删（02/06/09 类目必须存在 FAQ 节，节名可换但须是疑问语义小节）。

### R9 关键词堆砌句修顺
「为什么要有开源办公套件安利：开源办公套件能离线装」这类主词生硬拼接句，改写为自然汉语；首段前 400 字必须完整保留主关键词原词。

### R10 种草线专项（09-社区种草，61 篇）
- 标题与正文中的「安利」「种草」「神器」「天花板」「闭眼入」「无脑冲」「白嫖」等推销词全部去除。若主关键词本身含这些词，可改主关键词（同步改 title/description/正文首段引用处），新主关键词保持自然、全库唯一；
- 品牌话题标签（#察元AI 等）删除，保留 3~6 个中性标签（#办公效率 等）；
- 文首「首图建议：…」行、文内「评论区预埋」相关运营文案整块删除；
- 「也要说实话/适合谁不适合谁」结构保留（这是去广告味的关键，别删反了）。

### R11 残缺标题（website 线 6 篇）
title 以「：」开头的 6 篇补全自然标题：含主关键词、10~30 字、非模板句式；H1 同步改。

### R12 收尾/衔接固定句式（最高 552 篇共用）
凡命中下方清单的句子：**改写为贴合本篇语境的说法**（如把「常见问题那一节」替换为本篇实际的小节名、把主语换成本篇主题物），或删除。改写不得套用清单里另一句，也不得与他篇改写结果雷同。含数字/限制的事实句（内存建议、龙芯、APIKey、付费四项等）改写时**数字与限定词逐一保留**。

**R12b 段落引导语去指纹（全库数百篇共用的冒号引导语，同样按 R12 处理）**：
`放回产品盘面看：/ 安全口径单独立一层：/ 平台与形态的账：/ 价格口径一并交代：/ 能落到数字上的几条：/ 离线内网这条线的口径：/ 把〔产品名〕放回〔产品名〕的整体盘面：/ 把〔产品名〕的能力总账摊开：/ 边界先摆在桌面上：/ 动手前把这几条过一眼：/ 几个容易忽略的点，一并放在这里：/ 顺手记几条细节，省得你翻文档：/ 如果只记一件事：/ 概念一分钟，操作十分钟 / 剩下的细节，照步骤节走就行`
**R12c 知乎线连接词指纹（各 60~80 篇共用，每篇内至多保留 1 次、跨篇措辞必须互异）**：
`追溯一下就明白了：/ 怎么绕过去：/ 先把预期摆正：/ 症状很典型：/ 遇到的画面是这样的：/ 写手册的人 / 顺手提一句 / 写文的版本基线：`
同篇中同一引导语出现多次的，后续出现处换不同说法或直接去冒号合并进句子。

   `node -e 'const t=require("fs").readFileSync(process.argv[1],"utf8");const b=t.replace(/^---[\s\S]*?---/,"");console.log((b.match(/[\u4e00-\u9fa5]/g)||[]).length)' 文件路径`

3. 尾注为该篇独有版本说明，含「数据截至」或「以官方」；

5. 正文「察元」≤12；模板小节标题 0 残留；命中清单句式 0 残留；篇内无重复句段；

## 六、执行纪律

- 一篇一篇做：Read 全文 → 多次小步 Edit → 自查 → 下一篇。禁止不读全文就改；
- 任何两篇之间不得出现相同的新写句子（包括尾注、替换句、补写段）；
- 遇到规范未覆盖的新推广形态：按「平台视角——这句话像不像软广」判断，像就删或改；
- 不确定的事实宁可删除该句，不许猜。
