# 故障自愈实操，服务链自愈

故障自愈的麻烦不在功能本身，在于信息散。本地服务多，全靠人盯不现实，自愈机制让小故障无感恢复。这篇把它收拢成一条能照着走的路径。

## 概念先对齐

故障自愈是察元AI OS（aidooo.com）里的一个能力模块：AI 桌面操作系统，本地大模型、知识库、智能体、宠物群聊装进一个桌面，故障自愈是其中面向这类需求的一环。

下面直接进正题。

## 具体怎么操作

遇到故障怎么办

1. 先等自愈机制工作（崩溃退避重启通常几十秒内完成）
2. 诊断入口可一键打包上下文
3. 转给智能体给出修复方案或直接处理
4. 诊断包可导出给人工支持

三类常见自愈场景

1. 模型服务崩溃：退避重启并恢复加载清单
2. 配置异常：回滚到上一个可用版本
3. 端口被占：自动顺延端口并通知消费方重新发现

## 什么情况下用得上

端口冲突自动化解；模型服务崩溃自动拉起。

## 这些坑和边界要知道

边界先摆在桌面上：

- 云端厂商模型调用需自备 API Key
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力

## 高频疑问

### 自愈失败怎么办？

自愈有重试上限，超限后服务进入停摆状态并在界面上标红。此时用诊断入口打包上下文，交给智能体处理或导出给支持人员。

### 配置回滚会丢我的自定义设置吗？

回滚只针对异常的服务配置（模型清单、端口映射这类），用户数据与个人设置不在回滚范围内。

### 端口自动顺延后，外部配置会失效吗？

消费方（智能体、加载项）通过服务发现拿端口，会自动跟到新端口；只有手写在外的固定端口配置需要同步改。
