# MCP服务器入门指南：MCP 是智能体的手

MCP服务器这个词被搜得越来越多，但它到底指什么、和普通工具软件差在哪，说法很杂。这篇按官方口径给定义、给数字、给边界，产品以察元AI OS为例。

## 什么是MCP服务器

把MCP服务器拆开看，它指的是这样一类东西：察元AI OS（Chayuan AI OS，简称察元OS）是一款 AI 桌面操作系统，以完整桌面环境为壳，内置本地大模型五件套、引用式知识库、17 家外部 CLI 智能体管理、宠物群聊多模型讨论与系统级 MCP 控制面，支持 Windows/macOS/Linux（银河麒麟、统信 UOS）及 Docker 云桌面形态，断网可用、数据不出本机。

## 在察元AI OS里落在哪

MCP服务器在察元AI OS里的落点是MCP 服务管理：MCP 服务清单增删改（stdio、HTTP、SSE、本机 52583），先验证连接再保存，启停即同步写入支持 MCP 的 13 家智能体。

为什么值得单独说：MCP 是智能体的手，一处配置全家生效，改之前能验证连接省得排错。

## 最短上手路径

试一遍就明白：

1. 进入页面：打开「设置」，左栏点「MCP」。

2. 认识第一条「本机 MCP 服务」卡：名称「察元本机 MCP」＋「本机」徽标。运行中显示绿点与「端口 {port} · 运行中」，下面两行地址（行尾「复制」按钮，点击变「已复制」）：「本机」= http://127.0.0.1:52583/mcp（回环访问免 token）；「局域网」= http://<本机局域网IP>:52583/mcp?token=…（token 已内嵌在地址里）。卡片说明原文：「把本机工具注册表（备忘录/日历/提醒事项/窗口/系统等）经 MCP 对外提供；默认端口 52583（统一端口注册表，docs/port-registry.md）。局域网访问需携带 token（已内嵌在局域网地址里）。停用后各智能体配置中的 chatop 条目将被移除。」右侧「停用 / 启用」按钮可开关，不可删除。

3. 添加服务：第二张卡「MCP 服务（{count}）」，卡片说明原文：「启用的服务会自动写入各智能体的 MCP 配置：DeepSeek Harness · Claude Code · OpenCode · Codex · ZCode · OpenClaw；停用即从中移除。DeepSeek Harness 直接读取 ~/.dsh/mcp.json。」（页面提示列的是首批六家；实际传播按注册表覆盖 13 家外部 CLI，见步骤 5。）右上点「+ 添加 MCP 服务」，弹出同名编辑窗：

4. 管理清单：保存后列表出现新行——名称＋类型徽标＋「{count} 个工具」＋命令串或 URL，行尾三个按钮：「停用 / 启用」「编辑」（弹窗标题「编辑 {name}」，名称不可再改）「删除」。列表为空时显示「还没有 MCP 服务。点击上方「添加 MCP 服务」新建一条。」

5. 理解保存后系统做了什么：每次保存/启停/删除后，启用中的非本机条目被再生进仅有真相源 mcp.json（桌面形态在用户数据目录的 dsh-home/mcp.json；web/Docker 形态 ~/.dsh/mcp.json——DeepSeek Harness 直接读它），并全量传播进支持 MCP 的 13 家外部 CLI 配置：Claude Code（~/.claude.json）、ZCode（~/.zcode/cli/config.json）、Codex 与 Grok Build（各自 config.toml 的 # BEGIN chatop mcp 托管块）、OpenCode（~/.config/opencode/opencode.json）、OpenClaw（~/.openclaw/openclaw.json）、Kimi Code、Crush、Cursor CLI、Copilot CLI、Droid、Amp、CodeBuddy（各家自有配置文件）。三条硬规则：只动察元自己写过的条目名（你手工配的条目永不被碰）；内容不变不落盘；首次改写某家配置前自动留 .chatop-bak 备份。部分家失败时提示「清单已保存，但部分智能体配置传播失败：{failed}」（清单本身已保存好）。

6. 两个托管条目自动随行（不占你的清单、不可删）：chatop（控制面 stdio 自适配——智能体由此调用全部系统工具，这些调用受 G6 权限门管控；本机 MCP 服务停用时此条目从各家移除）与 chatop-kb（知识库 MCP，HTTP，随知识库服务是否在运行自动出现/移除）。

1. 「名称」：如 context7；不合法时红字提示「名称仅限字母/数字/点/横线/下划线（≤64 字符），且不能叫 chatop」。
2. 「类型」三选一：「命令行 (stdio)」/「HTTP」/「SSE」。
3. stdio 填「命令」（如 npx）、「参数（空格分隔）」（如 -y @upstash/context7-mcp）、「环境变量（每行 KEY=VALUE）」（如 API_KEY=xxx）；HTTP/SSE 填「服务地址 URL」（如 https://example.com/mcp 或 SSE 的 https://example.com/sse）与「请求头（每行 KEY: VALUE，可选）」（如 Authorization: Bearer …）。
4. 点「验证连接」（按钮变「验证中…」）：后端实际跑一遍 MCP initialize ＞ tools/list 握手——stdio 起子进程走标准输入输出，HTTP/SSE 先按 Streamable HTTP POST 试、被拒再退回 legacy SSE；30 秒超时。成功显示绿色「验证成功 · {count} 个工具」并展开「工具清单」（逐行工具名＋描述；连接成功但零工具显示「服务连接成功，但未提供任何工具」）；失败显示红色原因。未验证时底部提示「需验证连接成功后才能保存」。
5. 连接相关字段（类型/命令/参数/环境变量/URL/请求头）改动后需要重新验证；只有验证成功后右下「确定」才可点。「取消」放弃。

## 你可能会问

### 「确定」按钮一直是灰的？

必须先「验证连接」成功才能保存；而且只要改过任何连接相关字段（类型/命令/参数/环境变量/URL/请求头），验证结果即失效，要重新点「验证连接」。

### 验证一直失败/超时？

握手超时为 30 秒。stdio 型常见原因是命令冷启动慢（npx 首次要下载包）或本机没有该命令——先在终端手动跑一次该命令确认能启动；HTTP/SSE 型确认 URL 以 http(s):// 开头且本机可达（可用浏览器/curl 试）。修好后回弹窗重新验证。

### 名称为什么不能叫 chatop？

chatop 保留给列表第一位的本机 MCP 服务（托管条目同名），避免与自动注入的系统条目冲突。换一个名字即可。

### 升级会丢数据吗？

不会。覆盖安装与自动更新都保留数据目录；升级前把数据根目录整体备份一份更稳妥。

### 内网机器怎么升级版本？

用轻量安装包加模型压缩包的组合，逐文件校验后离线覆盖安装；也可以等维护窗口临时放行更新通道。
