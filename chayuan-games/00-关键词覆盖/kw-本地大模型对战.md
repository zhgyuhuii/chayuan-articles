# 本地大模型对战：断网也能办一场模型擂台

机房网口管制、展会现场网络瘫痪、或者你单纯不想让任何对局数据离开这台机器——这些场景里，云端模型集体出局，本地大模型对战正是为这些时刻准备的。本地大模型对战指的是对局双方由本机运行的模型担任、全程不经云端的对弈形式；在察元竞技场里，本地大模型对战通过 Ollama、LM Studio、Xinference 这类本地推理引擎免 Key 接入，整条链路可以完全离线。

断网办模型擂台，听上去像奢望，拆开看其实是三件小事的组合：模型在本机、裁判在本机、数据在本机。这篇把这三件事讲清楚。顺带回答一个高频顾虑：离线是不是功能缩水？往下看，答案是否定的。

## 拆词与相近概念辨析

与云端对局比，差别在三个字：不出门。云端对局里，模型跑在厂商服务器上，你的每手棋都要出门走一圈；本地对局里，模型权重躺在本机磁盘，推理发生在本机芯片上，网络断了照样打。离线的彻底程度也值得强调：不是「弱网可用」，是拔掉网线一切照旧。与离线单机游戏比，差别在对手的成分：单机游戏对面是写死的脚本，本地对局对面是真的大模型——只是它不住在云端，住你家硬盘里。这条对比还解释了一个常见疑问：本地模型会不会「偷工减料」。不会，它走的是同一套出招协议、同一套裁判校验，区别只在权重文件放在哪里。

数据边界也值得单独拆。竞技场的 API Key 明文只存本机应用数据目录，不上传；本地推理连 Key 都不需要，谈不上泄露；对局记录、天梯积分全部落在本机。一条链路从输入到输出都不出门，这才是「数据不出本机」的完整含义。顺带一提，API Key 的安全设计对本地模式是冗余的——本地连 Key 都没有，但这份冗余让两种模式可以随时互换，安全底线不因模式而变。

## 离线链路的三个环节

一场对局拆开是三个环节：模型推理、裁判判定、结果结算。本地模式下，推理由 Ollama 这类引擎在本机完成；裁判是纯逻辑代码，从不联网；TrueSkill 结算同样在本机算。三个环节都不碰网络，断网自然全程可用——这不是降级运行，是完整功能换了个住处。

三个环节里只有推理吃硬件，裁判与结算的算力开销可以忽略。所以本地体验的瓶颈几乎都在模型推理上：机器决定速度，参数量决定棋力，两个变量分清楚，调优方向才不会跑偏。

## 什么场景用得上

离线与内网环境：保密要求高的机房、教学机房、没有外网的工作环境，模型擂台照办不误。

隐私敏感场景：不想让任何棋局与提示词流向第三方，本地链路给你物理层面的安心。

演示与活动：展会、课堂、社区活动上，网络是现场活动的头号变数，本地对局把它直接消灭。活动上还有个实用技巧：提前把模型与对局环境调通，现场断网演示零依赖，翻车概率直线下降。试用与把玩也是同理——零成本试一批开源模型，看它们上桌什么表现，不用先充任何厂商账号。教学场景单独说一句：棋牌规则里藏着博弈论的入门教材，让学生看着两个本地模型对打、对照思维链学推理，零流量成本就能开一门实践课。研究场景同理：内网环境里批量跑对局、攒数据，不用过外网的合规审查，流程自己说了算。

## 本地擂台搭建三步走

三步。第一步，本机装好 Ollama（或 LM Studio、Xinference）并拉取想用的开源模型，模型文件体积不小，磁盘与网络提前留量。第二步，进设置 ＞ 模型配置，选择 Ollama 这类本地推理，免 Key 接入，点「测试连接」确认本机端点可达，把可用的模型勾选入库。模型选择给个起点：从参数量小的模型开始验证链路，跑通了再换大模型，每一步都有确认点，排错范围小。第三步，回大厅选玩法开局，人机局、机机观战、锦标赛照常安排，TrueSkill 评分也在本机照常结算。第三步之后的事与云端局没有区别：思维链照常滚、天梯照常记、复盘照常做——离线改变的是模型的住处，不是玩法。想给离线局加点气氛，把机机观战与锦标赛用起来，断网的机房也能办出赛会氛围。本地模型与云端模型还能同桌混战，断网时全本地、联网时混编，选手名单随你排。

## 三条边界

本地模型棋力有上限：开源小参数量模型不做深度搜索，废招概率比云端大模型高，系统有代走兜底，比赛能进行，但观赏性与竞技强度打折。把它当陪练与实验台正合适，当表演赛素材就要精挑对手。

硬件门槛真实存在：模型参数量与显存、内存直接挂钩，机器带不动就只能跑更小的模型，推理速度也受硬件制约，每手延迟会比云端明显拉长。延迟长就把对局当慢棋看，机机观战加锦标赛，挂机不占人力。

模型文件要自己下载：动辄数 GB 起步的权重文件，磁盘与下载时间都要提前安排，装机前规划好。下载一次长期复用，权重文件放着不会过期。

## 本地大模型对战常见疑问

### 断网真的全程能用吗

能。模型推理、裁判判定、TrueSkill 结算全部在本机完成，断网不影响开局与对局；用云端模型才需要联网。等待只来自本地推理速度，慢，但稳定。

### 本地模型打得过云端模型吗

多数情况下打不过：参数量与训练资源摆在那里。但相对座次与过程观赏是本地局也能给的东西，强度要求高就换云端模型对照着打。真正值得比的是相对座次：本地模型之间的高下，对选型同样有参考价值。

### 什么配置的电脑能跑

取决于模型参数量：小参数量模型普通机器就能跑，大参数量模型对显存与内存要求高。以机器跑得动、速度可接受为限，从小模型试起比较稳妥。速度不满意就降参数量或换更轻的玩法，五子棋这类玩法对小模型很友好。

### 对局数据会上传吗

不会。Key 与对局数据只存本机应用数据目录；本地推理模式下连模型流量都不出机器。想验证的话，断网开一局就是很直观的测试。

断网办模型擂台，做起来只要三步。察元竞技场把本地推理做成了一等公民：免 Key、完全离线、数据不出本机——网络好坏不再决定你能不能看模型打架，硬盘里的模型随时可以上桌。
