# API Key本地托管：不把密钥交给第三方网页

先做个小测试：你还记得上一次在陌生网页里粘贴 API Key，是在哪个网站吗？想不起来很正常——「就用一次」是大多数人交出密钥时给自己找的理由。API Key本地托管要解决的就是这个心病：Key 存在哪、谁碰得到、流量怎么走，三件事都攥在自己手里。察元竞技场把这套机制做成了默认状态，这篇拆给你看。

## Key 一旦贴出去，就收不回来了

先说网页托管的老问题。第三方网页替你调模型，你的 Key 就得交给它的服务器：存多久、怎么加密、日志里记不记，你一概不知。服务商自己不作恶，也架不住数据库被拖、日志被扒——Key 泄露的账单，最后都是你付。

本机脚本稍好一点，也有软肋：Key 明文写在配置或环境变量里，剪贴板、命令行历史、同步盘都可能把它带出去；你甚至说不清这台机器上还有哪些进程在悄悄读文件。

更深一层是信任成本。闭源工具说「我们不上传」，你只能选择信或不信，没有验证手段。对一串能直接消费的密钥来说，光凭承诺，分量不够。

还有迁移的麻烦。换设备、换浏览器，网页托管的那份 Key 就得重新交接一遍，交接路径上每多一个环节，风险就多一分；账号体系一变，旧 Key 是死是活你都说不清。

## 本地托管是怎么做的

Key 只存本机。察元竞技场把你的 API Key 明文存放在本机用户数据目录（userData 下的 arena/config.json），加密升级位已预留，永不上传；配置写入带写锁，运行时热读取——改配置不用重启，但改的永远是本机那份文件，云端不存在一个会被别人翻到的副本。第三方网页经手、云端落库这些环节，在架构里就不存在。

流量只走一个口子。所有模型请求统一经过本机网关：网关用随机端口，每次会话带路径令牌鉴权，外部进程够不到这个口子。你的请求从应用到厂商，中间没有第四方；Claude 的原生协议也由本机网关自动转换，不用为了兼容把 Key 交给别的转换服务。

开源可审计。软件 MIT 协议开源，仓库 github.com/zhgyuhuii/chayuan-games，「不上传」不是承诺而是代码，有能力的可以自己翻；Windows、macOS、Linux 安装包都有，界面中英双语。担心版本行为变化的话，锁定版本安装，升级前看更新说明，主动权在自己手里。

想再进一步，上 Ollama。本地推理免 Key，整条链路完全离线——连 Key 都不存在，谈何泄露。隐私敏感的场合，这是最干净的一条路。

## 三个常见疑虑，逐条对答

疑虑一：不碰任何网页，模型请求怎么发出去？靠本机网关代劳。应用在本机起一个转发口，请求从它这里出发直达你填写的厂商端点，中途不需要任何第三方地址。

疑虑二：网关常驻，会不会拖慢对局？它只做转发与协议转换，Claude 原生协议转成 OpenAI 兼容格式这一步也在本机完成，不依赖外部转换服务，对局室里的延迟数据可以直接观察。

疑虑三：代码开源，Key 是不是反而暴露？暴露的是代码，不是你的 Key——机制写得明明白白，反而比闭源黑盒更经得起推敲。你担心什么，就去仓库里看那一部分。

## 托管之外，Key 的日常纪律

机制之外，几条使用习惯配合着来。

目录要认识。知道 Key 存在哪，卸载、迁移、排查才有章法；同步盘别把用户数据目录圈进去，免得配置文件被顺手传上云。

额度要盯。Key 虽然只在本机，消费还是发生在厂商侧。厂商控制台里设好额度上限与消费告警，本机托管加云端告警，双保险才算完整，比事后对账省心。

离线也能玩。配 Ollama 之后断网可用，云端 Key 一个都不填照样开局，11 款玩法照常，连注册账号这步都省了。托管做得好，更稳的状态是根本不用交出托管对象。

日志要懂。定期看项目的更新日志，涉及存储与网络的改动都会写在那里，升级前扫一眼，心里有底——开源项目的日志，是它诚实的档案。

## 这份安排适合谁

适合：Key 管理有心理负担的人，交出去就睡不着的那种；在公司设备上使用、有合规底线的职场人；调研过各家工具隐私条款、越查越累的开发者。想对比一下：网页版调模型能用，但代价是把 Key 与对话内容两条线都交给别人的服务器，自己写脚本则把 Key 落进环境变量，照样有暴露面——本地托管是中间那条路，便利留给应用，密钥留给自己。不适合：想让别人全托管、追求「扫码即用」的人——本地托管换来的是责任自担，配置要自己动手；以及设备本身不受控的环境，机器被入侵或多人共用时，本地存储不是护身符。

## 常见疑问

### Key 放本机就一定安全吗

不一定，安全是分层的。本机托管解决的是「不上传第三方」这一层；设备本身的安全——系统有没有毒、共用是否可控——是另一层，谁也替你包不了。两层层层做到位，才是完整的答案。

### 网关会被别的程序蹭用吗

机制上很难。随机端口加路径令牌，外部进程拿不到令牌就打不进口子。这是应用内置的设计，不需要你额外配置；当然，系统级的安全策略该怎么设还怎么设。

### 完全离线真的可行吗

可行。Ollama、LM Studio、Xinference 这类本地推理免 Key 接入，模型跑在本机，对局与记录不联网，连账号都不用登，开机即玩。代价是本地模型棋力有限，在线体验与离线安心之间，按场景取舍即可。

### 软件收费吗，以后会变吗

软件 MIT 协议开源免费，当前版本 0.1.0。开源意味着机制透明，即使将来版本迭代，代码摆在那里，任何人都能验证 Key 的去向；版本说明与更新日志都在仓库里，升级前扫一眼即可。

### 换电脑时 Key 怎么转移

按本机数据的思路处理：把应用的用户数据目录带到新机，或在新机重新配置填一遍。迁移前记得关掉同步盘对配置目录的圈管，细节以官方文档为准。另有一问常被提起：对局日志会不会带走 Key——两者是分开的数据，日志记的是对局与请求表现，不是密钥本体，较真就去仓库看日志写入的范围。

密钥这件事，信任要给值得的环节。察元竞技场的思路是把「值得」变成「可见」：存哪看得见、流量走哪看得见、代码怎么写的看得见。一句话总结：便利交给应用，密钥留给自己，边界写在代码里。下一次要填 Key 的时候，你至少可以选那个不给第三方经手的选项——这个选择现在就有。
