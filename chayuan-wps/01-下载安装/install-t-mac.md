# macOS假成功修复装机指南：三平台安装包

macOS假成功修复这件事，卡住人的通常是三步：入口在哪、要点哪些按钮、做完怎么确认。这篇按察元AI文档助手的真实界面顺序走一遍，逐步排掉假成功的坑。假成功的迷惑性在于安装器全程不报错：进度条走完、界面提示完成，重启 WPS 后选项卡却迟迟不来。把权限、容器、重启这三件事按顺序排好，排查就不会走弯路。

## 修复前先核对的机器条件

- 系统要求：WPS Office 已安装；建议先完全退出 WPS
- 安装包：chayuan-6.1.2-macos-arm64.pkg / x64.pkg
- 说明：权限问题标准修复。

安装包通过官方渠道发布，别从陌生站点拿 pkg，修权限问题时再混进来路不明的包就更乱了。

## 按顺序走完安装四步

1. 取对应架构的 pkg（官方渠道）
2. 完全退出 WPS 后安装（运行中安装会被旧注册覆写）
3. 安装中若报容器写入失败，用官方 repair-mac-jsaddons-container.sh 脚本修复
4. 重启 WPS，看选项卡是否出现

## 修复脚本什么时候派上用场

修复脚本只对应一种情况：安装过程中明确提示容器写入失败。它修的是 WPS 沙盒容器里的 jsaddons 落位问题，跑完同样要重启 WPS、再看选项卡。假成功那类无提示的失败，问题不在容器，先给安装器补上完全磁盘访问权限才是正路；两类症状的处方不同，先分清再动手。

## Windows 侧的装法一句话

Windows：安装走 exe 包；双击后加载项进入 WPS jsaddons 目录，本机服务自注册并带看门狗；完全退出并重启 WPS。

## 拼写检查通过，模型链路才算通

装好后开一篇文档，直接用察元AI助理选项卡里的拼写与语法检查试一次，能出结果说明链路没断；写回动作的默认值也顺手在设置里过一遍。

- 没过的话，把宿主软件整个退干净再启动一次

## 安装之外还要知道的三条设计边界

- macOS 上没给完全磁盘访问权限，安装器会假成功
- 脱密用占位替换实现、且可逆还原，但免密恢复通道被刻意设计为不存在，密码遗忘时别指望绕过
- Win7 与 Win8 上 MCP 预编译二进制无法运行，需 Node 16 回落

这三条是设计层面的边界，与安装排障是两回事：排障解决「装没装上」，边界回答「装上之后什么能做什么不能」。先走完排查，再花时间理解边界，顺序颠倒了容易把权限问题误判成产品缺陷。

## 两类典型使用场景

个人给 WPS 装校对插件，政企统一给 WPS 加 AI 能力。两种场景在 mac 上的安装路径完全一致，差别只在单机与批量：批量部署把权限预检做在前面，单机用户则是装完才发现、照着排查路径走一遍。

## 装机前常被问到的三个问题

装机相关的提问大多集中在下面三条，先看一眼再动手，能少走不少弯路：

- 三个平台的安装入口分别在哪里？
- jsaddons 目录的路径是什么，手动放文件可行吗？
- 装完 WPS 里找不到菜单项，该从哪里查起？

### 修复脚本和验证那几步，断网环境能走完吗？

修复脚本处理的是本机容器写入问题，跑完打开 WPS 看选项卡也不涉及外网访问；整个流程里真正需要网络的一步，是从官方渠道取安装包。

### 假成功和容器写入失败是一回事吗

不是。假成功指安装器没拿到完全磁盘访问权限时报成功、文件实际没落位，先查权限；容器写入失败会在安装时明确提示，对应官方修复脚本，跑脚本即可。两条排障路径别混着走。

macOS 这条安装线上，权限是第一嫌疑：装完没动静，先想完全磁盘访问，再想容器，最后才轮到重装。
