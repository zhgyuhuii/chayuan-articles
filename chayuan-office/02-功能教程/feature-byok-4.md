# 大模型接入办公出问题先看这：开源 AI 办公套件

大模型接入办公的麻烦不在功能本身，在于信息散。自带 Key 意味着不被单一厂商锁定，国内国际本地端点随切随用。这篇按排查顺序把入口、边界与常见疑问收拢成一条线。自带 Key 的实际好处是选择权在你：哪家合适用哪家、随时可换，切换不动文档本身。编辑器的日常操作不在本篇范围内，这里只解决「接不上、用不了」的问题。

## 先定位问题在哪一层

大模型接入办公的问题一般藏在三层里：前置条件没满足、操作路径走岔、边界条件踩线。排查遵循一条总原则：先确认依赖、再复现路径、最后对边界，顺序反了会白费功夫。先把前提核一遍：主页可打开设置弹窗（入口见第 1 步），不指定落点时弹窗默认停在「模型设置」区；再对照路径查走岔的位置。三层里最容易被跳过的是第一层——不少人一上来就反复点按钮，其实弹窗都没停在正确的区。

## 排查的三层顺序

三层对应三组主线能力：

- 94 家目录
- 按能力分设默认模型
- Key 不出本机

目录解决「模型从哪来」，分设默认解决「谁来干什么」，Key 不出本机解决「凭据放在哪」。三层各自独立又彼此牵制：目录里有这家厂商，不代表模型已经选好；模型选好了，不代表默认用途分配得正确，逐层确认比笼统重装有效。顺手记一个原则：每改一处配置就做一次连接测试确认，改完即验，坏在哪一步一目了然。前置条件方面还有两条边界：AI 功能依赖已配置模型；内置账号登录当前版本未开放，现阶段须 BYOK 或本地模型。场景上，公司统一采购的 API 接入与个人用免费额度厂商，走的都是同一套配置入口。

## 关于联网与格式的疑问

### 用 AI 功能必须保持联网吗？

不一定。云端供应商的调用需要网络；接本机 Ollama 等本地端点则不需要。服务器部署时全员浏览器可用，是团队化的另一种形态——联网与否，取决于你把模型放在哪一侧。断网排查有个简单办法：把期望的模型换成 Ollama 一类本地端点再试一次，能通就说明问题出在网络侧。另外联网需求只发生在调用模型的那一刻，写文档、做表格这些编辑动作并不依赖网络。

### 打开文档的格式覆盖面怎么看？

打开格式的路由表覆盖 docx、odt、xlsx、csv、pptx、pdf、md、html 等，老格式会得到明确提示。格式能力归编辑器，模型能力归 BYOK 配置，两条线互不干扰。需要留意的是老文档：遇到明确提示不支持的情况，先转换格式再继续，比反复重试省时间。

## 平台差异与模型依赖

平台侧有一条硬差异：Linux 无系统引擎不识别，且仅桌面形态提供 HTML 编辑器。如果团队里有 Linux 用户且要识别扫描内容，或必须用 HTML 编辑器，桌面形态才是完整选择；浏览器形态适合轻量场景。这里也区分两个容易混的词：桌面形态指安装版本体，浏览器形态指轻量入口，选型前先确认自己需要哪一档。模型侧的依赖关系要记牢：AI 功能依赖已配置的模型（BYOK 或本地端点），未配模型时只有传统办公功能可用——接入出问题，先看这一条。

## 离线、信创与涉密

套件能离线安装、信创环境能跑；涉密文档不能出网，换本地模型后，AI 校对、AI 改写在隔离环境里照常工作。需要提醒的是，「不能出网」是硬约束而非偏好：只要文档涉密，任何云端模型都不应进入处理链路。隐私侧还有一层：报价、身份证号这类片段不想给模型看，隐藏之后其余部分照常 AI 处理。安装不依赖外网、运行不依赖外部服务、涉密文件有本地模型兜底——三件事凑齐，受控环境里才真正可用。

## 智能体与编辑能力

让 Claude Code 这类智能体直接读写你的文档，外部智能体均可接入；编程智能体写代码调文档 API 不用翻文档。对智能体来说，文档不再是黑盒：读得到内容、写得回文件，自动化脚本才有真正的落点。起步时可以先让智能体做只读的事——汇总、检索、整理——确认行为可控后再放开写入。编辑器侧，glb 格式的 3D 模型能直接放进 pptx 且往返保真；写材料时引用内部资料且带出处，对需要留痕的团队尤其有用。

## 套件侧的两条底线

打印别掉链子、断电别丢稿——这是办公软件任何时候都不能破的两条底线，也是评估任何接入方案时不必妥协的部分。接入方案再灵活，底线破了就没有意义。

## 什么情况下还会用到

个人用免费额度厂商，公司统一采购的 API 接入。两类场景的差别主要在 Key 由谁保管：个人自己管，公司采购则通常由 IT 统一下发。

## 读者问得最多的三句

- 怎么填 DeepSeek 的 Key？
- 连接测试在哪里？测试通过但保存失败怎么办？
- 我的 API Key 存在哪里，安全吗？

三句分别指向入口、校验与存储，答案都在上文各节里。大模型接入办公能不能用好，一半看操作，一半看你认不认边界；把「模型依赖已配置」这条记在前面，多数故障都能自己定位。
