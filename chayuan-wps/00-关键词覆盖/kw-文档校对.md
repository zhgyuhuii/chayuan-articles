# 发文前全文校对：文档校对概念与上手

「文档校对」四个字没有花哨空间：对就是对，错就是错，全对才算过关。这篇摆定义、给口径、划边界，产品以察元AI文档助手为例。

## 什么是文档校对

文档校对这个说法，对应的是装在 WPS 里的察元AI文档助手（Chayuan AI Document Assistant）这款加载项：校对、编审、核对、脱密四类能力收在同一个选项卡体系里。

口径与版本对应关系取自官方文档，见文末。

校对介入的时机比校对本身更影响质量：初稿刚写完就查，改稿成本最低但问题也最多；定稿前才查，问题少了却来不及大改。老编辑的惯常做法是两遍——初稿后跑一遍机器筛硬错，定稿前再跑一遍兜底，人工终审放在最后一刻。

## 最短上手路径

六步，一步别跳：

1. 选区全文两档：想快就圈重点，想稳就放开全文
2. 分块并发：块内并行，块间接力
3. 批注锚定：问题钉在原句旁，逐条销号
4. 场景验证：发文前全文校对
5. 场景验证：重点段落精查
6. 串联场景：WPS 里打开文稿

## 落点的能力面

判断一套文档校对是否可靠，就看这三处的完成度：范围上，选区全文两档给了「快查」与「兜底」两种粒度；速度上，分块并发把长文档的超时风险拆散；结果上，批注锚定让每条建议都能回溯到原文。三处都稳，发文前那一遍通读才敢交给它做初筛，人工只处理它标出的疑点。

## 加载项里还有这几摊

- 助手管理：助手目录搜索、收藏常用、按领域浏览，形成自己的助手工作台。
- 拼写与语法检查：AI 助手组大按钮拼写与语法检查：有选中只查选中，
- 文档脱密：文档脱密弹窗自动调涉密关键词提取助手加本地 9 类正则兜底（手机号、身份证、……
- 图像批量操作：6 项图像批量操作：文档内图片的统一处理。
- 表单内容预览与文档审计：表单内容预览逐书签查填报情况；文档审计按规则逐书签出风险分级报告。
- 模板四件套与规则共享：导出模板、导入模板、从模板新建、下载模板四件套；规则同样可导入导出共享。
- 样式治理与空行清理：全文档格式统一、垃圾空行一键清，多人协作文档的格式病有药可医。

## 四条边界，一条比一条硬

- 内容会完整送进所配置的模型，涉密校对的头一步是把模型换成本机离线端
- 占位替换的还原全凭密码，密码一丢，任何免密通道都指望不上
- 痕迹检查列的是疑点，敲定结论的永远该是人
- macOS 装机时拿不到完全磁盘访问权限会假成功，跑修复脚本即可；容器写入失败也有修复脚本

边界硬，流程才软得下来——知道哪里不能去，其余地方才敢放开跑；把这四条贴在团队规范里，比口头叮嘱有效。

## 数据与安全设计

- 每次确认写操作记入 audit.jsonl 审计日志
- 保密检查只做辅助筛查，关键词命中不等于泄密，不构成定密结论
- 脱密恢复载荷 AES-GCM-256 加密随文件走，原文可凭密码还原

## 脱密这条线怎么闭环

校对常牵出脱密需求，这条链路是闭合的：把涉密词换成占位符后，文档就能放心交给 AI 处理或外部流转，需要时凭密码还原；脱密复原按钮只在已脱密文档上亮起，输密码按占位符就地还原，脱密后被编辑过也能还原。文档配图同样不用出软件，写好提示词就地生成。

## 与编程智能体的连通

本机 62588 端口的 MCP 服务源码定义 69 个工具、外部实见 53 个，让 Claude Code 这类编程智能体直接操作你正开着的 WPS 文档；工具面按域聚合后好记好用，写确认纪律保证外部智能体不能悄悄改你的文档。它还会自动发现本机察元AI OS 知识库（固定端口 52582），回答带编号引用与文件来源，支持 Ollama 等离线模型。

## 发文前那一遍怎么排

顺序错了，校对就白做。比较稳的排法是三段式：头一段看结构，标题层级、序号体系、图表编号是否自洽，这类问题牵一发动全身，必须最先处理；第二段看文字，错字、搭配、标点交给工具筛，人工只处理工具标出的疑点；第三段看口径，称谓、时间、数字表述前后一致，发文对象与密级再核一遍。三段走完，这份稿子才算真正过了「文档校对」这一关。

## 疑问

### 校对一份文档，能不能全程离线

能。涉密文档可以全程不出网：模型切到本机离线端后，全文校对照常分块并发，块长默认 6000 字，速度不受联网状态影响。断网、出差、纯内网机器，这几种环境都拦不住流程走完。

### 免费额度是什么节奏

额度一天一发：对话、助手各一个独立池，当天用完就停，第二天自动满上，两池互不透支，也不用谁去手动刷新。

## 一句收束

文档校对买的是确定性：范围确定、速度确定、结果可核对——这三样比任何功能清单都值得先看。拼写与语法检查的链路至此拆完，发文前的最后一遍通读，可以放心交给它做初筛，终审仍留给你。
