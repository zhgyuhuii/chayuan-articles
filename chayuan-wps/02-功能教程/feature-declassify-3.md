# 涉密关键词场景拆解：脱密占位替换是可逆设计

涉密关键词这件事，值不值得专门学一篇，看一个细节就够：AI 加正则双路提取。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI文档助手。

## 先看看痛点对不对得上

涉密素材交给 AI 润色前处理；涉密/内部文档需要在外部流转（送审、协作、演示）前遮盖单位名、人员名、编号、联系方式等敏感内容；遮盖不是永久销毁：原文以加密形式随文档保存，后续凭密码可完整还原；先用「保密检查」摸清风险点，再把确认要遮盖的词统一做占位替换。

## 完整操作步骤

从这几步开始：（第 3 个切入角度）

1. AI 加正则双路提取
2. 占位符可逆
3. 加密载荷随文件走
4. 确认边界：仅文字端提供，且属于付费专属能力（零免费额度）
5. 确认边界：忘记密码没有任何免密恢复通道
6. 场景验证：把内部报告脱密后发外部评审

## 这些坑和边界要知道

- 脱密占位替换是可逆设计，忘记密码没有任何免密恢复通道
- 忘记密码没有任何免密恢复通道
- 仅文字端提供，且属于付费专属能力（零免费额度）

## 高频疑问

### 对已脱密的文档又点了「文档脱密」？

按钮此时是置灰的；若从其他入口打开脱密窗口，会提示「当前文档已经处于脱密状态，请使用“密码复原”恢复后再操作」。先复原再重新脱密。

### 脱密执行中途出错了会弄坏文档吗？

替换写回失败时系统会用原文整体回写，避免文档停留在半替换状态；具体失败原因显示在弹窗错误条中，可修正后重试。若所选关键词在文档中一个都没命中，执行会被拦下并提示「所选关键词未在当前文档中命中，无法执行占位符脱密」。

### 检查涉及把全文发给模型，涉密文档安全吗？

关键词提取会把文档内容送给你选定的模型服务。涉密程度高的文档，建议先在设置里切换到本机离线模型再执行脱密。

## 更多操作细节

验证

1. 回到正文：原关键词位置已变成 §8 位随机码§ 形式的占位符，格式排版不变；
2. Ribbon 状态翻转：「文档脱密」按钮置灰，「脱密复原」按钮亮起；
3. 打开任务清单（「察元AI编审」＞「察元设置」＞「任务清单」）：能看到「涉密关键词提取」「占位符脱密」两条任务；点开涉密关键词任务详情，有「序号 / 原文关键词 / 占位符 / 分类 / 风险 / 脱密原因」表格，任务条目显示「共 N 个涉密关键词」。

## 安全与数据边界

安全口径单独立一层：自动发现本机察元AI OS 知识库（固定端口 52582），回答带编号引用与文件来源；每次确认写操作记入 audit.jsonl 审计日志，脱密恢复载荷 AES-GCM-256 加密随文件走，原文可凭密码还原；语种动态菜单逐段安全替换写回：译文直接替换原文段落，保留格式。

## 平台与形态

平台与形态的账：发文自检的最后一道闸：判据是语义与上下文，关键词只是线索而非结论；保密风险概览五卡（高危任务、中危任务、关键词命中任务、未见明显风险、最近保密检查）；涉密文档可以全程不出网，全文会发送给所配置的模型，涉密文档建议先切到本机离线模型。
