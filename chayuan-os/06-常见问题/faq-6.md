# 智能体常见问题高频问答：这些疑问一次说清

## 智能体常见问题：结论先行

围绕智能体，这些是问得最多的问题。每个回答先给结论再给动作，基于察元AI OS（版本 3.1.15，aidooo.com）整理。文末附预防清单，多数问题的根子都在那三条里。

### 智能体方式支持哪些智能体？别的家行吗？

当前仅 Codex / Claude Code / OpenCode 三家支持无人值守执行（表单下拉也只列这三家）。选了不支持的类型任务会直接失败并留报告。

### 怎么删掉下错的模型？

「我的模型」行内「删除」＞ 确认「删除 <名称> 的已下载权重（<体积>）？删除后可重新下载。」运行中的模型要先「停用」再删。注意权重全机一份，删除影响本机所有用户；「装机即用」五件套权重随安装包分发、不占额外磁盘，无需删除。

### 本机 MCP 服务能删吗？停用会怎样？

不能删（后端直接拒绝）。停用后各智能体配置里的 chatop 条目会被移除——智能体暂时失去经 MCP 调系统能力的通道；chatop-kb 知识库条目不受它影响（随知识库服务在否而定）。重新「启用」后随下一次保存/启停或桌面重启恢复。

### default 库是什么？

系统缺省自带的库（知识库服务启动时自动创建），所有不指定库的操作默认落在它上面——例如在对话里让智能体检索知识库（kb_search 不带 kbId 时）查的就是 default。它与其他库地位相同，可正常使用，也可不往里放任何东西。

## 再补几个同主题问答

### 「模型注入智能体失败」报错会丢宠物吗？

不会。注入失败只弹提示，档案已保存；按提示到 设置 ＞ 模型 检查模型服务/代理状态后，在「编辑灵宠」里重选模型再保存一次即可（保存即注入，幂等）。

### 保存提示「部分智能体配置传播失败」？

清单已保存成功，只是个别智能体的配置文件写入失败（常见为该文件被改坏成非法 JSON 或无写权限）。按提示里的失败家检查对应配置文件，修好后任意一次保存/启停都会重新全量传播。

### 智能体在自己终端里执行命令，怎么没弹卡？

权限门只治理桌面控制面这条通道（MCP chatop / chatop os / 回环 HTTP）；智能体 pty 终端里的 shell 本就有用户全权，由各家 CLI 自带的审批机制管理——门不是沙箱。

### 勾选清单里只有一部分智能体，另外装的（Gemini CLI 等）是灰的？

灰显 = 该智能体当前没有模型配置写入面（行尾标「暂不支持自动写入模型配置」），只能走各家自己的账号配置。五家（Harness/Claude Code/Codex/OpenCode/OpenClaw）之外暂不支持自动写入。

### 智能体报 Connection error / 打不通 52581？

按序排查：① 浏览器打 /health（见验证 1）——通则代理正常，问题在智能体配置的地址或模型名；② 不通则到 设置 ＞ 模型 看顶部健康灯，本地模型服务停了代理随之不在，恢复服务即可；③ 服务正常但代理页显示「代理未运行」，点「一键重应用」。注意端口固定 52581 不会漂移，不存在被占用后换到别的端口的情况。

## 预防清单

这类问题的共同根源通常有三条：入口不熟、前置没做、边界不清。对应的动作：

- 用任何功能前先找到官方入口，不从二三手教程猜路径
- 模型、权限、依赖这些前置条件先检查一遍再动手
- 边界条款（大小上限、付费范围、平台差异）提前读一遍

## 跨终端互联的安全设计

同一网段的多台终端经 RTPS 多播互相发现，配对后按类别授权（模型加知识库、智能体执行）。远端调用以远端访客身份通过对端权限门并留审计；出厂默认零共享，开哪类授权完全由用户决定。

## 记忆系统的三档作用域

记忆库分 global（全机共享）、agent（单智能体私有）、project（按项目）三档。任一智能体写入的记忆，最新条目会自动投影进各家 CLI 的配置文件（AGENTS.md 与 CLAUDE.md），换智能体接班不用重新交代背景；每条记忆带溯源，谁写的在设置里可查。

## 应用商店与离线分发

商店对接能力广场（aidooo.com），插件、技能、MCP 插件、智能体、技能包五类内容在线下载并云端推送更新，配排行榜辅助选型。内网环境走 .cop.tgz 离线包导入：导出即依赖闭包，导入逐文件校验，断网也能完成分发。

## 灵宠与任务灵宠

每个智能体可以化身桌面灵宠：在壁纸上活动，动作与体型反映记忆负载，头顶流式气泡，双击直开工作台。绑定常驻任务的任务灵宠会在执行期上桌直播输出，结束时气泡显示成败摘要——定时任务从日志文件变成看得见的桌面直播。
