# 出招解析容错链：从标准JSON到截断补尾

向大模型要 JSON 是一场开盲盒：你在提示里写明格式要求，它回你一段裹着代码围栏的思维链，外加开头结尾两段寒暄。出招解析容错链就是为这个现实准备的：模型给出的原始文本，要经过一整条逐级放宽的清洗流水线，才可能变成裁判认可的一步棋。这篇按链路顺序拆解每一级做了什么、为什么按这个顺序排。

## 模型不按格式说话的几种姿势

先看对手有多难缠。推理型模型把思考过程包进思维链块，答案混在几百字的自我辩论里；受过代码语料熏陶的模型，热衷把 JSON 装进代码围栏再配一行语言标注；有的模型在 JSON 前后加「好的，以下是我的出招」这类客套；输出被 token 上限截断时，结构碎在半山腰；还有模型在键名与动作串里混入换行与全角空格，肉眼难辨，机器比对就崩。任何一种形态，都足以让一次天真的标准解析当场失败。

## 容错链逐级拆解

出招解析容错的第一级是剥思维链块：把包在思维链标签里的推理文本整体摘掉，只留答案部分。第二级剥代码围栏：去掉成对的围栏标记与语言标注，取出里面的净文本。第三级抽大括号：从混合文本里定位最像 JSON 的那一段，找成对的花括号，把中间的内容抠出来。

第四级截断补尾：对被截断的 JSON 做猜测性修复，按顺序先补引号再补花括号。顺序有讲究：引号不闭合时，后面的字符都被当成字符串内容，此时去补花括号，补出来的结构照样是坏的；先把开着的弦关上，再一层层关括号，结构才立得住。第五级空白规整：清掉混进键名与值的换行、多余空格，让字符串比对回到同一基准。第六级正则抽取：前五级都失败时，退而用正则在全文里搜动作字段的踪影。

跟着一个倒霉样本走一遍：模型输出以代码围栏开头，围栏里 JSON 写到一半被 token 上限截断。前两级剥掉思维链与围栏，第三级抽出残缺的花括号段，第四级发现字符串没闭合，先补引号再补花括号把结构立起来，第五级清掉动作串里混进的换行，标准解析终于通过。六级各干一件事，谁也没抢谁的活。

再往后还有两级：全文扫描合法动作串的回捞，与不看文本的启发式代走——那两层各有专门的设计，另文细讲。本文的重点是前面这六级清洗。

## 升级序列的设计逻辑

链路的排序原则是置信度递减、破坏性递增。剥思维链与剥围栏是有明确锚点的操作，删掉的文本边界清晰，置信度高；抽大括号开始有认错段落的可能；截断补尾已经是猜测性修复；正则抽取更是宽打宽用。顺序不是拍脑袋定的，是按错误代价排的：越靠前的操作越可逆、越不容易改动内容本身，越靠后的越激进。每一级产出都会立刻尝试标准解析，成功即停，绝不为了炫技把整条链跑满。这个「成了就收手」的纪律很重要：清洗动作本身就是对模型输出的干预，多干预一分，歪曲模型本意的风险就多一分。

出招解析容错的工况与模型的协议素养直接相关。协议画像统计每个模型的 JSON 格式遵守率，强模型可能常年停在前两级，弱模型则天天把整条链走到头。这也是观察模型成熟度的一个侧面：格式遵守率高的模型，通常在其他环节也更让人省心。

解析链住在引擎层的 LLM 玩家里，不在网关侧，这是职责使然。解析要对照当前局面的合法动作清单，而清单由裁判引擎给出，两者放在一起，比对才是本地调用；塞进网关会把规则知识外泄到传输层，架构就乱了。顺带说一句性能观感：这条链全是本机字符串处理，没有网络往返，单手解析的开销远小于一次模型请求本身，容错的代价主要在逻辑复杂度，不在你等模型出招的时长上。

## 边界

容错链不是万能钥匙，几条边界要认清。补尾是猜测性修复，补出来的 JSON 未必是模型本意，所以链路末端还有「只认合法动作清单成员」的闸门：修复产物里的动作若是非法串，照样被拦，绝不因为解析成功就放行非法棋。链路全程失败也不会卡死对局——重试回喂会把错误信息喂回模型再要一次，仍不行就启发式代走，代走超限判负，一局棋不会被一个抽风的模型 API 拖死。另外，解析是启发过程，存在把模型本意修歪的可能，极端情况可以从对局室的原始输出里自己核对：哪些手是模型本意、哪些走了兜底，结合思维链气泡的有无与复盘大体能看出来。

### 出招解析容错为什么不直接报错重试

重试是有的，但放在链路之后。多数格式破损可以本地修复，省掉一次昂贵的重新请求；重试留给真正无法挽回的输出。顺序反了，费用与延迟都会翻倍——每次格式瑕疵都打回去重问，弱模型的对局成本会失控。

### 容错链每一级都会跑一遍吗

不会，成了即停。每一级产出都会立刻尝试标准解析，成功就不再往下走；强模型的输出通常剥完思维链或围栏就通过了，整条链跑满的多半是协议素养欠佳的模型，这本身就是一种画像信号。

### 补尾补出来的 JSON 和原文差多少

只差结构收尾：闭合未完的字符串与花括号，不增删任何已有内容。它救回来的是「被截断的那句话」，不是新编的一步棋；动作是什么，仍以原文里已出现的字段为准。

### 截断补尾会不会补出错误的一步棋

会补出结构完整的 JSON，但动作未必合法，这正是末端闸门存在的意义。补尾只负责让结构立起来，动作合不合法由裁判的合法清单说了算，两道工序各司其职，谁也不越界。

### 思维链块剥掉后信息就丢了吗

对解析而言是丢了，对展示而言没有。对局室的思维链气泡实时流式展示的就是这段推理，剥离只发生在解析路径上，你看得到的照样看得到。

出招解析容错链是一段工作量藏在细节里的代码：每一级单看都不起眼，合起来才撑住了 85 家厂商、参差不齐的输出质量之下「一局能打完」的底线。工程里值钱的往往不是聪明办法，而是把笨办法排对顺序。
