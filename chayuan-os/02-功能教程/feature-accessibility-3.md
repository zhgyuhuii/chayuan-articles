# 界面缩放场景拆解：高分屏调缩放

界面缩放这件事上手不难，难的是选对档位、知道改动会影响什么。这篇把察元AI OS 的界面缩放从入口到联动行为梳理一遍，高分屏调缩放的思路也一并给出。

## 为什么值得了解

远程桌面或虚拟机里跑察元OS，动画与玻璃模糊会拖累帧率，全关掉换流畅是常见诉求；对动效敏感、容易眩晕的人同样需要减少界面动画；老机器靠关动效提速、高分屏靠调缩放找平衡，都落在同一个设置区里。

## 辅助功能：从入口到完成

第 1 步 · 进入辅助功能设置

1. 在哪里：Dock 点开「设置」应用，左侧栏选「辅助功能」分区。
2. 看到什么：标题为「视觉」的一张卡，说明文案：「减弱动效关闭 Dock 放大/弹跳与过渡动画；减弱透明移除玻璃模糊；界面缩放调整整个桌面（远程桌面/低性能环境建议开启前两项）。」

第 4 步 · 界面缩放

1. 这一步做什么：在「界面缩放」下拉框选一档：「85%」「100%（默认）」「115%」「130%」。
2. 这一步看到什么：整个桌面（含窗口、Dock、菜单栏）按所选比例即时缩放，无需重启。

连带联动的行为（无需另设）

1. 关窗特效：只要「减弱动效」开着，设置 ＞ 显示器 ＞ 窗口动效里选的 Burn-My-Windows 特效一律回落普通淡出；
2. Dock：「减弱动效」一开，图标放大/弹跳这类过渡动画跟着停（设置页说明原文：「减弱动效关闭 Dock 放大/弹跳与过渡动画」）；
3. 开关机画面：重启/退出的过渡动画一样会尊重「减弱动效」；
4. 智能体可代管：三个键都是系统设置工具的可读写键，一句「帮我把界面放大到 130%」就能让智能体改。

## 关键能力点

- 三开关即开即生效：勾上立刻起作用，取消立刻还原

## 落手前把限制看全

- 对话模型一次载入几个，看内存说话：8GB 的设备载一个即可，复杂任务会受限
- 云端厂商模型要用，得先备好各自的 API Key
- Docker 云桌面、跨终端互联是给爱折腾的人准备的进阶形态
- 龙芯平台不在本版支持范围；视频生成不落地本地，由云端路由出片

## 疑问集中答

### 「减弱动效」开启后，关窗特效为何不播了？

正常现象。减弱动效的优先级更高，关窗特效被自动压成普通淡出，显示器设置的窗口动效卡说明里写明了这一行为；想看特效，得先取消「减弱动效」。

### 界面缩放只对部分窗口起作用吗？

不是。全局 zoom 作用于整个桌面文档根，察元OS 里的应用窗口、Dock、菜单栏一起跟着缩放；智能体打开的原生网页窗这类壳外窗口例外。

### 减弱动效开着，Dock 的放大效果没了，坏了吗？

没坏，这是设定使然：减弱动效把 Dock 放大/弹跳一并关了（设置页说明写明）；想恢复放大，取消「减弱动效」就好，位置/大小设置照旧。

## 第 2 步 · 勾选减弱动效

1. 这一步做什么：勾选「减弱动效」复选框。
2. 这一步看到什么：立即生效——全界面注入 animation/transition 全部禁用 的样式，Dock 图标放大/弹跳、窗口过渡动画、锁屏/开关机动画全部停；「关窗特效」即使选了特效也会自动变成普通淡出。
3. 取消勾选即恢复动画。

## 第 3 步 · 勾选减弱透明

1. 这一步做什么：勾选「减弱透明」复选框。
2. 这一步看到什么：立即生效——移除全部毛玻璃模糊（backdrop-filter），半透明面板/弹窗变成实底显示。
3. 想恢复玻璃效果，取消勾选即可。

## 全部配完后的验证

1. 鼠标扫过 Dock（减弱动效开着），图标不放大不弹跳；开关应用窗口也看不到过渡动画。
2. 到 设置 ＞ 显示器 ＞ 窗口动效 把「关窗特效」选为非「无」的档位，保持「减弱动效」开着关窗——特效不播放（回落普通淡出）。
3. 把「界面缩放」切至「130%」，整个桌面元素马上变大；回到「100%」即复原。

## 补充答疑

### 辅助功能的三项设置，换台机器还会保留吗？

不会保留。三项配置只存在浏览器本地（localStorage），换机器或清了数据就得重新设置；智能体同样能经系统设置工具读写这三个键。

### 远程桌面卡顿，推荐怎么配置？

设置页说明文案里直接写了建议：远程桌面/低性能环境建议开启「减弱动效」+「减弱透明」前两项。

## 收尾前的要点清单

- 没有特殊前置：任何形态（桌面/网页/Docker）进 设置 ＞ 辅助功能 即可配置。
- 三项设置写在浏览器本地（localStorage 键 chatop_reduce_motion / chatop_reduce_transparency / chatop_ui_scale），即时生效、无需重启。
- 这三个键同时也是智能体可读写的系统设置键（设置工具 chatop_reduce_motion 等）——也可以直接对话让智能体代为开关。

## 它在整套桌面里的位置

界面缩放之外，这套桌面还有不少联动的部分：内置终端跑真实 shell、会话持久、环境延续；智能体对一台桌面能施加的操作，约等于熟练用户的操作集合，内置终端是明证；文件打开不挑格式，系统级默认打开体验；WebRTC 局域网共享桌面分主机、编辑者、观看者三级角色，共享房间与连接终端状态都可见。

## 账户与数据的几条边界

记忆功能需要提前打开并攒下足量数据，临时启用派不上用场；管理员侧管用户的动作很全：建号、停用、删除（删除会抹掉该用户全部数据），普通用户的密码重置、在线踢下线、开机登录开关也都归它管；全新安装时指定数据目录或导入拷贝根，再建管理员；目录位置自定，整套系统便能落在非系统盘，日后换机整目录搬走即告迁移；智能体不知道自己有哪些本机工具可用，就谈不上真正上手，技能手册镜像让它们开箱即会调用系统能力。

## 形态与端口速记

网页桌面（web/Docker 形态）落在默认端口上；对外暴露时发 9 位字母外网后缀链接，会话管理（wa）与踢线都从管理端做；内嵌浏览器窗经 webwindows 机制能被智能体接手；整套系统也能以无头方式驻留 Docker，作为多用户云桌面（察元AI工舱形态）供员工浏览器直达。
