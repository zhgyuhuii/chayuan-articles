# Docker端口冲突装机指南：团队统一 AI 工位

Docker端口冲突这件事，值不值得专门学一篇，看一个细节就够：浏览器即用。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 安装前确认

- 系统要求：任意可跑 Docker 的服务器
- 安装包：docker compose（察元AI工舱形态）
- 说明：端口占用与映射调整。

安装包从官网 aidooo.com 获取。

## 一步步来

1. 获取 docker-compose.yml
2. docker compose up -d 启动
3. 浏览器访问默认 52584 端口得到多用户网页桌面
4. 账户隔离，数据在服务器侧统一管理

## 怎么确认做成了

- 启动进入桌面，对话应用选本地模型能正常回复
- 首启初始化需要 5 到 30 秒，属正常现象，期间不用干预

## 这些坑和边界要知道

用之前要认的账：

- 云端厂商模型调用需自备 API Key
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 更多操作细节

起一个云桌面

1. 服务器上准备 docker compose 配置
2. docker compose up -d 启动工舱
3. 按需暴露端口（默认回环，外网访问自行映射）
4. 员工浏览器打开地址，各自账户登录使用

## 更多操作细节

上线前检查清单

1. 默认端口 52584 是否被占用（compose 映射可改）
2. 按团队人数评估内存：每并发一个本地模型约吃数 GB
3. 数据卷挂载出来，升级与备份都靠它
4. 管理员账户先建好，再开放普通用户注册

## 补充答疑

### 云桌面和桌面版功能一样吗？

核心能力面一致（对话、知识库、模型、办公），形态差异在：云桌面无本地文件直通、语音输入依赖浏览器权限、部分外设在浏览器里受限。

### 多少人共用一台服务器合适？

取决于是否同时跑本地模型：只做对话与知识库，十几人一台中配服务器可行；要并行跑本地推理，按并发数加内存或改用厂商模型分流。

### 数据存在哪里？

全部落在服务器的数据卷里（含用户空间、知识库、配置），挂载出来后备份一个目录等于备份全组。

## 能力面再摊开一层

- 浏览器即用
- 账户隔离
- 数据集中管理
- 端口暴露面自控

## 放回产品盘面看

把Docker端口冲突放回察元AI OS的整体盘面：（知识库对外服务，固定端口）；（本机 MCP HTTP 服务，回环免 token），docx/xlsx/pdf/csv/html 与扫描件 OCR，单文件不超过 48MB，GGUF、whisper 权重可以按路径直接导入（零拷贝）。

## 安全与数据边界

安全口径单独立一层：本机 Stable Diffusion 链路出图不联网，隐私与免费兼得，一台设备多人用，数据隔离是底线，管理员统一管账号比各自为战安全；隐私敏感环境先关遥测再干活，处置设备前清数据；（知识库对外服务，固定端口）。

## 平台与形态

平台与形态的账：整套系统无头跑在 Docker 里作为多用户云桌面（察元AI工舱形态）：员工浏览器打开即用，web 与 docker 形态提供 9 位字母外网后缀访问链接、wa 会话管理、踢线操作，Dock 文生图应用：提示词加负面提示词，生成后可设为壁纸或开 30 分钟自动换壁纸；设置桌面与 Dock：位置、自动隐藏、图标放大与大小、开机自动打开 Harness。
