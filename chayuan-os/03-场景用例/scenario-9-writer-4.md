# 写作者提效实录路线：AI写作这样落地

如果你是写作者，下面这些场景大概率不陌生：灵感与资料管理割裂。长线写作的上下文管理。这篇深度复盘以察元OS为工具，把这个岗位的AI写作工作流从头到尾串一遍。

## 这个岗位的三个真实痛点

- 灵感与资料管理割裂
- 长期项目上下文丢失
- 多智能体写作风格不一

## 用察元OS怎么解：工作流拆解

1. 共享记忆保持项目上下文
2. 知识库放参考资料
3. 本地模型保隐私

## 一天的使用节奏示例

以一个工作日为例：早上到岗先处理积压材料，用「共享记忆保持项目上下文」完成首轮处理；上午协作时段按流程推进；下班前把当天产出归档。长线写作的上下文管理。工具不改变职责边界，只是把重复劳动压缩掉。

## 边界与注意事项

- 生成类结果需要人工确认后采用
- 四家 CLI 智能体二进制约 1.3GB，完整安装占磁盘较大
- 建议先在低风险材料上试跑，形成自己的使用习惯后再铺开

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- API Key safeStorage 加密存储，仅注入子进程
- 全部本地服务只监听 127.0.0.1，数据不出本机
- 本地模型五件套随软件分发，断网即用

## 如实说说它的不足

- 四家 CLI 智能体二进制约 1.3GB，完整安装占磁盘较大

## 常见问题
### 知识库支持什么格式？

PDF、Word、Excel、HTML、Markdown、TXT 与图片 OCR；单文件 ≤48MB，异步摄取不阻塞。

### 知识库检索质量如何？

向量（sqlite-vec）+全文（FTS5）混合检索加 RRF 融合，可选 bge 重排精排与邻块扩窗；大库可选 Milvus 向量库。

### 支持哪些系统？

Windows 10/11（x64/ARM）、macOS（Apple Silicon/Intel）、Linux x64/arm64（deb/AppImage；银河麒麟 V10、统信 UOS 有专门适配），另有 Docker 服务器形态。
