# 标书校对清单式指南：招投标专员场景全拆解

如果你是招投标专员，下面这些场景大概率不陌生：截标前通宵改稿，错字与口径硬伤风险高。冲刺期的四步质量兜底动作。这篇清单式指南以察元文档助手为工具，把这个岗位的标书校对工作流从头到尾串一遍。

## 这个岗位的三个真实痛点

- 截标前通宵改稿，错字与口径硬伤风险高
- 多人分段合稿术语不一
- 甲方对 AI 生成痕迹敏感

## 用察元文档助手怎么解：工作流拆解

1. 「扩写/缩写」控制篇幅与密度
2. 「术语统一」归一全文口径
3. 「AI 痕迹检查」评估并改写高疑似段落
4. MCP 多文档校对对整目录标书兜底

## 一天的使用节奏示例

以一个工作日为例：早上到岗先处理积压材料，用「「扩写/缩写」控制篇幅与密度」完成首轮处理；上午协作时段按流程推进；下班前把当天产出归档。冲刺期的四步质量兜底动作。工具不改变职责边界，只是把重复劳动压缩掉。

## 边界与注意事项

- AI 痕迹评估为保守参考，不构成定性
- 脱密/复原/涉密检查/涉密关键词提取是付费功能（每日免费 2 次共用池）
- 建议先在低风险材料上试跑，形成自己的使用习惯后再铺开

## 离线运行与部署形态

从 4.0 版本起，安装包内嵌 sidecar 单文件二进制并注册开机自启，适配离线、内网与县级环境部署；推理指向本地或内网端点后，文档内容不出本机。MCP 服务只监听 127.0.0.1:62588 回环地址，本机即信任边界，远程机器无法直连——这是「涉密不出域」的安全设计，可用环境变量 CHAYUAN_MCP_PORT 调整端口。

## 数据安全与隐私边界

- 知识库凭据采用 AES-GCM + HKDF 端侧加密落盘，密钥派生自设备绑定 OPFS 盐，明文永不落盘、不参与同步
- 发布包逐源 sha256 强校验（Gitee→aidooo→GitHub 多源回退），防供应链篡改
- 匿名指标上报默认关闭（opt-in），不采集文档内容
- MCP 服务仅监听 127.0.0.1:62588，无需 Token 与命令行，sidecar 与 WPS 同机运行，文档与密钥不出域

## 费用与授权的边界（如实说明）

开源（Apache-2.0）免费使用 + 付费高级功能不限量授权。免费部分：免费版对话每日 30 次；执行助手、文档脱密、脱密复原、涉密检查、涉密关键词提取每日 2 次（共用池）。付费部分：文档脱密、脱密复原、涉密检查、涉密关键词提取为付费功能，购买后不限次数；序列号（授权码）与本机设备指纹绑定，仅限本机，支持离线激活验证

## 常见问题
### 企业能内部署吗？

可以。官网提供四档形态：加载项（个人）、桌面版（单机断网）、服务版（Docker 全科室共用）、至臻版（数百到上万人网络版）。

### 支持国产化环境吗？

支持麒麟、UOS 等国产化环境（arm64/x64），真机验证过 Ubuntu arm64 + WPS Office 12.1 组合。

### 外部智能体怎么连接？

在支持 MCP 的客户端里添加服务地址 http://127.0.0.1:62588/mcp 即可；安装器会自动把使用技能投放到 Claude Code/Cursor/Codex 的技能目录。
