# 用混合检索实操解决实际问题：场景化用法全记录

混合检索实操这件事，说简单也简单，说麻烦是真麻烦——麻烦不在功能本身，在于信息散落在各处，拼出一个完整流程要查好几篇资料。这篇文章把它一次讲全：是什么、入口在哪、具体步骤、边界在哪，全部基于察元AI OS的真实界面。

## 解决什么痛点

先测检索命中再上线问答；文档加载完，想先验证「能不能搜到、搜得准不准」再接给智能体用；智能体检索效果不对时，用同一个测试台对照排查（这里看到的＝kb_search 拿到的）；给领导的回复附上制度原文出处。

用户常搜的问法：知识库检索怎么测试？搜出来跟智能体查的一样吗；AI 回答后面的 [1][2] 是什么？怎么看出处原文。

## 一步步来：从入口到完成

模式切换

1. 右栏顶部有一个双挡切换：「问答」（默认）｜「检索」。点哪挡进入哪挡测试台（切换后原测试台的输入与结果不保留）。

「检索」· 检索测试台

想临时关掉语义路：到「设置」页签，嵌入链路卡里把「语义检索」切到「关闭」（旁侧提示「已关闭：仅全文检索」）。

1. 在输入框（占位符「检索知识库（全文 + 语义混合）…」）输入关键词或自然语言问题，点「检索」按钮或按 Enter（检索期间按钮转圈忙碌）。首次进入、还没搜过时面板显示说明卡：「检索测试」＋「输入关键词或自然语言问题，验证向量化与混合检索的效果；这也是 agent 工具 kb_search 看到的结果。」
2. 看到什么：命中的块以卡片列表返回，最多 8 条，按相关性从上到下排——每张卡片＝绿色序号徽章（1、2…）＋「文档名 · 标题路径」（标题路径即该块所属章节，如「第三章 > 报销流程」）＋命中文本片段（超长截断，尾部注明「（截断，完整原文用 kb_read_doc 按 docId 分页读）」；片段区域可滚动）。没有命中显示「没有命中——换个说法或检查嵌入模式是否开启。」。
3. 检索是怎么排序的（理解结果用，三步）：
    1. 一路向量近邻（语义相似，需要嵌入链路）＋一路 FTS5 全文（字面匹配；全文索引支持中文子串检索——环境不支持时退化为整词匹配）各自取候选；
    2. 两路按 RRF 融合排序取前若干，命中块连带前后相邻块扩窗拼接（所以片段里可能出现「…」衔接）；
    3. 重排（rerank）没有手动开关——本机模型服务里加载着 rerank 模型（如 BGE Reranker）时自动对候选精排；实例不在运行时自动回落融合次序。
    4. 嵌入模型换过会怎样：检索发现指纹不符时，「文档」页顶部出现橙色横幅「嵌入模型已切换（{stored} ＞ {now}），语义检索暂不可用，当前仅全文检索」（花括号处显示旧/新模型名），检索自动降级为纯全文继续出结果；横幅右侧「重建索引」按钮可一键重嵌全库（进度回到「文档」页看）。

「问答」· 引用式问答

选中的模型只对当前应用会话生效（按钮上显示所选模型名），不改设置页的默认对话链路；切库不影响所选模型。

1. 在底部输入框（占位符「基于知识库提问…（本地模型优先，云端兜底）」）输入问题，点「提问」或按 Enter（Shift+Enter 换行）。首次进入显示说明卡：「引用式问答」＋「回答只基于当前知识库，并标注引用出处；未加载本地模型时自动走云端兜底（可在设置里配置）。」
2. 看到什么：回答流式逐字输出（等待第一个字时显示「检索并生成中…」）；回答正文在依据处标注 [1][2] 引用编号；每轮回答（气泡）下方有「搜索到的文件」一行出处条——每个出处是一个「序号＋文档名」小胶囊。问答是多轮对话：提问后输入框清空，历史问答一直保留在面板里，可连续追问，列表自动滚到最新。
3. 看出处原文：点击任一出处胶囊，右侧滑出片段面板——头部＝序号＋文档名＋「下载文件」按钮＋关闭 ×；面板内先显示该块的标题路径（有则显示），下面是出处原文片段（该出处没有可展示文本时显示「（该出处没有可展示的片段文本）」）。再点同一胶囊收起面板，点别的胶囊切换内容；「下载文件」直接把该出处的原文件下载回来（保留原名）。
4. 答不了的问题：上下文不足以回答时，模型按系统规则回答「知识库中没有找到相关内容」，不编造——看到这句说明库里确实没有相关内容，或检索词太偏没捞到。
5. 会话内临时换模型：输入框左侧有一个模型按钮（对话气泡图标＋当前模型名，默认显示「自动（推荐）」），点击弹出模型树，顶部说明「选择本次会话的对话模型（不改动设置页默认链）」，树内容自上而下：
    1. 「自动（推荐）」——旁注「本地优先，云端兜底」；
    2. 「本地模型 · N」组：列出本机对话模型，行尾带「运行中/未运行」状态；模型未运行且模型代理不可达时该行灰选，悬停提示「模型未运行且代理不可达——先到「模型设置」启动」；组头出现「代理未就绪」标记表示懒加载通道不可用；
    3. 各厂商组（有模型清单的厂商才显示；密钥没配的组头带「密钥未配置」标记）；
    4. 「自定义 OpenAI 兼容」。

## 关键能力点

- 混合检索三路融合
- 编号引用可展开
- 会话内换模型
- 源文件可下载

## 它的局限也要说清楚

边界都在这：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重

## 高频疑问

### 片段为什么被截断？

检索面的单块片段有 1600 字符上限（截断处注明「（截断，完整原文用 kb_read_doc 按 docId 分页读）」），防止整篇文档灌进对话上下文。要看完整原文：出处面板「下载文件」拿原文件，或让智能体用 kb_read_doc 分页读。

### 检索「没有命中」，但文档明明加载了？

依次查三点：① 文档状态是不是「就绪」；② 嵌入链路是否可用（语义路缺席时只剩字面匹配，自然语言问法容易空）；③ 换成文档里的原词再试。若「文档」页顶部有橙色「嵌入模型已切换」横幅，先点「重建索引」。

### 测试台最多显示几条？kb_search 呢？

测试台固定取前 8 条；智能体工具 kb_search 默认取 5 条、可在调用时指定 1–20 条。两边走同一检索引擎与排序，只是条数不同。
