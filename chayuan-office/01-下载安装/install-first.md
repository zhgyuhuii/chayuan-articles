# Office首次配置：家供应商目录

用Office首次配置之前有一条边界要先知道：AI 功能依赖已配置模型。知道边界再用，这篇剩下的篇幅讲怎么把它用对。

## 安装前确认

- 系统要求：Windows 10 及以上，x64/arm64
- 安装包：NSIS 安装器 exe
- 说明：装完先配模型。

## 配置流程四步走

1. exe 安装包从官方渠道获取，镜像站的来路存疑
2. 双击安装
3. 启动后在设置里配置模型供应商（BYOK）或指向本机 Ollama
4. 开始页新建或打开文档

## 其他平台装法速览

macOS：官方渠道下载 dmg；拖入应用程序文件夹启动；设置＞模型设置里接入模型。

## 装完后的第一件事

新装环境先做一次贯通测试：设置里接好厂商 API 或本机 Ollama，开始页开一个 docx，让 AI 生成一段文字——链路有响应，环境就算就绪。

## 如何确认操作生效

- 开始页能新建六种格式文档，设置里模型可配置
- 若没有生效，先完全退出宿主软件再重启一次

## 上手前要认的三条边界

先把限制交代在前面，免得白忙一场：

- 内置账号登录当前版本未开放，现阶段须 BYOK 或本地模型
- AI 功能依赖已配置模型
- web/dsh 形态只含五个编辑器且无 HTML，购买与激活入口在那种形态里并不存在

## 高频疑问

### 一家供应商配了一半（只有 Key 没选模型）会怎样？

不勾选模型就无法通过保存校验（「至少勾选一个模型」）；未保存的草稿不生效，已启用列表不受影响。

### 之前配的模型突然报错说不存在？

厂商下架的旧 id 会在加载设置时按退役表自动改写到现役 id（见第 6 步末条），多数情况无感；若厂商整条路由变更，重新「获取模型列表」勾选新模型即可。

## 左栏供应商目录长什么样

第 2 步 · 认识左栏供应商目录

1. 顶部：筛选下拉（「全部 / 免费 / 需 Key / 无需 Key / 免费额度」）+「搜索供应商…」搜索框。
2. 目录分组（可折叠）：「已启用 · N」（有已启用厂商时才出现，行尾 ▾ 可展开看该厂商勾选的模型）+ 四个固定分组：国内平台 / 国际平台 / 本地与自建 / API 聚合，合计 94 家；每家带徽标（「需 Key」「无需 Key」「免费」「免费额度」）。
3. 左下角按钮「＋ 自定义供应商」：接任意 OpenAI 兼容接口，可自起名。

## 连接测试怎么跑

第 4 步 · 连接测试

1. 表单动作区点「测试连接」：对同一地址、协议、密钥发起一次模型列表调用，成功显示绿色「连接成功」，失败显示红色「测试失败：<原因>」（密钥错、地址错、网络不通都会在这里现形）。

## 三个设置区怎么分工

第 5 步 · 三区分工：按能力选默认模型

1. 「模型设置」区（本篇第 3-4 步）：管「哪家供应商 + 勾了哪些模型」。
2. 「默认模型」区：七类默认各一个下拉——对话 / 页面生成 / 质检（视觉审稿）/ 生图 / 视频生成 / 语音合成 / 语音识别，未设置时「自动（使用识别到的第一个可用模型）」；另有「图片来源默认」（自动/网络图片搜索/AI 生图模型/本地图片文件夹/矢量图形）与「单次输出上限（tokens）」（默认 32768，范围 1024–131072）。
3. 「生图、媒体与搜索」区：左侧能力树八组——网络搜索 / AI 生图 / 视频生成 / 图片解析 / 视频解析 / 语音合成 / 语音识别 / SVG 图像生成。模型类组从已启用厂商里投影出「支持该能力的模型」，可「刷新模型列表」、点选一个「设为默认」（或「恢复自动」）；「网络搜索」组按平台配 API Key（带「测试」按钮，主进程执行、Key 未保存也可测）。未启用的厂商给「去模型设置启用」直达链接。

## 密钥放在哪里、如何防泄

第 6 步 · 密钥存哪、怎么更安全

1. Key 明文保存在本机应用数据目录的 ai-settings.json（macOS 为 ~/Library/Application Support/ChaAI Office/ai-settings.json），不上传；界面回显用占位符（__keep__），重存不会泄旧值。
2. 写入前经主进程 schema 校验：密钥截断到 8192 字符、模型名 256、Base URL 必须是合法 http(s)，非法字段丢弃而不是整包拒绝。
3. 安全替代（进阶）：自定义端点的 profile 支持 apiKeyEnv——设置文件只存环境变量名，真实密钥放在启动应用的环境里（内联 Key 优先，二者都无则不注入），适合需要同步/共享配置文件的场景。
4. 厂商停止服务的旧模型 id 会自动改写：加载设置时按内置退役表替换（如 DeepSeek deepseek-chat/deepseek-reasoner＞deepseek-flash，智谱 glm-5-turbo＞glm-5.3-flash，内置账号的 gemini 系旧 id＞claude 系），旧配置文件直接可用。

## 配置生效的核对办法

验证

1. 左栏「已启用」组出现该厂商（带徽标），行尾点 ▾ 能展开看到勾选的模型名。
2. 打开任一编辑器 AI 面板顶部的模型选择器：勾选的对话模型应出现在列表里（生图模型进入绘画工具通道）。
3. 「测试连接」显示「连接成功」；或重开设置弹窗回该厂商，密钥栏显示「已配置（留空保持不变）」。
4. （进阶）打开 ai-settings.json，对应厂商 profile 的 enabled: true、models 数组与勾选一致。

## 开始配置前的检查点

- 主页可打开设置弹窗（入口见第 1 步）；不指定落点时弹窗默认停在「模型设置」区。
- 至少一家供应商的 API Key（在供应商控制台生成——目录里带「需 Key」徽标的厂商，表单里有「获取密钥」直达链接）；本地免 Key 服务见对应教程，不配 Key 的内置账号见对应教程（当前版本登录入口未开放）。
- 机器需联网。

## 这套配置体系的能力点

- 94 家目录
- 按能力分设默认模型
- Key 不出本机

筛选下拉里「免费 / 免费」两档徽标适合零成本先把链路跑通，「需 Key」档则对应要自备密钥的厂商；把目录按分组折叠展开几遍，哪家在哪个组、哪家带什么徽标心里有图，后面配默认模型时就不必来回翻找。

## 密钥与数据的本地边界

配置数据不出本机是这套体系的底线：密钥明文只落在本机应用数据目录的设置文件里，界面回显走占位符；需要同步配置文件的团队，可以只存环境变量名、把真实密钥留在启动环境里。厂商侧的模型 id 变动也由内置退役表兜底，旧配置文件不必手工迁移。
