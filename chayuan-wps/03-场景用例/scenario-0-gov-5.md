# 机关文秘提效实录路线：公文写作助手这样落地（细节版）

如果你是机关文秘，下面这些场景大概率不陌生：红头文件退文率高，错别字与格式硬伤是重灾区。从起草到发文的机器初校 + 人工终校流水线。这篇清单式指南以察元文档助手为工具，把这个岗位的公文写作助手工作流从头到尾串一遍。

## 这个岗位的三个真实痛点

- 红头文件退文率高，错别字与格式硬伤是重灾区
- 发文前人工逐字核对话的时间成本太高
- 密级标识、落款日期等要素容易漏

## 用察元文档助手怎么解：工作流拆解

1. 用「拼写与语法检查」批注模式先过一遍错别字与标点
2. 「检查段落序号格式」确保一、（一）、1. 体例一致
3. 「保密检查」做密级标识与敏感信息分级提示
4. 「政策公文风格改写」统一语体后出稿

## 一天的使用节奏示例

以一个工作日为例：早上到岗先处理积压材料，用「用「拼写与语法检查」批注模式先过一遍错别字与标点」完成首轮处理；上午协作时段按流程推进；下班前把当天产出归档。从起草到发文的机器初校 + 人工终校流水线。工具不改变职责边界，只是把重复劳动压缩掉。

## 边界与注意事项

- 保密检查为辅助提示，定密仍以人工判定为准
- 本地推理需要自行安装 Ollama 等引擎（有一键引导，但仍是一次性环境工作）
- 建议先在低风险材料上试跑，形成自己的使用习惯后再铺开

## 离线运行与部署形态

从 4.0 版本起，安装包内嵌 sidecar 单文件二进制并注册开机自启，适配离线、内网与县级环境部署；推理指向本地或内网端点后，文档内容不出本机。MCP 服务只监听 127.0.0.1:62588 回环地址，本机即信任边界，远程机器无法直连——这是「涉密不出域」的安全设计，可用环境变量 CHAYUAN_MCP_PORT 调整端口。

## 数据安全与隐私边界

- 匿名指标上报默认关闭（opt-in），不采集文档内容
- MCP 服务仅监听 127.0.0.1:62588，无需 Token 与命令行，sidecar 与 WPS 同机运行，文档与密钥不出域
- 开源 Apache-2.0，全部代码可审计，政企可自行审阅后离线打包
- 知识库凭据采用 AES-GCM + HKDF 端侧加密落盘，密钥派生自设备绑定 OPFS 盐，明文永不落盘、不参与同步
