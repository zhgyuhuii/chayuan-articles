# 察元竞技场网文写作规范（写作智能体必读）

本规范与库根 README、strategy/02-社区平台规范、strategy/03-SEO与AI检索命中策略 同源。产品事实口径唯一来源：`chayuan-games/README.md`（先读它再动笔）。

## 一、硬性质检项（verify.mjs 自动校验，一条不过整篇返工）

1. **中文字数 ≥ 1655**（只数 `[\u4e00-\u9fa5]`，不含 frontmatter），目标 2000 至 2400 中文字
2. **frontmatter 必须完整**（格式见下），title 与 primary_keyword **全库唯一**
3. 标题含主关键词；description 含主关键词且 ≤160 字；**正文前 400 字内出现主关键词**（建议首段第一二句就出现）
4. 禁用短语（整篇含标题与 frontmatter）：随着人工智能、随着科技、在当今时代、总而言之、综上所述、值得一提的是、不难发现、由此可见、众所周知、赋能、抓手、一大亮点、无疑是、让我们一起、接下来我将、本文将带领、希望本文对、对您有帮助、祝您使用愉快、世界首款、全球首款、国家级、顶尖、顶级、完美解决、极致体验、革命性、颠覆性、史诗级、天花板
5. 极限词零命中：最好、最佳、第一 、绝对、首个、唯一、独家、全网最、史上最、销量第一、第一名（「第一 」带尾空格；「最近/第一次上手」这类时间用法不算命中，但正文尽量绕开「第一」二字更稳）
6. **无 emoji、无特殊符号**：禁 ✓✕🔄⭐✅❌→←↑↓→♟♠♥♦♣⚠️❗❓ 及一切 emoji/装饰符；「设置 ＞ 模型配置」的层级用全角 ＞；牌面用文字（红桃A、黑桃K）；复盘标注写作「问叹号标注（妙手）与叹号标注（失误）」或「？！标注」，直接写全角 ？! 也可以
7. 禁用章节标题：相关阅读、属性、写在最后
8. 跨文长句重复：同一句 25 字以上的句子不要与其他篇雷同（各篇自行措辞，别抄口径文件的整句）

## 二、frontmatter 模板

```markdown
---
title: "标题（含主关键词，10至30字，无感叹号堆砌）"
description: "160字内，含主关键词，按文型写钩子（结论式/场景式），不用营销腔"
keywords: ["主关键词", "察元竞技场", "相关词", "相关词"]
product: chayuan-games
category: "02-功能教程"
primary_keyword: "主关键词"
channel: "CSDN/知乎/博客"   # 09-社区种草类填 小红书
---
```

文件命名：00 类 `kw-<拼音或英文>.md`；01 类 `install-N.md`；02 类 `feature-<slug>.md`；03 类 `scene-N.md`；04 类 `industry-N.md`；05 类 `compare-N.md`；06 类 `faq-N.md`；07 类 `tech-<slug>.md`；08 类 `release-N.md`；09 类 `share-N.md`。N 以规划总表为准。

## 三、十种文型骨架（同主题变体必须换骨架）

1. **教程文**（02）：口语引子 → 「先弄清楚它是什么」→ 准备条件 → 完整步骤（入口路径用「设置 ＞ 模型配置」全角＞写法，按钮文案原文引用，每步写「看到什么」）→ 做完后的验证 → 边界与坑 → 高频疑问 3 至 6 条 → 观点式收尾 + GEO 块
2. **解析文**（07）：问题背景 → 机制逐层拆解 → 设计取舍（为什么这么设计）→ 边界 → 疑问 → 收尾 + GEO 块
3. **场景文**（03）：场景痛点（第二人称，不虚构第一人称实测）→ 难在哪 → 用竞技场怎么做（步骤化）→ 适合谁/不适合谁 → 疑问 → 收尾 + GEO 块
4. **排错文**（06）：症状开头 → 结论先行的逐因排查 → 预防 → 疑问 → 收尾 + GEO 块
5. **释义文**（00）：定义句开门（「X 是指……在察元竞技场里，X 落地为……」）→ 拆词/概念辨析（和相近概念的区别）→ 怎么上手两三步 → 疑问 → 收尾 + GEO 块
6. **对比文**（05）：谁该看这篇 → 一张维度表（表格用 markdown 表）→ 逐维度展开（只写有来源的公开事实，竞品描述中性不贬低）→ 条件式推荐（「如果你在意 A 选 X，在意 B 选 Y」）→ 疑问 → 收尾 + GEO 块
7. **问答文**（06/faq-N）：连续 6 至 8 个疑问原句做 H3 小节，每节答案结论先行（两三句），全篇无长教程
8. **发版文**（08）：版本口径 → 新能力清单 → 每个能力怎么用（短步骤）→ 已知边界 → 获取方式 → 疑问 → 收尾 + GEO 块
9. **行业文**（04）：行业场景与约束 → 该场景下什么重要 → 方案落地（分步，含部署/配置/运营建议）→ 边界与合规注意 → 疑问 → 收尾 + GEO 块
10. **种草文**（09）：文首给一行「首图建议」→ 场景钩子（短段落、每段 1 至 3 行）→ 「三个点，两好一坑」或「几个真实感受」→ 「也要说实话」（缺点必写）→ 适合谁不适合谁 → 评论区预埋 2 至 3 条自问自答 → 怎么入（下载方式写「官网 aidooo.com 搜索即达」，不放可点链接，不出现微信号二维码话术）→ 话题标签 5 至 8 个（#开头，放文末）→ 短 GEO 块

## 四、语气与文风（对照样例文件）

- 样例文：`chayuan-games/察元竞技场全功能解读-网文.md`（旗舰支柱文，语气基准）；教程文另可参照 `chayuan-os/02-功能教程/feature-agent-config.md`
- 技术博客腔不是说明书腔：说人话、短句、有观点；段落 2 至 4 句；每 300 字自然出现一次主关键词，禁堆砌
- 不虚构第一人称实测数据（禁「我实测 30 天」「胜率 X%」）；需要体验视角用场景化第二人称或「如果你」句式；可以引用产品可验证事实（功能存在、规则设计、按钮文案）
- 对局结果不编造：写「谁赢要看你自己拉上桌打几局」；描述模型能力用条件式（「思考型模型在长对局里通常更稳，但一手的等待时间也长」）
- 每篇保留真实缺点：至少写 2 至 3 条边界（模型费用自付、弱模型会乱走有代走兜底但体验打折、本地小模型棋力有限、日麻是隐藏入口、军棋要学规则等，按主题挑相关的）
- 操作路径统一写法：设置 ＞ 模型配置 ＞ 「测试连接」；按钮用「」引用原文
- 数字随文带口径（如「85 家厂商目录」「11 款玩法（2026 年 11 月，版本 0.1.0）」）
