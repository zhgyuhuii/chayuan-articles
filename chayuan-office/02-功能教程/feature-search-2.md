# 正文搜索为什么这样工作：文件名与正文双路搜索

正文搜索这件事，卡住人的通常是三步：入口在哪、要点哪些按钮、做完怎么确认。这篇按察元AI Office的真实界面顺序走一遍，先解决在几百份文档里找条款原文。

## 这个功能到底解决什么问题

正文搜索是察元AI Office（aidooo.com）里的一个能力模块：开源 AI 办公套件，六编辑器一体，AI 嵌进每个编辑器，全文搜索是其中面向这类需求的一环。

下面直接进正题。

## 一步步来

按最短路径验证一遍：

第 1 步 · 打开搜索框

1. 在主页（Home 标签页）左侧文件栏顶部找到搜索框，占位文案「搜索文件名和内容…」。
2. 点进去直接输入即可；输入法组合（拼音候选未上屏）期间不会误触发搜索，等文字上屏后约 0.15 秒自动出结果，不需要按回车。

第 3 步 ·（可选）开启 Jev 搜索重排

1. 打开 设置（左下角账号行的齿轮按钮）＞ 左栏「本机文件搜索」。
2. 第一项开关「Jev 搜索重排」，说明文案原文：「把本机搜索的前 20 条命中片段发给 TypeSafe 的 Jev 模型，按相关性重新排序。默认关闭；开启后命中片段会离开本机。」
3. 打开开关后出现「Jev 端点」下拉（13 项，默认 OpenRouter）：OpenRouter / TypeSafe / Perplexity (v1 27B) / Perplexity (v1.2) / Perplexity (Flash v1.2) / Liquid AI (d1) / Liquid AI (d1-ultra) / OpenAI (gpt-6-luna) / Cloudflare (Clef) / Cloudflare (Clef-flash) / Kev (local) / Rizzo Flow (local) / Custom。
4. 非 Cloudflare 的云端端点需在「API Key」框填密钥（OpenRouter 占位符 sk-or-…）；选 Cloudflare (Clef) 系还要填「账户 ID」；Kev (local)、Rizzo Flow (local)、Custom 三类本机/自建端点不需要密钥。注意：选 Custom 还要求自建服务有地址和模型 ID，但当前设置面板没有提供这两项输入框（只留了设置文件与接口字段），普通用户请选 Kev (local) 或 Rizzo Flow (local)。
5. 点「测试连接」做一次双文档判定：显示「连接成功」或红色「+ 具体原因」（如密钥缺失、限流、超时等）。
6. 生效后的行为：结果达到 2 条以上时，取前 20 条的摘录发给所选端点打分，约 0.6 秒后按相关性重新排序；结果区出现「Jev」徽标（悬停提示「已由 Jev 按相关性重排」）。重排失败或超时（单次判定 4 秒超时）自动退回本机排序，不会报错打断你；同一查询与候选集的判定结果缓存 30 分钟，反复输入同样的话不会重复调用。

## 这些坑和边界要知道

如实说明，它不是万能的：

- web/dsh 形态只有五编辑器（无 HTML），且无购买激活界面

## 你可能会问

### 刚保存的文件搜不到？

索引是后台逐步进行的：应用启动约 4 秒后开始首轮扫描，之后文件变化经 1.5 秒防抖合批重扫，解析按队列逐个进行。搜索时若发现索引未跟上，界面会显示「正在索引 {n} 个文件…」并每 1.5 秒自动刷新结果——稍等即可，无需手动重建。单个文件解析超过 120 秒会被放弃并回收解析线程，不会拖死整体索引。

### 开启 Jev 重排会不会把我的文档传出去？

会传一小段：只把当前结果前 20 条的命中片段（每条约 1200 字符以内的摘录）发给你在「Jev 端点」选的服务，用于打分排序；文件名与文件夹名也会作为判定上下文一并送出。开关默认关闭；选 Kev (local)、Rizzo Flow (local) 或自建 Custom 端点则判定请求发往本机/自建服务器，不出外网。不开启就完全不发送。

### 开了 Jev 但没有出现 Jev 徽标？

依次检查：结果是否不足 2 条（少于 2 条不重排）；所选云端端点的 API Key 是否已填（本机端点除外）；点「测试连接」看具体报错。即使判定失败也不影响本地结果——只是退回本机排序。

### 哪些文件类型能搜到正文？

索引覆盖 22 种扩展名：docx / doc / xlsx / xlsm / xls / csv / tsv / ods / ots / pptx / ppt / odt / ott / odp / otp / pdf / md / markdown / txt / json / html / htm。超过 64 MB 的大文件只索引文件名和文件夹，不索引正文；隐藏文件（. 开头、~$ Office 锁文件、node_modules、Thumbs.db 等）不在索引范围内。

## 更多操作细节

第 2 步 · 读结果

1. 结果区顶部一行状态：命中总数「{n} 个结果」；若后台还在补索引，会转圈并显示「正在索引 {n} 个文件…」——结果会随索引进度自动变多，不用重搜。
2. 每条命中显示：文件类型图标、文件名（关键词高亮）、所在文件夹路径（高亮）、正文摘录（含关键词的上下文片段，关键词高亮）——没有正文命中的文件不显示摘录；右侧是修改时间。
3. 点任意一条直接打开该文件；点搜索框右侧的「清除搜索」按钮（aria 标签「清除搜索」）回到文件夹树。
4. 完全无命中时显示「没有匹配「{q}」的文件」。

## 更多操作细节

验证

1. 新建一个文档，正文里写入一个独一无二的无意义词（如 察元自检甲壳虫），保存到默认文件夹；几秒后在搜索框输入该词，应能看到该文件带高亮摘录出现在结果里。
2. 关闭「Jev 搜索重排」时，结果区永远不出现 Jev 徽标；开启并配置成功后，多结果查询会出现 Jev 徽标。
3. 开关状态即时持久化：重开设置弹窗，「Jev 搜索重排」的开关位置应与你上次选择一致。

## 补充答疑

### 搜索框输入后没反应？

先确认在主页左侧文件栏顶部（编辑器标签页里没有这个框）。拼音等输入法在候选未上屏时会刻意等待；上屏后 0.15 秒内出结果。查询最长取前 200 个字符，每次最多返回 100 条（页面按总数显示全部命中数）。

## 动手前再核对一遍

- 无需任何配置。索引范围 = 默认保存文件夹 + 你手动添加的文件夹根（外加最近打开与收藏的零散文件），随文件夹变化自动增补。
- 「Jev 搜索重排」默认关闭（见步骤 3）；关闭时纯本机检索，命中片段不出本机。
