# 拆开看定时任务：原理、架构与实现细节

这篇文章没有虚的，全是定时任务的实操细节：入口路径、按钮原文、做完后的界面变化，以及我踩过的坑。基于察元AI OS当前版本。

## 先对齐一下概念

设置 ＞ 常驻任务 里的无人值守定时任务：按「每 N 分钟」或「每天定时」自动执行一段任务指令——默认由全局默认对话模型直跑，也可交给 Codex / Claude Code / OpenCode 智能体无人值守跑，还能挂工作区、知识库、附件与联网检索；每次运行落一份 markdown 报告到 ~/always-on/，可立即运行、暂停与查历史。

周期巡检、每天早报、定时盯数据这类活交给它，早上来收报告即可。

先把这个定位立住，再看步骤。

## 背后是怎么运作的

周期巡检、每天早报、定时盯数据这类活交给它，早上来收报告即可。

能力面拆开看：两种排程（间隔与定点），markdown 报告归档；历史可查可重跑；预授权窗口夜间放行。

从提问口径看，用户最关心的是怎么让察元OS 每天定时帮我干活？

## 完整操作步骤

按最短路径验证一遍：

第 1 步 · 打开管理页

设置 ＞ 常驻任务：卡片标题「常驻任务（Always-on）」，说明行「按排程无人值守执行的无头任务：默认走对话默认模型（可指定代理命名空间模型）；每次运行落报告到 ~/always-on/。绑定灵宠后，任务执行时灵宠上桌并流式展示输出。」点蓝色「新建任务」弹表单；还没有任务时列表区显示「还没有常驻任务」。

第 2 步 · 逐字段填新建表单（弹窗标题「新建常驻任务」）

点「保存」；校验不过（名称空/指令空/排程超范围）会在页内提示「名称/指令/排程不合法」。

| 字段 | 是什么 / 怎么填 | 默认值 |
|---|---|---|
| 任务名 | 占位符「任务名（如：每日晨报）」，用于列表、通知与报告文件名 | 空（必填） |
| 任务指令 | 占位符「任务指令（每次运行发给模型的提示词）」，每次运行原样发给模型 | 空（必填） |
| 排程 · 模式 | 下拉二选一：「每 N 分钟」或「每天定时」 | 「每 N 分钟」 |
| 排程 · 数值 | 模式为「每 N 分钟」时填分钟数（1–10080，即最短 1 分钟、最长一周）；「每天定时」时填 HH:MM（切到该模式时自动预填 08:00） | 60 |
| 执行方式 | 下拉「执行方式：选智能体无人值守跑（完整智能体能力），或留空=模型直跑」：留空=「模型直跑（不经过智能体）」，或选 Codex / Claude Code / OpenCode | 「模型直跑（不经过智能体）」 |
| 模型 | 与建宠同款选择器：「自动（本地已装对话模型）」（=用全局默认对话模型）或「指定模型」（厂商＞类型＞模型树） | 「自动（本地已装对话模型）」 |
| 工作区 | 「工作区（智能体在此目录下执行）」下拉：不指定 / 已有工作区列表；旁边「+ 新建工作区」走系统选夹注册新目录。智能体方式=执行目录（不存在会自动创建）；模型直跑=在指令前注入「【工作目录】」提示 | 「不指定工作区」 |
| 知识库 | 「知识库（每次运行先检索相关片段注入）」下拉：不绑定 / 本机各知识库。每次运行按任务指令检索该库，命中片段以「【知识库参考】」块注入提示词 | 「不绑定知识库」 |
| 附件 | 「附件（注入头部样例）（≤3）」：点「+ 添加附件」从系统文件窗选文件（pdf/docx/xlsx/csv/md/txt 等），每个取头部约 3000 字注入；行内可 关闭 移除 | 无 |
| 启用联网搜索 | 勾选框「启用联网搜索（每次运行前检索最新信息）」：运行前按任务指令搜 web（约 6 条结果注入提示词，注明来源） | 不勾 |

第 3 步 · 认识任务行（保存后出现在列表）

每行从左到右：启用状态圆点（启用=绿点）＞ 任务名 ＞ 摘要（「每 N 分钟」或「每天 HH:MM」· 执行方式 · 模型名尾段或「默认模型」· 联网 · 知识库 · N 附件 · 工作区）＞ 最近一次运行结果（成功 / 失败，悬停可见状态）。新任务默认启用，并立即算出下次运行时刻。

## 几个容易忽略的细节

用之前要认的账：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重

## 常见问题

### 直跑任务报「未配置模型」？

任务没指定模型、且 设置 ＞ 默认模型 里也没有默认对话模型。二选一：在任务表单「指定模型」，或按对应教程配好默认对话模型。

### 任务会不会偷偷动我的文件？

模型直跑是无工具的无头调用（只生成文本，不做写动作）。智能体方式按所选智能体自身的能力与权限在你的工作区目录下执行，建议给定时任务指定专用工作区以收敛影响面。

### 任务失败，通知里只说「失败」，细节哪里看？

三处任选：任务行 悬停状态、「历史」里的错误摘要、~/always-on/ 报告的「失败原因」小节全文。

### 间隔最短/最长能设多少？

「每 N 分钟」合法范围 1–10080 分钟（一周）；「每天定时」为 HH:MM 24 小时制。超出范围保存时报「名称/指令/排程不合法」。

## 补充答疑

### 任务跑到一半电脑重启/页面刷新，会怎样？

每次运行写有运行态快照：重启后 5 分钟内仍在跑的任务恢复为执行中（绑定的灵宠重新上桌带气泡），10 秒内刚跑完的恢复结果摘要；已落盘的报告与历史不受影响。

### 智能体方式支持哪些智能体？别的家行吗？

当前仅 Codex / Claude Code / OpenCode 三家支持无人值守执行（表单下拉也只列这三家）。选了不支持的类型任务会直接失败并留报告。

## 更多操作细节

第 4 步 · 运行与控制（行内按钮）

1. 「立即运行」（琥珀色）：不等排程马上跑一次，页面提示「已触发运行…」；
2. 「暂停」/「启用」：暂停后不再排程（下次运行时刻清空），重新启用时按排程重算下次时刻；
3. 「编辑」：重开同一张表单（标题「编辑常驻任务」）改任意字段；
4. 「删除」：直接移除该任务（无确认弹窗）；
5. 行首下拉「未绑定灵宠」：选中一只灵宠即绑定（换绑时原灵宠自动解绑），任务执行时灵宠上桌+气泡，见对应教程。
6. 自动排程：后台调度器每 60 秒扫描一次，到点自动执行；间隔型=上次排程点 + N 分钟，每天型=下一个该 HH:MM（严格晚于当前时刻）。

第 5 步 · 看结果（三个去处）

1. 通知中心：每次结束推一条来源「常驻任务」的消息，标题「〈任务名〉 · 完成/失败」，正文为结果/错误摘要（最多 200 字）；
2. 运行历史：任务行「历史(N)」按钮展开最近 8 条（/ + 完成时间 + 报告文件名，悬停可见完整报告路径；全局历史保最近 100 条）；
3. 报告文件：每次运行写 〈用户主目录〉/always-on/〈任务名〉-〈时间戳〉.md，内含「〈任务名〉 · Always-on 运行报告」、任务 ID 与排程、起止时间与耗时、所用模型、状态（完成/失败）、任务指令与完整执行结果（或失败原因）。

整体用下来，常驻任务的流程是清楚的：入口集中、步骤有反馈、做完有验证。第一次照着走一遍，后面基本就是肌肉记忆了。卡住就回看常见问题那一节。
