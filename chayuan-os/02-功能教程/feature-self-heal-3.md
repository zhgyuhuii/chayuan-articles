# 崩溃重启落地记：服务链自愈

崩溃重启这件事，卡住人的通常是三步：入口在哪、要点哪些按钮、做完怎么确认。这篇按察元AI OS的真实界面顺序走一遍，先解决模型服务崩溃自动拉起。

## 为什么值得了解

端口冲突自动化解；模型服务崩溃自动拉起。

## 故障自愈：从入口到完成

遇到故障怎么办

1. 先等自愈机制工作（崩溃退避重启通常几十秒内完成）
2. 诊断入口可一键打包上下文
3. 转给智能体给出修复方案或直接处理
4. 诊断包可导出给人工支持

三类常见自愈场景

1. 模型服务崩溃：退避重启并恢复加载清单
2. 配置异常：回滚到上一个可用版本
3. 端口被占：自动顺延端口并通知消费方重新发现

## 关键能力点

- 崩溃退避重启
- 配置回滚
- 端口顺延重发现
- 故障转智能体修复

## 边界先摆桌面上

功能归功能，这几个边界先摆清楚：

- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力

## 高频疑问

### 自愈失败怎么办？

自愈有重试上限，超限后服务进入停摆状态并在界面上标红。此时用诊断入口打包上下文，交给智能体处理或导出给支持人员。

### 配置回滚会丢我的自定义设置吗？

回滚只针对异常的服务配置（模型清单、端口映射这类），用户数据与个人设置不在回滚范围内。

### 端口自动顺延后，外部配置会失效吗？

消费方（智能体、加载项）通过服务发现拿端口，会自动跟到新端口；只有手写在外的固定端口配置需要同步改。
