# 测试连接与获取模型有什么区别：两个按钮的正确用法

模型配置页里，「测试连接」和「获取模型」两个按钮挨在一起，长得很像，很多人随手点一个就走了。但测试连接与获取模型的分工并不相同：一个做轻量校验、失败会回退，一个严格实拉、绝不降级。把这两个按钮的机制拆开看，你配模型的姿势会准确很多。

## 测试连接：轻量校验，带兜底

「测试连接」做的事情是校验：它向厂商发起一次轻量的模型清单查询，用 GET /v1/models 这个口径核对你的 Key 与配置能不能通过校验。特点有两个。

一是快。它不拉全量清单，动作轻，反馈快，适合在填完 Key 后先点一下，确认「这把 Key 是活的」。

二是失败会静默回退。如果这次校验没通过，它不会把你卡在原地，而是静默回退到你在表单里手填的模型列表，让配置继续可用。这个设计的好处是配置流程不被一次网络抖动卡死；代价是你需要明白：当它给了你可以继续的反馈时，背后可能是校验通过，也可能是回退到了手填清单。遇到对局调不动模型的情况，先想想是不是后一种。

## 获取模型：严格实拉，绝不降级

「获取模型」做的事情是实拉：它用你当前未保存的输入，向厂商发起一次全量模型清单查询，用 POST /v1/models 的口径把该账号此刻可用的模型全列表拉回来，返回裸模型 id，你从列表里勾选入库。

这里有两个关键词值得逐个说。一个是「当前未保存的输入」：实拉用的就是你表单里此刻填的内容，也就是说你可以在保存之前先验证这份配置，改一个字符、拉一次，所见即所得，这是它比测试连接强的地方。另一个是「严格实拉不回退」：拉不到就是拉不到，它不会降级到任何兜底，所以它能给你一个干脆的结论——这次失败就是 Key、账号或网络三者里有一个真出了问题，回去排查，不要怀疑按钮。

另外提醒一个易混点：实拉返回的是裸模型 id，直接勾选入库即可，不要自行改写名字，改过的 id 可能与厂商实际接口对不上，对局调用的就是这串原文。

## 两个按钮怎么选

给一组场景化的用法。填完 Key 想快速确认能不能用，点「测试连接」，快；想把账号下可用的模型一次看全、省去凭印象手打模型名，点「获取模型」；改了配置还没保存、想先验证这份改动，点「获取模型」，因为它用的就是未保存的输入；怀疑配置有问题、想拿到一个不含糊的诊断结论，还是「获取模型」，严格实拉的失败最说明问题。

一句话分工：测试连接负责「别被网络抖动卡住」，获取模型负责「给你真实清单与真实结论」。日常顺序可以是先测试连接过一遍，再获取模型拉列表勾选，两下都不亏。

## 三种接入场景下的按钮表现

同样的两个按钮，在不同接入场景下看点不同，分开说。

目录厂商场景：两个按钮都按标准机制走，测试连接校验 Key、获取模型实拉清单，按本文的分工用即可，没有例外。

中转场景：清单与实况可能有出入，获取模型拉到的列表要再用对局验一验；测试连接通过也只说明中转网关可达，上游渠道稳不稳要看实战。

本地推理场景：Ollama 这类免 Key 服务，测试连接的价值不大，本机服务一般都在；获取模型反而是主力，拉到的列表就是你本地已装的模型，列表空了就回 Ollama 侧检查是不是没拉模型或服务没起。

场景感建立起来，按钮就不容易点错。

## 回退策略差异：一张表看清

| 对比点 | 测试连接 | 获取模型 |
|---|---|---|
| 请求口径 | GET /v1/models 校验 | POST /v1/models 实拉 |
| 用什么配置 | 当前输入 | 当前未保存的输入 |
| 返回内容 | 校验反馈 | 账号可用模型全列表（裸模型 id） |
| 失败行为 | 静默回退手填模型列表 | 严格失败，无回退 |
| 适合场景 | 快速确认 Key 可用 | 拉清单、验配置、下诊断 |

补充一个共同的点：这两个动作查的都是模型清单元信息，不是模型对话调用，常规情况下不产生对话 token 消耗，放心点。真正的费用大头在对局里，尤其机机观战与锦标赛的持续互搏。

表里的「失败行为」一行是两者最本质的差异，多说一句：回退设计照顾的是流程顺滑，适合网络不稳的环境；严格实拉照顾的是诊断确定性，适合排障场景。理解了这对取舍，两个按钮就不再是长得一样的两个，而是互补的一对工具。

## 边界与实话

三条说在前面。测试连接的回退机制是双刃剑，它让流程顺滑，也可能让一份有问题的配置看起来「能继续」，所以对局跑不起来时要回想到它。获取模型的严格失败对新手显得不够友好，但它换来的诊断确定性值得，遇到失败按 Key、账号状态、网络可达性三样顺序排查。还有，两个按钮都不能告诉你模型的棋力好坏——清单里有什么和你打得过谁，是两回事。

## 你可能会问

### 两个按钮会点坏配置吗

不会。它们都是读取性质的查询动作，不修改你已保存的配置，放心反复点。改动要落库靠的是保存动作，不是这两个按钮。

### 获取模型拉出的列表为空怎么办

按三样排查：Key 是否完整正确、账号是否欠费或受限、本机到厂商接口的网络是否可达。严格实拉失败一定有真实原因，排掉再试。

### 手填模型名还可行吗

可行，测试连接的回退机制就建立在手填清单上。但目录厂商的型号更新快，建议还是以获取模型的实拉列表为准，手填留给中转与特殊端点场景。

### 为什么获取模型要用未保存的输入

这是它的设计价值：让你在保存前验证改动，配置试错不用反复保存。想验证「存好的那份」，保持表单不动点它，效果等同。

### 测试连接通过了，打起来却调不到模型

先回想测试连接的回退机制：那次通过可能只是回退到了手填清单。重新点「获取模型」做一次严格实拉，拉不到就按 Key、账号状态、网络可达性三样顺序排查，结论会干脆很多。

### 两个按钮可以随便连点吗

可以，都是查询性质的轻量动作，不修改已保存的配置，也不产生对话消耗。反复验证配置时放心点，没有副作用。

两个按钮的差异说到底是一对取舍：顺滑与确定。竞技场把两个都给了你，会用的收益是配置环节又快又准。下一篇讲一个两个按钮都会高频出现的场景：OpenAI 兼容中转的接入。
