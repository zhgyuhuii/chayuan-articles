# MCP配置指南实战：一个真实场景的完整工作流

如果你正在琢磨MCP配置指南，大概率是被这些问题卡住的：入口在哪、要点哪些按钮、做完怎么确认。我第一次用察元AI Office的接入第三方 MCP时也绕了点弯路，这篇把正确顺序整理出来，照做十分钟内能跑通。

## 为什么值得了解

想让首页 AI 对话用上外部 MCP 服务的能力（地图检索、专用数据源、自建脚本服务等），手里有一个 MCP 服务的 URL（HTTP/SSE）或一条本地启动命令（stdio），想先验证它可用再接入，接数据库 MCP 出报告，接搜索 MCP 让 AI 查资料写稿。

用户常搜的问法：察元AI Office 怎么添加第三方 MCP 服务；MCP 服务怎么验证通不通？工具在哪看。

## 一步步来：从入口到完成

1. 打开入口：设置 ＞ 「MCP 管理」

1. 设置侧栏有独立分区「MCP 管理」。页首说明原文：「添加外部 MCP 服务，本应用作为客户端连接并调用其工具；已启用服务的工具会自动进入首页对话。」
2. 还没添加过时显示「暂未添加 MCP 服务，点击右上角「添加 MCP 服务」开始。」。

2. 点「添加 MCP 服务」，逐字段填表

1. 「名称」：自定义名字，用于在列表里展示和给工具命名（占位示例「例如：高德地图」）；留空保存时报「名称不能为空」；
2. 「连接方式」三选一（单选按钮组）：
    1. 「HTTP」/「SSE」：显示「服务地址」（占位 https://example.com/mcp；必须 http(s) 开头，否则报「服务地址必须是 http(s) URL」）和「请求头（JSON，可选）」（占位 {"Authorization": "Bearer …"}；需要鉴权时填，JSON 格式写错报「JSON 格式有误，请检查请求头/环境变量」）；
    2. 「本地进程 (stdio)」：显示「命令」（占位 npx；提示原文「启动本地命令并通过标准输入输出通信，例如 npx -y some-mcp-server」；留空报「本地进程的命令不能为空」）、「参数（每行一个，可选）」（占位 -y 换行 @some/mcp-server）、「环境变量（JSON，可选）」（占位 {"API_KEY": "…"}）；
    3. 新增的服务默认处于启用状态（编辑已有服务时保留其原启用状态）。

4. 管理列表中的服务

1. 每个服务一行：名称 + 连接方式标签 + 「N 个工具」（验证过）或「未验证」；
2. 行尾开关：「启用」/「已停用」——切换只改生效与否，不改配置；停用的服务其工具不会进入对话；
3. 「编辑」回到表单改字段；「删除」先变红色「确认删除」再点才真删；
4. 点行首箭头展开：应用现连该服务拉取实时工具列表逐个展示，另有「重新验证」按钮；该服务没有工具时显示「该服务没有可用工具」。

5. 在首页对话里使用

1. 已启用服务的工具自动注入首页 AI 对话的助手，命名格式 mcp__<服务名>__<工具名>；
2. 正常聊天提需求即可，助手自己决定调用哪个工具；你也可以直接点名（例如「用 mcp__高德地图__xx 工具查一下…」）。

## 接着回答几个常见问题

### stdio 服务会被谁启动？什么时候退出？

由察元AI Office 按注册的「命令 + 参数」在本机拉起并经标准输入输出通信；配置改动后旧连接作废、下次调用按新配置重连。第三方 npm 包请自行评估来源可信后再接入——它将以你的用户身份运行。

### 「验证失败」怎么排？

按类型查：HTTP/SSE 先确认 URL 能从浏览器/curl 直达（注意 /mcp 这类路径后缀、是否需要 Bearer 请求头）；stdio 先在终端手动跑一遍「命令 + 参数」确认能启动。密钥过期、代理拦截也会导致失败；改好后点「重新验证」。

### 保存时报「JSON 格式有误」？

「请求头」或「环境变量」框里填的不是合法 JSON 对象。格式应为 {"键": "值"} 的键值对；不需要时留空即可。

## 补充答疑

### 删除服务会把对话记录里的工具调用删掉吗？

不会。「删除」只移除这个服务的注册与连接；历史对话内容不受影响，只是之后无法再调用它的工具。

### 接了很多服务，对话会变得很慢或很乱吗？

应用对注入做了硬上限：最多 32 个服务、每个服务最多 200 个工具、注入对话的工具总量上限 400；连接超时 15 秒、单次工具调用超时 120 秒。服务太多时把不常用的停用即可，配置保留、随时再启用。

### MCP 管理和「本地 MCP 服务」有什么区别？

方向相反：「MCP 管理」是应用连出去调用别人的 MCP 服务（本篇）；「本地 MCP 服务」在 设置 集成，是应用开放自己给外部智能体操作 Office 文件。两者配置互不相通。

## 安装与运行答疑

### Linux 上扫描件 OCR 没生效？

Linux 无系统 OCR 引擎，扫描页保留位图不识别；macOS 与 Windows 走系统引擎自动识别。

### 老格式 doc 文件打不开？

明确不支持 doc 与 ppt 老格式，先转成 docx 或 pptx 再打开；odt 等 ODF 格式可导入但采取保守策略。

## 一个真实场景

财务与数据岗的典型用法：Sheets 导入多源 xlsx（Rust 边车保真往返），数据透视表与切片器做汇总，公式追踪与监视窗口排查错误。免费开源套件覆盖财务日常表格工作。注意：ODF 格式导入采取保守策略，复杂公式只保结果值。

## 顺带了解

标签页与窗口管理：标签页式多文档管理，窗口可拆分对照，多文档并行编辑。

为什么值得看：写材料经常要对照原稿与参考，多标签加分屏是刚需。

## 还有这个能力

批量操作与表单模式：文档批量、批量操作、表单辅助三组：批量转换与处理，书签转内容控件的表单化。

## 硬口径两三条

- 六编辑器：docx/xlsx/pptx/真文本 PDF/Markdown/HTML（web/dsh 形态为五编辑器）
- 94 家模型供应商目录（国内 29/国际 34/本地 9/聚合 22）、28 个适配器，4 种可选协议

## 如实说不足

- ODF 导入采取保守策略：脚注、批注、文本框不完整保留，无法证明正确的公式只保留结果值
- .doc/.ppt 老格式明确不支持打开，需要先转成 docx/pptx
- web/dsh 形态只有五编辑器（无 HTML），且无购买激活界面
