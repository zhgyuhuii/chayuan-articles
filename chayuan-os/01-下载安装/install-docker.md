# Docker部署装机指南：培训机房批量部署

用 Docker 把整套桌面搬进机房服务器，难点不在命令，在配置细节与上线检查。这篇按察元AI OS的实际部署顺序把每个环节过一遍，落点是团队统一的 AI 工位。

## 安装前确认

- 系统要求：任意可跑 Docker 的服务器
- 安装包：docker compose（察元AI工舱形态）
- 说明：工舱形态一条命令起服务。

安装包与 compose 配置都从官方渠道取，别用第三方转手的镜像文件。

## 一步步来

1. 获取 docker-compose.yml
2. docker compose up -d 启动
3. 浏览器访问默认 52584 端口得到多用户网页桌面
4. 账户隔离，数据在服务器侧统一管理

## 其他平台装法速览

Linux（deb）：按 CPU 架构选包：飞腾/鲲鹏选 arm64，兆芯/海光选 x64；sudo dpkg -i 安装 deb 包；应用菜单启动，首次启动自动初始化数据目录。

## 装完后的第一件事

首次登录桌面会自动弹出模型设置向导，四步配好默认模型并应用到智能体；随后到设置账号与找回里生成恢复密钥。向导别跳过：默认模型配好了，学员登录后直接就能用，不至于每个人先折腾一遍设置。这两件事做完，这台机器才算真正就绪。

## 怎么确认做成了

- 桌面起来后，拿对话应用配本地模型问一句，回复正常就算通过
- 头一回启动时的初始化大约 5 到 30 秒，等它自己跑完，不用管

## 容器路线的四条限制

走容器路线前，这几笔账先认下：

- 容器路线本身就属进阶形态，零运维经验的人独自折腾 Docker 云桌面或跨终端互联会吃力
- 云端厂商的模型不配钥匙，API Key 要各团队自己申请、自己管
- 8GB 内存的设备同时只加载一个对话模型，任务一复杂就容易到上限
- 龙芯平台暂未适配；视频生成本机不承担，统一走云端路由

## 起一个云桌面的完整动作

1. 服务器上准备 docker compose 配置
2. docker compose up -d 启动工舱
3. 按需暴露端口（默认回环，外网访问自行映射）
4. 员工浏览器打开地址，各自账户登录使用

四步里第 3 步最容易含糊：按需暴露端口的意思是，默认配置只绑回环地址，要给局域网里的终端用，就得在配置里显式写好映射再起服务。第 4 步登录之后各账户互不可见，学员的对话与知识库都锁在自己账户里，不需要额外设权限。

## 上线前的检查项

1. 默认端口 52584 是否被占用（compose 映射可改）
2. 按团队人数评估内存：每并发一个本地模型约吃数 GB
3. 数据卷挂载出来，升级与备份都靠它
4. 管理员账户先建好，再开放普通用户注册

逐条说下检查的用意：端口占用放在最前面查，是免得服务起来了才发现访问不通；内存评估放在采购前做，能省一轮返工；数据卷必须挂载出来，否则升级容器时数据跟着旧容器一起没；管理员与普通用户的注册顺序排好，权限边界从第一天起就是清楚的。

## 补充答疑

### 云桌面和桌面版功能一样吗？

核心能力面一致（对话、知识库、模型、办公），形态差异在：云桌面无本地文件直通、语音输入依赖浏览器权限、部分外设在浏览器里受限。机房授课用不到这几样时，差异可以忽略；拿不准就逐条核对，核对完再做选型也不迟。

### 多少人共用一台服务器合适？

取决于是否同时跑本地模型：只做对话与知识库，十几人一台中配服务器可行；要并行跑本地推理，按并发数加内存或改用厂商模型分流。

### 数据存在哪里？

全部落在服务器的数据卷里（含用户空间、知识库、配置），挂载出来后备份一个目录等于备份全组。

## 这种部署方式换来的四样东西

- 终端零安装，浏览器即用
- 账户隔离，每个学员一份独立空间，互不干扰
- 数据集中管理，都在服务器侧
- 端口暴露面自己控制，开多大口子自己说了算

## 为什么培训机房适合这条路线

机房管理的三件烦事——终端逐台装软件、学员数据散落各机、毕业季清机——恰好都被这条路线化解：终端只要能开浏览器就能上课，学员各用各的账户，数据全部落在服务器的数据卷里，清机季备份一个目录、重置镜像即可。机房里的电脑新旧不一也不影响使用，算力压力集中在服务器一台机器上，升级换代只动服务器。日后换新版本容器，数据卷原样保留，学员那边什么都不用动。

## 端口与访问控制的门道

服务默认监听回环地址，也就是只有服务器本机能访问；机房终端要用，得在 compose 里把 52584 端口映射出来。映射到内网网卡就够了，没必要暴露公网——培训场景的终端都在局域网里，少开一个公网入口就少一类风险。端口被占用时 compose 映射可以改，不必非守着默认值。服务器规格的思路也一样：先按答疑一节「多少人共用一台服务器」的口径估个上限再留余量——内存事后加条容易，数据卷中途迁移麻烦，规格尽量在采购时一次定到位。

Docker 云桌面（察元AI工舱）部署这件事，看十遍文档不如真机跑一遍——第一次 up -d 之后盯着把服务起稳，后面给其他机房复制这套配置就是体力活了。
