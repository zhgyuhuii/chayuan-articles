# 源码构建：开源仓库与构建入口

源码构建这条路，散的不是知识点，是入口与口径：源码从哪来、构建从哪起步、装完怎么验证。本文按顺序把这几件事收拢成单一路径，顺带交代源码视角下值得知道的几组事实。

## 为什么有人走源码这条路

绝大多数用户用安装包就够了，剩下少数人坚持从源码走，理由通常有三类：想确认代码到底做了什么的安全审计型用户；想改一两处行为再自用的定制型用户；以及单纯想看看项目结构的学习型用户。对前两类人来说，「能拿到源码」本身就是选型条件——闭源安装包给不了这种确定性。Apache-2.0 协议下的源码可以自由取用，这一层公开性是这条路线存在的前提。

走源码的代价也要摆在台面上：构建环境要自己搭、依赖要自己拉齐、版本更新要自己同步，安装包路线一键完成的事，源码路线每件都得动手。两条路线没有高下，只有合不合适。

## 安装前确认

- 系统要求：Windows 10 及以上，x64/arm64
- 安装包：NSIS 安装器 exe
- 说明：开源仓库与构建入口。

## 一步步来

1. 安装包两个官方来路：发布站点与仓库发布区，任选其一
2. 双击安装
3. 启动后在设置里配置模型供应商（BYOK）或指向本机 Ollama
4. 开始页新建或打开文档

这份四步清单名义上是安装包路线的走法，源码路线的读者也应该照着走一遍作为对照基线：先让官方构建的产物在自己机器上跑通，再着手自己的构建。基线跑不通的机器，构建出来的产物同样跑不通，先分清「环境问题」和「构建问题」，能省下大把定位时间——这是源码玩法里最容易被忽略的一条基本功。

## 做完后的验证

- 开始页能新建六种格式文档，设置里模型可配置
- 若没有生效，先完全退出宿主软件再重启一次

自构建产物也用这两条验收，结果与官方安装包一致才算构建成功。出现差异时优先怀疑本地环境的依赖版本，而不是急着改代码——多数「构建出来不对」的案例，最后都落在环境没对齐上。

## 几个容易忽略的细节

有些限制在动手前就要接受：

- web/dsh 形态只打包五个编辑器、无 HTML，购买与激活界面同样缺席

## 构建产物的形态能力

- 三平台五形态安装包
- 免 root 可装
- 麒麟与 UOS 走 AppImage 加 deb

从源码出发的构建产物同样落在这些形态里：构建脚本按平台产出对应的包体，Windows 侧是 NSIS 安装器，Linux 侧覆盖 deb 与 AppImage 一类。构建前先想清楚自己要产出哪种形态，比构建中途再翻配置省事。

## HTML 编辑器的工具面

预览与源码切换、点选元素就地编辑、样式面板、面包屑、Ask AI、插入骨架、图片去背景——这一组工具只在桌面形态的 HTML 编辑器里齐全；Linux 无系统 OCR 引擎，扫描页保留位图不识别，这条对从源码自构建各平台的用户同样成立。仓库以 Apache-2.0 协议开源，构建出的形态与能力对照上文边界核对即可。

## AI 面板与隐私细节

六端通用的 AI 面板：打开 AI 助手按钮进面板；报价、身份证号这类片段不想给模型看，隐藏后其他部分照常 AI 处理；常用助手组的拼写与语法检查结果以批注锚定原文（命中片段逐字一致）；D 模型直接进 pptx 且往返保真，这是多数在线编辑器做不到的。模型侧支持 BYOK 接入 94 家模型供应商与本机 Ollama 等本地端点，API Key 存本机 ai-settings.json 不上传，支持环境变量引用。

这几条隐私口径对走源码的用户有额外意义：密钥只落本机文件、回显走占位符，审计源码时可以直接在仓库里核对实现是否与声明一致；隐藏片段后照常处理的设计，意味着「不想给模型看的部分」有真实的机制兜底，而不是宣传话术。开源项目的可信度，正是靠这类可以逐行验证的细节积累起来的。

## 端口与设置备忘

知识库五级自动发现，注册表端口 52584，检索上下文预算默认 12000 字；十分区设置地图：通用、语言（22 种）、主题、模型、知识库、隐私等，通用区逐项可调；chaoffice 命令行 17 个子命令，自构建后同样可用。让编程智能体天生会用办公套件，写代码调文档 API 不用翻文档，这层设计对从源码入手的开发者尤为顺手。

## 什么情况下还会用到

个人替换订阅制办公软件；政企内网批量装机。

- 装包来源怎么确认？官方下载入口有几个？

### 从源码走一遍需要什么前置认识？

源码以 Apache-2.0 协议开源、可自行获取，构建属于进阶玩法；只想日常使用的话，三平台五形态安装包是更省事的路线，两条路装出来的能力一致，按需选择。

### 它能打开和处理的文件格式有哪些？

打开格式路由表覆盖 docx、odt、xlsx、csv、pptx、pdf、md、html 等；具体某一格式的编辑深度各不相同，以官方文档的格式对照表为准。
