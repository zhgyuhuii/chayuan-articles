# 一文分清开源排行榜：六档周期榜单

开源项目千千万，star 总量高只说明它火过，不代表它现在还活着。开源排行榜换了把尺子：看增量——这周谁在涨，比谁总量大更有参考价值。这篇把这把尺子的刻度与读法讲清。

## 什么是开源排行榜

这里的开源排行榜指门户里的开源榜单机制。门户本体是察元AI 能力广场：插件、技能、MCP、提示词、大模型资源一站检索与下载的智能体门户，榜单只是它的一层能力。

口径与数字依官方文档整理，截止时间见文末。

## 三个维度与六档周期

榜单分热门、新品、趋势三个维度；周期有日、周、月、季、半年、年六档，按 star 增量计算，快照每日同步抓取。无 GitHub 数据的条目按本站下载量兜底混排、star 增量优先；失效资源自动剔除出榜。三个维度各有用处：热门看当下密度，新品看首发动静，趋势看持续爬坡——配合周期档位，既能找「最近上升最快的 MCP」，也能做季度级的生态回顾，两类需求都照顾得到。

## 一条重要的透明规则

真实增量数据自 2026-09-15 起积累，此前的周期按星标总量排序并明确标注。这条规则值得单独讲：它承认了历史的局限，并把局限写在明面上——比起让你误以为所有名次都出自同一口径，先说清边界反而更可信。

## 周期档位的选择手感

六档周期不是摆设，选档位本身就是个判断动作：

- 找新鲜出炉的东西，用日档和周档：新项目首发后那阵子最能看出爆发力，但也要当心首发效应的虚火
- 做中期观察，用月档和季档：滤掉单周波动，留下的爬坡更扎实
- 看长线格局，用半年档和年档：能站上长档位的项目，基本经历过至少一轮维护考验

一个实用组合：先用季档圈出稳居前列的常客，再用周档捕捉新面孔，两份名单对照，生态的骨架和新血都有了。

## 增量榜单的局限

增量口径也有盲区，读榜时要心里有数：

- 慢热型项目吃亏：维护稳定但缺乏传播爆发的项目，增量常年平淡，名次不显眼
- 营销驱动的虚高：一轮运营活动能短期推高 star 增量，数字好看但含金量存疑
- 尺度偏单一：以 star 为主的度量，反映不了文档改进这类幕后贡献

所以榜单给线索、不给结论——名次是入口，进详情页看提交记录与议题活跃度，才算走完整流程。

## 用榜单找资源的走法

1. 进榜单页选周期（日/周/月）
2. 按板块切到 MCP 或插件等类目
3. 点开感兴趣的资源看详情
4. 结合下载量判断活跃度

第四步别省：star 增量量的是关注度，下载量量的是真实使用，两个信号互相印证，看走眼的概率才低——只看其中一个，都容易把噪声当趋势。

## 用榜之前要知道的

- 想在站内读完资源全文的人：条目只到元数据与出处，正文回源站读
- 不愿注册的人：下载、收藏都要登录，站内账号或微信扫码均可，没有例外通道

两条边界明了，榜单用起来就没有意外；意外多半来自没读边界，而不是榜单本身。

## 账号与支付

- 收藏上限 200 条
- 投稿与需求墙内容，审核通过才露面
- 购买记录按本机指纹查询
- 免费榜按输入价门槛专列；下单集中在购买授权页，付款走扫码；促销与免费额度可筛选

## 关于榜单的疑问

### 排名可以靠钱抬上去吗

不能。榜单按 star 增量与本站下载量计算，无付费干预位，商业力量进不了排序公式——这也是增量口径带来的副产品：买的存量容易，买的增量很贵。

### 为什么按增量而不是总量排

总量反映历史声望，增量反映当前动能；选开源工具要跟它的未来相处，不是跟它的过去相处，所以增量口径更贴近选型需要。

### 老项目会不会吃亏

会有影响，但透明规则兜底：增量数据积累之前的周期按星标总量排序并明确标注，新旧口径不混着算，读者心里有数。

## 增量思维还能用在哪

这套「看走向不看家底」的思路，出了榜单也适用：看项目看提交频率，看社区看新帖密度，看工具看更新日志的节奏。存量回答「它多大」，增量回答「它往哪走」；多数半死不活的项目，存量依然漂亮，增量早就归零——两把尺子都量一遍，判断才立体，选错方向的代价也小。

## 周边口径一并交代

- 模型智力排行按五维度综合评测：每维度 0-100 百分位、总分取五维等权均值，另有免费模型榜
- 模型调价、出新都勤，资讯页扫一眼心里有数
- 智能体应用板块收的形态资源开箱即用，独立跑或配合产品都行
- 购一次可装八款智能体、支持断网离线安装；既能单独装，也能打成技能包批量部署
- 桌面产品可从站内下载 Windows/macOS/Linux（含麒麟/UOS）安装包，官方安装包按平台架构给直链

开源榜单机制讲完。记住核心口径就够：三维度、六档周期、star 增量优先、降级透明标注——其余细节，用的时候回对应小节查即可，不必死记硬背。
