# 从 Phase1 到当前的演进：能力广场的实操要点

从 Phase1 到当前的演进常被用户问到。这篇实操要点从察元AI 能力广场的实际实现出发，讲清楚设计取舍与使用层面的意义。

## 一句话结论

版本演进的完整时间线：

- v门户上线（2026 上半年）：能力广场八大板块与产品家族页
- v内容护城河建设（2026 年中）：教程库采集 2.1 万+ 条（arxiv/github/B 站等）
- vSSR 快照 SEO 层（2026 年内）：SSR-lite 服务端首屏快照与动态 sitemap
- v商业化闭环（2026-06 起）：技能包买断制商城（token 限 3 设备）

版本策略的原则是行为变化写进更新说明、用户数据与版本解耦。

## 为什么这样设计

这个设计的动机可以概括为三点：把风险控制在机制而不是纪律里（靠制度约束人的行为总会失效，靠架构约束才稳定）；把复杂度封装起来（用户不需要理解内部实现，只需要理解行为边界）；把可验证性留给用户（声明的能力都能在产品里实际验证）。软件工程里没有免费的设计——每一条这样的取舍都是在「体验、安全、性能、成本」之间做的显式权衡，约束变了，结论就可能反转。
