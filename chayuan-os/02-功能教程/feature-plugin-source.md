# 一篇讲透插件源：准备、步骤、验证与边界

插件源这个话题我被问过三次以上，每次都要重新讲一遍。与其反复口述，不如写成一篇：从插件源与网络设置的入口讲到验证，中间的分支也一并说清，基于察元AI OS。

## 这个功能到底解决什么问题

设置 ＞ 插件源与网络管应用商店的「货从哪来」和插件安装的「网络怎么走」：内置三源（npm / npmmirror 镜像 / 社区精选）逐个开关，可添加自定义社区源与自定义技能源清单；底部的 npm registry 与 HTTP(S) 代理写入 dsh profile 目录的 .npmrc，应用商店 / 应用管理的插件安装（pnpm）都遵循它。

内网或特殊网络环境装插件的必经配置。

下面直接进入正题。

## 操作前的准备工作

- 无特殊前置；自定义源地址必须是 http(s):// 开头的可访问 URL。
- 自定义社区源需提供 community.json 格式清单：条目含 name / description / npm / repo / category 字段。
- 自定义技能源需提供 JSON 数组清单：条目形如 {repo, name, description}，repo 为 GitHub owner/name。
- npm registry / 代理改动只对之后的安装任务生效，进行中的安装不受影响。

## 从打开到做完的每一步

入口：Dock ＞ 设置 ＞ 左栏「插件源与网络」分区，页面四张卡片：「内置源」「自定义社区源」「自定义技能源」「网络与安装」。

1. 卡片一「内置源」——开关内置货源

1. 说明文案：「取消勾选的源不再出现在应用商店。」
2. 默认三项（勾选框，勾着=启用）：
    1. npm——官方 registry（https://registry.npmjs.org）；
    2. npmmirror 镜像——https://registry.npmmirror.com；
    3. 社区精选——社区 community.json 清单（jsDelivr CDN 分发）。
    4. 取消勾选某项即从应用商店的源列表隐藏它（只是不显示，不是卸载什么）；重新勾选即恢复。

2. 卡片二「自定义社区源」——加自己的插件清单

1. 表单两格：「名称」（占位「名称」，留空则用地址当名）＋「地址」（占位 https://…/community.json），点「添加」。
2. 地址必须以 http(s):// 开头，否则表单下方红字「地址需以 http(s):// 开头」，不入表。
3. 添加后下方列表一行 = 名称 + 地址 + 红字「移除」按钮。
4. 效果：打开 应用商店 ＞ 插件类目，顶部的源切换按钮（药丸）里多出你命名的这个源，点它即浏览该清单的插件。

3. 卡片三「自定义技能源」——加自己的技能清单

1. 表单同上（地址占位 https://…/skills.json），点「添加」；重复地址会覆盖不重复累加。
2. 说明文案：「清单为 JSON 数组，条目形如 {repo, name, description}（repo 为 owner/name）。添加后出现在应用商店·技能 tab 的源列表。」
3. 效果：应用商店 ＞ 技能类目，源切换按钮在「精选」「GitHub 仓库」之后并列出现你加的源。

4. 卡片四「网络与安装」——npm registry 与代理

1. 说明文案：「写入 dsh profile 目录的 .npmrc；应用商店/应用管理的插件安装（pnpm）遵循该 registry 与代理。留空即删除该项。」
2. 两个字段：
    1. 「npm registry」：占位 https://registry.npmmirror.com；
    2. 「HTTP(S) 代理」：占位 http://127.0.0.1:7890。
    3. 点「保存」：成功显示「已保存，立即对后续安装生效」（两框回显保存后的值）；失败显示「保存失败：<原因>」。
    4. 写入位置：~/.dsh/profiles/web/.npmrc（DSH_HOME 环境变量另设时在其 profiles/web 下）；实际写 registry= 与 https-proxy= 两键，留空保存即删除该键。该文件只由这张卡管理 registry/https-proxy 两个键，其余内容保留。

## 怎么确认做成了

验证

1. 保存 registry 后重新打开 设置 ＞ 插件源与网络，「npm registry」框应回显你填的值；终端 cat ~/.dsh/profiles/web/.npmrc 可见 registry=… 一行。
2. 添加一个自定义社区源后打开 应用商店 ＞ 插件类目，顶部源切换按钮应出现该源名称；取消勾选「npm」后回到商店，「npm」按钮消失。
3. 在「自定义技能源」加清单后，应用商店 ＞ 技能类目源切换按钮在「精选」「GitHub 仓库」后出现你的源。

## 适用场景

团队/社区维护了一份 community.json 插件清单或 GitHub 技能清单，想让应用商店直接收录，npm 官方源慢或连不上，装插件经常超时，想切国内镜像（npmmirror）或走本机代理；不想在某台离线机器上看到用不了的内置源；换国内镜像提速。

用户常搜的问法：装插件一直超时，能换国内源吗；怎么把公司自己的插件清单加进应用商店。

## 它的局限也要说清楚

如实说明，它不是万能的：

- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 高频疑问

### 添加自定义源没反应，只有一行红字？

地址必须 http:// 或 https:// 开头。另外清单本身要能被访问且格式正确（社区源 community.json / 技能源 JSON 数组），清单坏掉时商店里该源不出内容。

### 保存了镜像源，装插件还是走官方源？

.npmrc 只对保存之后发起的安装生效。重新发起安装（或装新插件）即走新源；之前失败的任务重试一次。

### 技能源和社区源有什么区别？

社区源面向插件（npm 包/git 仓库形插件，community.json 条目带 npm/repo 引用）；技能源面向技能（GitHub 仓库清单，repo 为 owner/name），出现在商店技能类目。两者互不通用。

### 关掉内置源会卸载已装插件吗？

不会。开关只影响应用商店源列表的显示与检索；已安装插件的启停/卸载在 应用管理 ＞ 插件 tab（见教程对应教程）。

## 补充答疑

### 代理怎么填？公司内网装不了插件？

「HTTP(S) 代理」填形如 http://127.0.0.1:7890 的代理地址（写 https-proxy 键）。内网环境建议镜像+代理二选一或组合使用：镜像解决 registry 可达性，代理解决整体出网。留空保存即清除。

## 安装与运行答疑

### 模型加载失败或提示内存不足？

系统有内存预算硬底线（总内存的 45%）保护：先卸载不用的模型再加载新的；8GB 设备建议一次只加载一个对话模型加一个嵌入模型。

### 升级会丢数据吗？

不会。覆盖安装与自动更新都保留数据目录；升级前把数据根目录整体备份一份更稳妥。
