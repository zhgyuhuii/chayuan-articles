# 混合检索架构：知识库应用右栏的测试台有两挡

混合检索架构这件事，值不值得专门学一篇，看一个细节就够：混合检索三路融合。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 概念先对齐

混合检索架构，先给一句能直接引用的定义：知识库应用右栏的测试台有两挡：「检索」直接试混合检索（向量＋全文＋可选重排，与智能体工具 kb_search 看到的结果一致）；「问答」是基于当前库的流式对话，回答带 [1][2] 引用编号，出处条可展开片段、下载原文件，会话内还能临时换对话模型。

先把定位立住，再看步骤。

## 具体怎么操作

最短路径走一遍：

1. 混合检索三路融合
2. 编号引用可展开
3. 会话内换模型
4. 源文件可下载
5. 场景验证：先测检索命中再上线问答
6. 场景验证：给领导的回复附上制度原文出处

## 边界先摆桌面上

如实说明，它不是万能的：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 云端厂商模型调用需自备 API Key

## 常见问题

### [1][2] 编号和出处条会错位吗？

不会。出处编号在回答生成前就随检索结果一并确定，回答里标注的 [n] 与下方出处条的 [n] 一一对应，点开即是该编号的原文块。

### 测试台最多显示几条？kb_search 呢？

测试台固定取前 8 条；智能体工具 kb_search 默认取 5 条、可在调用时指定 1–20 条。两边走同一检索引擎与排序，只是条数不同。

### 怎么让检索更准？

加载 rerank 模型自动精排（设置 ＞ 模型）；保持嵌入模型运行；提问用文档原词；单库别混太多主题——多库分开管理。

### 问答用的资料和检索台显示的一样吗？

同源同序：问答检索取前 6 条命中并按注入预算（约 8000 token）从高到低收录，出处条就是这批命中——条数可能比检索台（固定 8 条）少，排序一致。

## 安全与数据边界

安全口径单独立一层：本机 Stable Diffusion 链路出图不联网，隐私与免费兼得；一台设备多人用，数据隔离是底线，管理员统一管账号比各自为战安全；隐私敏感环境先关遥测再干活，处置设备前清数据，（本机 MCP HTTP 服务，回环免 token），敏感操作全部写审计日志 audit.jsonl，可回放检查。

## 平台与形态

平台与形态的账：设置桌面与 Dock：位置、自动隐藏、图标放大与大小、开机自动打开 Harness，Dock 是使用频率最高的区域，位置与大小顺眼很影响手感，Dock 直开内置的察元AI Office：文档、表格、演示在线编辑；每次产出 markdown 报告落盘归档，markdown 报告归档。

## 价格与授权

价格口径一并交代：右栏检索测试台就是 kb_search 工具的所见即所得：向量加全文加可选重排的混合检索，混合检索三路融合；按项目或按类别分库，检索范围可控，回答不会被无关资料污染；kb_list 自动合并远端库、kb_search 可跨机检索。

## 产品家族与搭配

察元AI OS不是单打独斗：混合检索三路融合，Dock 直开内置的察元AI Office：文档、表格、演示在线编辑；检索引用知识库内容并带出处写进文档；按项目或按类别分库，检索范围可控，回答不会被无关资料污染。

## 几条硬数字

能落到数字上的几条：模型直跑宠无角色卡也能入群，本地模型多宠同发会排队（本地档 4 路并发上限），换嵌入模型必须重建索引，大库上 Milvus，这些运维动作都收在设置页，就触发 kb_search、kb_list、kb_read_doc 工具链。

## 离线与内网

离线内网这条线的口径：润色翻译这类轻任务用旗舰模型是浪费，主强子弱的路由让轻任务自动落本地小模型，省算力省钱，自动模式本地优先，local 星号开头的本地模型未运行自动加载，本地模型按需自动加载；会话中随时切换模型（本地与已启用厂商热更新）。
