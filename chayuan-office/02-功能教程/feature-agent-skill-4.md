# 智能体技能实操出问题先看这：家智能体投放

智能体技能实操这件事，值不值得专门学一篇，看一个细节就够：7 家智能体投放。这个细节背后是一整套入口和验证链路，本文按排错视角完整拆开，出问题时照层定位。

## 先定位问题在哪一层

排智能体技能实操的错，顺序比速度重要：环境与模型先就位，然后对操作路径，最后核边界。三层各有一些典型症状，对号入座能省很多时间。

第一层的症状最容易识别：智能体压根调不动命令，十有八九是环境里 chaoffice 不可达，这层不通后面全免谈。第二层的症状是命令能跑但行为不对——技能没生效、旧会话还在用老口径、目录装错了位置，都属于路径层，照「正确的操作路径」逐步核对即可。第三层最隐蔽：一切看起来正常，某类文件就是不出结果，这时要怀疑的是格式或引擎边界，而不是操作。把症状先归层，再动手改，是整篇的方法论内核。

## 正确的操作路径

最短路径走一遍：

1. 7 家智能体投放
2. 版本化技能包
3. 场景验证：让 Claude Code 自动生成并操作文档
4. 串联场景：Docs 写正文，察元AI 页签全文校对出批注
5. 串联场景：Sheets 导入多源 xlsx（Rust 边车保真往返）
6. 串联场景：PDF 阅读器选区标注加问 AI

这份清单的用法是「从上往下、逐级验证」：前三步打通说明投放与生效链路健康；后三步是串联场景，单点功能正常但串联失败时，问题多半出在两个环节的衔接上，比如会话没有新开、文件路径不在智能体可读范围。每一步只验证一件事，失败时改一件东西，不要同时动多个变量。

## 进阶用法与边界

- 7 家智能体投放
- 版本化技能包

进阶的标志是从「单智能体单场景」走向「多智能体协作」：同一份技能包投放给多家智能体后，各家对同一指令的理解深度会有差异，交叉验证能快速暴露表述含糊的指令。边界意识同步升级——串联场景越多，边界层的排查权重越高，一份多源 xlsx 的往返失败可能是边车问题，也可能是源文件本身带扫描页。

## 排错时最先问的两个问题

### 技能链路依赖网络吗？

技能文件本身落在本机目录，智能体读取它不走网络；需要联网的是模型调用这一段——端点配的是云端厂商就要网，配本地端点则整体本地优先、离线可用。把「技能加载」与「模型调用」两段分开看，网络问题立刻清晰。

### 实操能覆盖哪些文件格式？

打开格式路由表覆盖 docx、odt、xlsx、csv、pptx、pdf、md、html 等，老格式给出明确提示，不会静默失败；API Key 存本机 ai-settings.json 不上传，也支持环境变量引用。核对格式时拿路由表当白名单用：表内的格式出问题查操作层，表外的格式出「打不开」属预期行为，别浪费排查时间。

## 数据在本机的口径

文档处理全部本机完成（PDFium 字符级提取加纯几何版面分析），证书加密 PDF 无法转换；搜索、数据库、浏览器这些 MCP 能力接进来后，AI 面板能做的事就不止改文档。排错时这条口径很有用：凡是宣称「要传到云端才能处理」的报错，都与设计相悖，优先怀疑配置而非架构。

## 智能体接入的协议层

让 Claude Code 这类智能体直接读写你的文档，办公自动化从此有了标准协议；外部智能体可接入，写材料引用内部资料、调文档 API 都不必翻文档。这层协议是「7 家智能体投放」的技术底座——正因为有统一的操作入口，一份 skill 才能同时喂给多家智能体。

## 数字备忘

CLI 29 工具；知识库五级自动发现，注册表端口 52584，检索上下文预算默认 12000 字。排错用到端口号时，先核对这个地址是不是注册表实际监听的端口；glb 3D 模型与扫描 PDF 转活文档（档案数字化的第一步）这类进阶能力，验证技能链路时可当作高阶测试用例。

## 形态边界与离线口径

web/dsh 形态只带五个编辑器、无 HTML，购买与激活界面不存在；本地优先、离线可用是主线设计，Linux 无系统 OCR 引擎、扫描页保留位图不识别这条限制在智能体链路里同样生效——智能体再聪明，也绕不过引擎层的硬边界。

## 大家都怎么问

- 怎么把 chaoffice 技能装进 Claude Code / Codex / Cursor？
- skill 装到哪个目录？怎么卸载？
- 升级主应用后 skill 要不要重装？

三平台五形态安装包决定应用在哪跑，skill 决定智能体会不会用，两层各查各的，多数「实操不出结果」的场景都能在十分钟内定位到层。

## 一条可复用的排错主线

把上文收拢成固定动作序列：先问「命令可达吗」，再问「技能装对了吗」，三问「会话新开了吗」，四问「格式在路由表里吗」，五问「是不是踩了形态边界」。五个问题按序过一遍，覆盖了绝大多数失败现场；全部通过仍异常的，再带着完整的层数判断去查端口与配置，效率远高于上来就翻日志。这个序列本身不依赖具体版本，版本更新后依然适用，变的只是每层内部的细节。
