# MCP配置实操：内网环境离线导 MCP 清单

很多人搜「怎么给 Claude Code / Codex 添加一个 MCP 服务」，搜到的多是概念解释，落不到操作。这篇以察元AI OS为准，把MCP配置实操从打开哪个应用讲到看到什么结果。

## 先弄清楚它是什么

MCP配置实操在察元AI OS里的形态一句话说清：MCP 服务清单增删改（stdio、HTTP、SSE、本机 52583），先验证连接再保存，启停即同步写入支持 MCP 的 13 家智能体。

概念一分钟，操作十分钟，这篇都覆盖。

## 边界先摆桌面上

功能归功能，这几个边界先摆清楚：

- 云端厂商模型调用需自备 API Key
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）

## 你可能会问

### 本机 MCP 服务能删吗？停用会怎样？

不能删（后端直接拒绝）。停用后各智能体配置里的 chatop 条目会被移除——智能体暂时失去经 MCP 调系统能力的通道；chatop-kb 知识库条目不受它影响（随知识库服务在否而定）。重新「启用」后随下一次保存/启停或桌面重启恢复。

### 保存提示「部分智能体配置传播失败」？

清单已保存成功，只是个别智能体的配置文件写入失败（常见为该文件被改坏成非法 JSON 或无写权限）。按提示里的失败家检查对应配置文件，修好后任意一次保存/启停都会重新全量传播。

### 局域网地址怎么用？

「局域网」行的地址已内嵌 token，直接点「复制」发给外部设备配置即可；回环的「本机」地址免 token。端口固定 52583（统一端口注册表，一号一口写死）。

## 更多操作细节

验证

1. 新条目验证成功并保存后，列表行显示「{count} 个工具」，数量与验证时一致。
2. 终端核对传播：cat ~/.claude.json 的 mcpServers 里出现你加的服务名；grep -A4 "BEGIN chatop mcp" ~/.codex/config.toml 能看到托管块内的条目。
3. 本机 MCP 服务健康：浏览器打开 http://127.0.0.1:52583/health，返回 {"ok":true,"service":"chatop-mcp","port":52583}。
4. 停用某服务后再看第 2 步的文件：该条目应已从各家配置中移除。

## 动手前再核对一遍

- 要收 MCP 的智能体已安装并被识别。
- stdio 型服务要求本机跑得起该命令（如 npx 首次运行需联网下载包）；HTTP/SSE 型要求服务地址以 http(s):// 开头且可达。
- 服务名称限字母/数字/点/横线/下划线（≤64 字符），且不能叫 chatop（保留给本机服务）。
