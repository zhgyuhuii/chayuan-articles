# 本地模型接口上手指南：照着做十分钟跑通

内网机器要把本地模型共享给全机软件，过去要折腾好几个工具拼起来。现在察元AI OS把这件事做成了一个功能：模型代理。下面按我实际操作的顺序走一遍，包括容易踩的坑。

## 先弄清楚它是什么

模型代理是察元AI OS 里所有大模型能力的统一出口：一个 OpenAI 兼容地址 http://127.0.0.1:52581/v1（固定端口，随系统自启，无需手动启用）。智能体 / 脚本只要配这一个地址，就能用 local/<模型id> 调本地模型（未运行会自动拉起）、用 <厂商id>/<模型名> 转发云端厂商（真实厂商 key 由代理在本机凭证库解析，调用方免 key 直连）。

让全机所有 AI 软件共用一套模型配置的关键设计：地址只有一个，模型随便换，客户端无感。

按真实界面写，按钮文案原样引用。

## 动手前的准备

- 无需任何配置：代理随本地模型服务（chatop-models）自启，端口按注册表写死 52581（一号一口，不顺延、不换号；被占时由桌面启动序清场保证原位可用）。
- 只监听本机回环（127.0.0.1 / ::1），本机之外的请求一律 403——局域网其他设备不能直接调用。
- 调 local/<id> 需该模型已下载 / 导入；调 <厂商id>/<模型名> 需该厂商已启用并加入代理路由。

## 实操全过程

1. 理解代理模型（概念）

本地模型（llama-server 实例）──┐

├─＞ 模型代理 127.0.0.1:52581 ─＞ 对话 · 知识库 · 智能体

云端厂商（厂商路由转发）───────┘

1. 统一命名空间：本地模型叫 local/<模型id>，云端厂商模型叫 <厂商id>/<模型名>（如 local/qwen3.5-4b-q4km、deepseek/deepseek-chat）。调谁都走同一个地址、同一套 OpenAI 兼容协议。
2. 免 key 直连：代理对鉴权层一律放行——不带 key、带任意值都能调用；Authorization 头仅用于审计归因（恰好匹配在册虚拟 key 记智能体名，其余记 anonymous）。真实厂商 key 只在代理服务端解析，永不出本机凭证库。
3. 本地自动拉起：调 local/<id> 时模型已安装但未运行，代理会自动加载它（并发去重，等待窗口较长；内存守卫照常拦截超预算加载）。未安装返回 404「未下载：可到「设置 ＞ 模型设置」的模型库下载」。
4. 好处：以后换模型、换厂商，智能体配置里的地址都不用动——只改模型名即可。

2. 打开代理设置页

打开 设置 ＞ 模型，左栏「本地模型」组（默认展开）里点「模型代理设置」。页面自上而下分区：运行状态 ＞ 服务地址 ＞ 虚拟 key ＞ 被代理模型 ＞ 厂商路由 ＞ 调用审计。

3. 看运行状态（最上面一张卡）

1. 绿点 + 「代理运行中」，右侧灰底等宽字显示当前基址 http://127.0.0.1:52581/v1；
2. 代理未运行时显示红点 + 「代理未运行」，且服务地址区顶部只显红字「代理未运行」；
3. 右侧「一键重应用」按钮：重启代理 listener（端口重读持久化值，仍固定 52581），改动路由后如遇异常可点它，绿色提示「代理已重应用」。

4. 认识服务地址区（端点清单）

标题「服务地址」+ 基址代码块，每行一个端点：可用性圆点（绿 = 该能力可用）、「复制」（复制完整 URL，点击后绿色提示「已复制」）、「配置帮助」（展开该端点的 curl 示例，可照抄）。五个固定端点：

区底固定说明：「免 key 直连：本机任意智能体不带 key 即可用（审计归因 anonymous）；Bearer 虚拟 key 可选（上方签发，用于审计归因与吊销管控）。模型名形如 local/<id>（本地）或 <厂商>/<model>。」

| 行标签 | URL | 用途 |
|---|---|---|
| 「对话（OpenAI 兼容）」 | http://127.0.0.1:52581/v1/chat/completions | 会话主端点；同端口另有 /v1/responses（Codex 协议）与 /v1/messages（Anthropic 协议），见「配置帮助」展开注释 |
| 「嵌入」 | http://127.0.0.1:52581/v1/embeddings | 向量化（知识库） |
| 「重排」 | http://127.0.0.1:52581/v1/rerank | 检索精排 |
| 「语音识别」 | http://127.0.0.1:52581/inference | 音频 multipart 上传转写 |
| 「模型清单」 | http://127.0.0.1:52581/v1/models | 列出全部可调模型 |

5. 让智能体 / 脚本接入（怎么用）

bash

curl http://127.0.0.1:52581/v1/chat/completions \

-H "Content-Type: application/json" \

-d '{"model":"local/<你的模型id>","messages":[{"role":"user","content":"你好"}]}'

## 做完后的验证

验证

1. 浏览器打开 http://127.0.0.1:52581/health：返回 {"ok":true,"service":"chatop-model-proxy"} 即代理在运行。
2. 浏览器打开 http://127.0.0.1:52581/v1/models（免 key）：返回 JSON {"object":"list","data":[...]}——已安装本地模型是 local/<id> 条目（带 running 运行标记与 capabilities 能力数组），已加入代理的厂商是 <厂商id>/<模型名> 条目。
3. 代理设置页顶部显示绿点「代理运行中」，基址代码块为 http://127.0.0.1:52581/v1。
4. 发一次真实调用（上面 curl 示例换成自己的模型名）：正常返回聊天 JSON；调未运行的本地模型首次会有加载等待。

## 什么情况下用得上

不明白「模型代理」是什么、向导和文档里反复提到的 52581 是干嘛的，把本地模型共享给全机软件，想让某个智能体 / 自写脚本用上本机的本地模型和已配置厂商，但不想逐家配地址和 key；智能体报连接不上模型，需要确认代理在不在运行、怎么验证它工作正常。

用户常搜的问法：模型代理的作用是什么？为什么只配一个地址；127.0.0.1:52581 是什么服务。

## 它的局限也要说清楚

用之前要认的账：

- 代理只监听本机回环，跨机访问需要另行打通
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 你可能会问

### 调 local/ 模型返回 404「未下载：可到「设置 ＞ 模型设置」的模型库下载」？

这个 id 的模型本机没装。到 设置 ＞ 模型 ＞ 本地模型 组对应分类的「模型库」下载，或在「我的模型」核对真实模型 id（引用串要和清单里的 local/<id> 完全一致）。

### 需要填 API key 吗？被请求会不会泄露厂商 key？

不需要也不会。代理只监听本机回环、免 key 直连；转发云端时真实厂商 key 由代理在本机凭证库（~/.dsh/.credentials.yaml）里解析并只在服务端注入，调用方永远接触不到。

### 能从局域网其他电脑访问这个代理吗？

不能。代理只接受本机回环请求，其余一律 403 loopback-only。这是设计行为：密钥与模型都在本机，不对外暴露。

### 调用报「未知模型命名空间「xxx」：应为 local/<id> 或 <厂商id>/<模型>」？

模型名写错了，或该厂商还没加入代理路由。错误响应会附带当前路由表里的可用命名空间（(deepseek, agnes, …)）供对照；厂商加入方法见对应教程 第 8 步。

## 补充答疑

### 智能体报 Connection error / 打不通 52581？

按序排查：① 浏览器打 /health（见验证 1）——通则代理正常，问题在智能体配置的地址或模型名；② 不通则到 设置 ＞ 模型 看顶部健康灯，本地模型服务停了代理随之不在，恢复服务即可；③ 服务正常但代理页显示「代理未运行」，点「一键重应用」。注意端口固定 52581 不会漂移，不存在被占用后换到别的端口的情况。

### 调本地模型第一次特别慢，是不是坏了？

大概率是代理在自动拉起模型：已安装未运行的 local/<id> 首调会触发加载（引擎进程启动 + 权重加载 + 健康检查），大模型需要等待。想常驻不冷启动，去 设置 ＞ 模型 ＞ 我的模型 手动「启动」并「钉住」。

整体用下来，模型代理的流程是清楚的：入口集中、步骤有反馈、做完有验证。第一次照着走一遍，后面基本就是肌肉记忆了。卡住就回看常见问题那一节。
