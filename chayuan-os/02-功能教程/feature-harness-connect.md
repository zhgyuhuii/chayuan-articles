# 远程连接：地址加测试连接

远程连接这件事，卡住人的通常是三步：入口在哪、要点哪些按钮、做完怎么确认。这篇按察元AI OS的真实界面顺序走一遍，先解决笔记本连机房工作站。

## 一句话说清定位

远程连接能做的事拆开就这几件：地址加测试连接，会话走远端。对应的界面入口是Harness 连接远程

概念一分钟，操作十分钟，这篇都覆盖。

## 前置条件

- 远程侧需有一个可访问的 dsh web 服务（浏览器能直接打开其页面），地址形如 http://192.168.1.5:52584（dsh web 主实例端口 52584，统一端口注册表口径）。
- 本机与远程侧网络互通（同局域网或路由可达），且远端服务正在运行。

## 完整操作步骤

入口：Dock ＞ 设置 ＞ 左栏「Harness 连接」分区，两张卡片：「DeepSeek Harness 地址」「局域网访问」。

1. 填入远程 dsh web 地址

1. 卡片说明文案：「留空使用当前 dsh 站点；填入远程 dsh web 地址（如 http://192.168.1.5:52584）后，新打开的 DeepSeek Harness 窗口将连接该站点。已打开的窗口不受影响。」
2. 输入框（占位示例 http://127.0.0.1:3080——此为历史端口示例，dsh web 现行端口为 52584）填入远程地址，点「保存」。留空保存 = 清除设置，回到当前 dsh 站点。
3. 保存后无弹窗，字段内容即当前生效值；设置经窗口间同步广播，无需重启。

3. 连接后的桌面行为

1. 保存远程地址后，新打开的 DeepSeek Harness 会话窗口（Dock ＞ DeepSeek Harness，或在已有 Harness 窗口点右上「+」新建）都加载远程站点（地址自动追加 ?shell=default&chatop_ctx=harness 参数）；远程源没有本机 chatop host 路由，窗口保持普通 shell 形态。
2. 已打开的窗口不受影响，继续连原站点；要切换需关掉旧窗口重开。
3. 清空地址保存后，新窗口回到本机 dsh 站点。

## 怎么确认做成了

2. 「测试连接」验证可达性

1. 点「测试连接」按钮，右侧状态文字依次变化：
    1. 「检测中…」——探测中（对 地址/ 发一次 no-cors 请求；未填地址时探测当前页面源）；
    2. 「在线」——同源可达（典型场景：留空测本机）；
    3. 「可达（跨源受限，无法验证内容）」——跨源探测成功（远程地址的正常表现，只证明网络通，不校验页面内容）；
    4. 「无法连接」——请求失败，地址不通或服务未启动。

验证

1. 填入远程地址 ＞「保存」＞ 点「测试连接」，看到「可达（跨源受限，无法验证内容）」或「在线」即网络可达；「无法连接」则核对地址、端口（52584）与远端服务状态。
2. 保存后打开一个新的 DeepSeek Harness 窗口（Dock ＞ DeepSeek Harness，或在已有 Harness 窗口点右上「+」），窗口应加载远程站点内容；此前已开的窗口保持不变。
3. 清空地址 ＞「保存」，再开新窗口，应回到本机 dsh 站点。

## 适用场景

dsh 服务部署在另一台机器（内网服务器 / Docker），本机桌面只想做操作界面，会话窗口要连远端，多台机器想共用同一个 dsh 实例的会话与插件，笔记本连机房工作站；填了远程地址后窗口连不上，想验证地址是否可达。

用户常搜的问法：对话窗口能连另一台机器上的 dsh 吗；设置里的『Harness 连接』是干什么用的。

## 几个容易忽略的细节

用之前要认的账：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 云端厂商模型调用需自备 API Key
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力

## 常见问题

### 测试连接显示「可达（跨源受限，无法验证内容）」，算连上了吗？

算。该探测用跨源 no-cors 请求，只要返回响应（哪怕是 opaque 响应）就说明地址可达；这条提示是远程地址的正常结果。它不校验对端是不是 dsh——对端内容不对时窗口仍可能异常，以新开窗口实际加载为准。

### 填了远程地址，旧对话窗口怎么还在连本机？

设计如此：「已打开的窗口不受影响」，地址只在窗口创建时读取。关掉旧窗口重开即连远程。

### 新窗口白屏或一直加载？

先「测试连接」：若「无法连接」，核对地址与端口（dsh web 端口 52584；示例占位符里的 3080 是历史端口）；若可达仍白屏，多为远端 dsh 版本与会话页参数不兼容，清空地址恢复本机连接排查。

### 这个设置和「局域网访问」有什么区别？

「DeepSeek Harness 地址」改的是本机窗口连谁（出方向）；「局域网访问」是把本机桌面共享给同一网络的手机浏览器（入方向）。两者都在 设置 ＞ Harness 连接 分区下，互不影响。

### 远程 dsh 的会话和本机是同一份吗？

窗口连到哪个 dsh 站点，会话就落在那个站点里；切回本机后看到的是本机会话，两侧不自动同步。

## 更多操作细节

4. 第二张卡「局域网访问」（同分区附带功能）

1. 勾选「开启局域网访问」：允许同一网络的手机通过浏览器访问本机桌面，卡片显示访问地址、「复制」按钮与二维码（扫码即达）。
2. 取消勾选即关闭；宿主不可用时显示「宿主不可用」。
3. 此卡与远程 Harness 地址相互独立：局域网访问是把本机桌面暴露给手机，Harness 连接是把本机窗口指向远端。

## 放回产品盘面看

把远程连接放回察元AI OS的整体盘面：换个智能体接班不用重新自我介绍，记忆全机共享是系统级的黏合剂；本机轻薄、远端肥厚时，桌面只当壳，遥测开关、清除桌面数据（破坏性操作有警示）；它能把应用造出来挂上桌面。

## 安全与数据边界

安全口径单独立一层：全部本地服务默认只监听 127.0.0.1 回环地址，数据不出本机，本机 Stable Diffusion 链路出图不联网，隐私与免费兼得；一台设备多人用，数据隔离是底线，管理员统一管账号比各自为战安全；隐私敏感环境先关遥测再干活，处置设备前清数据，（本机 MCP HTTP 服务，回环免 token）。
