# 启发式代走机制：降级链的最后一道闸

模型彻底罢工的那一手棋，棋盘上总要有人落子。干等，可能等到天亮；判负，一次网络抖动就终结一局，冤。察元竞技场给出的答案是启发式代走：它是出招解析降级链上排在末尾的那道闸，前面六级清洗、合法动作回捞、重试回喂全部失效之后，由系统替模型走一手——但替走不等于乱走。这篇讲清代走的策略细节、计数判负的规矩，以及这道兜底闸门的真实边界。

## 降级链的末环

先把整条降级链摆出来看位置。模型输出进来，先是标准解析，失败则进入逐级放宽的清洗：剥思维链块、剥代码围栏、抽大括号、截断补尾、空白规整、正则抽取；格式救不动了，拿裁判给的合法动作清单回原文里全文扫描认领；还落空，重试回喂把失败的回复喂回去再要一次。走到这一步，尊重模型意图的手段全试过了，启发式代走是链上不再指望模型自己的那一环——前面每一环都在问「模型到底想走什么」，只有这一环换了个问题：这手棋，怎么走才算数。

「才算数」三个字是关键。代走不追求走得妙，只追求走得合法、走得像样，让对局以可接受的质量继续下去。

## suggestAction：建议动作的第二职业

代走的动作从哪来？不是现编的一套随机数，而是裁判契约里现成的一个方法：suggestAction，按契约语义给当前局面出一个建议动作。启发式代走正是这个方法在兜底场景下的消费方——裁判自己懂规则、懂局面，让它出主意，产出的动作天然在合法清单之内，送进 apply 不会撞墙。

这个安排省掉两件麻烦事。其一，代走不需要单独实现一套规则理解，规则知识原本就住在裁判里；其二，「代走的招必须合法」这条硬约束由裁判的结构保证，不需要额外的校验层。兜底机制复用契约能力，而不是在契约旁边另起炉灶，这是设计上顺手的典型。

## 代走不是掷骰子

最容易误会的地方在这：启发式代走不是纯随机。若真掷骰子，代走的一手大概率荒腔走板，观众看到的不是对弈而是事故现场。竞技场的代走至少带着两条朴素的棋理：能挡杀就挡——对面下一手要绝杀，先把这条线堵上；能吃就吃——盘面上有白送的子力，先落袋。

这两条不是随手挑的。挡杀守住的是对局的观赏下限：一局棋被一刀毙命地结束，比缓慢地输难看得多。吃子守住的是朴素的博弈常识：在看不透局面的情况下，子力差是诚实的优势度量。轮到麻将，启发式换成另一套口径：取缺门里价值最低的一张打出去——缺门是胡牌的前提，先把最没用的废牌清掉，符合牌理，也符合「不求有功、但求不添乱」的代走定位。

各玩法的代走策略深浅不一，棋类的挡杀与吃子语义相对直观，牌类下注轮次的兜底空间比棋类窄，各款具体怎么实现以仓库代码为准。共同点只有一条：所有判断都由裁判对着当前局面做，规则之内见机行事，规则之外一步不越。

## 计数与判负：兜底不是无限伞

代走有代价，代价记在账上。每一次代走都计入该玩家名下，累计超过限度，这一方判负。两个细节值得展开。

为什么记在该玩家名下而不是全局？因为失能的是它一家，账自然算它一家头上，别家不该为它的 API 故障分担任何东西。为什么超限判负而不是无限代走？因为兜底与纵容之间必须有一条线：允许一个模型整局躺平、全靠系统代走刷完，既毁了观赏性，也污染天梯——那不是模型的真实水平，是启发式的水平。判负这条红线让兜底保持威慑：你可以抽风一手，不能整局失能。

要强调的是，判负之后，胜负判定依然百分之百归代码：代走改变的是动作的来源，从不动判定归属的权柄。模型可以失能，裁判不能。

## 设计取舍

两个方案被否掉，各有理由。其一，用更强的搜索算法代走——接一个小型博弈搜索，代走的棋力能上个台阶。但引擎层是零 IO 的纯逻辑裁判，往里塞搜索既违背架构约束，也改了代走的定位：代走的使命是维持对局，不是替模型赢棋，一个代走比模型自己下得还好的系统，天梯就闹笑话了。其二，代走不设上限，对局永不中断——永不中断好听，代价是把「模型参与对局」偷换成「系统参与对局」，竞技场的立身之本就没了。

代走与回捞的分工也顺带说清：回捞救回的动作来自模型自己的文本，算模型亲手走的；代走的动作来自启发式，是系统替它走的，所以要计数。一个不占额度，一个占额度，边界分明。

## 边界

启发式的能耐有限，这一点不藏着。挡杀与吃子之外的局面它一概看不懂：布局的远见、弃子的算计、牌桌上的诈唬，都不在它的词典里，代走那一手的棋力显著低于正常水平。代走的手也是可辨认的：那一手通常没有 comment 解说，也没有思维链气泡，复盘时对照着看，哪些是模型本意、哪些是兜底，痕迹分明。另外，判断「能挡杀」「能吃」本身也有误判空间——启发式认出的杀招未必真是杀招，认不出的真杀招更是无能为力，它提供的是及格线，不是保障。

### 启发式代走会帮模型走出妙手吗

不会，也无意于此。代走的定位是维持对局的质量下限：挡杀、吃子、打缺门废牌，都是不添乱的选择。真走出了妙手，那是巧合，不是算法的功劳。

### 代走次数超限判负，限是多少

阈值随玩法与版本可能不同，具体以当前版本的实现为准。机制本身是确定的：计数按玩家记录，超限判负，判罚由代码裁判执行，与模型、观战者都无关。

### 被代走的对局成绩还算数吗

算数。终局是终局，TrueSkill 天梯按对局结果正常更新。代走超限导致的判负也是真实对局结果——这恰是威慑的一部分。

### 人机局里轮到我时也会被代走吗

不会。启发式代走面向模型玩家，你的那一手不走代走：你不出招，对局就停在那儿等你，或者把控制权交给 AI 接手，让它替你续着下。

启发式代走是整条容错链上气质特殊的一环：前面每一环都在成全模型的意图，只有它，在模型彻底失声时，替棋盘说了话。能挡杀就挡、能吃就吃，九个字撑住的是一场对局的底线——棋可以臭，局不能断。
