# AGENTS.md场景实战：从需求到交付

很多AGENTS.md的教程只讲是什么，不讲怎么做；或者讲了一半步骤，剩下的让你自己悟。这篇反着来：步骤写全、按钮文案原样引用、每步的界面反馈都说清楚，用的是察元AI OS（aidooo.com）。

## 解决什么痛点

在 Claude Code / Codex 等工具里攒过一批 CLAUDE.md / AGENTS.md 记忆，换到察元OS 后不想手动搬家，会话里聊出了稳定偏好，想蒸馏成一条长期记忆，又怕系统乱记东西；清理过时记忆；每次新会话都要重新自我介绍（称呼、常用语言、项目路径），想让所有智能体默认就知道。

用户常搜的问法：怎么让所有智能体都记住我的称呼和技术栈；以前 Claude Code 的记忆文件能搬到察元OS 吗。

## 具体怎么操作

入口：Dock ＞ 设置 ＞ 左栏「记忆」分区。页面由三张卡片组成：「用户记忆」「跨智能体记忆采集（枢纽制）」「会话提炼（默认关）」。卡片右上角有「?」按钮（悬停提示「使用帮助」），点开显示「怎么设置 / 怎么验证」两段官方说明。

1. 手动添加（来源①）

1. 「用户记忆」卡片顶部输入框（占位文案「输入要记住的一条事实或偏好」）输入一行内容，点「添加」按钮（或直接回车），条目立即出现在下方列表。
2. 每条记忆右侧有一个小号来源徽标：user=你手动添加，mcp:claude-code 等形如 mcp:<智能体>=某家智能体经工具写入，refine=会话提炼入册——谁写的永远可追溯。
3. 条目行尾「关闭」删除该条；删除后投影（见步骤 6）随之更新。列表为空时显示「还没有记忆条目」。
4. 适合最核心的几条；一两句说不清的内容不适合进记忆。

2. 智能体写入（来源②）

1. 已连接 chatop MCP 的智能体（Claude Code / Codex / OpenCode / ZCode / OpenClaw 等）可在对话中直接说「记住我喜欢用 pnpm」之类，智能体经 memory_create / memory_update / memory_delete / memory_list / memory_search 五个工具读写同一份记忆。
2. 写入按作用域隔离：智能体不显式指定时默认写进自己的桶（agent:<智能体>，只有它自己可见）；只有明确写 global 的才全机共享。
3. 2026-10-18 起 memory 工具为 T0 直放（设置 ＞ 隐私与存储 ＞ 智能体权限门中不设确认），写入不再弹确认卡；每次工具写入都记入 <userData>/audit.jsonl 审计（来源 + 放行/拒绝）。

3. 会话提炼（来源③，默认关）

1. 「会话提炼（默认关）」卡片中点「现在提炼」，按钮变「提炼中…」。过程：读取最近最多 8 个 dsh 会话存档里的用户发言，交给本地模型蒸馏出最多 8 条候选事实。
2. 成功后提示「新增 {n} 条候选，待确认」，候选进入下方待确认队列（绝不直接入册）；没有可提炼内容时提示「没有提炼出新的候选」。
3. 失败时给出具体原因，如「本地模型未运行——先在「模型」里加载一个对话模型再提炼」「未找到会话存档（session.jsonl.zstd）」「近期会话里没有可提炼的用户发言」。
4. 勾选「自动提炼（每日一次，产生候选仅通知提醒）」可保存该偏好。

4. 跨智能体记忆采集（来源④，枢纽制）

1. 「跨智能体记忆采集（枢纽制）」卡片中点「开启采集（总授权）」——首次开启即总授权。授权后按钮组变为「关闭采集」「现在采集」并显示「已授权」，下方出现逐家开关。
2. 支持声明式记忆的五家（checkbox 逐家可关，默认全开）：Claude Code / ZCode / Codex / OpenCode / OpenClaw。各家读取的文件：
    1. Claude Code：~/.claude/CLAUDE.md、~/.claude/memory/MEMORY.md
    2. ZCode：~/.zcode/AGENTS.md
    3. Codex：~/.codex/AGENTS.md
    4. OpenCode：~/.config/opencode/AGENTS.md
    5. OpenClaw：~/.openclaw/workspace/AGENTS.md、~/.openclaw/workspace/MEMORY.md
    6. 点「现在采集」（进行中显示「采集中…」）：读取上述文件的用户段落（markdown 列表行），自动剥除察元自己的投影段（防反馈环），与既有记忆/候选精确去重，内容未变化的文件不重采（哈希台账）。成功提示「新增 {n} 条候选，待确认」。
    7. 待确认队列硬上限 5000 条，超限部分显式提示丢弃数，不静默丢。
    8. 采集来的候选默认落来源智能体自己的桶（agent:<家>），审阅时可一键升级为全机共享（见步骤 5）。

5. 待确认队列审阅：入册 / 丢弃 / 升为全机共享

1. 待确认列表每条候选左侧是来源徽标（如 codex），右侧三个动作：
    1. 「入册」：确认为记忆。提炼候选入册后默认全机共享；采集候选入册保持在自己桶内（仅该智能体可见）；
    2. 「升为全机共享」：仅非 global 候选（采集进来落在智能体桶里的）显示此按钮，点它=入册并直接升为 global 作用域，全部智能体可见；
    3. 「丢弃」：不要这条，从队列移除。
    4. 多条候选时相近内容自动聚合成组：组头显示「相似 {n} 条」徽标与「整组入册」按钮；顶部还有「全部入册」「全部丢弃」批量按钮，提示行「相近候选已聚合，可整组处理；逐条审阅仍可单独操作。」
    5. 队列为空时显示「暂无待确认候选」。候选不入册就是不入册——逐条确认制保证垃圾进不来。

6. 自动投影：记忆怎么被智能体用上

1. 记忆每次增删改（含设置页删除），桌面主进程在 500ms 内自动重投影到以下文件的 chatop 托管段：
    1. 主目录 ~/AGENTS.md（只装 global 条目，Codex / OpenCode 等多家 CLI 共读）；
    2. ~/.claude/CLAUDE.md（Claude Code 原生读取）、~/.zcode/AGENTS.md、~/.codex/AGENTS.md、~/.config/opencode/AGENTS.md、~/.openclaw/workspace/AGENTS.md（各装 global + 该家自己桶的条目）。
    3. 托管段以 <!-- chatop:memory-begin (managed section; edits inside are overwritten) --> 与 <!-- chatop:memory-end --> 标记包裹，标记外的内容一字不动；段内是「## User memory (chatop)」加逐条列表，只装最新 60 条（每条截断到 400 字符，更旧的经 memory_list 查询）。
    4. 记忆清零时托管段被移除；文件若因此变空则整个文件删除。

## 关键能力点

- 三档作用域
- 自动投影进配置文件
- 每条记忆可溯源
- 入册丢弃两处置

## 别在这几处栽跟头

边界都在这：

- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 高频疑问

### 智能体说「记不住」我的偏好？

该智能体需经 chatop MCP 连到本机（设置 ＞ MCP 确认「察元本机 MCP」运行中且已写入该智能体配置）。另外检查记忆作用域：智能体默认写自己的桶，其他智能体看不到；想全机共享，在对话里明确说「记住为全局」，或把该条删了手动重加。

### 点「现在提炼」提示「本地模型未运行」？

蒸馏用本地对话模型（只找已运行的对话实例，不自动拉起）。到 设置 ＞ 模型 加载一个对话模型后再回来提炼。会话存档格式不可解析时会提示降级为手动整理，属正常保护。

### 多用户会串记忆吗？

不会。记忆存本机 os-data，按用户分库隔离，切换/登录不同用户各看各的。

整体用下来，用户记忆的流程是清楚的：入口集中、步骤有反馈、做完有验证。第一次照着走一遍，后面基本就是肌肉记忆了。卡住就回看常见问题那一节。
