# 虚拟Key操作详解：真实界面步骤与常见坑

虚拟Key这件事，说简单也简单，说麻烦是真麻烦——麻烦不在功能本身，在于信息散落在各处，拼出一个完整流程要查好几篇资料。这篇文章把它一次讲全：是什么、入口在哪、具体步骤、边界在哪，全部基于察元AI OS的真实界面。

## 是什么与为什么

模型代理设置页的进阶用法：被代理模型树形多选后一次应用进多个智能体、厂商路由的加入 / 移出、虚拟 key 的签发与吊销（审计归因用）、调用审计查看，以及每个本地模型一键生成各家智能体的可复制配置片段。基础概念与运行状态见对应教程。

给外部工具开权限又不想交出真实厂商 Key，虚拟 Key 加审计是标准答案。

下面直接进入正题。

## 操作前的准备工作

- 已理解 M7：代理固定 127.0.0.1:52581、免 key 直连；本页四区（虚拟 key / 被代理模型 / 厂商路由 / 调用审计）都在 设置 ＞ 模型 ＞ 「模型代理设置」页。
- 「应用…」写智能体配置文件需桌面形态；厂商路由要有可加入的对象。
- 虚拟 key 与审计纯属可选：不签 key、不看审计，代理照常工作（归因记 anonymous）。

## 从打开到做完的每一步

1. 被代理模型：树形多选 + 一次应用多个

页面第三区标题「被代理模型（local/ 本地 + 厂商路由）」，右侧三个按钮：「全选」「清空」和蓝色主按钮（未勾选时显「统一应用…」，勾了 N 个显「应用选中（N）…」）。下方是一棵三级复选树：

1. 第一级组：「本地与自建 · local/」（本机图标，按本地分类再分组）+ 各厂商路由组（厂商 logo）；组行可折叠、带计数药丸；
2. 第二级是模型分类（本地按「对话 / 嵌入 / …」，厂商按「对话模型 / 图像理解 / …」类型）；第三级是模型叶子（等宽引用串 local/<id>、<厂商id>/<模型名>），运行中的本地模型带「运行中」标记；
3. 勾分组 = 全选其下；树底说明原文：「树形多选：厂商 ＞ 模型分类 ＞ 模型名；厂商组只列已配置密钥且可用的模型。勾选分组即全选其下，『应用选中』一次写入多个。」
4. 勾选后点「应用选中（N）…」弹出应用对话框：
    1. 顶部蓝色 chips 列出已选模型，下方提示「已选 N 个模型 · 多选时 Harness 写入完整模型清单、OpenCode 写入可切换清单；Codex/Claude/OpenClaw 只有一个默认模型槽位，取第一个。」；
    2. 智能体勾选清单默认全勾五家：「DeepSeek Harness（模型下拉）」「Claude Code（~/.claude/settings.json）」「Codex（~/.codex/config.toml）」「OpenCode（~/.config/opencode/opencode.json）」「OpenClaw（启动环境注入）」；本机感知到但不支持自动写入的智能体灰显并注「暂不支持自动写入模型配置」；
    3. 点「应用」逐家写入，逐项显示「已写入」或红色错误；点「关闭」收起。写入内容 = 代理地址 + 模型引用串（免 key，写入前自动备份可回退）。
    4. 不勾任何模型直接点「统一应用…」：退回兜底——优先取「设置 ＞ 默认模型」选定的本地对话模型，其次第一个已装本地模型、再取厂商路由第一个模型，打开同一弹窗（此时弹窗内是树形多选，可再改选）。
    5. 每个模型叶子行尾另有单发按钮「应用」（只写这一个模型）。

2. 厂商路由：移出（加入在模型设置）

第四区标题「厂商路由（加入代理的厂商经代理转发）」。每行：厂商 logo + 厂商名 + 路由 id（等宽小字）+ 转发地址与点名模型清单，行尾「移出」按钮——点击即从代理路由表移除（绿色提示「厂商已移出代理」），该厂商模型从 /v1/models 清单与各选择树消失；厂商密钥仍留在凭证库，随时可重新加入。加入入口不在本页（候选选择树已按 2026-10-13 用户裁定移除）：去 设置 ＞ 模型 的厂商卡点「加入代理」；默认模型页保存、建宠选厂商模型时系统也会自动补建路由。一行都没有时显示「尚未加入任何厂商」。

3. 虚拟 key：签发与吊销（审计归因用）

第二区标题「虚拟 key（每智能体一枚，真实厂商 key 永不出凭据库）」：

1. 右侧下拉「＋ 签发 key」，四个选项：harness / codex / opencode / openclaw；选中即签发，绿色提示「key 已签发（只显示一次）」；
2. 签发结果完整明文只显示这一次：绿底框「新 key（只显示这一次，点击复制）：<key>」，点 key 串复制（提示「已复制」）。key 形如 chatop-agent-<智能体名>-<随机串>；
3. 列表里只显示在册未吊销的 key：脱敏串（chatop-agent-<智能体名>-…<末4位>）+ 智能体名 + 「吊销」按钮（提示「key 已吊销」）。同一智能体重签会自动吊销旧 key（一键一活）；
4. 没有 key 时显示「尚未签发任何 key」。
5. 语义（重要）：代理 2026-10-13 起不做任何 key 验证——不带 key、带错 key、带已吊销 key 都照常放行。签发 key 的仅有价值是把代理审计记录归因到具体智能体（否则记 anonymous），并保留吊销管控能力。

4. 调用审计：看谁调了什么

最后一区标题「调用审计（元数据；正文日志默认关闭）」：

1. 每条记录一行：时间 + 智能体名（签过 key 的记 key 名，否则 anonymous）+ 模型与端点 + 状态码（200 绿色，非 200 红色）+ 耗时 ms；新记录在上（页面取最近 100 条，服务端环形保留 300 条）；
2. 没有记录时显示「暂无调用记录」；
3. 右上勾选框「记录正文（默认关）」：打开后审计附请求 / 响应预览（各截前 200 字），提示「正文日志开关已更新」。涉及对话内容，排障时临时开，看完建议关回。

5. 「帮助」：可复制的智能体配置片段

被代理模型树里 local/ 本地模型行尾有「帮助」按钮（厂商模型行没有），点开「接入指南」弹窗，标题「接入指南 · <模型引用串>」。为该模型动态生成、逐块「复制」的片段：

1. 「curl 经代理」：完整 curl 命令（Bearer 为最近签发的 key，没有则留空——代理免 key 也放行）；
2. 「Claude Code」：~/.claude/settings.json 的 env 段写法（ANTHROPIC_BASE_URL 不带 /v1，另有 ANTHROPIC_AUTH_TOKEN、ANTHROPIC_MODEL）；
3. 「Codex」：~/.codex/config.toml 的 [model_providers.chatop-proxy] 表写法（base_url 指 http://127.0.0.1:52581/v1、wire_api = "responses"）；
4. 「OpenCode」：~/.config/opencode/opencode.json 的 provider 表写法（model 须写全 chatop-proxy/<模型id>）；
5. 「OpenClaw」：启动环境变量写法（OPENAI_BASE_URL / OPENAI_API_KEY / OPENCLAW_API_KEY）；
6. 该模型正在运行时，多一块「直连实例」（不经代理直连引擎端口的 curl，注释注明「运行中的本地实例可直接访问（不经代理/无需 key）」）；嵌入 / 重排能力模型各多一块对应 curl。
7. 点任意块右侧「复制」提示「已复制」，右下「关闭」收起。这些片段与「应用」按钮实际写入的内容由同一生成函数产出（单一事实源，不会两边漂移）。

## 做完后的验证

验证

1. 签发 key：下拉选 codex ＞ 出现绿底「新 key（只显示这一次，点击复制）：chatop-agent-codex-…」；列表新增一行脱敏串 + codex。点「吊销」后该行消失。
2. 树形多选应用：勾 2 个模型 ＞ 「应用选中（2）…」＞ 弹窗 chips 显示 2 个 ＞ 勾 Codex「应用」＞ 打开 ~/.codex/config.toml，默认模型 = 第一个勾选模型，模型目录可见全部注入模型。
3. 厂商路由：本页点某厂商「移出」后，浏览器刷新 http://127.0.0.1:52581/v1/models，该 <厂商id>/… 条目消失；回模型设置厂商卡点「加入代理」可恢复。
4. 审计：用任一智能体发起一次对话，回本页「调用审计」出现新行（时间 / 智能体 / 模型+端点 / 200 / 耗时）；带签发 key 调用的行首智能体名是 key 对应名。

## 谁需要这个功能

给第三方工具开模型通道；厂商模型不见了 / 不想再让某家厂商走代理——管理厂商路由，想一次把多个模型写进智能体，让智能体内部可切换（而不是只写一个默认模型），想知道「哪个智能体在什么时候调了哪个模型、成功没有」——看调用审计，或给每个智能体签发归因用的虚拟 key。

用户常搜的问法：虚拟 key 是干什么的？怎么签发和吊销；怎么把好几个模型一次写进 Codex / OpenCode。

## 几个容易忽略的细节

功能归功能，这几个边界先摆清楚：

- 虚拟 Key 泄漏可随时吊销，真实 Key 不出凭证库
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重

## 高频疑问

### 虚拟 key 忘了或怀疑泄露怎么办？

原值无法回显（只显示一次）。点该行「吊销」再重签一枚即可，旧 key 立即失效——且按免 key 语义，失效 key 的请求只是归因降级为 anonymous，不会 401；泄露的实际风险仅是冒用归因，吊销即消除。

### 为什么本页没有「加入厂商」的入口？

按 2026-10-13 用户裁定，候选选择树已移除（与被代理模型树冗余）：加入统一走 设置 ＞ 模型 的厂商卡「加入代理」；默认模型保存、建宠选厂商模型也会自动补路由。本页只保留「移出」。

### 厂商模型行点不了「帮助」？

「帮助」按钮只在 local/ 本地模型行（直连实例块依赖本地引擎端口）。要厂商模型的手写接入片段，参照 M7 第 5 步的通用 curl，把模型名换成 <厂商id>/<模型名> 即可。

### 一次应用了 5 个模型，为什么 Codex / Claude Code 里默认只有一个？

Codex、Claude Code、OpenClaw 只有一个默认模型槽位，多选时取第一个（提示原文见第 1 步）；Harness 写入完整清单进模型下拉，OpenCode 写入可切换清单（CLI 内可切）。

如果只记一件事：虚拟 Key 签发与吊销。剩下的细节照步骤节走就行。
