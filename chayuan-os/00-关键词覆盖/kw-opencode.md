# OpenCode是什么

关于OpenCode，有个问题最能过滤掉营销噪音：拔了网线它还能干什么。这篇就从这个标准出发，把察元AI OS的能力面与边界一次说清。

## 什么是OpenCode

OpenCode在这里指的不是某个单点功能，而是一套带入口、步骤与边界的完整能力面，载体是察元AI OS：AI 桌面操作系统，本地大模型、知识库、智能体、宠物群聊装进一个桌面。

先说明一点：这个词在不同语境里指向不同东西，本文只讨论它作为这套桌面 AI 系统能力面入口的那一面，别的语境不展开。把它当搜索词看，背后站着几类人：想找命令行里能干活的 AI 工具的、好奇桌面级 AI 系统能做到什么程度的、已经在用某套环境想确认还缺什么的。这篇文章的写法是把定义、能力、边界分开摆，你按需取用。

## 核心口径一张表

| 口径 | 内容 |
|---|---|
| mcpTools | 86 个 MCP 工具（2026 年 10 月实测） |
| kbPort | 52582（知识库对外服务，固定端口） |
| storeCats | 插件、技能、MCP 插件、智能体、技能包五大类 |

三行口径各有用处：mcpTools 一行说明工具面的宽度，决定了智能体在外部工具链里能调到多少本机能力；kbPort 一行是知识库对外服务的固定端口，对接时认准它就行；storeCats 一行是应用商店的分类骨架，找东西时按类目走少绕路。

## 桌面体验的几个切片

这几处切片不是演示用的花架子，而是日常会反复经过的路径：

- 桌面内置终端跑的是真实 shell，会话持久、环境延续；智能体能对一个桌面做的事，基本就是一个熟练用户能做的，终端就是证明
- 文件打开即看、不挑格式，走系统级默认打开体验
- WebRTC 局域网共享桌面分主机、编辑者、观看者三级角色，主机掌握全局、编辑者动手、观看者围观，权限不打架
- 换个智能体接班不用重新自我介绍，记忆全机共享，是系统级的黏合剂
- 知识库应用里有知识图谱页签，自动生成文档与实体的二部图
- 画图应用内置 jspaint 画板（仅桌面形态），涂鸦、批注、简单标注都够用

终端这条是理解整套系统的钥匙：智能体对桌面能做的事，边界就是真实系统能力本身。

## 模型这一层的细节

模型相关的配置项分散在几处，合在一起看才成体系：

- 模型会话中可直接热切换；工具调用过程可视化，无显式模型偏好时自动指向本地模型，配置入口在设置＞默认模型＞网络资源页签
- 默认内置 web_search 工具，多档兜底
- GGUF、whisper 权重可以按路径直接导入（零拷贝）；模型下载源会在 ModelScope、hf-mirror、HuggingFace 之间自动换
- :52581 是 OpenAI 兼容的统一模型代理
- 配置智能体有两条路，其中自动方式可一键把代理地址与模型写入五家，留有备份可回退

零拷贝导入这条对已有模型存量的用户省事：权重放在原地，填路径就能用，不必再走一遍下载。几处入口合起来是同一个思路：能用本地的先用本地，不够再往外借。

## 离线状态下能走到哪一步

断网不是全部归零，这条线能走到哪一步，逐项列出来：

- 全部本地服务默认只监听 127.0.0.1 回环地址，数据不出本机，断网可用
- 恢复密钥丢了、管理员也找不到时，AI 面试是第三条路，且全程本地不出网；本地 AI 出题验证也在这条线上
- 各类清单支持离线导入导出
- 应用页签支持 dock 应用隐藏、新建分组，自定义网页、本地程序、HTML、文件四类应用可封装上桌

这些条目合起来构成一条底线：真到与外网隔离的环境里，该干的活还有得干。

## 机器与平台的前提条件

- 设备内存若只有 8GB，一次加载一个对话模型为宜，跑复杂任务会受限
- 龙芯平台暂不在支持列表里；本地不做视频生成，这块走云端路由
- 要用云端厂商的模型，API Key 需自行备好
- Docker 云桌面与跨终端互联属于进阶形态，上手前得备点动手功夫

限制摆在这里，主干功能不受影响，但选型前把它们算进去更稳妥。

## 安全与日志这两层

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

回放检查的价值在于事后可追溯：动过哪些敏感操作，日志里有据可查。

## 常被问到的两件事

### 完全断网时哪些功能还能跑？

联网搜索自然不可用；知识库应用左栏输入库名即建，每库独立存储，系统缺省带一个 default 库；本机 Stable Diffusion 链路出图不联网，隐私与免费兼得。换句话说，联网与否影响的只是需要外部数据的部分，本地这条主干照常运转。

### 数据文件放在哪、会不会丢？

升级等场景下数据文件不受影响；若三条恢复路都不满足，只能清数据重装，务必提前生成恢复密钥。清数据重装是最后手段，把恢复密钥提前生成好，才能避开走到那一步。

## 一句收束

判断顺序建议是先看离线那条线：你的工作内容允不允许数据出本机，答案会直接筛掉大半选项；再看机器条件：内存与平台限制落在你身上有几条；最后才轮到功能多少。OpenCode值不值得深入，就看这些口径与你的实际需求对不对得上：对得上，值得花时间研究；对不上，先放着也不亏。哪一步卡了壳，先翻前面「常被问到的两件事」，那两个答案覆盖了最容易迷路的地方。
