# 红头文件对比排查路径：AI 功能依赖已配置的模型

很多人搜「怎么让 AI 的修改像 Word 修订一样显示，可以逐条接受/拒绝」，搜到的多是概念解释，落不到操作。这篇以察元AI Office为准，把红头文件对比从打开哪个应用讲到看到什么结果。

## 排错先归到哪一层

排红头文件对比的错，顺序比速度重要：环境与模型先就位，然后对操作路径，最后核边界。三层各有一些典型症状，对号入座能省很多时间。

举几个对号的例子：审阅页签的接受、拒绝按钮一直置灰，多半落在第一层——文档里压根没有待处理修订，或文件被保护了；compare 命令报 --out 文件已存在，属于路径层的参数问题，加 --force 即可；对比文件拿到 Word 里打开却看不到修订痕迹，那就要核对生成环节是否走对了命令。先归类，再动手，比从头到尾重试快得多。

## 应用内比较与命令行对比

第 5 步 · 应用内「比较」两份文档

1. 「审阅」页签右侧「比较」组点「比较」按钮（提示「比较:选择另一个文档,按段落对比差异」），弹出文件选择框，选另一份 .docx。
2. 左侧弹出「比较结果」面板：标题行显示「与 <文件名> 相比:新增 {n} 段,删除 {n} 段,修改 {n} 段」；下方逐段列出差异卡（左边原文/右边新稿对照），连续相同的段落折叠成一行「… {n} 段相同 …」；两份内容完全一致时显示「两个文档内容一致」。点面板右上 关闭 关闭。

第 6 步 · CLI 红头对比：chaoffice docs compare

```
chaoffice docs compare 原稿.docx 修订稿.docx --out 对比.docx
```

产物是一份带修订痕迹的对比文件：以修订稿为底，所有差异都写成插入/删除修订（作者默认 ChaAI Office，日期默认当前时间）——与 Word「审阅 比较」的产物同类。命令完成后摘要形如 A.docx vs B.docx: 3 inserted, 2 deleted, 5 changed paragraph(s) in 对比.docx。

1. 终端执行：
    1. 常用参数：「--granularity word|char」控制改动段落按词还是按字符级细分（默认 word）；「--ignore formatting,case,whitespace」忽略格式/大小写/空白差异；「--author 名字」「--date ISO时间」改写修订作者与日期；「--force」覆盖已存在的 --out 文件（或在 chaOffice 正开着该文件时写入）。
    2. 对比文件用本文编辑器、Word 或 WPS 打开，即看到第 2 步同款的接受/拒绝界面。
    3. 同族命令：chaoffice docs read 文件.docx --revisions 可列出文件里的待处理修订；chaoffice docs apply 文件.docx --track --ops ... 把编辑落成修订（作者默认 AI Assistant，可用 --author 改）。

## 三项结果算数

三项结果都对上，排查就算通过：

1. 开「修订追踪」后发一句「把第二段里的『2025 年』都改成『2026 年』」：改动处应出现插入/删除修订标记，审阅页签「接受」按钮提示总数增加；点「拒绝所有修订」文档恢复原样并提示「已拒绝所有修订」。
2. 点「AI 总结修订」：AI 面板新增一轮回复，只含统计与风险清单，文档修订数不变。
3. 终端跑第 6 步示例命令后用本文编辑器打开 对比.docx：应能看到带作者 ChaAI Office 的插入/删除修订；命令输出的摘要中 inserted/deleted/changed 数字与肉眼核对一致。

## 修订链路的四项能力

- 通用修订格式
- 逐条接受拒绝
- AI 总结修订
- 双稿对比

## 疑难杂症在这里查

### 「接受」「拒绝」按钮是灰的？

文档里没有待处理修订（提示「没有可处理的修订」），或文档处于保护状态。先让 AI 在「修订追踪」开启时改一轮，或打开一份本身带修订的文件。

### docs compare 报 --out 文件已存在？

对比产物默认不覆盖已有文件，加 --force 重跑；目标文件正被 chaOffice 打开时同样需要 --force。

### Word 打开对比文件能看到这些修订吗？

能。修订以标准 OOXML 修订标记（w:ins/w:del）写进文件，Word/WPS 的审阅功能照常显示作者与时间、可逐条接受/拒绝；同样地，Word 里做的修订在本文编辑器里也能读和处理。

### 对比文件里的修订作者怎么是 ChaAI Office？

这是命令的默认值，不代表哪里出了问题。想让署名换成自己，跑 compare 时带上「--author 名字」参数即可，日期同理可用「--date」指定。

## 排查前备齐两样

- 在文档（Docs）编辑器中打开一个 docx，并打开右侧 AI 面板；已配置至少一个对话模型。
- CLI 对比需要本机终端里可用的 chaoffice 命令，以及两份本地 .docx。

## 顺带认识这套套件的底细

红头对比只是这套套件的一角，与排查相关的底子有这些：支持批量处理，省去逐份打开的重复劳动；改动保持字节保真，不会弄乱整个文件的既有格式；Linux 下无系统 OCR 引擎，扫描页保留位图不识别；安装包覆盖三平台五形态。

## 数据口径补充

涉及数据与留痕的几条：文件多了靠搜索定位，支持正文级搜索；表格与演示只建空文件；AI 的每处改动都留痕可审，便于事后核对；加密备份随文件走。
