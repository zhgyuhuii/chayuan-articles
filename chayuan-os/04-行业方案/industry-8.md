# 医疗卫生AI方案落地：AI 桌面操作系统

## 医疗卫生为什么需要这套方案

医疗卫生行业的文档与信息工作有几个共性：材料格式要求严、数据敏感不能乱传、人手紧重复劳动多。察元AI OS的切入点不是推倒重来，而是把 AI 能力装进现有流程，数据不出本机是底线设计。

## 落地路径：三步走

1. 基础层：先把模型设置向导跑通，验证环境与模型可用
2. 流程层：医疗卫生日常最高频的文档环节（配置云端厂商模型所属的场景）交给 AI 处理，人只做审核
3. 治理层：权限门与审计机制上线，形成使用规范

## 关键能力对齐

### 模型设置向导

- 概念页解释模型代理机制
- 默认对话模型选择
- 统一应用到智能体

### 配置云端厂商模型

- 国内/国际/本地/聚合四组厂商目录
- OpenAI 风格与阿里百炼风格 API 自动适配
- 填 Key 后可测试连通再启用

### 下载本地模型

- 内存预算分层推荐
- 断点续传与多路换源

### 离线导入模型权重

- 路径导入零拷贝
- 扫描本地放置的模型
- whisper 语音权重同样支持

## 一个行业侧影

内网与涉密单位用户的典型链路：

1. 官网下载全量离线包（含五件套权重，约 4.7GB）
2. U 盘搬运到内网机器安装，离线包逐文件校验
3. 本地模型对话、知识库问答、AI 办公全链路离线用
4. 跨终端互联按需开授权，出厂零共享

断网环境获得与联网几乎等同的 AI 能力面。

提醒：涉密使用需本单位审批，工具只提供技术可行性。

## 合规与边界

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

行业落地最容易翻车的不是技术，是把边界讲清楚。
