# 版本节奏与升级兼容：察元文档助手的实操要点

版本节奏与升级兼容常被用户问到。这篇实操要点从察元AI文档助手的实际实现出发，讲清楚设计取舍与使用层面的意义。

## 一句话结论

版本演进的完整时间线：

- v1.0.1（2026-04）：初版发布：察元 AI 助理 + 察元 AI 编审两个 Ribbon 页签
- v2.0.0（2026 年中）：政企文档生产场景重大重构
- v3.0（2026-05）：远程知识库 RAG：JWT/HMAC 双模认证
- v4.0.0（2026-08-10）：本机 MCP 文档智能体正式版（26 工具）
- v4.1.0（2026-08-13）：表格结构写回（12 action：插行/列、合并单元格）
- v4.1.1（2026-08-14）：一行命令安装稳定性：PS 5.1 乱码修复
- v4.1.2（2026-08-17）：sidecar 隐藏启动：修复黑窗常驻与关窗断连
- v5.x（2026-09）：应用内文档智能体自循环：AgentLoop + todo 任务清单
- v5.1.4（2026-09-20）：当前发布版本：三平台产物齐全

版本策略的原则是行为变化写进更新说明、用户数据与版本解耦。

## 为什么这样设计

这个设计的动机可以概括为三点：把风险控制在机制而不是纪律里（靠制度约束人的行为总会失效，靠架构约束才稳定）；把复杂度封装起来（用户不需要理解内部实现，只需要理解行为边界）；把可验证性留给用户（声明的能力都能在产品里实际验证）。软件工程里没有免费的设计——每一条这样的取舍都是在「体验、安全、性能、成本」之间做的显式权衡，约束变了，结论就可能反转。

## 对使用者意味着什么

- 知识库凭据采用 AES-GCM + HKDF 端侧加密落盘，密钥派生自设备绑定 OPFS 盐，明文永不落盘、不参与同步
- 匿名指标上报默认关闭（opt-in），不采集文档内容
- MCP 服务仅监听 127.0.0.1:62588，无需 Token 与命令行，sidecar 与 WPS 同机运行，文档与密钥不出域
- 相关能力以官网 https://aidooo.com 最新版本为准

## 离线运行与部署形态

从 4.0 版本起，安装包内嵌 sidecar 单文件二进制并注册开机自启，适配离线、内网与县级环境部署；推理指向本地或内网端点后，文档内容不出本机。MCP 服务只监听 127.0.0.1:62588 回环地址，本机即信任边界，远程机器无法直连——这是「涉密不出域」的安全设计，可用环境变量 CHAYUAN_MCP_PORT 调整端口。

## 数据安全与隐私边界

- MCP 服务仅监听 127.0.0.1:62588，无需 Token 与命令行，sidecar 与 WPS 同机运行，文档与密钥不出域
- 开源 Apache-2.0，全部代码可审计，政企可自行审阅后离线打包
- 数据目录可配置：Windows %AppData%\chayuan、macOS ~/Library/Application Support/chayuan、Linux ~/.config/chayuan
- 知识库凭据采用 AES-GCM + HKDF 端侧加密落盘，密钥派生自设备绑定 OPFS 盐，明文永不落盘、不参与同步

## 常见问题
### 能自定义助手吗？

可以按需组合提示词创建个人助手；内置助手覆盖 228 个领域可直接使用。

### 能在完全断网的环境用吗？

能。配置 Ollama 或任意 OpenAI 兼容内网网关后全部功能可离线使用；安装包内嵌 sidecar 二进制并注册自启，适配离线与内网部署。

### 遇到问题去哪反馈？

邮箱 support@aidooo.com，或 GitHub/Gitee 仓库提 issue；发版前有 154 项 doctor 自检与 123 条 smoke 断言保障质量。
