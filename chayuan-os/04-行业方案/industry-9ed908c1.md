# 建筑设计行业怎么用察元OS：从痛点到落地

建筑设计行业的文档与信息工作有其固有节奏：专业术语与口径需要全篇一致，人工核对容易漏。察元AI OS在建筑设计场景下的定位，是把可标准化的环节交给工具、把判断留给从业者的「人机协同」。本文按痛点→能力→落地步骤→边界的顺序，给出建筑设计行业的完整应用路径。

## 建筑设计行业的典型痛点

- 专业术语与口径需要全篇一致，人工核对容易漏
- 新人上手慢，经验沉淀在个人手里而非工具里
- 临时性、突击性材料多，加班赶稿是常态

## 对应的能力组合

- **技能页签与技能商店**（技能商店）：技能管理页签：启停（改写 SKILL.md 元数据）、打开目录、删除（入废纸篓）、tar.gz 离线导出导入；技能商店可搜索 GitHub 技能仓库一键安装（内置 anthropics/skills 等精选）。
- **对话（DeepSeek Harness 会话）**（AI对话）：「对话」应用是内嵌 dsh 会话运行时的 AI 会话窗口：多会话多开、流式输出、工具调用、本地/云端模型一键切换；⌥Space 全局唤起。
- **四家 CLI 智能体**（CLI智能体）：Claude Code、Codex、OpenCode、OpenClaw 四家命令行智能体以「应用」形态运行：真实 pty 终端、绑定工作区目录、多标签；二进制随安装包分发（约 1.3GB），开箱即用。
- **内置应用全家桶**（系统应用）：浏览器、我的电脑、应用管理、应用商店、备忘录、提醒事项、日历、音乐、媒体播放器、文本编辑、PDF 预览、图片查看、文生图（Stable Diffusion）、画图、Markdown 预览、Monaco 代码编辑、废纸篓、帮助中心等 20+ 内置应用。

## 落地四步

1. 盘点本岗位高频文书/信息任务，挑最耗时的两个作为切入口
2. 按会议组织者场景的工作流试跑一周，记录节省的环节
3. 把常用任务固化为助手或规则模板，团队复用
4. 建立人工复核节点：工具产出 → 从业者裁决 → 定稿

## 合规与边界

- 涉密与敏感材料遵循本单位管理规定，必要时使用离线部署形态
- Docker/云通道等进阶形态需要一定动手能力
- 行业判断责任始终在人，工具输出作为参考

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 本地模型五件套随软件分发，断网即用
- 全部本地服务只监听 127.0.0.1，数据不出本机
- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）

## 常见问题
### 知识库检索质量如何？

向量（sqlite-vec）+全文（FTS5）混合检索加 RRF 融合，可选 bge 重排精排与邻块扩窗；大库可选 Milvus 向量库。

### 和察元AI文档助手什么关系？

同家族：文档助手装在 WPS 里做校对编审；OS 是完整桌面系统，两者可通过 MCP/技能协作。

### 断网能用吗？

能。本地模型对话、知识库、桌面与应用、智能体终端均可离线；仅模型下载、云端模型、应用更新需要网络。
