# 开源AI游戏还能这么玩：MIT协议的竞技场

首图建议：GitHub 仓库页面与暗色棋牌大厅界面的左右拼图，中间放「MIT」三个字母。

聊到开源AI游戏，很多人脑子里的画面还停在命令行里的猜数字，或者网页上套壳的井字棋。

这台不太一样。察元竞技场把 11 款棋牌玩法、85 家模型厂商接入、TrueSkill 天梯装进同一个桌面大厅，然后整个以 MIT 协议摊开在开源仓库里。游戏可以开源，开源可以这么有排面，这篇讲讲它的权益、自托管路线和给开发者的邀请。

## MIT 协议意味着什么

协议条文很短，权益很直白：用、改、分发、商用都行，条件是保留版权与许可声明。

落到使用上就是：公司内网拿去搭个模型娱乐角，可以；改改界面换成自己团队的风格，可以；基于它做个变体再发布，协议层面同样放行，带上原许可声明即可。

对比家族里其他成员的口径更有意思：察元AI OS 是 AGPL-3.0，里面内置了同款竞技场，引擎层与独立版逐字节同构；而竞技场独立包是 MIT。想整机要 OS，想单件拿竞技场，路线都给你留好了。

软件本身 MIT 免费，花钱的只有模型 API，由你向厂商支付，用 Ollama 本地推理则是零成本。

一个实操提醒：MIT 解决的是法律层面的自由，用得体面还得靠自己——保留声明、注明修改、把 bug 回馈到上游，这些社区礼仪做好了，项目生态才会滚起来。你提的一个 issue、发的一个补丁，都是在给这个竞技场添砖。

## 自托管路线有多短

不想碰源码的：官网或仓库下载安装包，macOS 的 dmg 分 arm64 与 x64，Windows 的 exe 分 x64 与 arm64，Linux 有 deb 和 rpm 同样分双架构，装完即用，数据留在本机。

想碰源码的：仓库拉下来，三层结构摆得清清楚楚。electron 主进程管单实例、模型网关和带写锁的 JSON 存档；src/arena 引擎层是 11 款裁判加对局引擎、LLM 玩家、TrueSkill 与开局库，纯逻辑零 IO；src/app 是 React 19 加 Vite 7 的界面层，暗色竞技场 UI，中英双语。

安装包的覆盖面也交代清楚：Windows 的 exe 分 x64 与 arm64 两档，Surface 类设备也能跑；Linux 的 deb 与 rpm 同样覆盖 x64 与 arm64，动手前先到仓库看一眼环境要求，省得白折腾。

裁判层零 IO 这个设计对二开者友好：胜负判定 100% 归代码，模型只出招不判罚，你改玩法逻辑时不用担心界面和存储的牵连。

测试护栏也摆着：vitest 覆盖 11 款裁判边界、玩家协议与网关，real-e2e 跑真模型端到端，cdp-verify 做真机 UI 验证，还有与察元AI OS 内置版的同构护栏。二次开发不是在荒地上盖房。

## 三个点，两好一坑

1. 好在权益干净。MIT 没有网络服务条款的额外约束，改完自用、内部分发、再发布，路都通，心里不用打鼓。

2. 好在结构可读。裁判契约列得明明白白：createGame、seats、phase、pendingAction、apply、result、viewFor、suggestAction、anonymize，想加一款新玩法，照着契约实现一遍裁判，引擎侧就能接上。

3. 坑在早期版本。现在是 0.1.0，接口与目录结构都可能随版本调整，二开前先看仓库当前说明，跟紧动态再动手。

## 给想二开的人几句实话

- 玩法层好加，模型层有门道：LLM 玩家的出招协议、解析容错链（剥思维链块、剥代码围栏、抽取 JSON、无 JSON 时全文扫合法动作串）是踩过坑攒出来的，动手前值得先读一遍。
- 麻将里的日麻立直是大厅隐藏入口，引擎完整可用，走 mjai 协议事件流，想研究 mjai 的人可以拿它当参考实现看。
- 文档与代码的同步可能有滞后，遇到对不上的地方以代码为准，欢迎去仓库提 issue。

## 读源码的推荐顺序

想啃源码的人，给一条从易到难的路线。

先读裁判层：11 款玩法一款一个裁判，纯逻辑零 IO，规则写得干净，从五子棋读起，一晚上就能建立全局感。

再读对局引擎与 LLM 玩家：出招协议、解析容错链、限流退避、启发式代走，工程精华大半在这里，是把「不可靠的模型」驯化成「可用的棋手」的全部心法。

然后是 TrueSkill 与开局库的实现，收尾再看 UI 层。想抄界面风格的，暗色竞技场那套观感也值得拆着看。

## 家族其他开源件

一个冷知识：竞技场不是家族里孤零零的一件。

察元AI Office 与察元AI 文档助手是 Apache-2.0，察元AI工舱是 GPL-2.0，察元AI OS 整机是 AGPL-3.0，对外门户是察元AI广场 aidooo.com。不同协议对应不同使用姿势，竞技场挑了 MIT，把二开自由度给足，这个选择本身就是一种态度。

按需取用：研究 LLM 对局工程盯竞技场仓库，要完整桌面 AI 环境看 OS，要办公套件看 Office，各回各家。

## 也要说实话

- 0.1.0 阶段的功能与界面都可能随版本调整，截图对照不上是常态，以实际软件与仓库为准。
- 源码路线需要 Node 与前端基础，装依赖跑环境的时间别低估，纯玩家直接用安装包就好。
- 开源项目没有客服，问题靠 issue 区与文档自助，回复节奏看维护者，急事先翻历史记录。

适合谁：想找一套能改能散的开源棋牌底座、或想研究 LLM 对局工程的开发者。不适合谁：只想当个成品玩家、从不打开仓库的人——也能玩得开心，只是 MIT 的另一层价值你没用到。

## 评论区高频问题

### MIT 商用真的不要钱吗？

协议层面不用，保留版权与许可声明即可。真正要花钱的是模型 API 调用，向厂商支付，这笔跟协议无关。

### 我能加一款新玩法进去吗？

裁判契约和测试护栏都在，理论上可行，工作量取决于玩法复杂度。建议从翻翻棋这类轻规则读起，比一上来啃德州扑克轻松。

### 和察元AI OS 内置版有什么区别？

引擎层逐字节同构，体验基本一致。区别在包的形态与协议：OS 整机是 AGPL-3.0，竞技场独立包是 MIT，按你的场景选。

## 怎么入

开源仓库搜 chayuan-games，MIT 协议全文就摆在仓库里；官网 aidooo.com 搜索即达。开发者建议直接看仓库，普通玩家下载安装包就行。

开源的意义在于你能拿它做什么，这份邀请函已经写好。
