# 怎么新建一个知识库：RAG概念与上手

RAG 常被讲成玄学，其实判断标准很朴素：资料是不是放在你自己的库里、检索范围是不是你说了算。这篇围绕这两点，把察元AI OS里知识库应用的做法摊开。

## 什么是RAG

RAG 是检索增强生成的缩写，思路是先从你的资料里检索相关片段，再交给模型组织答案，回答有出处、范围可控。在这套系统里，它落到知识库应用上，载体是察元AI OS（Chayuan AI OS）：AI 桌面操作系统，本地大模型、知识库、智能体、宠物群聊装进一个桌面。

和把全部资料塞进一个超长上下文相比，RAG 走的是另一条路：资料留在库里，问题来了先检索，再把命中的片段交给模型。好处直观：资料量可以远超模型上下文容量，回答自带出处，涉及哪份文档可以指给你看。代价是多了一步检索，库分得好不好，直接决定检索命中的质量。

## 怎么新建与分库

建库动作本身极轻：知识库应用左栏输入库名即建，每库独立存储，系统缺省带一个 default 库。真正值得花心思的是分库策略：

1. 按客户分：给每个客户建独立资料库，检索范围天然隔离，回答不会被别的客户的资料污染
2. 按类别分：制度与技术资料分库，查制度时不掺进代码片段
3. 串联离线场景：全量离线包含五件套权重，约 4.7GB，从官方渠道获取，内网机器也能一步到位

库建错也不心疼，秒建秒删。三个场景的共同点是「边界」二字：客户甲的资料不该出现在客户乙的回答里，制度问答不该混进旧版本的条款。分库就是给检索画边界，画得越贴合使用场景，回答越干净。

## 检索质量的几个小习惯

- 库名带上用途，比如「客户甲 · 交付资料」，半年后还能一眼认出它装了什么
- 过期文档及时删：RAG 不会替你判断资料新旧，旧版制度留在库里，回答就可能引用错版本
- 扫描件先确认文字层可读，纯图片的 PDF 若没有文字层，检索会漏掉它的内容
- 别把毫不相干的资料堆进一个库，检索范围越杂，命中噪声越多

## 落点的能力面

- 多库并存
- 独立存储互不干扰
- 秒建秒删

这三条合起来，知识库才从「仓库」变成「工作台」：建库没有心理负担，试错成本接近零，分库策略可以随业务慢慢长出来。

## 知识库周边的两个功能

- 知识图谱：知识库应用的知识图谱页签，自动生成文档与实体的二部图
- 用户记忆：全局记忆库三档作用域（global 全机、agent 单智能体、project 按项目）

## 先把限制说在前面

- 设备内存 8GB 的话，同时只跑一个对话模型，复杂任务会打折扣
- 龙芯机器眼下不在支持范围；视频生成本地不做，交给云端路由
- 云端厂商的模型调用，API Key 要自己带
- Docker 云桌面与跨终端互联是进阶形态，没点动手能力会卡壳

边界摆清了反而好决策，主线功能并不受这些影响。

## 数据与安全设计

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用
- 模型库按本机内存预算分层推荐（能跑/勉强/跑不动三档标记）
- 本机统一 OpenAI 兼容出口（127.0.0.1:52581）：智能体只配一个地址，代理只监听本机回环，跨机访问需要另行打通

## 两个高频疑问

### 检索这条路离线能走通吗？

断网时云端模型不可用，可设自动回落本地；联网环境下内置 web_search 工具默认走 DeepSeek 搜索。常驻任务新建时可写指令、选模型或智能体（或直跑）、配工作区知识库与联网开关，最新条目自动投影进各家 CLI 的 AGENTS.md 与 CLAUDE.md。

### 库里的资料存放在什么位置？

全新安装时选数据目录或导入拷贝根，创建管理员；数据目录自选意味着整个系统可以装在非系统盘，换机迁移就是拷整个目录，不必逐库导出。若 Office 或 WPS 引用不到知识库，九成是服务没起或端口被占，按三层检查逐层定位即可。

## 桌面形态与 Dock 生态

它不是一个软件窗口，是一整套桌面环境，这是操作系统形态与工具软件形态的分水岭：能放歌能放片，整套系统还可无头跑在 Docker 里作为多用户云桌面（察元AI工舱形态），员工浏览器打开即用。Dock 是使用频率最高的区域，位置与大小顺眼很影响手感；任何网页或本机程序都能变成桌面应用，常用工具一键直达，与知识库、模型联动，共享同一个模型代理；Dock 直开内置的察元AI Office，文档、表格、演示在线编辑；常驻任务每次产出的 markdown 报告落盘归档，配合知识库正好做资料沉淀。

## 离线与 U 盘搬运

全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重。完全隔离的内网没法在线下载，U 盘搬运权重文件是最现实的路径，系统为此做了零拷贝导入；帮助中心离线可读，断网也能查手册。

## 一句收束

RAG 的价值不在概念，而在分库之后的检索干净度：多库并存、互不干扰、秒建秒删，这三条决定了你愿不愿意长期把资料交给它。具体操作回看前文「怎么新建与分库」一节。
