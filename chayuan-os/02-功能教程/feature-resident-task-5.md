# 巡检机器人怎么做：每小时巡检服务状态

先说这篇能帮你干什么：读完能在察元AI OS里独立完成巡检机器人，路径是每天早上自动生成行业早报。步骤里的每个「」按钮都是界面原文。

## 先弄清楚它是什么

巡检机器人能做的事拆开就这几件：markdown 报告归档，预授权窗口夜间放行；历史可查可重跑；两种排程（间隔与定点）。对应的界面入口是常驻任务

按真实界面写，按钮文案原样引用。

## 具体怎么操作

上手按顺序做：（第 5 个切入角度）

1. 两种排程（间隔与定点）
2. markdown 报告归档
3. 预授权窗口夜间放行
4. 历史可查可重跑
5. 场景验证：每天早上自动生成行业早报
6. 场景验证：每小时巡检服务状态

## 怎么确认做成了

验证

1. 新建一个每 60 分钟、指令「用一句话报时」的直跑任务，点「立即运行」：约几十秒后任务行出现 ，通知中心出现「〈任务名〉 · 完成」。
2. 点「历史(1)」：列出一条 记录，悬停显示 ~/always-on/ 下的报告路径；用「我的电脑」打开该文件能看到完整报告（模型、耗时、输出全文）。
3. 把排程改成「每天定时」并填一个 1 分钟后的 HH:MM：等约 1–2 分钟（调度器 60 秒扫描一轮）应自动执行一次。

## 谁需要这个功能

要定时跑的任务需要读写某个项目目录（工作区）或参考知识库资料；任务跑完只看到通知一闪，想知道完整输出去哪看、失败了为什么；每小时巡检服务状态；想让 AI 每天早上自动生成晨报/日报、每小时盯一次某个信息源，人不在电脑前也要跑。

用户常搜的问法：怎么让察元OS 每天定时帮我干活；常驻任务选『模型直跑』还是选智能体？有什么区别。

## 几个容易忽略的细节

功能归功能，这几个边界先摆清楚：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 云端厂商模型调用需自备 API Key

## 接着回答几个常见问题

### 间隔最短/最长能设多少？

「每 N 分钟」合法范围 1–10080 分钟（一周）；「每天定时」为 HH:MM 24 小时制。超出范围保存时报「名称/指令/排程不合法」。

### 任务会不会偷偷动我的文件？

模型直跑是无工具的无头调用（只生成文本，不做写动作）。智能体方式按所选智能体自身的能力与权限在你的工作区目录下执行，建议给定时任务指定专用工作区以收敛影响面。

安全口径单独立一层：断网环境、涉密内网、不想花钱调 API，这三类需求都指向同一件事：把模型放在自己机器上跑，一台 16GB 内存的机器跑两个 8B 模型必然卡死；跨机检索依赖两台机器在线，命令行 AI 编程智能体一茬茬冒，一台机器管十几家、配置互不打架，是这套系统的核心场景之一。

离线内网这条线的口径：local 星号开头的本地模型未运行自动加载，本地模型按需自动加载；会话中随时切换模型（本地与已启用厂商热更新），无显式模型偏好时自动指向本地模型。
