# TTS语音合成：会议全程记录

TTS语音合成的在线服务一大把，但会议录音这种东西，很多人根本不愿往上传。这篇只讲本地做法：录音、转写、归档在自家机器上闭环，产品以察元AI OS为例。

## 什么是TTS语音合成

TTS语音合成严格说是文字转语音，用途偏「听」：通知播报、有声内容、无障碍朗读；日常搜索这个词的人，相当一部分其实想要的是反方向——把语音变成文字，用途偏「记」：会议纪要、访谈整理、口述速记。两个方向常被混在一个词下讨论，本文按多数人的实际意图，以「录音转文字」为主线。这套系统里对应的功能面是录屏与语音记录：桌面右键录制屏幕；语音记录是录音加转写加保存位置设置，贴顶长条边说边出字。载体察元AI OS（Chayuan AI OS）是 AI 桌面操作系统：本地大模型、知识库、智能体、宠物群聊装进一个桌面。

文中数字与界面行为均核对自官方文档，版本对应关系见文末。

## 在察元AI OS里落在哪

TTS语音合成在察元AI OS里的落点是录屏与语音记录。它值得单独一节：转写在本地完成、录音不上传，开一场会顺手把速记做完。这也是它和「随手开个录音应用」的区别：转写不外包，速记不等人工。

## 落点的能力面

- 桌面级录屏：从桌面右键直接发起，录制的是屏幕画面，配合语音记录，演示与讲解能同步留存
- VAD 切分逐段转写
- 保存位置可设

VAD 切分的意思是先检测人声段落、再逐段送转写：长会议不会因为一口气录两小时就丢内容，纯静音部分也不浪费算力。

## 几个典型场景

功能清单看十遍，不如对着场景想一遍自己的日常：

- 会议全程记录：开场打开语音记录，贴顶长条边说边出字；散会时文稿已经在本地，直接归档，不必再等人工整理速记
- 口述灵感收集：走路或通勤时想到什么说什么，回头对着转写稿整理，比打字快得多
- 完全离线的环境也有对应方案：全量离线包含五件套权重，约 4.7GB，从官方渠道获取

录音是最不该随手上传的东西之一：会议内容、口述草稿往往带着内部信息，本地转写把「传出去才有得用」这道坎直接移掉。

开会时的两个小习惯：开场说一句日期与主题，日后检索转写稿时就有锚点；重要结论当场口头复述一遍，文稿里自然留下记录，省得事后争论。

## 转写稿的后续利用

转写稿落盘后不是终点。存成 md 或 txt，拖进知识库即可参与后续检索——上传支持 txt、md、html、docx、xlsx、pdf，单文件不超过 48MB；之后在对话里让智能体「查一下某次会议关于某事的结论」，比翻录音快得多。周会开多了，这套沉淀就是团队自己的记忆。

录屏与语音记录可以各用各的，也可以配合：录屏幕走桌面右键，记讲话开语音记录；演示类内容两者同时开，回放时有画面有文稿，缺什么补什么。

## 本地转写与云端转写的差别

落到使用上就三点：录音出不出门、要不要按用量付费、断网还能不能用。本地方案这三点都占优，代价是对机器有一点内存要求，以及首次使用要把语音权重下载到位。想清楚这三问，选哪条路基本不用纠结。转写质量还与说话习惯相关：离麦克风近一点、语速稳一点，文稿干净程度立竿见影。

## 用之前要知道的边界

- 8GB 内存的设备，同时加载多个对话模型不现实，一次一个为宜，复杂任务受限
- 龙芯平台暂无支持；视频生成不在本地做，经云端路由
- 云端厂商模型的调用，API Key 需提前备好
- Docker 云桌面、跨终端互联这类进阶形态，对动手能力有要求

这几条不拦着正常使用，事先知道心里有底。语音这条线对机器的要求不算苛刻，真正卡人的往往是「愿不愿意把录音交给云端」这个心理关，而本地链路天生没这个问题。

## 数据与安全设计

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

录音文件与转写稿都留在本机指定目录，配合审计日志，敏感操作有迹可查。

## 语音功能的常见疑问

### 录音转写这活要联网才能干吗？

不用。转写由本机的 whisper 语音权重完成，对话、嵌入、重排、语音端点齐备，录音不出机器；需要联网的是云端厂商模型那部分，断网时可设自动回落本地，联网搜索这类功能自然也用不了。换言之，拔掉网线，录音、转写、落盘这条链路照样走完。

### 录下来的音频和文稿放在哪里？

保存位置可设：语音记录自带保存位置设置，按你指定的目录落盘；这些数据文件不受升级影响。换机器时按目录整体拷走即可。建议指定一个专门目录并定期备份，转写稿这种东西丢了最难补。

## 一句收束

TTS语音合成相关功能的取舍，就看两件事：录音愿不愿意出本机、转写结果要不要即时可编辑。本地链路对这两问都是肯定答案，剩下的差别只在细节体验；上文「语音功能的常见疑问」里的答案够应付多数现场问题。
