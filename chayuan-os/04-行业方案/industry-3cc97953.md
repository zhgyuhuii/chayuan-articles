# 农业信息化行业怎么用察元OS：从痛点到落地

农业信息化行业的文档与信息工作有其固有节奏：多岗位协作时版本混乱、批注流转低效。察元AI OS在农业信息化场景下的定位，是把可标准化的环节交给工具、把判断留给从业者的「人机协同」。本文按痛点→能力→落地步骤→边界的顺序，给出农业信息化行业的完整应用路径。

## 农业信息化行业的典型痛点

- 多岗位协作时版本混乱、批注流转低效
- 跨部门数据与引用需要反复核对出处
- 历史文档数字化程度低，检索与复用困难

## 对应的能力组合

- **.cop.tgz 离线插件包**（离线插件包）：插件依赖闭包打包导出为 .cop.tgz，离线直拷导入（校验路径穿越、零网络），支持多选批量安装。
- **技能页签与技能商店**（技能商店）：技能管理页签：启停（改写 SKILL.md 元数据）、打开目录、删除（入废纸篓）、tar.gz 离线导出导入；技能商店可搜索 GitHub 技能仓库一键安装（内置 anthropics/skills 等精选）。
- **创建插件向导**（AI插件开发）：名称+描述+图标（Tabler Icons 全集 5130 枚 41 分类，或 Emoji+12 色底色）一键生成真实 dsh 插件包并安装，中文包名自动转 npm slug。
- **终端与文件管理**（终端模拟器）：zsh 持久会话终端、我的电脑文件管理器，以及文本编辑、Monaco 代码编辑、Markdown 预览、PDF 预览、图片查看、媒体播放器等内置应用全家桶。

## 落地四步

1. 盘点本岗位高频文书/信息任务，挑最耗时的两个作为切入口
2. 按家庭用户场景的工作流试跑一周，记录节省的环节
3. 把常用任务固化为助手或规则模板，团队复用
4. 建立人工复核节点：工具产出 → 从业者裁决 → 定稿

## 合规与边界

- 涉密与敏感材料遵循本单位管理规定，必要时使用离线部署形态
- 云厂商模型调用需自备 Key，免费额度视厂商政策
- 行业判断责任始终在人，工具输出作为参考

## 离线运行与部署形态

完全断网可用是察元AI OS 的基础设计：本地模型对话（llama.cpp 引擎随软件分发，无需 Python/CUDA）、知识库导入/检索/问答、桌面与文件/终端/编辑器等系统应用、四家智能体终端与管理，全部离线工作；仅模型下载、云端模型调用、应用更新需要联网。装机自带五件套模型：Qwen3-4B（对话）、bge-m3（嵌入）、bge-reranker-v2-m3（重排）、whisper-small-int8（语音识别）、piper 中文语音合成。

## 数据安全与隐私边界

- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）
- 全部本地服务只监听 127.0.0.1，数据不出本机
- API Key safeStorage 加密存储，仅注入子进程

## 常见问题
### 升级会丢数据吗？

不会。覆盖安装/自动更新保留数据目录；升级前备份 dsh-home 更稳妥。

### 技能和插件有什么区别？

技能（SKILL.md 目录）教智能体「怎么做某类事」；插件（dsh 插件）给桌面增加「新应用或面板」；两者都可离线导出导入。

### 知识库支持什么格式？

PDF、Word、Excel、HTML、Markdown、TXT 与图片 OCR；单文件 ≤48MB，异步摄取不阻塞。
