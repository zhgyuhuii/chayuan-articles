# Office卸载安装：三平台五形态安装包

卸载一台机器上的办公套件，看似简单，实际各家平台路径不同、残留处理各异，信息散得到处都是。本文围绕 Office卸载这件事，把三平台的移除路径、残留核对与重装注意收拢成一条能照着走的清单。

## 安装前确认

- 系统要求：Windows 10 及以上，x64/arm64
- 安装包：NSIS 安装器 exe
- 说明：干净移除。

## 完整操作步骤

1. exe 安装包从官方站点或仓库发布区获得
2. 双击安装
3. 启动后在设置里配置模型供应商（BYOK）或指向本机 Ollama
4. 开始页新建或打开文档

## 装完后的第一件事

安装完成的验收顺序：先试六编辑器新建（docx/xlsx/pptx/PDF/Markdown/HTML），再接模型做一轮 AI 校对；两线都通过才算环境恢复。这一步同时是「重装修复」的前置：卸载后遇到疑难问题重装时，别只看应用能打开就收工。

## 怎么确认做成了

- 开始页能新建六种格式文档，设置里模型可配置
- 若没有生效，先完全退出宿主软件再重启一次

这套验证清单换个方向用就是卸载验收：应用入口消失、文件关联回落、命令行不再响应，三条全中才算移除干净。装与卸共用一套核对思路，方向相反、方法一致。

## 三平台的移除路径

Windows 侧走系统设置里的应用列表，找到对应条目执行卸载，NSIS 向导装进去的东西由同一入口收回来；安装时注册的 docx/xlsx/pptx 等文件关联会随卸载释放，双击文档不再唤起本应用。Linux 侧 deb 用包管理器卸载，与安装对称；AppImage 最直接，删除那个可执行文件即完成，没有系统条目需要清理。麒麟与 UOS 机器按当初选的包型对号入座，装的是哪种、卸的就走哪条路。

批量场景多一步通知：团队成员的自动化脚本若引用了命令行子命令，卸载前先打招呼，否则脚本会在无声中失败，排查起来比重装还费劲。

## 注意事项与真实边界

移除前先把几条边界认了：

- web/dsh 形态只有五个编辑器、不含 HTML，购买与激活界面也不在其中

## 卸载前该知道的形态事实

- 三平台五形态安装包
- 免 root 可装
- 麒麟与 UOS 走 AppImage 加 deb

形态决定了移除方式：NSIS 装进系统的走系统卸载入口，deb 走包管理器，AppImage 免安装、删掉文件即完成移除。搞清楚当初装的是哪种包，卸载就成功了一半。

## 卸载时的数据残留

API Key 存本机 ai-settings.json 不上传，支持环境变量引用；模型档案与设置同样落在本机。动手移除前，先决定这些配置的去留：确定不再用，连配置文件一起清掉才算干净；只是升级重装，保留配置能省掉重新填 Key 的功夫。文档文件本体由你自己存放，与应用卸载互不相干，这点可以放心。

「干净移除」的操作定义可以记成三查：查应用本体、查文件关联、查用户目录下的配置。三处都清了，机器上就没有痕迹；只做了第一步的，属于「卸载了一半」，下次装别的办公软件遇到关联抢注，多半就是残留配置在作怪。

## 转换与识别的口径

开始页签转换下拉五项：PDF 转 Word、Excel、PPT、Markdown、HTML；扫描页转 PPT 与 Excel 文字不可编辑；Linux 无系统 OCR 引擎，扫描页保留位图不识别；仅桌面形态提供 HTML 编辑器。重装前把这几条边界记下，装回后对照检查，能确认环境恢复到位。

## 数字与命令备忘

chaoffice 命令行 17 个子命令，卸载后这些命令随应用一并消失，依赖脚本的流程要提前改道；支持 BYOK 接入 94 家模型供应商与本机 Ollama 等本地端点。常用助手组的拼写与语法检查结果以批注锚定原文（命中片段逐字一致）；D 模型直接进 pptx 且往返保真，这是多数在线编辑器做不到的；glb 3D 模型也在支持之列；扫描 PDF 能变成可搜索可引用的活文档，这是档案数字化的第一步。

## 智能体与外部接入

外部智能体可直接操作文档，让 Claude Code 这类智能体直接读写你的文档，办公自动化从此有了标准协议；写材料引用内部资料且带出处，写作与知识库一条链打通。卸载后这些外部接入随之中断，依赖智能体流水线的团队要在移除前通知到位。

## 什么情况下还会用到

政企内网批量装机；个人替换订阅制办公软件。

## 大家都怎么问

- 移除后想彻底清理，配置文件藏在哪些地方？
- 麒麟/UOS 系统装哪个包？需要 root 吗？
- 第一次打开弹出的三页欢迎是什么，必须看完吗？

### 移除过程会不会依赖网络？

不会走网络流程：exe、deb、AppImage 三种形态的移除都在本机完成，其中 AppImage 删除文件即告结束，系统级包走各自的标准卸载入口。整个过程不涉及账号、不涉及远端状态，断网环境下照样能卸得干干净净。

### 卸载后再装回来，文档会受影响吗？

不会。文档文件独立于应用存放，格式处理遵循字节保真口径——改一个字不该弄乱整个文件的格式，转换与创建全支持；重装后打开原文件即可继续。

移除这件事的要点浓缩成一句：先认清当初装的包型，再按对应路径卸，最后核对配置残留。其余细节，上文各节按需回看。
