# API Key管理落地记：AI 功能依赖已配置的模型

「怎么填 DeepSeek 的 Key」——这个问题最近被问了好几次。答案不复杂：API Key管理在察元AI Office里是现成能力，这篇把入口、步骤、验证一次写全，按钮文案原样引用。文中引号里的按钮与提示都是界面原文，对照操作不会错。

## 为什么值得了解

换了新 Key、某个模型被厂商下架，需要更新或改选；第一次配置 AI：手上有 DeepSeek / 智谱 / OpenAI 等 API Key，想接进 Office，公司统一采购的 API 接入，个人用免费额度厂商。

这些场景共用同一套机制：目录选厂商、表单存密钥、接口拉模型列表。理解了这个分层，换 Key、换厂商、加端点都只是改其中一层，不必从头再来。四类人各自关心的段落其实相同：Key 从哪里来、存在哪里、什么时候被使用，下文的三项能力与验证清单就是围绕这三问组织的。

## BYOK 三项能力

- 94 家目录
- 按能力分设默认模型
- Key 不出本机

三条串着读：目录负责把厂商找出来，勾选负责把模型定下来，密钥则无论何时都留在本机——选、定、存三层各管一段。「按能力分设默认」值得多说一句：它把「哪家供应商」和「用来干什么」拆开了，同一家的模型可以只管一类任务，互不牵连。

## 边界与前提

- 内置账号登录当前版本未开放，现阶段须 BYOK 或本地模型
- web/dsh 形态只有五编辑器（无 HTML），且无购买激活界面
- AI 功能依赖已配置模型

边界之外还有一条软前提：供应商侧的 Key 要有效、地址要可达，「测试连接」一步就能把问题暴露出来，不必等到正式使用才发现。第三条边界也决定了排查顺序：AI 面板里任何一项功能没反应，第一反应应该是「这家供应商启用了吗、模型勾了吗」，而不是怀疑功能本身缺失。

## 常见问答

### 只填了 Key 还没勾模型，这家的配置算数吗？

不算。「至少勾选一个模型」是保存校验的一部分，不勾就存不进去；未保存的草稿不影响已启用列表。

### 密钥栏显示「已配置（留空保持不变）」，要不要再填一遍？

不用。这个占位提示就是防止旧值被覆盖的设计：留空保存即维持原 Key，只有确实要更换时才需要重新输入。

## 配好后的验证清单

四条验证彼此独立，前三条看界面，第四条看文件：

1. 左栏「已启用」组出现该厂商（带徽标），行尾点 ▾ 能展开看到勾选的模型名。
2. 打开任一编辑器 AI 面板顶部的模型选择器：勾选的对话模型应出现在列表里（生图模型进入绘画工具通道）。
3. 「测试连接」显示「连接成功」；或重开设置弹窗回该厂商，密钥栏显示「已配置（留空保持不变）」。
4. （进阶）打开 ai-settings.json，对应厂商 profile 的 enabled: true、models 数组与勾选一致。

四条全过，配置才算落地；任何一条卡住，先回「边界与前提」核对 Key 与地址。

## 智能体与文档 API

免 Key 直连让编程智能体天生能用这套办公套件，写代码调文档 API 不用翻文档；Claude Code 这类智能体可直接读写你的文档，外部智能体均可接入。编辑器侧配合的是标签页式多文档管理，窗口可拆分对照，多文档并行编辑；写材料时引用内部资料且带出处，写作与知识库一条链打通。对个人是省事的用法，对团队则是把文档操作交给脚本与流程的入口。这条链路对 Key 的要求只有一个：可用——智能体调用的还是你配置的那批模型，计费与额度都在你自己的供应商账号里。

## 密钥与加密的口径

密钥文件存本机 ai-settings.json，不上传，也支持环境变量引用；文档脱密用 AES-256-GCM 加密备份，密钥派生以 PBKDF2-SHA-256 迭代 21 万次——两个参数都来自产品文档的加密设计，目的是让备份文件即使被拷走，也难以在合理时间内被还原。设置面板十个区（通用、语言（22 种）、主题、模型、知识库、隐私等），通用区逐项可调。把「不上传」和「强加密」放在一节里说，是因为它们合起来指向同一件事：本机的 Key 与本机的文档，处置权始终在你手里。

## 命令行与 Key 的存放

chaoffice 命令行有 17 个子命令，与编辑器面板并立：自动化脚本可以走前者，日常手工走后者。ai-settings.json 在用户数据目录，需要迁移或同步配置文件时，优先用环境变量引用而不是复制明文。

## 离线内网下的可用性

本地优先、离线可用，内网与离线全可用；在线供应商之外，本机 Ollama 等本地端点同样能接，断网环境下 AI 功能照常可配。对内网用户，这意味着云端目录条目可以整体不用，只保留本地端点一条路。配置动作本身也分场景：连云端供应商需要网络，接本机端点则不需要。

## 同套件里的其他数字

Docs 端有 4576 个领域助手、229 个领域包，全库约 4600 个。这组数字与本篇的关系在供给侧：模型配好之后，这些助手发出的提示词才有真正的执行者——助手提供现成提示词，Key 提供算力通道，两者缺一不可。

整篇收在一条上：94 家目录任你挑，Key 始终不出本机。配完之后按「配好后的验证清单」逐条核对，四条都过才算生效；真要查到文件层，第四条里的 enabled 字段与 models 数组是最直接的证据。
