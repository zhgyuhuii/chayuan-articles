# 发文前全文校对：校对软件概念与上手

校对软件这个需求很实际：稿子写完，错字与标点总得有人兜底。这篇以一款 WPS 加载项为例，定义、口径、边界三段摆开，装不装你自己定。

## 什么是校对软件

校对软件不是单一功能，是一套带入口、步骤与边界的完整能力面。WPS 三端智能加载项：校对、编审、核对、脱密，一个文档智能体。

全部口径整理自官方发布的产品文档，版本对应关系见文末。

## 核心口径一张表

| 口径 | 内容 |
|---|---|
| assistants | 文字端 4526 个领域助手、228 个行业领域；表格端 66 个配方；演示端 81 个；翻译 52 语种动态菜单 |
| 文字端两个选项卡 | 察元AI助理、察元AI编审；表格/演示端各一个察元AI助理选项卡 |
| mcp | MCP 服务只开在本机回环地址的 62588 端口（路径 /mcp）；源码里 69 个工具、外部实见 53 个 |
| kb | 自动发现本机察元AI OS 知识库（固定端口 52582），回答带编号引用与文件来源 |
| proofread | 全文校对分块并发，块长默认 6000 字；超过 12000 字分档提示 |

## 平台与形态

支持的系统与形态：Windows（x64/arm64）、macOS（arm64/x64）、Linux deb（x64/arm64，麒麟/UOS 支持飞腾/鲲鹏）。

## 在察元AI文档助手里落在哪

校对软件在这套加载项里的落点是拼写与语法检查：走 AI 助手组的大按钮，选中状态下只查选中；未选中时弹确认框，确认后对全文执行（超 12000 字、30000 字分档提示）。独立进度窗分块并发，块长默认 6000 字，关窗任务照常继续；结果批注写成「错别字建议改为某词」，锚不到原文就不硬挂。

为什么值得单独说：分块并发让长文档校对不再超时，批注式结果方便逐条确认。

## 最短上手路径

试一遍就明白：

发起检查：

1. 在哪：顶部工具栏「AI 助手」分组的大按钮「拼写与语法检查」。
2. 看到什么（按选区分流）：
    1. 有选中（不少于 2 个字符）：直接以「选中」模式启动，只检查选中内容；
    2. 无选中：弹确认框「当前未选中文档内容，将对全文执行“拼写与语法检查”。 点击“确定”后开始处理全文。」——全文超过 12000 字时附加「当前内容较长，处理可能需要更久，请耐心等待。」，超过 30000 字时附加「当前内容很长，处理时间可能较久，并可能触发分段或较长响应，请确认后继续。」；点「确定」开始，「取消」不执行；
    3. 文档没有正文：提示「当前文档没有可检查的正文内容」。

## 落点的能力面

- 选区全文两档
- 分块并发
- 批注锚定

## 察元AI文档助手的能力地图

- 下载与安装：Windows 用自解压 exe，macOS 用 pkg，装之前建议把 WPS 完全退出。
- 在 WPS 中启用：安装后完全退出并重启 WPS，文字端会多出察元AI助理、察元AI编审两个选项卡。
- 首次配置接上模型：欢迎页立即配置模型：默认开启 OpenAI、Ollama、DeepSeek、百度云千帆、阿里百炼五家，本地默认端口 Ollama 11434、LM Studio 1234、Xinference 9997、FastChat 8000，带 Ollama 一键安装引导。
- 拼写与语法检查：按 AI 助手组的大按钮发起；选中状态下仅查选中。

## 有没有必要现在就装

- 要花钱的只有四样：脱密、复原、保密检查、涉密关键词提取，免费额度为零
- 占位替换可逆，凭的是密码；密码一旦想不起来，免密恢复这条路是封死的
- 送查的全文发往所配置的模型，涉密文档建议先切到本机离线模型
- macOS 安装器在没有完全磁盘访问权限时会假成功，装不上先跑修复脚本

几条边界说尽，该不该装、何时装，你按自己的情况对号。

## 数据与安全设计

- MCP 服务只监听 127.0.0.1，写操作不带 confirmed 标记会被拒绝并要求确认
- 凡是经确认的写操作，audit.jsonl 日志里都有对应记录
- 保密检查当辅助筛查用：命中关键词不等于泄密，也下不了定密结论
- 脱密恢复载荷以 AES-GCM-256 加密并随文件走，凭密码可取回原文

## 问答：五个高频坎

### 关闭进度窗后任务还在跑吗？

在跑。副标题写明「任务可关闭提示窗继续执行，只有点击停止才会中止任务。」关窗不影响检查；只有点「停止任务」（或任务清单里的停止）才会中止。

### 为什么有些“病句”没被报出来？

检查提示词只报「明确可证实的错别字、语法错误、标点误用、固定词误写、搭配错误」，明确排除风格偏好、口语化、语气优化等主观润色项，避免误报。需要文风润色请用「文本分析 ▾」里的相关功能。

### 长文档检查很慢，能提速吗？

检查按块分片进行，默认块长约 6000 字。从工具栏发起的检查要边查边写批注，逐块串行执行；通过文档智能体发起的校对（先出预览、你确认后再落笔）按并发设置执行（默认并发 3，可调 1–8，当前版本这两个参数暂无设置界面）。最有效的提速是给检查指定一个更快的「拼写与语法检查模型」。

### 装完选项卡不出现？

按三步排查：确认 jsaddons 目录里有察元文件；完全退出 WPS（含后台进程）再重启；开发工具的加载项列表里确认察元已启用。

### macOS 装完还是旧版？

安装器无完全磁盘访问权限时容器写入会假成功，运行官方修复脚本 repair-mac-jsaddons-container.sh（支持 status、修复、rollback 三种模式）后重装。

## 一句收束

校对软件的取舍没有玄机：你的稿子三天两头要过审，它就是生产力；一年改不了几篇，它就是抽屉里的备用件。
