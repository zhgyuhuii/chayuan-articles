# 任务灵宠上手指南：照着做十分钟跑通

任务灵宠这件事，说简单也简单，说麻烦是真麻烦——麻烦不在功能本身，在于信息散落在各处，拼出一个完整流程要查好几篇资料。这篇文章把它一次讲全：是什么、入口在哪、具体步骤、边界在哪，全部基于察元AI OS的真实界面。

## 它是什么，为谁服务

把一只灵宠绑定到常驻任务后，任务每次执行时这只灵宠自动上桌（不钉住也会上桌），头顶气泡流式滚动任务输出（相位标签「思考中」/「输出中」）；任务结束后 10 秒内气泡切换为结果摘要（绿色「完成」/红色「失败」），同时向通知中心推一条「常驻任务」消息。

定时任务的进度从日志文件变成桌面上的实时直播，跑没跑、成没成一眼可见。

按真实界面写，按钮文案原样引用。

## 先确认这些再开始

- 桌面形态（察元AI OS）：任务灵宠的气泡与上桌表现都在桌面灵宠层。
- 至少一个常驻任务：设置 ＞ 常驻任务 ＞ 「新建任务」（没有任务时建宠表单的绑定下拉只有默认项）。
- 任务要能跑起来：
- 「模型直跑（不经过智能体）」方式：模型代理需在运行（本机固定 127.0.0.1:52581，随模型服务自启）；任务未单独指定模型时用全局默认对话模型；
- 「智能体无人值守」方式：仅 Codex / Claude Code / OpenCode 三家支持，其余家不可选。
- 一只灵宠。

## 具体怎么操作

第 1 步 · 建常驻任务（设置 ＞ 常驻任务）

1. 打开 设置 ＞ 常驻任务（分区标题「常驻任务（Always-on）」，说明行含「绑定灵宠后，任务执行时灵宠上桌并流式展示输出」）。
2. 点蓝色「新建任务」弹出表单，逐项填：
    1. 任务名（占位符「任务名（如：每日晨报）」）与任务指令（每次运行发给模型的提示词）；
    2. 排程：「每 N 分钟」（1–10080）或「每天定时」（HH:MM）二选一；
    3. 执行方式：留空「模型直跑（不经过智能体）」，或选 Codex / Claude Code / OpenCode 无人值守跑（完整智能体能力）；
    4. 可选增强：模型（与建宠同款选择器，「自动」=用全局默认对话模型）、工作区、知识库（每次运行先检索注入）、附件（≤3 个）、勾选「启用联网搜索（每次运行前检索最新信息）」。
    5. 点「保存」，列表出现该任务行（默认启用，圆点绿色）。

第 2 步 · 绑定灵宠（两条路任选，绑定真相源都是灵宠档案的 taskId）

1. 路 A（设置面）：设置 ＞ 常驻任务 ＞ 找到任务行，行首下拉默认显示「未绑定灵宠」＞ 展开列出全部灵宠 ＞ 选中一只即完成绑定。在设置面改绑另一只时，原来那只自动解绑（设置面保证一个任务只挂一只灵宠；灵宠档案侧的任务字段本身也只有一个）。
2. 路 B（建宠/编辑宠表单）：建宠或右键「编辑灵宠」＞「绑定常驻任务（任务灵宠）」下拉（默认「不绑定（普通灵宠）」）＞ 选任务名 ＞ 保存。

第 3 步 · 触发执行

1. 等排程：调度器每 60 秒扫描一次到期任务自动执行；也可点任务行琥珀色「立即运行」按钮（页面提示「已触发运行…」）。
2. 绑定后名册里该宠状态徽标变为下次运行倒计时（「即将运行」/「N 分钟后」…）。

第 4 步 · 执行期：灵宠上桌 + 流式气泡

1. 任务开始时，绑定的灵宠自动出现在桌面（即使没钉住也上桌，这是任务灵宠的专属在场规则；名册徽标变琥珀「任务执行中」）。
2. 灵宠头顶出现气泡，实时滚动任务输出：
    1. 相位标签「思考中」（琥珀色呼吸点）：模型在组织答案、还没有文字流出（长思考静默期也是这个状态，防「假死画面」）；
    2. 相位标签「输出中」（蓝色波点）：文字正在流（1.5 秒内有新内容即为该相位）；
    3. 气泡是滚动尾窗：只显示最近约 200 个字符，新内容从底部顶入（完整输出不在这里看，见第 6 步）；
    4. 模型直跑走流式接口逐字出；智能体方式按 CLI 标准输出逐行进气泡。
    5. 未绑定灵宠的任务照常执行，只是桌面不出现任务灵宠，结束后仅收到通知。

第 5 步 · 结束：结果气泡 + 系统通知

1. 任务结束（成功或失败）后的 10 秒停留期内，气泡切换为结果态：
    1. 成功：绿色气泡，标签「完成」+ 摘要文本（输出的前 120 字）；
    2. 失败：红色气泡，标签「失败」+ 摘要文本（错误信息的前 120 字）。
    3. 同时通知中心推一条来源「常驻任务」的消息：标题「<任务名> · 完成/失败」，正文为摘要（最多 200 字；失败为红色错误级别）。
    4. 10 秒后气泡消失；未钉住、也不是被双击启动的灵宠随之退场回名册（带退场动画），钉住的留在桌面。

第 6 步 · 事后核对（三个去处）

1. 报告文件：每次运行产出一份 markdown 报告，落在 <用户主目录>/always-on/<任务名>-<时间戳>.md（含任务、时间、模型、状态、任务指令与完整输出/错误）。
2. 运行历史：任务行「历史(N)」按钮展开最近 8 条（/ + 完成时间 + 报告文件名，悬停可见完整报告路径）。
3. 最近状态：任务行名字右侧的 / 是最近一次运行结果。

## 收尾检查

验证

1. 按第 2 步绑定后，设置页任务行下拉显示所绑灵宠名；底栏「灵宠」名册里该宠出现倒计时徽标。
2. 点「立即运行」：桌面出现该灵宠 + 头顶气泡滚动输出（相位在「思考中」/「输出中」间切换）；结束后 10 秒内气泡变绿「完成」+摘要，通知中心出现「<任务名> · 完成」条目。
3. 任务行点「历史(1)」：列出一条 记录，悬停能看到 ~/always-on/ 下的报告文件路径；用文件管理器打开该路径能读到完整报告。

## 什么情况下用得上

给定时任务的执行过程要一个「看得见」的桌面窗口：任务在跑、跑到哪、成没成，扫一眼桌面就知道；巡检类任务的值守宠，建宠表单里有个「绑定常驻任务（任务灵宠）」下拉，不知道选了会怎样，任务跑完气泡一闪就没了，想知道完整结果去哪里补看。

用户常搜的问法：绑定了常驻任务的灵宠是干什么的？怎么让任务结果在桌面上显示；任务灵宠头顶的气泡显示的是什么？为什么只有最后一段字。

## 它的局限也要说清楚

用之前要认的账：

- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限

## 常见问题

### 任务选了智能体方式，为什么运行失败？

无人值守执行当前仅支持 Codex / Claude Code / OpenCode 三家（表单下拉也只列这三家）。失败会留痕：任务行 、「历史」里可看错误，报告文件的「错误」小节有详情。

### 结果气泡一闪就没了，来得及看吗？

停留期固定 10 秒。错过就看三处：通知中心的「常驻任务」条目（含摘要）、任务行的 / 与「历史」、~/always-on/ 报告全文。

### 页面刷新/电脑重启后，正在跑的任务宠还在吗？

在。每次运行会写运行态快照，页面刷新或重启后：5 分钟内仍在跑的恢复为「执行中」（灵宠重新上桌带气泡），10 秒内刚跑完的恢复结果摘要。

### 任务灵宠和我自己双击打开的工作台窗口会冲突吗？

不冲突。任务执行时灵宠的相位（思考中/输出中）会压过会话推导状态优先显示；任务结束 10 秒后恢复正常在场规则。

如果只记一件事：执行期流式输出。剩下的细节照步骤节走就行。
