# 拼写与语法检查怎么用：察元文档助手速查手册

错别字检查是察元AI文档助手里使用频率很高的一项能力。它的「拼写与语法检查」这样工作：面向错别字、语法、标点、固定搭配等「可证实」问题的结构化校对：输出可解析的 JSON 问题清单（原文引用+修改建议+理由），默认以批注写回钉到具体位置，适合长文批量审校前的初筛。这篇速查手册从入口、步骤、场景讲到技巧与边界，新手照做能跑通，老手能查漏。

## 它是什么，解决什么问题

面向错别字、语法、标点、固定搭配等「可证实」问题的结构化校对：输出可解析的 JSON 问题清单（原文引用+修改建议+理由），默认以批注写回钉到具体位置，适合长文批量审校前的初筛。

从任务视角看，它对应的关键词是「错别字检查」——也就是用户带着这个需求搜索时，最应该被满足的那类任务。

## 操作步骤

1. 在 WPS 中打开待审文档，进入「察元 AI 助理」页签
2. 点击「拼写与语法检查」，选择结构化校对模式
3. 等待模型逐段分析，生成问题清单（每条含原文引用、建议改法、判定理由）
4. 逐条确认后以批注写回正文，或切换为直接替换/仅生成报告模式

## 适用场景

- 红头文件发文前的错别字兜底自检
- 标书、制度文件长文的批量初筛
- 论文提交前的语法与标点清理

## 实用技巧

- 同音字（的/地/得、象/像、做/作）与形近字（己/已/巳、戊/戌/戍）是中文高频错误，校对清单会显式覆盖
- 先用结构化校对生成清单人工复核，再用「纠正拼写和语法」整段修正，两步配合效率更高
- 批注模式保留了人工裁量权，每一处修改都可见、可拒绝

## 注意事项与边界

- 校对由大模型推理完成，输出为结构化建议，最终采用与否由人工决定
- 保密检查、AI 痕迹检查为辅助参考，不构成定密或定性结论

## 离线运行与部署形态

离线与内网是这款加载项的一等公民设计：通过 Ollama 或任意 OpenAI 兼容网关（LM Studio、Xinference、One API、New API、FastChat、Custom OpenAI）即可在无公网密钥的情况下完整使用全部功能；产品内置本地引擎一键安装引导，自动检测环境并在官网与 ModelScope 镜像之间择优下载，适配国内网络。需要注意的是，加载项本身不内置模型权重，本地推理需要先装好 Ollama 等引擎（引导流程会带你完成）。

## 常见问题
### 知识库功能怎么用？

设置中绑定知识库服务（JWT/HMAC 认证），即可对选中文字做核对、总结、问答，结果带引用并可下载原文。

### 免费额度用完会怎样？

对话超过每日 30 次会提示；MCP 调用返回 LICENSE_REQUIRED 错误码，次日恢复或升级付费。

### 什么是 MCP 文档智能体服务？

加载项内置的本机服务（46 工具/15 域），外部 AI 编程工具（Claude Code、Codex、Cursor 等）连上后可直接打开、读取、修改、批注本机 WPS 文档，写操作默认只预览、传 confirmed:true 才落盘。
