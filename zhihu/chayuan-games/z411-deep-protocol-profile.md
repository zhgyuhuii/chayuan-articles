# 察元竞技场协议画像细看的机制与取舍，一次说清

协议画像细看这件事，拆到零件级再看一遍：察元竞技场在里面的部分没有什么黑魔法，可靠性全是笨功夫垒起来的。功夫笨在哪几处，下面逐一说。

先交代一个少有人用的检验法：专门观察协议画像细看出错时的状态。顺的时候表现拉不开差距，故障那一下才见真章：报错是不是人能读懂的、重试是不是原地就能完成、数据有没有丢。这些地方文档着墨极少，而你一个月后去留的决定，往往就取决于它们。

先把几条前提钉住：它处理的问题真实存在，解法却不靠魔法；核心链路全在对局室里，运气帮不上忙；代价摆在明面上，没有藏着的部分；它也不面向所有人，适不适合你，得先对照。

### 为什么这样设计

一层一层看：二是通用：一套出招协议跨 11 款玩法，下完五子棋就能上牌桌打斗地主。操作面上还留了一条路，把对局数据带去自建分析，手册里写得比较细。

收敛到一种内部协议之后，矩阵坍缩成一列：引擎只测一种协议，网关只测转换层，Anthropic协议转换是额外要多测的那一段，范围收得很窄。再发一路等于双倍费用双倍延迟，而且两边的需求本来就该同源——观众看到的思考与裁判收到的答案，理应是同一次思考的两个投影，分开反而不诚实。这句别略过。

### 一个反直觉的细节

斗地主的叫地主、德州扑克的四条街下注、掼蛋的队友配合、麻将的缺门取舍，如今都收进了对弈的范围。这边参赛的是大语言模型，不是特化的引擎。遵守率平平但棋风凶悍的，被归为「散装猛将」。

画像里每个数字，对应的都是真实对局里摸得着的体验差别。棋类 ； 军棋暗棋 ； 支持自由布阵（两击或拖拽）并附明棋教学档，工兵能飞雷，司令阵亡则亮旗。

事件进到界面层，对局室把它画成气泡。气泡装的是出招模型的自言自语，讲「我是这么想的」。围棋古称手谈，棋枰上的较量被视为才华的直接呈现。

常有人来问：成绩为什么按玩家名头分开记、不并成一份全局账？ 数据 100% 留在本机：模型 API Key 明文存于本地，天梯积分连同对局记录都写进本机的 JSON 存档，不出机器、不报云端。

### 工程上的取舍

锦标赛用循环赛攒积分，终了榜单自动给出，挂机跑前先把额度盘算好。多读几份画像之后再回看手册，还能对上更多细节。这一层常被当成终点，其实再往下挖还有内容。

胜负这事的裁定权 100% 归零 IO 的纯逻辑裁判引擎，模型只负责落子。最容易误会的地方在于：启发式代走并非纯随机，它只消费引擎层抛出的状态与事件，规则判定一概不做，网络也不直接碰。若本文只能记住一件事，就记这句。

LLM竞技场沿用的正是这般设定：模型即选手，任务即赛场，积分即战绩。至于外行看棋的三道坎，规则不熟是其一，看不出一手的好坏是其二。

### 这套设计的代价

也有很多人拿它和同类逐项比。我的观察是：同价位的选手功能重合动辄七成往上，胜负手往往落在参数表之外，比如响应稳不稳、边界情况接不接得住、更新日志写得上不上心。这些差别得靠时间泡出来，泡出来之后就很难装作看不见。

### 它不是给所有人的

适用面照例交代：三种声音来路和立场都不同，把气泡跟解说搭着读，表的和里的各看一层。也正因如此，LLM竞技场更该视作一个类目词，而非某件产品的名字；要分辨一篇文章谈的是哪种竞技场，盯住赛场即可。

上手路线我建议走两级台阶。头一级只通主链路，把最核心的那件事原样跑通，不碰任何定制；第二级才轮到按习惯调配置。台阶迈反了的人，多半中途弃用，末了还丢下一句「不好用」，实际错的是路径。

默认值这一格也别跳过。开箱那一下的顺不顺，多半系于它：往冒险的方向设，新面孔容易栽跟头；往安稳的方向设，老面孔又嫌拖沓。两头都稳住的方案不好找，这一格算是交了卷。

整套机制走完一遍，没有魔法，全是把笨功夫做足。我长期把它留在手里的理由也简单：可靠这回事，只有拆开看了才看得见。

### 画像的读法与样本

先立一个理解画像的前提：它本质是统计读数，样本怎么攒有讲究。与其押一场超长对局，不如拿你的模型名单做轮快问快答，多轮短局攒出的画像更扎实。数字稳的模型往往格式规矩，档案里见性格；把几份画像摆在一起对照，比单看一份更出信息。

### 机制相关的边角

配置动过之后画像若漂移，未必是它变了，先按手册核对重试回喂的顺序。哪个模型动辄触发容错，画像里能看出来；TrueSkill 天梯、形势曲线、回放也在同一套系统里。Anthropic协议转换是额外多测的那一段，这笔账不适合用蛮力算；有的模型动不动进入长考，观摩前心里要有数。
