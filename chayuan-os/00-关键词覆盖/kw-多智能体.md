# 多智能体是什么：暂不支持龙芯平台

多智能体这个词有两层读法：学术语境指多个智能体协作的架构，日常语境指一台机器上同时养着好几个 AI 编程智能体。这篇取后一层，讲讲十几家 CLI 智能体在同一台机器上如何被识别、安装、管理。

## 什么是多智能体

日常说的多智能体，就是命令行 AI 编程智能体一茬茬冒、一台机器管十几家、配置互不打架这件事。载体察元AI OS（Chayuan AI OS）是 AI 桌面操作系统：本地大模型、知识库、智能体、宠物群聊装进一个桌面，多智能体的识别与管理就长在这个桌面上。

## 在察元AI OS里落在哪

多智能体在察元AI OS里的落点是支持的智能体总览：内置 DeepSeek Harness（系统级）加 17 家外部 CLI 智能体统一管理：Claude Code、Codex、OpenCode、OpenClaw、ZCode、Gemini CLI、Qwen Code、Kimi Code、Cursor CLI、Copilot CLI、Droid、Amp、Grok Build、CodeBuddy、Crush、Aider、Goose，各家能力矩阵标明能否一键安装、写入模型、收系统技能、收 MCP、记忆采集。

## 第一步：应用商店看名单

1. Dock 点「应用商店」＞ 顶部页签选「智能体」。工具条下方显示说明「一键安装/升级本机 CLI 智能体，装完自动进入应用管理与桌面」，列表首行显示计数「16 个智能体 · 安装态自动识别，未安装不进入应用管理」。
2. 每行从左到右：图标 ＞ 智能体名 ＞ 能力徽标（system 紫 / L2 绿 / L1 蓝）＞ 安装态（绿色「已安装」（后跟 · v<版本>）或灰色「未安装」）＞ 安装方式明文（等宽字体，如 npm install -g @anthropic-ai/claude-code）＞ 右侧按钮。
3. 列表固定 16 行（17 家外部 CLI 去掉察元自家的 ZCode），顺序：Claude Code、Codex、OpenCode、OpenClaw、Gemini CLI、Aider、Goose、Qwen Code、Kimi Code、Crush、Cursor CLI、Copilot CLI、Droid、Amp、Grok Build、CodeBuddy。DeepSeek Harness 是系统自身，不走商店。

## 第二步：应用管理看本机识别结果

1. Dock 点「应用管理」＞ 顶部页签「智能体」。
2. 默认只列已识别的智能体，顶部计数「本机智能体 · {n} 型」；勾选「显示未安装」（勾选状态会记住）可看全量排查视图。
3. 每行：图标 ＞ 能力徽标 ＞ 名称（被隐藏过的带「已隐藏」徽标；未识别的标灰「未检测到」）＞ 状态行：
    1. 已识别：「已检测（managed）· 版本 {x.y.z}」——managed = 察元管理态（商店安装/升级版或安装包内置版）；homeDir = 家目录探针命中（自己装的）；path = PATH 里找到命令；
    2. 未识别：「未检测到安装迹象（装好后自动上架/恢复）」。
    3. 行尾按钮：「隐藏」/「恢复」（控制 Dock 上架）与「删记录」；顶部的「重新扫描」（扫描中显示「扫描中…」）随时重测，装完新 CLI 后点它即可，无需重启。
    4. Dock 上架规则：未识别或被隐藏的智能体不显示；识别到的自动上架成正常应用图标。

## 多智能体的另一种形态：宠物群聊

群聊与 CLI 是同一种思路的两个出口：让多个模型各展所长，再把结果摆到一起。

- 建群：群名加勾选至少两只成员，选协同方式，可选群分区（桌面出图标双击进群），发一条命题
- 并行讨论：全员同轮作答、谁也不等谁，思考状态条与流式气泡一起冒出来
- 对话中使用知识库：在 dsh 会话、灵宠或群聊里说一句「查一下知识库里的什么」
- 灵宠对话窗：多会话 Tab、流式回复、附件上传，输入框旁有知识库绑定与模型选择（含智能路由自动选模型）

CLI 智能体管的是「干活的 AI」，宠物群聊管的是「讨论的 AI」——多个模型围绕同一命题各自输出，对照着看，比单模型的回答多一层参照。

## 上规模前的几条边界

- 8GB 内存档的设备，一次只载入一个对话模型，复杂任务受限
- 龙芯平台目前未纳入支持；本地不提供视频生成，视频生成经云端路由
- 云端厂商模型的调用得自备 API Key
- Docker 云桌面、跨终端互联属于进阶玩法，动手能力是入场券

多智能体环境下内存压力来得更快，这几条先核再上规模。

## 数据与安全设计

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

## 智能体管理的常见疑问

### 我装了 ZCode，为什么 Dock 里看不到？

ZCode 是察元自家 CLI，注册表标记暂不上 Dock（应用管理 ＞ 智能体里能看到它的识别状态）。它仍会收系统技能、MCP 同步与记忆采集。

### 为什么 Aider 和 Goose 没有「安装」按钮？

这两家不经 npm 分发、也没有官方脚本通道，商店行不提供安装入口（安装方式一栏为空）。按官方途径自行安装后，应用管理 ＞「智能体」＞「重新扫描」即自动上架（Aider 探针 ~/.aider / ~/.aider.conf.yml / PATH 里的 aider；Goose 探针 ~/.goose / PATH 里的 goose）。

### L1、L2 徽标代表什么？

徽标取自注册表 abilityLevel：system = 察元自身；L1 = 基础启动（终端 + 工作区即开即用）；L2 = 在 L1 之上支持本地模型接入与记忆采集等深度整合（当前为 Claude Code、Codex、OpenCode 三家）。徽标是能力档位标记，不是逐项开关——OpenClaw 徽标是 L1，但 2026-10-29 起同样具备模型配置写入面（见矩阵「模型写入」列），逐项能力以矩阵各列为准。

### 全量包和轻量包怎么选？

全量包含推理引擎与模型权重约 4.7GB，装完即完整离线；轻量包约 1GB，模型后续在模型中心单独补。内网机器直接全量包。

### 数据目录在哪里？

对话、知识库、模型配置都在数据根目录下，备份这一个目录等于备份全部；路径在设置的关于页可查。

## 一句收束

多智能体的管理成本不在安装而在维护：谁能装、谁已识别、谁收了哪些能力，能力矩阵与识别状态给了答案。拿不准时回看前文「智能体管理的常见疑问」，五问覆盖了绝大多数现场问题。
