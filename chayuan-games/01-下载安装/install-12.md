# 竞技场接入OpenAI兼容中转：OneAPI、NewAPI手填端点

有人的 Key 不是从厂商官网直接办的，而是从公司团队或自建的中转站发的：一个 OneAPI 或 NewAPI 的地址加一把中转 Key。这种情况下目录厂商那条「点选即填」的路走不通，要用另一条路——手填端点。这篇讲竞技场接入OpenAI兼容中转的完整做法，顺带把中转选型的注意项说清。

## 中转是什么，为什么能接

先说原理。竞技场对所有厂商一律走 OpenAI 兼容协议，同时开放了手填 baseUrl 的能力：任何提供 OpenAI 兼容接口的端点，不管背后是谁的服务，填上地址与 Key 就能接。这条能力的本意是覆盖各类自托管与代理场景，OneAPI、NewAPI 这类接口网关正好落在这个范围内。

OneAPI、NewAPI 是常见的开源接口分发与网关项目：上游对接各家模型厂商，下游对外提供统一的 OpenAI 兼容接口，团队用一把分发 Key 调用多个上游模型。很多公司与工作室用它统一管理模型额度，你手里的「中转 Key」就是从这类系统发出来的。

识别方法也简单：你的 Key 若是在一个网页后台里创建、调用地址与厂商官方域名不同、文档里写着 OpenAI 兼容这几个字，基本就是中转形态，走本篇的手填路。

## 动手前先问中转方三个问题

中转接入的失败大多出在信息不全，动手前把这三件事问清楚。

接口地址的完整形式：调用地址给到哪一层、要不要特殊后缀，以中转方文档为准，照抄最稳。可用模型清单：中转后台配置了哪些上游模型、有没有访问限制，先要一份清单心里有底。计费与额度规则：怎么扣费、有没有倍率、额度去哪查，这三样决定你的预算管理方式。

三问之后再进竞技场配置，验证环节的失败率会低很多。

## 配置步骤：与目录厂商的差别在哪

进设置 ＞ 模型配置。目录厂商不需要填地址，中转场景多了「填端点」这一步，整体顺序如下。

先选好中转配置的入口，把中转方给你的接口地址填进 baseUrl 位置。地址怎么填、填到哪一层，以中转方文档给的调用地址为准，各家系统给的形式不完全一样，照抄中转方提供的完整地址最稳。

再把中转 Key 填入对应位置。然后点「测试连接」快速过一遍可达性，通过后点「获取模型」实拉这份中转账号可用的模型列表，从返回的裸模型 id 里勾选入库。中转的模型清单取决于中转方配置了哪些上游渠道，拉出来是什么就是什么。

最后回大厅开局验证：开一局人机局或机机观战，看思维链气泡、每手延迟与 token 用量是否正常。中转链路多一跳，出招延迟通常比直连厂商略高，能稳定出招就算接入成功。

还有个建议：同一家中转如果发给你多个不同上游的 Key，各配一份分开验证，混着用出了问题说不清是哪条渠道的责任，分开才有干净的归因。

## 验证失败的常见归因

中转场景的验证失败，按命中率从高到低有三个归因。

地址填错层级：调用地址抄漏了路径，或者抄成了网页地址而不是接口地址，照文档重抄一遍。Key 无效或额度耗尽：中转 Key 被禁用、过期或余额不足，去中转后台查状态。上游渠道不可用：中转背后的某个厂商渠道挂了或被限流，这种失败往往时好时坏，换个时段再试就能区分。

三层归因从外到内排查，多数中转问题在第二层就能定位。排查无果时找中转方，竞技场侧能做的退避、代走、兜底都已经做了。

## 中转选型的四条注意

一是稳定性自负。中转是第三方的转发服务，上游渠道质量、并发能力、维护状态都由中转方决定，竞技场有 429 退避与代走兜底，整局不会卡死，但中转频繁抽风时对局节奏会很难看。

二是信任问题想清楚。你的调用流量、对话内容都经过中转方，把流量交给谁，等于把可见性交给谁，选自建或可信来源的中转，别用来路不明的廉价渠道。

三是清单与实况可能有出入。中转后台的模型列表不代表每个渠道当前真的可用，拉出来的清单以实拉为准，实际能不能用要用对局验证，打几局比看清单准。

四是计费规则归中转方。你与中转方之间怎么计费、有没有倍率，是你们之间的约定，与厂商官方价格是两套账，预算管理按中转方的规则来。

## 边界与实话

三条说在前面。中转接入的体验上限由中转方决定，竞技场能保证的是本机侧的赛制公平与兜底机制，保证不了链路质量。地址填错层级时验证会失败，照中转方文档抄完整地址，不要自己拼。另外，公司网络里的中转常见内网部署，外网机器可能根本够不到那个地址，办公网与家庭网的表现可能不一致，跨网络使用前先各验证一遍。

再补一条：中转方升级或迁移地址时，你的配置会突然失效。遇到「昨天还好好的今天就不行」这类情况，先去中转方的公告或后台看一眼地址有没有变，再回来动配置。

## 你可能会问

### 中转 Key 和厂商官方 Key 有区别吗

对竞技场没有区别，都是 OpenAI 兼容端点的凭证，配置动作一致。区别在背后：中转 Key 背后是网关的转发与中转方的计费规则，官方 Key 直连厂商。

### baseUrl 要不要带 /v1 这样的后缀

以中转方文档给出的调用地址为准，它给什么你填什么。判断方法也简单：填好后点「测试连接」，可达就是填对了，失败就核对地址细节。

### 中转能接 Claude 模型吗

取决于中转方有没有把 Claude 渠道做成 OpenAI 兼容输出，列表里拉得到就能用，拉不到就接不了。竞技场自带的 Claude 原生协议自动转换只针对 Anthropic 官方原生接口那条路。

### 公司中转和个人中转怎么选

都不是竞技场层面能替你决定的事。原则只有两条：来源可信、规则透明。中转选型属于你自己的供应链决策，竞技场对两者一视同仁。

### 手填端点有安全风险吗

风险不在填这个动作，在你把流量交给谁。中转方能看到经过它的请求内容，选可信来源，敏感场景考虑自建中转，把信任链收短。

### 中转和目录厂商可以同时配吗

可以，互不冲突。愿意的话还能让中转模型与直连厂商的模型同台，顺带检验中转链路的质量，一举两得。

中转这条路的入口是手填端点，核心动作是「照抄中转方给的地址，实拉清单，对局验证」。把这三下做对，OneAPI、NewAPI 还是别的什么网关，接法都一样。下一篇讲 Key 本身：存哪了、安不安全。
