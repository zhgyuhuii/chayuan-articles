# 记忆投影机制为什么这样工作：每条记忆可溯源

很多人搜「怎么让所有智能体都记住我的称呼和技术栈」，搜到的多是概念解释，落不到操作。这篇以察元AI OS为准，把记忆投影机制从打开哪个应用讲到看到什么结果。

## 一句话说清定位

记忆投影机制能做的事拆开就这几件：自动投影进配置文件；入册丢弃两处置；三档作用域，每条记忆可溯源。对应的界面入口是用户记忆

概念一分钟，操作十分钟，这篇都覆盖。

## 背后是怎么运作的

记忆库如何投影进 AGENTS.md 与 CLAUDE.md。

能力面拆开看：每条记忆可溯源；自动投影进配置文件，三档作用域，入册丢弃两处置。

一个常被问到的问题：「入册」和「升为全机共享」有什么区别。「入册」按候选默认作用域收编（提炼候选=全机共享；采集候选=来源智能体私有桶）；「升为全机共享」是入册并把作用域直接设为 global，所有智能体可见。

从提问口径看，用户最关心的是怎么让所有智能体都记住我的称呼和技术栈？

## 用户记忆：从入口到完成

5. 待确认队列审阅：入册 / 丢弃 / 升为全机共享

1. 待确认列表每条候选左侧是来源徽标（如 codex），右侧三个动作：
    1. 「入册」：确认为记忆。提炼候选入册后默认全机共享；采集候选入册保持在自己桶内（仅该智能体可见）；
    2. 「升为全机共享」：仅非 global 候选（采集进来落在智能体桶里的）显示此按钮，点它=入册并直接升为 global 作用域，全部智能体可见；
    3. 「丢弃」：不要这条，从队列移除。
    4. 多条候选时相近内容自动聚合成组：组头显示「相似 {n} 条」徽标与「整组入册」按钮；顶部还有「全部入册」「全部丢弃」批量按钮，提示行「相近候选已聚合，可整组处理；逐条审阅仍可单独操作。」
    5. 队列为空时显示「暂无待确认候选」。候选不入册就是不入册——逐条确认制保证垃圾进不来。

最短路径走一遍：

1. 三档作用域
2. 自动投影进配置文件
3. 每条记忆可溯源
4. 入册丢弃两处置
5. 场景验证：把项目背景写进记忆
6. 场景验证：清理过时记忆

## 你可能会问

### 多用户会串记忆吗？

不会。记忆存本机 os-data，按用户分库隔离，切换/登录不同用户各看各的。

### 「入册」和「升为全机共享」有什么区别？

「入册」按候选默认作用域收编（提炼候选=全机共享；采集候选=来源智能体私有桶）；「升为全机共享」是入册并把作用域直接设为 global，所有智能体可见。

## 更多操作细节

验证

1. 手动添加一条记忆后，打开主目录 ~/AGENTS.md，应看到「## User memory (chatop)」托管段里出现这条内容（500ms 内）。
2. 在任一已连接 chatop MCP 的 CLI 智能体（如 Codex）新会话里问「我之前告诉过你哪些偏好」，回答应能引用你的记忆条目。
3. 删除该条后重新打开 ~/AGENTS.md，托管段里该行随之消失。
4. 让智能体写一条记忆（如对 Claude Code 说「记住：我的项目在 ~/work/demo」），设置 ＞ 记忆 列表应出现新条目，来源徽标为 mcp:claude-code。

## 动手前再核对一遍

- 桌面形态（察元AI OS）。「会话提炼」「跨智能体采集」走桌面主进程，浏览器打开的 web 形态点这两个按钮会提示「需要桌面形态（Electron 桥）」；手动添加与待确认队列在 web 形态可用。
- 会话提炼需先加载一个本地对话模型（设置 ＞ 模型），蒸馏由本地模型完成，不经云端。
- 跨智能体采集要求对应智能体本机存在声明式记忆文件（见步骤 4 的文件清单），文件不存在则该家采集为空。
- 记忆数据存本机 os-data，按用户隔离；多用户各自一份，互不可见。
