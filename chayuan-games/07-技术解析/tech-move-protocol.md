# 大模型出招协议设计：move与comment的取舍

让大模型落一手棋，听起来是个简单活：让它回个坐标就行。真做过的人都知道没这么便宜——模型是一台不肯只说坐标的机器，它总要解释、要犹豫、要顺手写篇小作文。大模型出招协议要解决的就是这件事：怎么把一台语言机器的自由输出，变成裁判引擎能吃下的一步棋。察元竞技场给出的答案是 {move, comment} 这对结构，外加分层的思考模式。

## 出招结构：一招一带解说

LLM 玩家统一按 {move, comment} 出招。move 是动作本体，走解析链清洗后交给裁判判定落子；comment 是给观众看的一句话解说，模型用一句话交代它这步的盘算，比如「炮二平四封锁中路，防你卧槽马」。

把 comment 写进协议而不是当成可选装饰，是算过账的。棋牌竞技场的观赏性有一半来自「看懂模型在想什么」，对局室的思维链气泡已经承载了实时推理流，而 comment 是模型自己提炼的一句话结论，信息密度高、阅读成本低，复盘时逐手扫一遍，整局的思路脉络就出来了。协议画像统计的是出招习惯，comment 补的是「性格」这一面。

comment 与思维链气泡也不是重复劳动。思维链是全过程直播，几百字、想到哪流到哪；comment 是模型自己写的摘要，落在动作旁边，逐手读它，一局棋的思路主线几分钟就串完。对局室的三个信息通道各有源头：move 撑起棋盘与形势曲线，comment 撑起解说，思维链撑起全程直播，互不掺和，界面按需取用。

## 两段思考与三段思考

不同强度的模型，给同样的输出要求会得到参差的结果，协议因此做了分层。

基础形态是直接输出 {move, comment}。强模型支持两段思考：「分析：……」放开推演，「答案：{json}」收束落子，解析器在答案段内先行解析，不必等整条输出流完。深度规则模式（DEEP_RULES）要求更狠，三段输出：分析段推演三条候选着法线，每条交代自己走什么、对方最强应对、局面如何，其中至少一条吃子线、一条防守线，单条不超过 120 字；结论段不超过 30 字，一句话定板；答案段给出最终 JSON。字数上限不是刻意刁难，是给 token 成本与出招节奏上闸——深度模式每手的思考量本来就大，不设限的推演会把锦标赛拖成马拉松。

拿象棋举例，深度模式会把要求拆得很具体：吃子线要交代吃谁、对方怎么反打，防守线要交代挡在哪、护住哪个子，每条线自带局面评估，最后用不超过 30 字收一个结论，再交 JSON。看强模型照着这个框架打一局，推理的骨架清清楚楚，比看十段泛泛的思维链都直观。

## 喂给模型什么

协议的另一面是输入。喂给模型的局面信息里，着法与事件历史的优先级高于棋盘图示，合法步的清单跟着局面一起给，多人玩法还要附上合作语境。历史优先，因为语言模型读事件序列比解读一张图在行得多；合法清单显式附上，因为模型的规则记忆并不可靠，把「你现在能走哪些」白纸黑字列出来，既压低非法出招率，也为解析容错备好比对基准。这份清单与出招协议是配套工程：清单圈定范围，协议规定格式，解析链负责把模型输出按回清单。

## 设计取舍

为什么坚持结构化 JSON 而不是自由文本再猜？自由文本省事在前、还债在后：解析阶段要从散文里猜意图，猜错的代价是非法动作、对局崩坏。结构化把格式义务前置给模型，解析链只在格式破损时介入，责任边界清楚。comment 为什么不参与判定？判定只认动作真值，comment 是表达层产物，混进判定既污染裁判的中立性，也会诱导模型在解说里夹带判罚倾向。深度模式为什么不默认全开？它增加每手延迟与费用，强模型收益明显，弱模型的三条线推演可能条条跑偏——按模型与场景选择，比一刀切合理。

协议与容错链的配合也顺理成章：协议是正门，格式对了直接进；容错链是侧门，格式破损就地抢救；全文回捞是窗户，抢救无效再从文本里认领动作。三道口子的宽严顺序排好，模型的本意被层层保留，而不是一次解析失败就全盘作废。

## 边界

出招协议依赖模型的结构化输出能力，这条腿是有长短的：弱模型遵守率低，容错链会兜底，但那一手的 comment 可能缺失、动作可能被代走，观赏性打折。comment 由模型自行生成，质量随模型波动，偶尔有模型的解说与实际落子对不上——解说归解说，动作以 move 为准。深度模式的字数上限约束的是表达，不约束思考质量，个别模型会在限额内塞满车轱辘话，这也是协议画像里能观察到的真实差异。还有一条给办赛的人：深度模式的等待时间比基础形态长，锦标赛里全开深度档，一晚能跑完的对局数会明显变少，排程前先算好这笔时间账。

### 大模型出招协议为什么不以自由文本为主路

自由文本也支持，但排在容错链末段。模型输出自由文本时，解析链的回捞环节会从全文里找合法动作串；可这是兜底而非主路，主路始终是结构化 JSON，因为它可验证、可统计、可复盘，自由文本一样都占不到。

### comment 能关掉吗

comment 是协议字段，两段与深度模式下都是输出的一部分。对局室的解说气泡与思维链气泡是分开的展示层，你只想看棋，把注意力放在落子与形势曲线上就行，comment 不影响判定与积分。

### 答案段内先行解析是什么意思

两段思考模式下，解析器不必等整条输出流完：流式输出里一出现答案段的标记，解析就在那一段上先行启动。模型前半段的分析还在滚动，落子判定已经开始排队，对局的等待节奏因此更紧凑。

### 深度思考档所有模型都能开吗

协议层面任何模型都会收到三段输出的要求，但执行质量差别很大。思考型强模型的三条候选线往往真有内容，弱模型的深度模式常变成格式填空。建议对弱模型用基础形态，把深度档留给值得的对手。

大模型出招协议是模型与裁判之间的翻译条约：模型说它的语言，裁判收它的格式，协议居中定规矩。{move, comment} 这对看似简单的结构，撑起了观赏、复盘、画像一整条体验链，观众看得懂，裁判裁得准。规矩定得越清楚，桌上吵的架就越少。
