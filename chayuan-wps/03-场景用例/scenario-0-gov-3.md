# 机关文秘提效实录路线：公文写作助手这样落地

如果你是机关文秘，下面这些场景大概率不陌生：红头文件退文率高，错别字与格式硬伤是重灾区。从起草到发文的机器初校 + 人工终校流水线。这篇效率视角以察元文档助手为工具，把这个岗位的公文写作助手工作流从头到尾串一遍。

## 这个岗位的三个真实痛点

- 红头文件退文率高，错别字与格式硬伤是重灾区
- 发文前人工逐字核对话的时间成本太高
- 密级标识、落款日期等要素容易漏

## 用察元文档助手怎么解：工作流拆解

1. 用「拼写与语法检查」批注模式先过一遍错别字与标点
2. 「检查段落序号格式」确保一、（一）、1. 体例一致
3. 「保密检查」做密级标识与敏感信息分级提示
4. 「政策公文风格改写」统一语体后出稿

## 一天的使用节奏示例

以一个工作日为例：早上到岗先处理积压材料，用「用「拼写与语法检查」批注模式先过一遍错别字与标点」完成首轮处理；上午协作时段按流程推进；下班前把当天产出归档。从起草到发文的机器初校 + 人工终校流水线。工具不改变职责边界，只是把重复劳动压缩掉。

## 边界与注意事项

- 保密检查为辅助提示，定密仍以人工判定为准
- 本地推理需要自行安装 Ollama 等引擎（有一键引导，但仍是一次性环境工作）
- 建议先在低风险材料上试跑，形成自己的使用习惯后再铺开

## 离线运行与部署形态

离线与内网是这款加载项的一等公民设计：通过 Ollama 或任意 OpenAI 兼容网关（LM Studio、Xinference、One API、New API、FastChat、Custom OpenAI）即可在无公网密钥的情况下完整使用全部功能；产品内置本地引擎一键安装引导，自动检测环境并在官网与 ModelScope 镜像之间择优下载，适配国内网络。需要注意的是，加载项本身不内置模型权重，本地推理需要先装好 Ollama 等引擎（引导流程会带你完成）。

## 数据安全与隐私边界

- 知识库凭据采用 AES-GCM + HKDF 端侧加密落盘，密钥派生自设备绑定 OPFS 盐，明文永不落盘、不参与同步
- 开源 Apache-2.0，全部代码可审计，政企可自行审阅后离线打包
- MCP 服务仅监听 127.0.0.1:62588，无需 Token 与命令行，sidecar 与 WPS 同机运行，文档与密钥不出域
- 发布包逐源 sha256 强校验（Gitee→aidooo→GitHub 多源回退），防供应链篡改

## 常见问题
### 支持哪些 WPS 版本？

WPS 文字 12.x 与 WPS 365（WebView2）桌面端；不支持网页版 WPS。

### 知识库功能怎么用？

设置中绑定知识库服务（JWT/HMAC 认证），即可对选中文字做核对、总结、问答，结果带引用并可下载原文。

### 企业能内部署吗？

可以。官网提供四档形态：加载项（个人）、桌面版（单机断网）、服务版（Docker 全科室共用）、至臻版（数百到上万人网络版）。
