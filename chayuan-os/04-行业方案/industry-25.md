# AI 桌面操作系统：创业团队AI方案路径与边界

## 创业团队为什么需要这套方案

创业团队行业的文档与信息工作有几个共性：材料格式要求严、数据敏感不能乱传、人手紧重复劳动多。察元AI OS的切入点不是推倒重来，而是把 AI 能力装进现有流程，数据不出本机是底线设计。

## 落地路径：三步走

1. 基础层：先把模型设置向导跑通，验证环境与模型可用
2. 流程层：创业团队日常最高频的文档环节（配置云端厂商模型所属的场景）交给 AI 处理，人只做审核
3. 治理层：权限门与审计机制上线，形成使用规范

## 关键能力对齐

### 模型设置向导

- 概念页解释模型代理机制
- 默认对话模型选择
- 统一应用到智能体

### 配置云端厂商模型

- 国内/国际/本地/聚合四组厂商目录
- OpenAI 风格与阿里百炼风格 API 自动适配
- 填 Key 后可测试连通再启用

### 下载本地模型

- 内存预算分层推荐
- 断点续传与多路换源

### 离线导入模型权重

- 路径导入零拷贝
- 扫描本地放置的模型
- whisper 语音权重同样支持

## 一个行业侧影

小团队负责人的典型链路：

1. 服务器 Docker 部署察元AI工舱云桌面
2. 员工浏览器打开即用，账户隔离
3. 共享模型代理与知识库，配置统一
4. 常驻任务统一跑巡检与日报

一台服务器全组使用，配置与数据集中管理。

提醒：需要一台性能尚可的服务器与基本的 Docker 能力。

## 合规与边界

- 敏感操作全部写审计日志 audit.jsonl，可回放检查
- API Key 用 safeStorage 加密存储，遥测可整体停用

行业落地最容易翻车的不是技术，是把边界讲清楚。

## 选型核对清单

- 付费口径：免费下载使用，购买只停提醒、不锁功能
- 试点建议：先选一个三人以内小组、一个高频场景跑两周再扩大

## 安全与数据边界

安全口径单独立一层：本地 AI 出题验证；命令行 AI 编程智能体一茬茬冒，一台机器管十几家、配置互不打架，是这套系统的核心场景之一，右键是桌面操作的集大成入口，用智能体打开把文件直接交给 AI 处理；Ctrl 或 Cmd 加 K 唤起：搜应用、文件、内容，加问 AI 知识库直答，支持语音输入。

## 平台与形态

平台与形态的账：Ctrl 或 Cmd 加 K 唤起：搜应用、文件、内容，加问 AI 知识库直答，支持语音输入；键盘党的启动器：一个快捷键管启动、找文件、直接问 AI 三件事，问 AI 直答卡；四本日历把生活与工作分开记，AI 能读会写，文件管理器右键直接把文件交给智能体，是最顺手的 AI 入口之一。

## 几条硬数字

## 离线与内网

离线内网这条线的口径：可选自动（本地优先）或指定；润色翻译这类轻任务用旗舰模型是浪费，主强子弱的路由让轻任务自动落本地小模型，省算力省钱，自动模式本地优先，local 星号开头的本地模型未运行自动加载。

## 能力总账

把察元AI OS的能力总账摊开：在 dsh 会话、灵宠或群聊里说一句查一下知识库里的什么，CLI 智能体经 MCP 自动接入；对配对终端开模型加知识库授权；Office 或 WPS 引用不到知识库，九成是服务没起或端口被占，三层检查定位到具体一层，生图模型不配好，画图应用与智能体的生图指令都落空。
