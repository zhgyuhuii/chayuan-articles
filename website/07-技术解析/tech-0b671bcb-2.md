# 教程库的采集与门类体系（实操要点）

这是「能力广场技术解析」系列的一篇。教程库的采集与门类体系是理解这款产品设计哲学的关键切面——看完你会明白它为什么这样设计、这样设计换来了什么、代价是什么。

## 一句话结论

2.1 万+ 条教程来自结构化采集（arxiv 1.3 万 / github 7 千+ / B 站 7 百+ / awesome 与精选），按 topic（llm/agent/rag/prompt/deploy/finetune/multimodal/mcp/skill 等）×type（文章/仓库/视频/课程/书/文档）双维组织；采集有源注册表纪律：发现新源先登记、下次优先复采。

## 为什么这样设计

这个设计的动机可以概括为三点：把风险控制在机制而不是纪律里（靠制度约束人的行为总会失效，靠架构约束才稳定）；把复杂度封装起来（用户不需要理解内部实现，只需要理解行为边界）；把可验证性留给用户（声明的能力都能在产品里实际验证）。软件工程里没有免费的设计——每一条这样的取舍都是在「体验、安全、性能、成本」之间做的显式权衡，约束变了，结论就可能反转。

- 政企可私有化部署（Docker），数据自主可控
- 网站不存任何二进制文件，安装一律跳转原始地址
- 注册仅需基础信息，支持图形验证码；会话走 JWT Cookie
- 相关能力以官网 https://aidooo.com 最新版本为准

## 动手验证

1. 带着本文结论去产品里找到对应入口
2. 构造一个最小场景验证行为是否符合描述
3. 观察边界情况的表现（断网、权限、并发）
4. 把验证结论沉淀进团队内部文档

## 离线运行与部署形态

对断网环境，广场的配合方式是：先在联网机器上完成检索与命令复制，再转入内网执行；政企可私有化部署整套门户（Docker + nginx，含 SQLite 数据与 SSR 快照层）。
