# Docker端口冲突装机指南：团队统一 AI 工位

Docker端口冲突值得不值得单开一篇，一个细节就能说明白：员工浏览器打开地址就能进桌面。这份从容背后是一整套入口与验证链路，本文以察元AI OS 为底，把它完整拆开。

## 安装前确认

- 系统要求：任意可跑 Docker 的服务器
- 安装包：docker compose（察元AI工舱形态）
- 说明：端口占用与映射调整。

安装包从官方发布渠道获取，服务器上的部署文件同样以官方交付的为准。

## 一步步来

1. 获取 docker-compose.yml
2. docker compose up -d 启动
3. 浏览器访问默认 52584 端口得到多用户网页桌面
4. 账户隔离，数据在服务器侧统一管理

## 怎么确认做成了

- 启动进入桌面，对话应用选本地模型能正常回复
- 首启初始化需要 5 到 30 秒，属正常现象，期间不用干预

## 端口被占了怎么查

登录服务器先查占用：`lsof -i:52584` 或 `ss -ltnp | grep 52584` 都能列出占用该端口的进程，输出为空说明端口空闲。确认占用者是可停的服务就停掉再起 compose；是别的关键业务，就走改映射这条路，不要硬抢。

## 改端口映射的做法

compose 的 ports 段写成 宿主端口:容器端口 的形式，比如 52585:52584，宿主侧换号、容器内保持默认，`docker compose up -d` 重新拉起即生效。改完记得同步两件事：员工访问的地址换成新端口，防火墙或云安全组放行新端口。后文服务链自愈里的端口被占自动顺延，与这里的对外映射是两回事，别混用。

## 回环监听与外网暴露的取舍

默认只监听回环，意味着只有本机能访问服务，这是收窄暴露面的稳妥默认。要给团队用，就得在 compose 里显式映射到网卡地址，而暴露那一刻起，端口面就等于业务面：只放真正需要的端口，其余保持回环；公网直达的场景再加一层反向代理或访问控制。前文「端口暴露面自控」的价值就在这里——开多少、留多少，决定权在使用者手里。

## 先要认下的几条账

- 云端厂商的模型想用起来，API Key 要自己先行准备
- Docker 云桌面、跨终端互联属于进阶玩法，动手能力有一定要求
- 8GB 内存的机器同一时刻载入一个对话模型为宜，任务一复杂就吃力
- 龙芯平台暂无对应版本；视频生成本地不承担，交由云端路由输出

## 起一个云桌面的动作序列

1. 服务器上准备 docker compose 配置
2. docker compose up -d 启动工舱
3. 按需暴露端口（默认回环，外网访问自行映射）
4. 员工浏览器打开地址，各自账户登录使用

## 上线前的检查清单

1. 默认端口 52584 是否被占用（compose 映射可改）
2. 按团队人数评估内存：每并发一个本地模型约吃数 GB
3. 数据卷挂载出来，升级与备份都靠它
4. 管理员账户先建好，再开放普通用户注册

## 三个常被问到的问题

### 云桌面和桌面版功能一样吗？

核心能力面一致（对话、知识库、模型、办公），形态差异在：云桌面无本地文件直通、语音输入依赖浏览器权限、部分外设在浏览器里受限。

### 多少人共用一台服务器合适？

取决于是否同时跑本地模型：只做对话与知识库，十几人一台中配服务器可行；要并行跑本地推理，按并发数加内存或改用厂商模型分流。

### 数据存在哪里？

全部落在服务器的数据卷里（含用户空间、知识库、配置），挂载出来后备份一个目录等于备份全组。

## 这套形态换来的四点

- 浏览器即用
- 账户隔离
- 数据集中管理
- 端口暴露面自控

## 固定端口的服务有哪些

知识库对外服务走固定端口；本机 MCP HTTP 服务只监听回环、免 token；docx/xlsx/pdf/csv/html 与扫描件 OCR，单文件不超过 48MB；GGUF、whisper 权重可以按路径直接导入（零拷贝）。

## 多人共用的安全底线

多人同跑一台设备，先把数据隔离这条底线守住，账号由管理员统一管理，好过各用各的；隐私敏感的环境，开工前先把遥测关掉，设备要转手处置时记得先清数据；本机的 Stable Diffusion 出图链路不经网络。

## 工舱形态与 Dock 的细节

整套系统可以无头方式跑在 Docker 里，充当多用户云桌面（察元AI工舱形态），员工开浏览器即达；对外暴露时用 9 位字母外网后缀生成访问链接，wa 会话管理与踢线操作都在管理侧；Dock 上的文生图应用收提示词与负面提示词，出图后可设为壁纸，或开启每 30 分钟自动换壁纸；桌面与 Dock 的位置、自动隐藏、图标放大与整体大小、开机自动打开 Harness 都在设置里调。

## 服务自愈与回环监听

服务链自愈：崩溃退避重启、配置异常回滚上一可用版本、端口被占自动顺延并让消费方重新发现；默认只监听回环端口。知识库在 Office 或 WPS 那头引用不到，通常问题出在服务没起或端口被占，三层检查一层层过，总能落到具体的一层。

## web 形态与办公入口

web 与 Docker 形态的网页桌面走默认端口；内置的察元AI Office 挂在 Dock 上，点开即用，文档、表格、演示皆可在线编辑。

## 应用封装与常驻任务

应用页签里可将 dock 应用隐藏、按新建分组归类，自定义网页、本地程序、HTML、文件这四类对象都能封装成桌面应用；常驻任务在设置里新建，指令自己写，执行者可选模型或智能体（也能直跑），工作区知识库与联网开关一并配上；编辑面板负责改模型、知识库与人设，输入框旁有知识库绑定与模型选择（含智能路由自动选模型），检索引用知识库内容并带出处写进文档。

Docker 云桌面（察元AI工舱）这件事，真机操作一遍比看十遍文章有用，从检查端口占用那一步开始练手最合适。
