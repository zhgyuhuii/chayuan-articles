# 出版发行行业怎么用察元OS：从痛点到落地

出版发行行业的文档与信息工作有其固有节奏：多岗位协作时版本混乱、批注流转低效。察元AI OS在出版发行场景下的定位，是把可标准化的环节交给工具、把判断留给从业者的「人机协同」。本文按痛点→能力→落地步骤→边界的顺序，给出出版发行行业的完整应用路径。

## 出版发行行业的典型痛点

- 多岗位协作时版本混乱、批注流转低效
- 跨部门数据与引用需要反复核对出处
- 历史文档数字化程度低，检索与复用困难

## 对应的能力组合

- **多智能体共享记忆**（智能体记忆）：全部智能体的单一事实源记忆：项目进最新 60 条投影进 AGENTS.md/CLAUDE.md，六家智能体共享同一份记忆。
- **应用商店**（AI应用商店）：插件/技能双类型商店（规划五类商品：插件/技能/MCP/提示词/智能体+技能包），aidooo.com 为默认首选源；免费直下，付费走内嵌收银台 webview，支持断点续传、sha256 校验、原子换入。
- **四家 CLI 智能体**（CLI智能体）：Claude Code、Codex、OpenCode、OpenClaw 四家命令行智能体以「应用」形态运行：真实 pty 终端、绑定工作区目录、多标签；二进制随安装包分发（约 1.3GB），开箱即用。
- **MCP 服务与同步**（MCP服务器）：系统级 MCP server（stdio `chatop mcp` + 本机 HTTP 52583，回环免 token）；MCP 配置自动传播注入六家智能体（claude-code/opencode/codex/zcode/openclaw/dsh）；设置里有 MCP 分区管理与清单离线导入导出。

## 落地四步

1. 盘点本岗位高频文书/信息任务，挑最耗时的两个作为切入口
2. 按小内存设备用户场景的工作流试跑一周，记录节省的环节
3. 把常用任务固化为助手或规则模板，团队复用
4. 建立人工复核节点：工具产出 → 从业者裁决 → 定稿

## 合规与边界

- 涉密与敏感材料遵循本单位管理规定，必要时使用离线部署形态
- 四家 CLI 智能体二进制约 1.3GB，完整安装占磁盘较大
- 行业判断责任始终在人，工具输出作为参考

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- 全部本地服务只监听 127.0.0.1，数据不出本机
- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）
- 遥测可完全停用（DSH_TELEMETRY_DISABLED）

## 常见问题
### 什么是系统级 MCP？

系统提供 chatop MCP server（80+ 工具），智能体能开窗、嵌网页、跑终端、读写便签日历、换壁纸截屏等；配置自动同步到六家智能体。

### 应用商店卖什么？

插件与技能为主（规划含 MCP/提示词/智能体/技能包五类），默认源为 aidooo.com；免费直下、付费内嵌收银台，支持断点续传与 sha256 校验。

### 察元AI OS 是什么？

一个插件化的 AI 桌面操作系统体验：macOS 风格桌面为壳，整合 AI 对话、四家 CLI 智能体、本地大模型服务、本地知识库与系统级 MCP 控制面，断网可用、数据不出本机。
