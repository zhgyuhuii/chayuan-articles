# 文生图模型怎么用：手把手走一遍完整流程

这篇文章没有虚的，全是文生图模型的实操细节：入口路径、按钮原文、做完后的界面变化，以及我踩过的坑。基于察元AI OS当前版本。

## 先对齐一下概念

在 设置 ＞ 默认模型 里给「文生图」「图生图」两类任务各选一个默认模型：选「自动」（系统按「本地优先、否则云端第一个匹配」解析）或指定某个已启用厂商的图像生成模型；保存后写入系统技能伴随文件 models.md 并分发到各智能体，智能体经本机模型代理（127.0.0.1:52581）调用它出图。本地 Stable Diffusion 权重链在「文生图」应用内，与此处是两条独立链路。

生图模型不配好，画图应用与智能体的生图指令都落空。

按真实界面写，按钮文案原样引用。

## 前置条件

- 要指定具体模型：先在 设置 ＞ 模型 配好并启用至少一家有图像生成模型的厂商。列表来源 = 本地已装模型 + 已启用厂商。
- 「自动」不需要任何配置，但没有可用模型时它什么也选不出（显示「无可用模型」）。
- 云端调用经本机模型代理（固定 127.0.0.1:52581）转发；保存选厂商模型时要求代理在运行。

## 完整操作步骤

1. 进入页面

打开 设置，左栏第二项「默认模型」。左栏分类竖栏中：「默认文生图模型」（第 5 项）与「默认图生图模型」（第 6 项）。点选其一，右栏卡片标题同名，说明文案：「选择该分类的默认模型；保存后写入系统技能（models.md）并自动分发到各智能体。云端厂商经本地 52581 代理调用（真实 key 不出凭证库）。」卡片右上角两个按钮：「管理本地模型…」与蓝色「设置…」。

2. 认识选择区（单选树）

卡片主体是一个圆点单选列表，自上而下：

1. 「自动」行——默认选中。后面跟灰字解析结果：「当前自动使用：{模型}」（本地有则形如 本地 · <模型id>，云端有则形如 <厂商名> · <模型id>）；一个都没有时显示「无可用模型」；
2. 「本地模型」组——列出具备 image-gen 能力的本地模型（行尾绿点 = 运行中）。当前内置目录没有可安装的本地图像模型（Stable Diffusion 1.5 是占位条目，权重链在「文生图」应用内，见步骤 6），所以文生图页这组通常不出现；图生图页没有本地组（本地无此能力）；
3. 各已启用厂商组——组头是厂商名，下面按等宽字体列该厂商的图像生成模型（按模型 id 的图像类特征匹配，如 -image-、dall-e、qwen-image-*、imagen 等；厂商模型类型由模型名自动识别，无需手动归类）。同一个厂商模型在文生图、图生图两页都会出现（两页都取厂商的图像生成类）；
4. 列表为空时（文生图页）显示「该分类暂无可用模型。点击右上「设置…」去模型设置启用厂商或安装本地模型。」；图生图页没有本地能力，空时只显示「自动」+「无可用模型」。

3. 「自动」的含义（本地优先逻辑）

「自动」的解析顺序：本地第一个可用模型 ＞ 云端第一个匹配的厂商模型 ＞ 都没有（无可用模型）。解析结果显示在「自动」行右侧灰字里，随本地/厂商配置变化自动更新，不需要手动刷新。

4. 选定模型并保存（两条路）

保存成功后右上角绿色提示「已保存，系统技能已更新并分发到各智能体」；选了厂商模型时保存动作还会自动把该厂商加入代理路由（真实厂商 Key 不出凭证库）。失败显示红色错误——代理停摆时报「模型代理未运行，无法接入云端厂商（先在模型设置里确认服务状态）」。

1. 路 A（点选 + 底部保存）：直接点树里某个单选行（「自动」/本地/厂商模型），然后点页面底部右侧「保存并更新技能」（进行中显示「保存中…」）；
2. 路 B（弹窗，确定即生效）：点右上蓝色「设置…」弹出对话框，标题「选择默认文生图模型」（或「选择默认图生图模型」），说明「列表 = 本地模型 + 已启用厂商；点「确定」立即生效」。弹窗内是同款单选树（「自动」+ 可折叠的「本地模型」组与各厂商组，厂商组带 logo、组头右侧显示数量药丸与折叠时的选中摘要；打开时自动展开「本地模型」组和包含当前选中项的厂商组，其余折叠，点组头展开/收起）。选中后点「确定」（进行中显示「正在应用…」）立即保存，点「取消」放弃；点弹窗外遮罩也可关闭。
3. 想改回「自动」：点「自动」行（主树或弹窗均可）再按上述任一路保存即可。

5. 保存后谁在用它

1. 生成 models.md：表格里出现「默认文生图模型 | <厂商> · <模型> | <厂商id>/<模型>（经代理路由）」一行（图生图同理；表格列为「分类 | 默认模型 | 调用（模型名）」），随系统技能包分发到各智能体（dsh 用户技能根与各 CLI 智能体技能目录）；
2. 智能体按技能手册经模型代理调用：POST http://127.0.0.1:52581/v1/images/generations（模型名带命名空间，如 agnes-2/agnes-image-2.1-flash），返回 {data:[{url}]}；对 /v1/chat/completions 发图像类模型时代理也会自动换算成 images 调用并把结果包成 !image 文本；
3. 本地命名空间（local/*）在 images 端点会明确 404（「本地暂无图像生成模型，请使用厂商路由」）——所以当前默认图像模型实际只有云端链路。

6. 相关：设置 ＞ 模型 ＞ 本地「生图」分类

设置 ＞ 模型，左栏「本地模型」组里选「生图」分类：模型库里有一条「Stable Diffusion 1.5」（带黄色 beta 标），行尾按钮「前往画图应用」——本地 SD 权重的下载与运行都在「文生图」应用里完成，不在模型服务里，也不会出现在第 2 步的「本地模型」组。（注：该按钮的跳转链在代码里以小写应用 id 寻址，与注册名大小写不一致，点击可能无反应——届时直接从 Dock/启动入口打开「文生图」即可。）

## 收尾检查

验证

1. 保存后回到本页：「自动」行或树中选中项与你的选择一致；重开页面状态保持。
2. 已选厂商模型时，浏览器或终端访问 http://127.0.0.1:52581/v1/models（免 key）：清单出现 <厂商id>/<图像模型名> 条目。
3. 终端实测出图链路：curl -s http://127.0.0.1:52581/v1/images/generations -H 'content-type: application/json' -d '{"model":"<厂商id>/<模型名>","prompt":"a cat"}' 应返回含图片 URL 的 JSON（需该厂商余额/额度可用）。

## 什么情况下用得上

已配置了带图像生成的厂商（如 Agnes、阿里百炼 qwen-image 系），不知道在哪里设为默认，看到默认文生图/图生图页面只有「自动」和云端厂商，想知道「自动」到底会选谁、本地能不能选；云端生图要质量，想让智能体（Harness / Claude Code / Codex 等）直接生成图片，需要先告诉它默认用哪个图像模型。

用户常搜的问法：怎么设置默认的文生图模型；默认文生图模型的『自动』是什么意思。

## 几个容易忽略的细节

用之前要认的账：

- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 全量安装包含模型权重约 4.7GB，轻量包约 1GB，完整离线能力需要额外下载权重

## 高频疑问

### 模型下拉/树里看不到刚启用的厂商模型？

本页厂商列表与 设置 ＞ 模型 的「已启用」状态同一条判定链：确认厂商卡状态行为「已开启 · 显示在 Harness 模型下拉框」，且「获取模型列表」快照里勾选了「图像生成」组的模型；新勾选后回本页重进即可看到。

### 图生图和文生图有什么区别？为什么图生图没有「本地模型」组？

两个分类都从已启用厂商的「图像生成」类模型里选；本地目前只有文生图能力（SD1.5 仅文生图），所以图生图页没有本地组，只有「自动」+厂商模型。选好默认后智能体按 models.md 分别引用。

### 为什么「本地模型」组是空的？本地不是能跑 Stable Diffusion 吗？

本地 SD1.5 走「文生图」应用的独立链路（WebGPU + 应用内下载权重），不经过模型服务，因此不会出现在默认模型列表里；模型目录里的 sd15 只是占位指路条目。默认图像模型这条链当前只支持云端厂商路由（本地命名空间在 images 端点明确 404）。两条链路互不影响：改这里的默认模型不会改变「文生图」应用的行为。

### 保存时报「模型代理未运行，无法接入云端厂商」？

选了厂商模型时保存会自动确保该厂商的代理路由可用，这要求模型代理（52581）在运行。到 设置 ＞ 模型 查看服务健康灯（顶部状态条），服务正常后回来重新保存。

整体用下来，设置默认图像生成模型的流程是清楚的：入口集中、步骤有反馈、做完有验证。第一次照着走一遍，后面基本就是肌肉记忆了。卡住就回看常见问题那一节。
