# 一篇讲透自动接力：准备、步骤、验证与边界

自动接力这个话题我被问过三次以上，每次都要重新讲一遍。与其反复口述，不如写成一篇：从群聊讨论控制的入口讲到验证，中间的分支也一并说清，基于察元AI OS。

## 这个功能到底解决什么问题

群聊窗口头部的一条控制条管住整场讨论的节奏：「继续讨论/结束讨论」手动推进或随时叫停，「」自动接力开关（带停滞保护），「」共识模式（达成一致自动停），「」联网搜索注入；配合消息流里的命题钉条、@提及、视角分工，让多灵宠讨论不跑飞、不刷屏。

不设控制的群会无限聊下去，共识模式让它们互相评审收敛出结论，视角讨论强制多角度避免一窝蜂说一样的话。

下面直接进入正题。

## 开工前检查这几样

- 已按对应教程建群并发过至少一条命题（部分按钮在讨论进行中才有意义）；
- 「/」等开关按群的协同方式显隐：串行/多步骤群不显示「」，多步骤群不显示「」（详见下表显示条件）。

## 实操全过程

第 1 步 · 认识控制条（群名与成员头像栈右侧，从左到右）

| 按钮/元素 | 悬停提示原文 | 说明与显示条件 |
|---|---|---|
| 「重试离席成员」 | — | 仅当有成员调用失败时出现（琥珀色）；点击把失败成员按原上下文重跑一轮，不占轮次 |
| 「继续讨论」 | — | 手动推进一轮；讨论进行中置灰 |
| 「结束讨论」 | — | 讨论进行中红色可点；点击立即全停并即刻置灰；本来就没在跑时点击无反应（不刷「讨论已结束」） |
| 免打扰（铃铛图标） | 「免打扰」 | 开启后左栏群名前加静音图标、不再亮未读绿点 |
| 编排状态 chip | — | 串行/多步骤群显示 |
| 「ON/OFF」 | 「自动接力（默认开启）：一轮结束后成员自动继续讨论，无需手点「继续讨论」；点结束讨论或关闭本开关即停，连续无有效回复自动暂停」 | 并行群与串行群显示（多步骤群不显示）；默认 ON（橙色） |
| 「ON/OFF」 | 关时显「视角讨论（默认开启，与共识模式互斥）：成员按各自人设承担不同视角任务（挑毛病/核实/展开/举例），避免全员说同样的话；开启共识模式即切回收敛讨论」；开时显「共识模式：多智能体自动推进讨论直到达成共识自动停止（也可随时点结束讨论终止）」 | 仅并行群显示；默认 OFF（青色=ON） |
| 「ON/OFF」 | 「联网搜索（DeepSeek）—群聊轮次自动检索并注入参考」 | 默认 OFF；开启后每轮按命题检索并注入「【联网搜索结果（provider=…，供参考、引用请注明来源）】」块；未配置/失败/超时一律静默跳过，不阻塞发言 |
| 「纪要」 | 「生成群聊纪要（AI 总结本群讨论要点）」 | 见对应教程 |
| 「管理」 | 「管理群聊（改名/成员/模式设置）」 | 见对应教程 |
| 「清空记录」 | 「清空本群聊天记录」 | 清空本群全部消息（含接力交接单），不可撤销 |
| 「」 | 「搜索本群消息」 | 开/关搜索框（当前版本输入不过滤消息流，见常见问题 Q5） |

第 2 步 · 讨论中的可视信号（看懂再操作）

1. 消息流里：「{名} 思考中」小条（排队/思考）＞ 流式气泡（带闪烁光标）＞ 落账定稿；被中止/失败的气泡以虚线斜体样式标注「中断」；
2. 头部成员头像栈：正在发言的成员右下角亮绿点；
3. 「继续讨论」与「结束讨论」互为镜像：讨论中「结束讨论」红色可点、「继续讨论」置灰；空闲时反过来（点完「结束讨论」立即置灰，不用等 15 秒活跃窗口消退）；
4. 左栏群条目的「讨论中」徽标有 15 秒平滑窗口——轮次间隙里徽标不闪烁消失。

第 3 步 · 继续 / 结束

1. 「结束讨论」随时可点，效果是全停：
    1. 正在「思考中/发言中」的成员全部中止（已流出但未完成的段落会以「中断」样式落账，不凭空蒸发）；
    2. 自动接力、共识推进、串行续轮调度全部清空，接力交接单一并清空；
    3. 消息流落「讨论已结束」系统条；
2. 「继续讨论」按群模式各显神通：
    1. 并行群 = 手动再跑一轮（同一命题手动接力最多 5 轮，超出提示「已达本轮讨论轮次上限」）；
    2. 串行群 = 推进下一轮（轮次计数保留，「从头重新执行步骤链」才重置）；
    3. 多步骤群 = 从头重跑步骤链；
    4. 有成员失败过时（出现「一位成员暂时离席（调用失败，可在群设置重试）」系统条），先点「重试离席成员」补跑失败者。

第 4 步 · 自动接力（，默认开）

1. 默认 ON：一轮结束、全员空闲后约 5 秒自动开下一轮，不需要你点任何按钮；
2. 想改回手动：点 切到 OFF（此时用「继续讨论」逐轮接力）；
3. 停滞保护：接力开轮后没有任何灵宠成功回复（模型/代理故障）时，自动暂停并提示「连续无有效回复，自动接力已暂停（发出新消息后自动恢复）」——开关不会被翻掉，你发新消息即恢复；
4. 成员失败会先自动自救：提示「成员离线，正在自动排查并重连…」，按故障类型预热引擎后自动重试（最多 2 次），重试耗尽才落「暂时离席」交给「重试离席成员」。

第 5 步 · 共识模式（，仅并行群）

1. 点 切 ON：
    1. 自动关闭 ；
    2. 消息流落系统条「已切至共识模式（收敛讨论）：视角任务暂停，全员中立作答直到达成共识」；
2. 此后每轮结束自动判定（约 5 秒一查）：
    1. 达成（最近一轮回复里「同意/共识/一致/赞成/没意见/没问题/就按/可以/OK」等信号过半）＞ 「已达成共识，自动停止」，共识模式随之自动关闭；
    2. 未达成 ＞ 「尚未达成共识，继续推进…」自动续轮；
    3. 连续 2 轮没有任何灵宠新回复 ＞ 「连续无有效回复，共识推进已自动暂停（请检查模型服务后重试）」并自动关闭共识模式；
    4. 随时可用「结束讨论」硬终止。

第 6 步 · 视角讨论（默认开启，无需操作，看懂即可）

并行群非共识模式下，每轮讨论类命题（含「讨论/分析/利弊/观点/怎么看/建议/方案/为什么/评价/聊聊」字样）自动给成员派视角任务，注入其系统提示；接龙等短答命题不派。任务原文如下（{persona} 为该灵宠人设，引文为任务段主体）：

分配规则：

1. 成员人设各不相同 ＞ 按人设关键词映射（含「抬杠/反方/挑刺」＞反方、「严谨/核实/审计」＞核查者、「展开/脑洞/创意」＞展开者、「举例/案例/实战」＞举例者，其余＞自由补充）；
2. 人设全空或全员雷同 ＞ 按成员顺序固定套用 反方 ＞ 核查者 ＞ 展开者 ＞ 举例者，多出的成员自由补充；
3. 单成员群与共识模式不派视角；视角跨轮、跨重试保持恒定；
4. 每轮开始前引擎还可能落「决策门控：{names} 参与本轮」系统条——由决策模型挑最相关的成员发言（并召回一名人设差异最大的旁观者补盲区）；决策面缺席/超时时全员发言（行为不变）。

| 视角 | 任务原文 | 含义 |
|---|---|---|
| 反方 | 「你是反方——上一轮（或命题）的结论要挑毛病：找漏洞、举反例、说哪里站不住；不要附和。」 | 专职唱反调 |
| 核查者 | 「你是核查者——验证上一轮（或命题）里的论据是否站得住：哪些有依据、哪些是臆断；不要附和。」 | 专职查证据 |
| 展开者 | 「你是展开者——沿着上一轮（或命题）往没人说过的方向延展：新角度、新场景、新可能；不要复述已有结论。」 | 专职开脑洞 |
| 举例者 | 「你是举例者——用具体例子/案例/数字支撑或反驳上一轮（或命题）的观点；不要空谈。」 | 专职摆事实 |
| （自由补充） | 「贡献一个别人没说过的信息或角度；不要复述他人结论。」 | 第 5 只及以后的成员 |
| （异质召回） | 「你本来旁观，但你的视角和大家不同——请补充一个所有人都忽略的角度；不要重复任何已说过的观点。」 | 被门控安排旁观的差异视角成员 |

第 7 步 · @提及与插话

1. @提及：消息里写 @灵宠名（名字需与档案名完全一致），发送后：
    1. 只有被点名的成员接单；
    2. 消息流落系统回执「@{名} 已接单（其余成员旁观）」；
2. 插话：讨论进行中你随时可以发言（不会叠加新轮）：
    1. 并行群：当前轮结束后自动接力转答你的新消息；
    2. 串行/多步骤群：标记打断——当前成员说完即弃旧队列，续轮转答新命题；流水线在跑时插话会并入命题槽（标注「用户补充」）而不是重开；
    3. 话题分段：消息流顶部钉着「【本轮命题】 + 命题原文」钉条，标记当前讨论从哪开始；更早场次折叠成「查看更早的 {n} 条消息」（首次展开显示 200 条，之后每点一次「再展开 {n} 条更早消息」多显 500 条，可「收起更早消息」）。

## 怎么确认做成了

验证

1. 讨论进行中点「结束讨论」：所有「思考中/发言中」立即消失，出现「讨论已结束」系统条，「结束讨论」按钮变灰、「继续讨论」恢复可点。
2. 并行群点 切 ON：出现「已切至共识模式…」系统条且 自动变 OFF；持续几轮后出现「已达成共识，自动停止」或「尚未达成共识，继续推进…」。
3. 发「@{某灵宠名} 你怎么看」：消息流出现「@{名} 已接单（其余成员旁观）」，只有它一只发言。
4. 发一条含「讨论/分析」字样的命题：多只成员的发言应呈现明显分工（一只挑毛病、一只举例子等），而不是各说各的相似观点。

## 什么情况下用得上

强制反方视角挑方案毛病，群讨论停不下来（一轮接一轮自动续），想让它停下或只推一轮；让模型互相评审直到意见收敛，想让几只灵宠辩到「达成共识」为止，而不是无限发散。

用户常搜的问法：宠物群聊怎么停止讨论？停了怎么继续；共识模式是什么？达成一致会自动停吗。

## 高频疑问

### 串行群插话后怎么又从头讨论了？

串行群的新人类命题会重置轮次并从头起链——这是「新命题=新讨论」的口径；想补充而不是重开，等本轮结束再发，或接受引擎把插话并入当前命题（流水线在跑时插话会并入命题槽，标注「用户补充」）。

### 共识模式一直不收敛？

判定是启发式：最近一轮过半成员明确表达同意词才算共识。成员人设太爱唱反调时可能久拖；可点「结束讨论」终止，或改用串行接力人工控制节奏。

### @了灵宠但全员都说话了？

@名字必须与灵宠档案名逐字一致（含空格）；写错一个字就当作普通消息全员回应。可先在群管理面板「成员列表」核对名字。

### 成员失败后还要手动重试吗？

先不用：引擎会自动排查重连（「成员离线，正在自动排查并重连…」），按故障类型自动预热并重试至多 2 次；仍失败才落「暂时离席」，此时点头部「重试离席成员」。

整体用下来，群聊讨论控制的流程是清楚的：入口集中、步骤有反馈、做完有验证。第一次照着走一遍，后面基本就是肌肉记忆了。卡住就回看常见问题那一节。
