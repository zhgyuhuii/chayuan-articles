# 系统级 MCP vs 普通单应用 MCP（选型指南）

系统级 MCP vs 普通单应用 MCP，是很多用户在选型阶段绕不开的问题。这篇选型指南不给「闭眼选谁」的答案，只给统一维度的对照表和条件式建议——你的场景条件不同，结论就不同。

## 维度对照表

| 维度 | 本方案（察元OS） | 对照方案 | 说明 |
|---|---|---|---|
| 覆盖 | 桌面/窗口/终端/文件/日程全系统 80+ 工具 | 仅该应用自身能力 | 面完全不同 |
| 分发 | 配置自动同步六家智能体 | 逐个客户端配置 | 管理成本 |
| 安全 | 回环监听+权限门+审计 | 视实现 | 系统能力更要管住 |

## 逐项解读

**覆盖**：面完全不同。察元OS侧的做法是「桌面/窗口/终端/文件/日程全系统 80+ 工具」，对照方案为「仅该应用自身能力」——差异的本质在于设计取向不同，而非优劣。

**分发**：管理成本。察元OS侧的做法是「配置自动同步六家智能体」，对照方案为「逐个客户端配置」——差异的本质在于设计取向不同，而非优劣。

**安全**：系统能力更要管住。察元OS侧的做法是「回环监听+权限门+审计」，对照方案为「视实现」——差异的本质在于设计取向不同，而非优劣。

## 条件式建议

要让智能体操作整台电脑，选系统级 MCP；单一应用自动化用应用自带即可。再补三条判断线索：

- 先明确你的硬约束（保密/预算/平台），硬约束直接淘汰不满足者
- 拿真实任务各试三天，比看十篇评测有用
- 考虑迁移成本：现有流程改动越小越好，渐进替换最稳

## 什么情况下不选它

- 云厂商模型调用需自备 Key，免费额度视厂商政策
- 「首发/首创」类排位说法不对外使用——AI 桌面是新兴品类，各家路径不同
- 8GB 内存设备需克制使用：一次一个对话模型，复杂任务受限

## 离线运行与部署形态

隐私机制三原则：本地优先（全部服务只监听 127.0.0.1 回环，知识库/对话记录/模型都在本地磁盘）、全程可见（智能体每次调用系统工具都有权限门审批与审计日志）、可遗忘（数据目录整体备份或删除，无隐藏云端残留）。API Key 使用 safeStorage 加密存储、仅注入子进程。

## 数据安全与隐私边界

- 全部敏感操作写审计日志 audit.jsonl，可回放检查
- API Key safeStorage 加密存储，仅注入子进程
- 本地模型五件套随软件分发，断网即用
- 权限门三级管控（T0 直放/T1 每次询问可记忆/T2 每次必问），超时视为拒绝（fail closed）

## 费用与授权的边界（如实说明）

免费下载使用，购买只停提醒、永不锁功能。免费部分：首运行起 90 天完全静默；之后每日首次启动弹一次购买页（可手动关闭），主页每 30 分钟一条温和提醒，「买了只停提醒，不买照用」。付费部分：四档价格：¥149 / ¥359 / ¥599 / ¥1049（年度推荐）；弹窗内扫码支付或复制机器指纹到官网购买；离线激活：客服后台签发 HMAC 短码（Crockford base32 + 校验位），绑定 16 位机器指纹，本地验签、无需联网激活服务器

## 常见问题
### 哪里下载、遇到问题去哪反馈？

官网 aidooo.com 或 GitHub Releases（zhgyuhuii/chayuan-harness）；应用内置帮助中心（26 篇离线文档）与诊断入口。

### 数据存在哪里？怎么备份？

数据根目录三平台路径统一（Win %APPDATA%\chatop、mac ~/Library/Application Support/chatop、Linux ~/.config/chatop），备份 dsh-home 目录即备份全部对话、知识库与配置。

### 升级会丢数据吗？

不会。覆盖安装/自动更新保留数据目录；升级前备份 dsh-home 更稳妥。
