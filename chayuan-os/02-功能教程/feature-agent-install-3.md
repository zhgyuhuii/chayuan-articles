# npm装智能体实战：补装新出的智能体

npm装智能体这件事，值不值得专门学一篇，看一个细节就够：npm 一键装 13 家。这个细节背后是一整套入口和验证链路，下面完整拆开，基于察元AI OS。

## 为什么值得了解

想在察元OS 里用 Claude Code、Codex 等编码智能体，不知道从哪里装，某个智能体（如 Aider）商店里没有安装按钮，不知道怎么装进来；批量给团队装齐智能体，已装的智能体想升级版本，或装完没在 Dock 看到图标。

## 实操全过程

入口：Dock 点「应用商店」＞ 顶部页签选「智能体」。列表共 16 行（17 家外部 CLI 中察元自家的 ZCode 不上商店），每行有图标、名称、L1/L2 徽标、安装态（「已安装 · v<版本>」或「未安装」）与安装方式明文。

升级与版本管理

1. 行尾「检查更新」按钮（仅 npm 家有）：向 npmmirror 查询该包最新版本。有新版 ＞ 行内出现琥珀色「可升级到 v{版本}」，安装按钮变为「升级」；已是新版 ＞ 灰色「已是最新」；查询失败（网络）则不显示结论。
2. 已安装的行安装按钮显示「重装」（重装与升级同链：重下当前/最新包并更新版本清单）。
3. 版本三处可见：商店行「已安装 · v<版本>」；应用管理 ＞「智能体」状态行「已检测（managed）· 版本 {x.y.z}」（managed = 察元管理态；homeDir/path = 自装命中）；升级收尾时行内进度最后显示「已升级 {智能体}@{版本}」。
4. 未安装的行若有官网，行尾有「官网」链接（经系统浏览器打开），9 家在列：Claude Code、Kimi Code、Crush、Cursor CLI、Copilot CLI、Droid、Amp、Grok Build、CodeBuddy。

装完之后：Dock 开窗即工作台

1. Dock 点该智能体图标 ＞ 打开它的应用窗口（窗口标题 = 智能体名）。
2. 首次进入是选择工作区空态：面板标题「选择工作区启动」，列出已有工作区（没有则显示「暂无工作区」），或点「选择文件夹…」（副文本「系统对话框中选择或新建」）现场选/新建目录。
3. 选定后进入工作台：顶部工作区标签条 + 终端面板，启动该智能体的原生 CLI 界面（启动动画「正在启动 {名称}…」，提示「首次启动可能需要几秒；如出现信任提示，请选择允许」），直接输入任务即可。标签条上「+」= 当前工作区新会话、「+」= 再开一个工作区；工具条还提供「附件」（选文件放入工作区并告知 CLI）与「KB 派活」（选知识库、写任务，检索片段带出处注入 CLI）。

## 关键能力点

- npm 一键装 13 家
- 官方脚本两家
- 自装自动探测
- 5 秒感知上架

## 它的局限也要说清楚

如实说明，它不是万能的：

- Docker 云桌面、跨终端互联这类进阶形态需要一点动手能力
- 8GB 内存设备建议一次只加载一个对话模型，复杂任务受限
- 暂不支持龙芯平台；本地不提供视频生成（视频生成走云端路由）
- 云端厂商模型调用需自备 API Key

## 高频疑问

### 安装报「未找到可用的 npm（环境 PATH 与 nvm/volta/homebrew 均无），请先安装 Node.js」？

本机没有可用的 Node.js/npm。先安装 Node.js，回到商店重新点「安装」。

### 安装失败（exit 非 0 或下载失败）怎么办？

多为网络问题：npm 默认走 npmmirror 镜像源，Codex 二进制与平台包补齐失败会自动换代理链重试。直接再点一次「安装」（已装一半的会重新走完整安装链，不留半成品）。

### Windows 上装 Cursor CLI 报「脚本安装暂不支持当前平台」？

脚本通道仅 macOS/Linux。按错误提示，用该家官方提供的 Windows 安装方式手动安装；装完后应用管理 ＞「智能体」＞「重新扫描」即可上架。

## 更多操作细节

第一类 · npm 包一键安装（13 家）

覆盖：Claude Code、Codex、OpenCode、OpenClaw、Gemini CLI、Qwen Code、Kimi Code、Crush、Copilot CLI、Droid、Amp、Grok Build（mac）、CodeBuddy。

1. 找到目标行（安装方式一栏显示 npm install -g <包名>，如 npm install -g @anthropic-ai/claude-code）。
2. 点行尾蓝色主按钮「安装」。
3. 安装中：按钮变为「安装中…」，该行边框转蓝，行下出现蓝色小字逐行流式显示安装输出；窗口底部同时出现等宽字体的日志条滚动累积（保留最近 30 行）。同一时间只跑一个安装，其他行的安装/升级按钮暂不可点。
4. 成功：日志条出现「{短名} 安装完成，已加入应用管理」（短名 = 行内命令名，如 claude、codex），该行安装态刷新为绿色「已安装 · v<版本>」，Dock 自动出现该智能体图标。
5. 失败：日志条出现红色「{短名} 安装失败：{原因}」，典型原因形如 {包名} 安装失败 (exit {码})：{输出末尾}；排查后再次点「安装」重试即可。
6. 个别家的额外补齐步骤（自动进行，进度可见）：
    1. Codex：npm 平台包未发布，主进程自动从 GitHub releases 下载对应平台二进制补齐（直连失败自动经代理链重试）；
    2. Amp / Droid / Crush：安装尾段自动补齐平台二进制，日志出现「已补齐 {智能体} 平台二进制」；补齐失败则整个安装按失败处理（「{智能体} 平台二进制补齐失败：…」），不留半成品。
    3. 察元的受管安装落在当前用户数据目录的 agents/<智能体>/ 下（带版本清单），与系统全局 npm 环境互不影响；行内展示的 npm install -g … 是该家官方通用安装方式的说明。
    4. 图标：商店、Dock、应用管理共用同一官方图标链（按注册表声明的官方源自动下载缓存，30 天过期重下；下载失败显示首字母占位图，不影响安装与使用）。

## 更多操作细节

第二类 · 官方安装脚本（Cursor CLI；非 mac 的 Grok Build）

1. Cursor CLI：安装方式一栏显示 curl -fsSL https://cursor.com/install | bash。点「安装」即执行该官方脚本（自带平台探测），完成后日志显示「已通过官方脚本安装 cursor」，同样自动上架。此通道仅 macOS/Linux；Windows 上点「安装」会报「该智能体的脚本安装暂不支持当前平台（请按商店展示的官方命令手动安装）」，需按官方方式手动安装。
2. Grok Build：mac 上同第一类走 npm；非 mac 系统（其 npm 平台包限制 darwin）点「安装」自动降级执行 xAI 官方脚本 https://x.ai/cli/install.sh（行内安装方式仍按 npm 展示）。

## 更多操作细节

第三类 · 自行安装后自动探测上架（Aider、Goose 等）

1. Aider 与 Goose 既无 npm 受管包也无官方脚本通道，商店行没有安装按钮（安装方式一栏为空）；按各自官方途径自行安装（装到本机即可）。
2. 装好后：Dock「应用管理」＞「智能体」＞ 点「重新扫描」（按钮变「扫描中…」）。察元按三级信号探测，任一命中即上架：
    1. ① 察元管理态（商店装的）② 家目录探针——Aider 看 ~/.aider / ~/.aider.conf.yml，Goose 看 ~/.goose ③ PATH 里能找到命令（aider / goose）。
    2. 自己用 npm install -g 等方式装的任何一家（含 13 家 npm 家）也走同样探测自动上架；版本号可能显示为 -（探测命中但拿不到版本，属正常）。

这篇把安装智能体的链路拆完了。卡住就回看常见问题那一节，多数坎都在那里。
